## Findings: what ships today

There are two different measurements: account subscription windows used for routing, and job token/cost totals. Cursor spend belongs beside these, not inside the five-hour or weekly utilization fields.

## Verified Cursor contract and limits

Official [Admin API](https://cursor.com/docs/account/teams/admin-api): Basic authentication uses the team admin key as username, empty password, at `https://api.cursor.com`. POST `/teams/spend` returns current-cycle member spend: `spendCents` is on-demand only; `overallSpendCents` includes included usage. Preserve fractional cents and `subscriptionCycleStart`. POST `/teams/filtered-usage-events` supplies model, optional token counts and `chargedCents`; sum the latter for cost, not model-only `totalCents`. Paginate fully; both time bounds are inclusive. POST `/teams/daily-usage-data` supplies daily activity, not a detailed model-cost breakdown; requests cover at most 30 days. Events and daily data aggregate hourly, so poll at most hourly.

The [API overview](https://cursor.com/docs/api) documents default limits of 20 requests/minute, 60 for usage events, and `Retry-After` on 429. Do not assume Admin POST endpoints support Analytics ETags. Team admins create the key; use the least read access the issued key permits. Do not call billing-limit write endpoints.

Plan eligibility remains a documented inconsistency: the [Teams dashboard](https://cursor.com/docs/account/teams/dashboard#api-endpoints) explicitly includes Team and Enterprise, except AI Code Tracking; the overview labels Admin API Enterprise. Target both Team and Enterprise, verify the actual read at connection time, and record a real-plan acceptance test before release. No documented individual-plan `/teams/*` path is established by these sources. Never use dashboard session cookies or private `cursor.com/api/dashboard` endpoints.

## Proposed provider boundary

Implement in Rust obid, not in agents or phone networking. There is no existing generic provider protocol to implement: today there are tool-specific quota parsers and `Asked::{Said,Silent,ModelRan}`. Keep that quota pipeline intact. Introduce an account-usage service with two independent capabilities: quota snapshots from existing CLI adapters, and spend snapshots from `CursorAdminUsageProvider`.

Suggested internal interface: `fetch(context, previous) -> Result<SpendSnapshot, UsageError>`, with injected HTTP client, clock, vault accessor and cancellation. Context names an opaque connection ID, selected member, requested interval and generation; it never serializes the key. Typed failures distinguish missing secret, rejected key, insufficient access, throttling, offline and malformed data. The service owns scheduling/persistence; the provider owns decoding and aggregation.

Add optional `cursorUsage` to account API objects, leaving every existing key and enum untouched. Suggested fields: version, source string, availability string, fetchedAt, lastAttemptAt, nextAttemptAt, stale, member identity, currency, cycleStart, optional cycleEnd, cycleTotalCents, cycleOnDemandCents, todayCents, todayStart, timezone, model summaries, coverage start/end and completeness. Availability/source are extensible strings in new optional structures, not new cases in old Swift enums. Missing numbers mean unknown. Use fixed-point decimal internally, explicit USD formatting at display time, and range/finite checks at ingestion. The response must never contain team-wide raw records or secret references that expose credentials.

Bind each Oby Cursor account explicitly to one connection and exact member identity. A searchTerm is not an identity check: paginate spend results and match the chosen member exactly. Do not infer that a Cursor CLI login has team-admin access. Prefer email filtering for events because their numeric userId differs from encoded spend/member IDs. Shared team keys may back several local accounts; schedule once per connection and fan out selected-member aggregates. Reject ambiguous mappings and purge old aggregates on account removal, member reassignment or connection replacement.

## Secret storage and connection setup

Use F17/#60's Oby-secret boundary, already represented by `core/crates/obid/src/vault.rs`: Keychain service `com.deskree.oby.runner.vault` in the Mac runner home, otherwise protected `home/vault/secrets.json` (0700 folder, 0600 file, ownership/link validation). Give each connection a name such as `oby.cursor.admin.<opaque-id>`. Config stores only that reference and member mapping.

Initially accept the key through existing `obid vault … add NAME` stdin entry. The current vault deliberately has no API taking or returning values; do not quietly add a paste field backed by a generic settings endpoint. A future protected Electron connection flow needs its own reviewed write-only local secret ingestion contract. Settings shows only connected/missing/rejected and Replace/Disconnect; there is no reveal or read-back action. Do not re-enable the launch-hidden Vault page.

Only obid's provider reads the secret immediately before an allowlisted HTTPS request. Never pass it to CLI login storage, agents, MCP, prompts, env, argv, caches, artifacts, telemetry or phone payloads. Disable cross-origin redirects and auth/header/body logging. Register both the literal secret and the exact Basic authorization encoding with redaction/scanning; test the encoding of `key:` explicitly rather than assuming existing base64 handling covers it. Run outgoing argument scanning before auth injection; the deliberate credential header goes only to the approved Cursor origin. If vault validation or scanning fails, send nothing. Record sanitized connection-use metadata, never raw API errors that might echo the key. Disconnect cancels work and removes secret/mappings/cache; rotation changes generation so old in-flight responses cannot repopulate state.

## Polling, cache and aggregation

Use one cancellable hourly worker per configured connection while obid runs. At startup load cache immediately and fetch only when due; no connection means no timer. Coalesce status reads, multiple windows and manual refresh into the same due check. Add jitter without polling faster than hourly after success. Persist next-attempt state so restarting cannot hammer the API. Sleep/wake produces one overdue refresh, not a catch-up burst.

Store normalized selected-member snapshots in a separate versioned `home/cursor-usage.json`, using private atomic storage like `Usages`. Keep no raw team responses or event bodies. Persist successful values and coverage separately from attempt/error state. Corruption resets to unknown; failed refresh retains clearly stale prior values. Mark stale after two hours without success. A missing key is unavailable immediately; 401/403 suspend retries until replacement or explicit revalidation; 429 honors Retry-After with exponential backoff/jitter, and transient errors back off with a cap. Limit concurrency to one and pace ordinary endpoint requests below 20/minute and events below 60/minute across all accounts sharing the connection. Bound pages, bytes and request duration; exceeding bounds yields incomplete, never a successful total.

First read spend to identify the cycle. Fetch all selected-member events for that cycle in bounded time slices and pages, replacing interval aggregates only when each interval is complete. Recompute current cycle on each hourly refresh initially: this handles late events without relying on undocumented stable event IDs. If scale requires incremental ingestion later, reconcile the entire cycle periodically and retain coverage state. Never deduplicate solely by timestamp/model/token tuple: distinct requests can be identical. Avoid overlapping inclusive intervals by ending each at next-start minus 1 ms. If cycleStart changes, create a new generation; never carry old model totals into it. Do not invent cycleEnd by adding 30 days.

Compute today using an explicit saved reporting timezone (default the Mac's), querying exact local-midnight bounds with DST-aware calendar arithmetic. Reaggregate on timezone change; phone timezone does not silently change the report. Sum event charged cost by model for today and cycle, with separate input/output/cache counts when present. Unknown token data is unknown, not zero. Daily activity is an optional supplementary call, split into ≤30-day ranges; it cannot supply dollar totals or a complete model breakdown by itself. Spend and event endpoints may lag differently: retain independent as-of/completeness information, and show a reconciliation difference rather than forcing totals to match.

## What the user sees

Keep Sangam's account row layout; propose Cursor-specific spend text within it and an expandable detail view in active Electron and iPhone Settings. This is a design proposal, not permission to alter the frozen Swift Mac app. Keep its existing fields compatible; schedule any native Mac feature only after an owner decision.

Show “Spend this cycle” (overall), “On-demand this cycle”, “Today” with reporting timezone, and a model breakdown with costs and available token counts. State “Updates hourly”, last successful update, stale/error and partial-coverage messages. Explain that this covers the selected member's Cursor activity across clients, not just Oby. Never show a five-hour/week bar, remaining allowance or reset prediction based on these spend fields. Monthly spend limits are not included-token allowances. Leave existing quota-based “most room”, reserve and failover decisions unchanged.

Without access show “Usage unavailable, needs an Admin API key”, with Team/Enterprise admin guidance. Invalid key and insufficient access have distinct actionable messages; offline with cached data shows that data as stale. No successful response must not look like $0. A complete, valid empty event interval may show $0; a missing member or incomplete pages may not.

Optional “Oby-run Cursor jobs” is a separate local view: count started/completed jobs and actual reported token/cost data from existing job records, tagged by account, job and attempt. Label missing coverage and “Oby jobs only”; retries/failovers must not duplicate cumulative turn totals. Do not add local estimates to Admin totals or use them as account quota. No CLI token-file or browser database scraping is needed.

2. Add opaque connection/member configuration in `config.rs`/account configuration as appropriate and vault lookup in `vault.rs`. Test protected storage, no read-back, ownership/symlink refusal, secret rotation, account deletion and exact membership matching. Add literal/Basic-header leak tests against logs, errors, API answers and agent data using synthetic secrets only.
3. Implement allowlisted HTTP provider with injected mock transport. Fixture-test auth, pagination, 401/403/429, Retry-After, timeouts, redirect rejection, fractional cents, absent tokens, partial pages, and response size bounds. No real key in tests.
4. Implement worker/cache integration in `jobs.rs` and lifecycle in `lib.rs`. Fake-clock tests cover hourly coalescing, persisted due times, wake, retry caps, cancellation, stale retention, corrupt cache and rejection of old generations after disconnect. Verify no work without a configured connection.
5. Test aggregation across billing rollover, inclusive midnight boundaries, DST days, >30-day daily ranges, late events, identical legitimate events and endpoint lag. Confirm unavailable/partial never becomes zero or changes quota routing.
6. Extend account serialization/broadcast in `accounts.rs`/`api.rs` and shared optional decoding in `apps/shared/Runner.swift`. Test status/event parity and new-server/old-Swift compatibility. Extend iPhone `Usage.Snapshot`/Settings without changing existing Claude/Codex rules; add focused iOSTests/shared presentation fixtures for unavailable/stale/partial/accessibility and currency formatting.

Run its typecheck and focused renderer checks; compare the proposed detail against Sangam's design before implementation. No Swift Mac feature work. Optional local job totals come afterward, reusing `job.rs`/`acp.rs` accounting and testing repeated cumulative events and retries.
8. Run the repository's touched-suite check and clean secret scan.
