How artifacts are shared today, and where Oby fits

Claude makes great artifacts, but they live and get shared inside Claude: an org, a list of invitees, or a public link that can only be looked at. Nobody's agent can answer anybody else's. Oby already keeps artifacts on the Mac, and already has a way for Obys to talk. Joining the two is a small step, and it's the part nobody else has.

The verdict, so far

Worth testing

Sharing across people, tools and companies, with answers coming back as words, is a gap in Claude, T3 Code and MCP Apps alike. It fits Oby's own idea: trust between different people's agents.

Mostly built

obid stores versioned artifacts (html, markdown, image, pdf, canvas), secret-scans them and serves them sandboxed. The Sphere already carries sealed asks and answers. Missing: an artifact as something one Oby sends another.

Risks to check

Claude has no public artifacts API; the bridge has to go through the owner's own Claude Code, and its artifacts are off by default in headless runs. Public links need a host; local first says the owner's own Sphere.

What makes it “100% Claude compatible”

  • Keep Claude's own files. A Claude Design canvas is a canvas.json plus one .dc.html file per artboard; a Claude Code artifact is one .html or .md file. Oby keeps them as they are, so they can go back to Claude unchanged. Oby's own canvas kind needs to read Claude's canvas.json, or keep it beside its own.
  • Move them with the owner's Claude Code. Claude has no public API for artifacts (only an admin Compliance API). Claude Code's Artifact tool reads and publishes them on the owner's own login, so that's the bridge, and Oby still never touches a Claude login. Artifacts are off by default in claude -p runs: the first spike.
  • Render Claude's runtime. A .dc.html board needs Claude's support.js runtime to draw. Oby can show a Claude canvas through a public Claude link, or render a static export (Claude Design exports standalone HTML and a project zip). Which one is the second spike.
  • Speak MCP Apps. It's the open way agents show interactive UI, in Claude, ChatGPT and VS Code. Showing an MCP App as an Oby artifact keeps Oby vendor agnostic.

The smallest test

  1. “Send this to Ben”, or Share › Ben: one artifact version for one member, as a new typed exchange on the Sphere (Ben's protocol). His Oby keeps the copy in its own store and shows it on Home.
  2. What Ben says comes back through the ask and answer that already exist (ASK, PEER contracts): quoted, never acted on. A yes, a no and ideas are just answers; there's no approval workflow.
  3. “Bring this in”: the owner's Claude Code reads a claude.ai artifact link and obid stores the files, scanned like any artifact.
  4. Later: send back to Claude, public links from the owner's Sphere, and the animated Oby invite.
