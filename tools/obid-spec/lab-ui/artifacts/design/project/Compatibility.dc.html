Research · how it works underneath · 20 November 2026

Claude's artifacts are files. Oby can keep the same files, and draw them itself.

Read from the files of this very canvas (its index, its boards, and the Design type's runtime and format guide, which every canvas serves), Claude Code's artifact docs and T3 Code's source. What's confirmed is marked; what needs a spike says so.

1. Two kinds of Claude artifact

A page

One .html or .md file, versioned, at claude.ai/code/artifact/<id>. Claude wraps it in a shell on a sandboxed claudeusercontent.com origin under a strict policy: scripts only from cdnjs, unpkg, jsDelivr /npm/, Tailwind's and jQuery's CDNs; fonts from Google; images as data or SVG; 16 MiB at most. A page can also ask for runtime capabilities at publish (a shared database, who's viewing, comments, downloads, connectors, asking Claude) through window.claude: those exist only on Claude.

An artifact made from a type

Design, Design System, Slides and others are types: a fixed editor page (its index.html, app.js, dc-runtime.js) that reads the artifact's own files under project/. A Claude Design canvas is exactly those files plus pictures kept by id in an asset store (/_blob/<id>). Confirmed: this canvas is one.

The runtime (dc-runtime.js, 198 KB) is React 18, which is MIT, plus Anthropic's own code, which has no license. It parses the template into React elements, draws a template while it's still streaming in (the hint-* attributes), and talks to Claude's editor over postMessage (design mode, edits, errors). Oby doesn't copy it. Oby writes its own runtime for the same format, open source, from the format alone.

5. Moving between Claude and Oby

  • Claude has no public API for artifacts; its Compliance API is for admins. Claude Code's own Artifact tool is the way in and out: it reads any file of an artifact by path, uploads assets, creates an artifact from a type (Design) with files under project/, and publishes new versions to the same link. Confirmed: this canvas was built that way.
  • So the owner's own Claude Code, on their own login, does the moving, as a job in the own lane. Oby never holds a Claude login.
  • Spike: Claude Code's docs say artifacts are off by default in claude -p runs, which is how Oby starts Claude Code. Find the setting that turns them on there, or carry the move another way.

6. Agents without Claude

“Make this an Oby artifact” has to work with Codex or Cursor alone. T3 Code solved the same thing for every provider: its own MCP server gives each agent html_preview (render the page in a headless browser, return a picture, its height and the console) and html_render (show it in the thread). Its pages get the app's theme as CSS variables and speak the MCP Apps messages (ui/notifications/size-changed, ui/open-link, host-context-changed). MIT, read on main at 1c379b63.

  • One tool for every agent. obid already gives every owner's job its own MCP server (Tetrix's tools). Add oby_artifact, which conversations already have, and oby_artifact_check, so Claude Code, Codex and Cursor all publish the same way. Jobs keep .obi/artifacts/.
  • One format guide. Oby's own written guide to the canvas format, given to whichever agent makes the artifact. The format is plain HTML, a small template language and one JavaScript class: any good model can write it.
  • Oby draws it. Its runtime renders the result, so nothing needs Claude Design. Claude only comes in when the owner picks Claude artifacts, or sends one there.
  • MCP Apps on the outside. A page that speaks MCP Apps also shows inside Claude, ChatGPT and VS Code, so an Oby artifact isn't tied to Oby either.

7. Spikes, in order

  1. Oby's runtime draws this canvas's ten boards like Claude does, compared board by board in pictures.
  2. Codex and Cursor each make a canvas from the guide alone, and it draws without errors.
  3. Claude Code in a headless run reads a Claude canvas into obid, and publishes one back to the same link.
  4. A Claude page that loads a CDN script runs in Oby offline, after its import.
  5. With Ben: an artifact as something one Oby sends another in the Obysphere.

Reading a file format to stay compatible is ordinary; shipping Anthropic's runtime is not, so Oby's runtime is written fresh. Worth a short legal look before launch.
