# refactor(electron): conversations, turns and inbox items through the reducer, by revision

<!-- Roadmap R06-07 · Sprint 4 · R06 Events that clients only apply · effort M · risk medium -->

### Sangam's screen

uses an existing screen: apps/electron/src/renderer/src/ChatView.tsx, AskCard.tsx and Sidebar.tsx (no visual change)

### Outcome

Every object obid sends reaches the Mac app through the same reducer and the same 'newer revision wins' rule, so an older answer can never undo a newer event for any kind.

### Status and scope

Proposed (roadmap R06-07, milestone R06 Events that clients only apply).

**Why:** Turns merge by id (live.ts:105, :559), conversations replace by id (live.ts:603), inbox items replace by id (live.ts:548), and sync() special-cases a restart (live.ts:754-760). This is the race class of #1707 and #1709 for the kinds that have no guard.

**In:**
- `conversation`, `conversationGone`, `turn`, `turnAsks`, `inbox`, `accounts`, `github` and the status into live-state.ts, with the revision rule (no revision: taken as it comes).
- REST reads (GET /v1/conversation, /v1/conversations, /v1/inbox, /v1/jobs, /v1/status) go through the same `apply` as snapshots.
- sync()'s merge rules replaced by snapshot-then-pending-events through `apply`.

**Out:**
- The optimistic fields (R06-10, R06-11).
- `step`, `delta`, `roomPost`, `peerThread`, `transcript`: they stay view-side, forwarded as they are.

### Actors and ownership: what obid owns

- Revisions of conversations, turns and inbox items (R06-03).

### Actors and ownership: what the apps show and send

- Nothing changes for the owner.

### Steps

- Add `revision?: number` to Conversation, Turn and InboxItem in shared/obid-wire.ts.
- Move each case from live.ts's `apply` into live-state.ts with its test (LIVE-5 to 9); prove LIVE-5 red without the rule.
- Make sync() build one snapshot and apply pending events through `apply`; delete its special cases.
- Keep `publish()` feeding chats.ts and tasks.ts unchanged.
- Run `npm test`, and on a real Mac `npm run test:core` and `npm run test:chat-first`.

### Acceptance scenarios

- LIVE-5 (proposed): Given turn T at revision 3 from an event, when GET /v1/conversation answers T at revision 2, then T stays at revision 3.
- LIVE-6 (proposed): Given inbox item I answered on the iPhone (event at revision 4), when the Mac's own older answer arrives at revision 3, then the card shows the iPhone's answer.
- LIVE-7 (proposed): Given a conversation deleted on another device, when an older conversation list arrives, then the conversation stays deleted.
- LIVE-8 (proposed): Given a reconnect, when the snapshot and the events that came during its read are applied, then the state equals obid's newest copy of every object.
- LIVE-9 (proposed): Given objects without `revision` (an obid before R06-03), when they come, then they are applied in arrival order as today.
