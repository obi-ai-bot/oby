# feat(obid): export what Oby learned, with every secret cleared

<!-- Roadmap R12-12 · Sprint 9 · R12 Developer workflows · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

The owner writes one file with memories, learned workflows, routines, repository settings and profiles, and no secret or login can be in it.

### Status and scope

Proposed (roadmap R12-12, milestone R12 Developer workflows).

**Why:** #1300: no export route exists (grep of core/crates/obid/src); docs/install.md has a manual copy list for moving Macs.

**In:**
- POST /v1/export to a folder the owner names: write `oby-export-<date>.zip.part`, rename when complete.
- Manifest `oby-export.json`: `format: oby-export`, `version: 1`, obid version, sections memory, workflows, routines, repos (settings and checks, no clones), profiles, and a `cleared` list.
- Never include `api-token`, `vault/`, `keys/`, `logins/`, `accounts/`, `devices.json`, `gateway-devices.json`, `push/`, `sphere/`, `memory/declined.jsonl`.
- Empty values whose names match one secret-name pattern in config values, check commands and MCP arguments; strip user and password from URLs; list each in `cleared`.
- Scan the whole archive with crate::secrets and gitleaks before the rename; a finding or a scan that cannot run writes nothing.

**Out:**
- Import (R12-13).
- Conversations, transcripts and jobs.
- The Settings screen (#1301).

### Actors and ownership: what obid owns

- What goes in, the clearing, the scan and the atomic rename.

### Steps

- Define the manifest types with serde and a version check.
- Write an allowlist of what goes in (never a denylist of what stays out).
- Write the clearing function once and test it on config, checks and MCP arguments.
- Zip to `.part`, scan, then rename.
- Document it and shorten docs/install.md's copy list.

### Acceptance scenarios

- MOVE-1 (proposed): Given a home with memories, routines and repos, when POST /v1/export completes, then the zip has the manifest with `version: 1` and those sections, and no `.part` file is left.
- MOVE-2 (proposed): Given a home with a vault, devices, logins and a Sphere membership, when it is exported, then none of those files is in the archive.
- MOVE-3 (proposed): Given a check command with `API_KEY=abc` and an MCP URL with a password, when exported, then both are emptied and both are in `cleared`.
- MOVE-4 (proposed): Given a secret the name pattern misses, when the scan finds it, then no file is written and the answer says why.
- MOVE-5 (proposed): Given the scanner cannot run, when export runs, then nothing is written.

Contract: new: docs/contracts/moving.md (prefix MOVE)
