# feat(obid): take over a job, with one hold guard at the lowest point

<!-- Roadmap R12-07 · Sprint 9 · R12 Developer workflows · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

The owner takes a stopped or finished job, gets the exact command to resume its session in Terminal, and obid touches neither its worktree nor its session while they hold it.

### Status and scope

Proposed (roadmap R12-07, milestone R12 Developer workflows).

**Why:** #611 and #986: no route hands a job off, and no hold exists (no `takenOver` in job.rs or jobs.rs). Without one guard, a round, rebase, publish or cleanup can run while the owner edits the worktree or resumes the same session file.

**In:**
- POST /v1/jobs/{id}/take-over: sets `takenOver` (time, by) in the job file; a queued or running job is stopped first, as Stop does.
- GET /v1/jobs/{id}/handoff: worktree path, tool, session id and the exact command (`cd <worktree> && claude --resume <session>`, Codex's resume), with `CLAUDE_CONFIG_DIR` or `CODEX_HOME` set to the account's folder path, never a token.
- One function `hold::guard(job)` that every step must pass: round start in the worker, follow-up, Try again, publish, merge, rebase round, cleanup, archive, delete. Steps that waited (a queued check, a merge waiting on GitHub, admission) call it again when the wait ends.
- obid's own steps are refused while held and leave the job as it was. An owner's explicit action (Try again, Publish, Delete) on a held job ends the hold first and is recorded, because Oby forbids nothing.

**Out:**
- Hand back (R12-08).
- The buttons (R12-09).
- Jobs in Oby's box: their session is in a private login copy; `handoff` answers 409 with why until a follow-up moves the transcript (#986).

### Actors and ownership: what obid owns

- The hold, its guard, the handoff command and the record in the job's changes.

### Actors and ownership: what the apps show and send

### Steps

- Add `takenOver` to Job and persist it.
- Write `hold::guard` and call it from the transition layer (R04) so every step passes it; list every caller in the test.
- Add the re-check after each wait (queued check, merge wait, admission).
- Add take-over (stop first) and handoff routes; build the command from the job's tool, session and account folder.
- Make the owner's own actions end the hold first and record it.
- Write takeover.md and runner-api.md.

### Acceptance scenarios

- TAKEOVER-1 (proposed): Given a held job, when any of obid's own steps (round, follow-up, Try again by rule, publish, merge, rebase, cleanup, archive) reaches it, then it passes through `hold::guard` and does nothing, and a test lists the guard's callers.
- TAKEOVER-2 (proposed): Given a merge that waited on GitHub, when the owner takes the job over during the wait, then the merge does not run when the wait ends.
- TAKEOVER-3 (proposed): Given a held job, when obid restarts, then the job is still held.
- TAKEOVER-4 (proposed): Given an own-lane Claude Code or Codex job, when GET /v1/jobs/{id}/handoff is read, then it returns the worktree, session and command, and no token or vault value (a test fails if one appears).
- TAKEOVER-5 (proposed): Given a held job, when the owner clicks Try again, then the hold ends first, the job's changes say so, and Try again runs.
- TAKEOVER-6 (proposed): Given a running job, when take-over arrives, then the job stops as Stop does before `takenOver` is set.
