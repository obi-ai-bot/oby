### Sangam's screen

engine only

### Outcome

Every later R04 refactor runs against a fixed record of what Stop, Try again, Another round, a finished run, a failed run, a limit wait and a restart do today, so a behaviour change shows as a red test, not as a bug report.

### Status and scope

Proposed (roadmap R04-02, milestone R04 One owner for job state).

**Why:** jobs.rs took 111 of the last 250 fix commits. The end-state decision is an OR of four conditions in an update closure in `work` (jobs.rs:7197-7222); next_round clears 17 fields by hand (jobs.rs:14231); the restart path in Jobs::open (jobs.rs:1138-1260) writes status without update(). None of these has a test that names the full set of side fields it touches.

**In:**
- Unit tests in job.rs/jobs.rs test modules for the pure parts: next_round's exact field list, the needs_you/failed decision for each End variant (Failed, NeedsYou with and without session, AccountLimit, Asked, hands_over), end_done on an inactive job.
- API tests with fake-claude in tests/jobs_api.rs for: Stop of a running job, Try again after failed/interrupted/stopped, Try again on a never-started job (today: refused), Another round (review_round_again), words to a done job (follow-up), dismiss, move.
- A restart test in tests/long_jobs.rs: a Running job file with and without session, cut, phase Check.
- A table in new docs/contracts/job-state.md listing each pinned behaviour as JOBSTATE-n, status 'implemented (characterized)'.
- A `state_owner` test that counts status writes, jobs.rs store.save( calls and branch-carry comparisons, with today's counts as a shrink-only ratchet.

**Out:**
- Changing any behaviour, including the known #1649 race: the race test is written and marked #[ignore = "#1649"] until R04-04.
- Real CLI runs.

### Acceptance scenarios

- JOBSTATE-1 (proposed): Given a running job, when the owner stops it, then its status is stopped at once, stoppedBy is set, waiting, resumesAt and unjudged are empty, and finished is set.
- JOBSTATE-2 (proposed): Given a failed job with a session, when the owner sends the Try-again words, then it is queued with round+1, and finished, dismissed, archived, limit, reason, stoppedBy, nextStep, resumesAt, unjudged, stalled, waiting and the account-limit fields are empty.
- JOBSTATE-3 (proposed): Given a run that ends NeedsYou with a session, when the worker ends, then the job is interrupted with nextStep kept; given the same end with no session and tries left, then it is failed with nextStep empty.
- JOBSTATE-4 (proposed): Given a job file left running with a session and no cut, when obid starts, then the job is queued and continues in its session, and recovery.restarts grows only on an unclean stop.
- JOBSTATE-5 (proposed): Given a job whose follow-up on the same branch is at work, when the owner sends the Try-again words to the first job, then obid refuses with 409 and the job does not change.
- JOBSTATE-6 (proposed): Given a job that never started (no session, no moves), when the owner sends the Try-again words, then obid refuses with 409 (today's behaviour; R04-06 changes it).
