# feat(obid): Try again and brain-made follow-ups carry a command id

<!-- Roadmap R02-06 · Sprint 1 · R02 Commands that are safe to repeat · effort S · risk medium -->

### Sangam's screen

engine only

### Outcome

A brain tool call that the CLI repeats, or a Try again that obid itself sends twice, starts one round or one follow-up.

### Status and scope

Proposed (roadmap R02-06, milestone R02 Commands that are safe to repeat).

**Why:** brain/actions.rs `message_job` calls `follow_up` (actions.rs:727) which calls shared.jobs.create with no key; `dispatch` (actions.rs:272) creates at 320 the same way. Try again's words go through message_as (jobs.rs:4086) and `next_round` (jobs.rs:14231) with no check that this press was already applied. #1851.

**In:**
- Key for brain-made work: conversation turn id + tool call id (or + the tool's arguments hash if the call id does not reach obid).
- Key for Try again: job id + the revision the press was made on; a press on a revision already moved past answers with the job as it is.
- Store the key on the job it made (`requestId`).

**Out:**
- The UI card that groups a failing chain in Needs you (#1851's second to-do: needs Sangam).
- Storing the task chain (R04).

### Actors and ownership: what obid owns

- The command id rule in jobs.rs and brain/actions.rs.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Interfaces and dependencies

- Job JSON: optional `requestId` (shared with R02-05).

### Steps

- Find whether the MCP `tools/call` id reaches brain/tools.rs `call`; if not, use turn id + tool name + arguments hash.
- Pass the key into NewJob in `message_job`, `follow_up` and `dispatch` (brain/actions.rs).
- In message_as, for Try again's words, check the receipt for job id + revision before next_round.
- Write RECEIPTS-12 to 14.

### Acceptance scenarios

- RECEIPTS-12 (proposed): Given a conversation turn whose oby_tell_job to an ended job started a follow-up, when the same call comes again in that turn, then no second follow-up starts and the tool answers with the first.
- RECEIPTS-13 (proposed): Given an ended job at revision R, when Try again for revision R arrives twice, then the job runs one more round.
- RECEIPTS-14 (proposed): Given oby_dispatch called twice with the same call in one turn, then one job starts.
