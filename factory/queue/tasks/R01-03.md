# chore(factory): a red nightly run on dev pauses the factory's merges and becomes a fix task

<!-- Roadmap R01-03 · Sprint 1 · R01 Safety net · effort S · risk low · rewritten 2026-11-13 by docs/ci-architecture.md -->

### Sangam's screen

engine only

### Outcome

When last night's Linux run on dev is red, the factory doesn't merge anything else into dev until a fix has merged. It says which tests failed, and the orchestrator writes one fix task for them. So the nightly run is read by the one actor that merges all day, rather than by nobody.

### Status and scope

Proposed (roadmap R01-03, rewritten by docs/ci-architecture.md). The owner chose "nightly only" on 2026-11-13: no merge queue and no required check on dev, so a break that only shows up once changes are combined is found at night. This task is what makes that safe.

**Why:** before #2166, every GitHub run was red for weeks and nobody noticed, because nothing read them. A nightly run with the same fate would be worse than none.

**In:**
- `factory/bin/job merge`, before it merges: read the latest `schedule` run of the Linux workflow on dev (`gh run list --workflow linux.yml --branch dev --event schedule --limit 1 --json conclusion,headSha,databaseId,createdAt`)
- When that run failed and no pull request merged into dev after its `headSha` fixes it (a task file whose `FIXES` names the run, or the owner's word), the job goes to `needs-human` with the run's link and the failed tests' names (from R01-02's summary, else `gh run view --log-failed`, the last 80 lines, quoted as data)
- `job queue` prints `nightly red: <run>` while it is; the orchestrator writes one task file `A00-<n>.md` naming the tests, uncommitted, once per red run
- The owner's word lifts the pause for one merge (`job feedback`, as for any needs-human job): "Oby forbids nothing"
- R01-14's Mac nightly result pauses merges the same way

**Out:**
- Branch protection, required checks or a merge queue on dev (not chosen)
- Opening GitHub issues (the factory reads and writes none)

### Steps

- Add the nightly read to `cmd_merge`, one `gh` call per merge.
- Add the fix rule and the needs-human message.
- Make `job queue` show the red night; teach SKILL.md to write the fix task once per red run.
- Prove it with a real or forced red night; link it.

### Acceptance scenarios

- CI-7 (proposed): Given the latest nightly run on dev failed and no fix merged since its commit, when `job merge` runs, then the job goes to needs-human with the run's link and failed tests, and nothing merges.
- CI-8 (proposed): Given the latest nightly run passed, or a fix merged after a red one, when `job merge` runs, then it merges as before, with one more `gh` read.
- CI-21 (proposed): Given a red nightly run, when the orchestrator next lists the queue, then exactly one fix task file names that run's failed tests.
