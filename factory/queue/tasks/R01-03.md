# chore(process): a merge into dev waits for Check and the Mac check

<!-- Roadmap R01-03 · Sprint 1 · R01 Safety net · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

No pull request merges into dev, by Oby or a person, until GitHub's Check is green on its head; Oby's own Mac check still runs before it publishes. Oby needs no new code: it already waits for a head's checks and merges pinned to that head.

### Status and scope

Proposed (roadmap R01-03, milestone R01 Safety net).

**Why:** dev and main have no branch protection (gh api .../branches/dev/protection: 404). obid already reads statusCheckRollup (github.rs:431), holds on a failed check (MERGING-39), asks when checks run past an hour (MERGING-5), arms auto-merge pinned to the head when GitHub reports BLOCKED (MERGING-41, merge.rs:1647) and merges by REST with `sha: head` (merge.rs:1577). Without a required check, an empty rollup merges at once.

**In:**
- Branch protection on dev and main with Check as the only required status (owner step)
- AGENTS.md 'How we work' and docs/ci.md: Check green and the Mac check both gate a merge into dev
- One real Oby job on this repository proving the hold

**Out:**
- Code changes in obid (none needed)
- A self-hosted Mac runner for the Apple suites

### Actors and ownership: what obid owns

- Nothing new: the existing MERGING-5, 39 and 41 behavior.

### Actors and ownership: what the apps show and send

- Nothing changes for clients: the Merged stage already says 'GitHub will merge it when its checks pass'.

### Files

- AGENTS.md
- docs/ci.md
- docs/contracts/merging.md

### Steps

- After R01-02 has run green on dev at least once, the owner adds branch protection on dev and main: required status Check, not strict about up-to-date.
- Update AGENTS.md 'How we work' and docs/ci.md: a merge into dev needs Check green on the head and the repository's Mac check (scripts/oby-check.sh) passed on the same commit.
- In docs/contracts/merging.md, add a one-line cross reference from MERGING-41 to CI-7.
- Dispatch one small Oby job on obi-ai-bot/oby; record that it was armed for auto-merge and merged after Check; link the job and PR.

### Acceptance scenarios

- CI-7 (proposed): Given dev requires Check and Oby has learned to merge into dev, when Oby's job's PR passes the Mac check but Check is still running, then obid arms GitHub's auto-merge pinned to that head (MERGING-41) and the PR merges only after Check is green.
- CI-8 (proposed): Given Check fails on the head, when obid reads the PR, then it does not merge and starts one fix round (MERGING-39).

Contract: new: docs/contracts/ci.md

### Tests

- Existing merge_api::merging_41_github_holds_it_so_obid_arms_auto_merge_pinned_to_the_head covers CI-7's obid side; the real-PR run is the end-to-end proof.

### Done when

- gh api repos/obi-ai-bot/oby/branches/dev/protection lists Check as required.
- One Oby PR into dev merged by GitHub's auto-merge after Check passed, linked in the PR body.
- `scripts/oby-check.sh` passes.
