## What
Every factory step runs on one account today: `oby-feed` starts each build on `--account` (default `deskree-team`), and obid's reviewer rule picks the reviews by itself. The owner uses Claude Code, Codex and Cursor accounts and wants to choose, per step, which account and model runs it. One file per project, `factory.json` (schema `oby.factory/1`), says so.

## Why
- **The owner's idea:** "factory settings as a JSON file that we can change visually with options." The owner's answer (2026-11-15): one file per project, kept by obid.
- **Mixing tools per step is what no other product offers** (research in docs/design/oby-slash-and-factory-settings/README.md, §1 and §3.3).

## How
1. The file: `profiles/<profile>/projects/<project>/factory.json` in obid's home, 0600, written whole by rename. Its shape is in docs/design/oby-slash-and-factory-settings/README.md, §3.2: `steps.intake|spec|build|approve` with `tool`, `account`, `model`, `effort` and `byRisk`; `steps.gate` and `steps.prove` (`runsOn`, `shards`, `mode`, `timeoutS`); `steps.review.code|ux|ui|security|proofs` with `when`; `steps.review.second`; `whenFull` (`wait` or `any`); `preset`; `concurrency`; `rounds`.
2. `GET /v1/projects/{id}/factory/settings` → `{settings, revision, options, hints}`. `options`: each tool's accounts in this profile, with the models and efforts `GET /v1/settings/models/options` already lists. `hints` come from B00-10 (null until then).
3. `PUT` with `{settings, revision}` → `200 {revision}`, `409` on a stale revision, `422 {problems: [{path, message}]}` for an unknown key or tool, an account not in this profile or not that tool's, a model not in that account's options, an effort the model doesn't take, or an unknown `when` surface. Never a silent fix. `?dryRun=1` checks without saving (B00-09's JSON view).
4. No file: the answer is the Careful preset, built from today's `factory/config.json` routing and `.claude/agents/*.md` models, at `revision: 0`.
5. A preset changes who runs a step and its effort, never a gate (`gate`, `prove`, protected paths, the two reviews a security path needs): the research is in docs/design/oby-slash-and-factory-settings/README.md, §3.3.

### Formal verification
A Kani harness over the pure check: for every settings value, it either answers a list of problems or a value whose every model is in its account's options (no value is both saved and invalid).

Acceptance (each scenario a test named after it; time faked through the existing hooks, never a sleep):
1. FACTORYSET-1 (`factoryset_1_no_file_is_careful`): `GET` on a project with no file answers the Careful steps with `revision: 0`.
2. FACTORYSET-2 (`factoryset_2_a_bad_model_is_named`): `PUT` with `steps.review.second.model: "gpt-6"` on an account whose options lack it answers `422` with path `/steps/review/second/model`, and the file is byte-identical.
3. FACTORYSET-3 (`factoryset_3_stale_revision`): `PUT` with a stale `revision` answers `409` and writes nothing.
4. FACTORYSET-4 (`factoryset_4_another_profiles_account`): an account of another profile answers `422`.
5. FACTORYSET-5 (`factoryset_5_file_mode_and_rename`): the file is 0600, and a crash between write and rename leaves the old file whole.
