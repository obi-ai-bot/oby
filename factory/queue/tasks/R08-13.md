# refactor(obid): one login_copy and one strip in place of the per-tool login-copy families

<!-- Roadmap R08-13 · Sprint 7 · R08 One interface for every agent CLI · effort M · risk high -->

### Sangam's screen

engine only

### Outcome

A boxed run's private login copy is made by one function from the row's `LoginLayout`, so the refresh-token rule is written once and a table test proves no tool's copy keeps one.

### Status and scope

Proposed (roadmap R08-13, milestone R08 One interface for every agent CLI).

**Why:** jobs/logins.rs (3,911 lines) has `without_refresh` (1173), `codex_without_refresh` (1878), `cursor_without_refresh` (1907), `copy_cursor` (2248), `copy_account_login` (2132), `copy_account_folder` (2169) and `copy_login` (2303), each stripping its own way; 10 fix commits on the file. Map: 'Login refresh is fragile and keeps being reworked' (high).

**In:**
- `login_copy(account, layout) -> PrivateCopy` and `strip(layout, value)` in jobs/logins.rs.
- Delete `without_refresh`, `codex_without_refresh`, `cursor_without_refresh`, `copy_cursor` and their twins.
- A table test over every layout: no copy keeps a refresh token or a file outside `keep`.

**Out:**
- Any change to which login is read, when it is refreshed, or which runs get a copy.
- Own-lane runs (no copy, LANE-1, LANES-12/13/18).

### Actors and ownership: what obid owns

- What a boxed run's login copy holds.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Steps

- Before any change, run every KEYCHAIN-* and ACCOUNTS-18 test and the logins.rs tests (`a_keychain_copy_carries_no_refresh_token`, `no_codex_login_copy_carries_a_refresh_token`, `a_cursor_login_copy_has_no_refresh_token`, `claude_json_is_trimmed_to_the_auth_keys`, `a_codex_job_gets_its_login_and_not_its_config`) and record the names.
- Write KEYCHAIN-11 and ACCOUNTS-22 as golden tests against today's functions first; they must pass on dev before the change.
- Write `login_copy` and `strip`; switch callers one tool at a time, the golden tests green after each.
- Delete the replaced functions.
- Lower `obid_lines_limit` by the lines removed; request two reviews by different tools (security path).

### Acceptance scenarios

- KEYCHAIN-11 (proposed): Given every provider's `LoginLayout` and a login holding an access token, a refresh token and other fields, when obid makes a boxed run's copy, then the copy holds only the layout's `keep` fields, never a refresh token, and is byte-for-byte today's copy for the same input.
- ACCOUNTS-22 (proposed): Given a Codex `auth.json`, a Cursor login file, a Cursor Keychain login and a Claude Code Keychain login, when obid copies each, then Codex's has `tokens.refresh_token` set to `""`, Cursor's holds only `accessToken` and `apiKey`, and Claude Code's carries only what calls the API.

Contract: docs/contracts/keychain.md (existing, last KEYCHAIN-10) and docs/contracts/accounts.md (existing)
