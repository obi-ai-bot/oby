# chore(process): changelog.d notes per PR and an upgrade-safety audit before each tag

<!-- Roadmap R09-15 · Sprint 8 · R09 Ship and debug safely · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

Every PR into dev carries a short note; a release collects them into CHANGELOG.md. Before a tag, a written audit checks stored shapes, API removals, Swift closed enums and a real update from the last release.

### Status and scope

Proposed (roadmap R09-15, milestone R09 Ship and debug safely).

**Why:** There is no CHANGELOG or per-PR note; nothing checks before a tag that a job file, config, vault or accounts shape still loads, while the Swift iPhone app needs an add-only API (AGENTS.md).

**In:**
- changelog.d/<branch>.md per PR, with a README in changelog.d/ for the format.
- new: scripts/changelog.sh collects and removes them at release.
- A CI job that fails a PR into dev with no note unless it has the `no-changelog` label.
- new: .claude/skills/upgrade-safety/SKILL.md: the audit list (released-shape fixtures, the API snapshot, Swift closed enums, a real update from the last release on a Mac), run before R09-14's tag.

**Out:**
- Writing the shape fixtures and API snapshot themselves (R01).

### Steps

- Write the note format and the collector.
- Add the CI job and the label.
- Write the audit skill in Oby's own words, naming R01's fixtures and snapshot.
- Test RELEASE-4 and 5 in scripts/oby-check-test.sh style.

### Acceptance scenarios

- RELEASE-4 (proposed): Given a PR into dev with no changelog.d file and no `no-changelog` label, when CI runs, then the notes job fails.
- RELEASE-5 (proposed): Given three notes in changelog.d, when scripts/changelog.sh runs for version X, then CHANGELOG.md gains one X section with the three and changelog.d is empty.

Contract: docs/contracts/release.md (from R09-14)

### Done when

- The job fails a test PR without notes and passes one with the label.
- The audit ran once before a real tag.
