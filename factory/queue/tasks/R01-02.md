# chore(ci): the nightly run uses nextest, keeps a JUnit report and names flaky tests; Electron joins it

<!-- Roadmap R01-02 · Sprint 1 · R01 Safety net · effort S · risk low · rewritten 2026-11-13 by docs/ci-architecture.md -->

### Sangam's screen

engine only

### Outcome

The nightly Linux run on dev tells exactly which tests failed and which passed only on a retry. It keeps a JUnit report as an artifact, and its step summary lists failed and flaky tests by name: what R01-03's factory check reads. The Electron app's typecheck, tests and build join the nightly run.

### Status and scope

Proposed (roadmap R01-02, rewritten by docs/ci-architecture.md). GitHub runs tests nightly only (the owner's decision of 2026-11-13), so there is no merge queue, no sharding and no required Check: one nightly run's time holds nobody up.

**Why:**
- `cargo test` prints failures only in a long log, with no report a program can read.
- It can't retry a known flaky test, so one flake turns a whole night red.
- No Linux run covers the Electron app.

**In:**
- In linux.yml, `cargo test` becomes `cargo nextest run --workspace --locked --profile ci --no-fail-fast`, with a pinned nextest (`taiki-e/install-action` by SHA)
- new `core/.config/nextest.toml`: a `ci` profile with JUnit output, `slow-timeout`, and the override block R01-13 fills
- Upload `target/nextest/ci/junit.xml` (retention 14 days)
- A step summary listing failed tests and tests that passed only on a retry
- An Electron job: Node 22, `npm ci`, typecheck, test, build, in apps/electron. It runs nightly, from `workflow_dispatch`, and with the `full-ci` label.

**Out:**
- Per-pull-request tests (the owner's "nightly only")
- The flaky list's entries (R01-13)
- macOS, larger or self-hosted runners

### Steps

- On a throwaway branch with `workflow_dispatch`, run nextest once and compare it with `cargo test`. nextest runs each test in its own process: watch `tests/swift_client.rs`'s per-process build and anything relying on shared state. If nextest can't run obid's tests as they are, keep `cargo test`, parse its output for the summary, and say so.
- Add the profile, the upload, the summary and the Electron job.
- Prove a red night and a flaky test (one made to fail on its first attempt only) on throwaway branches; link the runs.

### Acceptance scenarios

- CI-3 (proposed): Given a nightly run where one test fails, when it ends, then the run is red, its summary names the test, and its JUnit report is an artifact.
- CI-4 (proposed): Given a listed test that fails once and passes on retry, when the nightly run ends, then it is green and its summary lists the test as flaky.
- CI-5 (proposed): Given a nightly run, then the Electron app's typecheck, tests and build run in it.
