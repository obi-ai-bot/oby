# chore(ci): path lanes, a sharded obid suite and one required Check job

<!-- Roadmap R01-02 · Sprint 1 · R01 Safety net · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

A pull request runs only the lanes its paths reach, the obid suite finishes in under 30 minutes over parallel shards, and one job named Check says pass or fail for the whole run. Each run keeps a test report as an artifact that a PR can link.

### Status and scope

Proposed (roadmap R01-02, milestone R01 Safety net).

**Why:** linux.yml runs every job on every PR (a docs change waits for the full Rust suite) and has no single status to require. The rust job runs `cargo test --workspace` in one job with a 60-minute limit over about 1,129 integration tests and 1,243 unit tests. There is no Electron job at all. A skipped job reports success under its name, so requiring individual jobs would let a skipped lane pass.

**In:**
- A detect job: core/** -> Rust lane; apps/electron/** -> Electron lane (npm ci, typecheck, test, build); cloud/** -> control-plane lane; docs-only -> link check only; Cargo.lock, core/Cargo.toml, .github/**, scripts/oby-check*, tools/**, e2e/** -> every lane. A push to dev runs every lane.
- Rust tests sharded over 3 or 4 jobs (cargo nextest --partition count:k/N)
- A Check job with needs on every lane and if: always(), failing when detect or any needed lane failed or was cancelled
- JUnit report per shard uploaded as an artifact

**Out:**
- Apple suites (they stay on the Mac)
- Branch protection (R01-03)

### Actors and ownership: what obid owns

- Nothing changes in obid.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- .github/workflows/linux.yml
- docs/ci.md
- new: core/.config/nextest.toml

### Steps

- Add the detect job with a pinned paths-filter action or a short git diff script; write the path table into docs/ci.md.
- Split the rust job: one fmt and clippy job, then N nextest shards with `--partition count:k/N --no-fail-fast`; keep the bubblewrap and gitleaks setup in each shard.
- Add the Electron lane (Node 22, npm ci, typecheck, test, build) in apps/electron.
- Add the Check job (needs all lanes, if: always()) that fails on any failure, cancel, or detect failure.
- Add a nextest JUnit profile and upload target/nextest/ci/junit.xml per shard.
- Prove CI-5 and CI-6 on a throwaway branch with a deliberately failing test, and link both red runs in the PR.

### Acceptance scenarios

- CI-3 (proposed): Given a pull request that changes only docs/**, when the workflow runs, then only the docs lane runs and Check passes.
- CI-4 (proposed): Given a pull request that changes core/Cargo.toml, when the workflow runs, then every lane runs.
- CI-5 (proposed): Given one Rust shard fails, when the workflow ends, then Check fails and names that lane.
- CI-6 (proposed): Given the detect job fails, when the workflow ends, then Check fails rather than passing over skipped lanes.

Contract: new: docs/contracts/ci.md

### Tests

- ci_3..ci_6 proven by linked workflow runs on throwaway branches (a red run for CI-5 and CI-6).

### Done when

- A docs-only PR and a core PR show different lane sets and one Check status.
- A red run shows Check failed for a failing shard.
- `scripts/oby-check.sh` passes on the same commit.
