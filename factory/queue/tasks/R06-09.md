# feat(electron): resume obid's stream with `after` and refetch only on `resync`

<!-- Roadmap R06-09 · Sprint 6 · R06 Events that clients only apply · effort S · risk low -->

### Sangam's screen

engine only (main process; no screen changes)

### Outcome

After a sleep, a dropped connection or a stream ended for lag, the Mac app gets what it missed without reading every list again; it reads them again only when obid says `resync` or restarted.

### Status and scope

Proposed (roadmap R06-09, milestone R06 Events that clients only apply).

**Why:** Every reconnect reads status, 100 jobs, the inbox, up to 10 pages of conversations, GitHub work and limits (live.ts:741-746), and notify.ts did the same (notify.ts:353).

**In:**
- main/live.ts keeps the last `id:` and reconnects with `?after=` when status has `events-replay-v1`.
- A `resync` event, or a first connection, runs the snapshot reads; a replay does not.
- sseReader in shared/obid-wire.ts reports the `id:` field.

**Out:**
- Inferring a gap from the numbers (see R06-02 notes).

### Actors and ownership: what obid owns

- The ring, the epoch and `resync` (R06-02).

### Actors and ownership: what the apps show and send

- Nothing visible; fewer reads after a reconnect.

### Files

- apps/electron/src/main/live.ts
- apps/electron/src/shared/obid-wire.ts
- apps/electron/src/renderer/src/test/mainLive.test.ts

### Steps

- Make sseReader pass the id with each event.
- Keep the last id in main/live.ts (memory only); reconnect with `?after=`.
- Treat `resync` as 'read the snapshot now', then apply pending events.
- Write LIVE-12 to 14 against a fake obid stream; prove LIVE-12 red when main always refetches.
- Run `npm test`, and on a real Mac sleep and wake the Mac with the app open and check the window.

### Acceptance scenarios

- LIVE-12 (proposed): Given the stream drops after id E-40, when main reconnects and obid replays, then main reads no list and the window shows the replayed changes.
- LIVE-13 (proposed): Given obid restarted (new epoch), when main reconnects with E-40, then it gets `resync`, reads the snapshot and the window shows obid's state.
- LIVE-14 (proposed): Given an obid without `events-replay-v1`, when main reconnects, then it reads the snapshot as today.
