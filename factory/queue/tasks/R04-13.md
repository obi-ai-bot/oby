# feat(obid): a per-job transition log

<!-- Roadmap R04-13 · Sprint 7 · R04 One owner for job state · effort M · risk low -->

### Sangam's screen

engine only

### Outcome

Each job keeps a short record of every command it accepted or refused and what it changed, so a failure can be explained from data and a restart can read the last transition instead of guessing.

### Status and scope

Proposed (roadmap R04-13, milestone R04 One owner for job state).

**Why:** Restart recovery in Jobs::open approximates the last state from status, phase and cut (jobs.rs:1195-1245); in-memory sets (followed, handed, publishing) are lost on restart (jobs.rs:876-909). Bug reports today rebuild what happened from transcript text.

**In:**
- Jobs::apply appends one JSON line per command to home/jobs/<id>/events.jsonl before the job file is saved: time, command, run token, from status, to status, refused why.
- Masked as the transcript is; swept with it after 30 days (transcript.rs KEPT_DAYS).
- Jobs::open reads the last line to log what the job was doing when obid went down; behaviour of the restart does not change yet.

**Out:**
- Using the log to change restart decisions (decide after R04-15).
- An API route or a page that shows it (would need Sangam's design).

### Actors and ownership: what obid owns

- The transition log and its sweep.
