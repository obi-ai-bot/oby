## What
- **Finding from V01-44's audit** (its `build.md`, "Audit: scans of outgoing content", the lines for `scripts/oby-check.sh`'s scan group and `.github/workflows/ci.yml`): the gate's and CI's secret scans read the change through git, which obeys `.gitattributes` and diff drivers, so one line a branch adds hides a file's text from gitleaks.
- **Where:**
  - `scripts/oby-check.sh`, group `scan`: `gitleaks git . "--log-opts=$base..HEAD"` reads `git log -p`, and `uncommitted_leaks` pipes `git diff HEAD` to `gitleaks stdin`. `factory/checks.sh` and the gate VM run this group.
  - `.github/workflows/ci.yml`, step "gitleaks over the new commits": `gitleaks git . "--log-opts=-m $range"`.
- **Reproduced** on gitleaks 8.30.1, with a `ghp_` token in a committed `n.txt`:
  - `gitleaks git . --log-opts=<base>..HEAD` exits 0 under `n.txt -diff`, `n.txt binary` and `n.txt diff=hide` with a `diff.hide.textconv`. It exits 1 with no attribute.
  - `git diff HEAD | gitleaks stdin` over an uncommitted change exits 0 under `-diff`, `binary`, `diff=hide` (textconv) and `diff=ext` (`diff.ext.command`). It exits 1 with no attribute.
- **Harm:** a branch with one `.gitattributes` line passes the gate's and CI's scan with a secret in it, past the "Secret scan" non-negotiable.

## Why
AGENTS.md, "Non-negotiable": everything that leaves is scanned for secrets first. obid's own push scan already reads with `--text --no-ext-diff --no-textconv` (`core/crates/obid/src/publish.rs`, `DIFF`). V01-44 did the same for `factory/bin/test-run` and `factory/bin/job` (`factory/bin/outgoing.py`). The check and CI are the scans left.

## How
- Give `gitleaks git` a `--log-opts` that holds `--text --no-ext-diff --no-textconv` (gitleaks passes `--log-opts` to `git log -p`), or scan `git log -p --text --no-ext-diff --no-textconv <range>` through `gitleaks stdin`. Check which one gitleaks 8.30.1 honours.
- `uncommitted_leaks`: `git diff --text --no-ext-diff --no-textconv HEAD`.
- The same options in `ci.yml`'s step.
- Both files are security paths and the check's own files, so the change waits for the owner.
