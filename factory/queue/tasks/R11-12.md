# feat(obid): put a secret in the vault over loopback: GET/PUT/DELETE /v1/obid/vault

<!-- Roadmap R11-12 · Sprint 8 · R11 Connections: MCP, sign-in and the vault · effort S · risk medium -->

### Sangam's screen

engine only

### Outcome

The Mac app lists vault names, adds a value and removes one without a terminal. The value goes only in a loopback request body, never in a conversation, a turn or a log.

### Status and scope

Proposed (roadmap R11-12, milestone R11 Connections: MCP, sign-in and the vault).

**Why:** #898: values enter only by `obid vault --config <path> add NAME` on stdin (vault.rs:12-15); 'No API takes or returns a value'. So pasting into the conversation wins, and the key reaches the model (#899). Vault::names, add and remove (vault.rs:522, 530, 580) already check name and value and teach the redactors at once.

**In:**
- GET /v1/obid/vault: sorted names without obid's own oby. names, never a value.
- PUT /v1/obid/vault/{name} with {"value": "…"} only, at most vault::LONGEST plus a little: Vault::add, 204; 422 with obid's words for a refused name or value or an oby. name.
- DELETE /v1/obid/vault/{name}: 204 or 404.
- PUT and DELETE need the owner's signed words from the Electron main process; none of the three is on the gateway; no request body is logged.

**Out:**
- The Settings page (R11-13).
- The secret ask (R11-14).
- Ciphertext at rest (#1029).

### Acceptance scenarios

- VAULT-1 (proposed): Given a signed PUT /v1/obid/vault/staging-key with a strong value, when obid saves it, then it answers 204, GET lists staging-key, and the next /v1 answer that would hold the value shows [vault: staging-key].
- VAULT-2 (proposed): Given a weak value, a bad name or an oby. name, when it is put, then 422 with obid's words and nothing is saved.
- VAULT-3 (proposed): Given any vault route, when a paired phone sends it through the gateway, then it is refused.
- VAULT-4 (proposed): Given a saved value, when obid's log, every event and every answer of the test run are read, then the value appears in none of them.
- VAULT-5 (proposed): Given an unsigned PUT or DELETE, when obid reads it, then 403 and nothing changes.
