# docs(api): move docs/runner-api.md's sections into docs/api/<area>.md and leave an index

<!-- Roadmap R13-17 · Sprint 10 · R13 How we work · effort M · risk medium · new 2026-11-14 from R13-15's first slice -->

### Sangam's screen

engine only

### Outcome

Each API area has its own file in `docs/api/`, named like its contract, and `docs/runner-api.md` becomes a short index that keeps every old heading with a link to where its text went. Fewer conflicts between pull requests, faster reads.

### Status and scope

Proposed (new, R13-15's follow-up: R13-15 landed the map below and taught tools/brain and obid's CAPS-2 test to read `docs/api/*.md`).

**Why:** `docs/runner-api.md` is about 2,900 lines and changes in most pull requests, so it conflicts with nearly every job that touches the API. R13-15 left the move out so it conflicted with none of the jobs editing the file then, and so a 3,000-line move doesn't go stale while it waits for the owner (AGENTS.md is a security path).

**In:**
- Move each section unchanged into `docs/api/<area>.md`, as the map below says, produced mechanically from the map against `dev` as it is at build time, so the move can be redone in minutes after a rebase.
- `docs/runner-api.md` keeps every old heading as an index line with its link, so 'docs/runner-api.md, "<section>"' citations still resolve.
- The AGENTS.md lines that say "change the API doc in the same pull request" (Build and run, Done), per area: the area file whose routes the change touches.
- The link to the API doc in `docs/business-contract-template.md`, the `docs/runner-api.md` box in `.github/pull_request_template.md`, and the API doc in `.github/ISSUE_TEMPLATE/feature.yml`.
- `tools/brain/test/repo.test.ts`: `retired_8_reads_every_api_doc` asserts that every real `docRoutes` entry is in `docs/runner-api.md`; after the move they are in `docs/api/*.md`, so that assertion changes to match (still non-empty).

**Out:**
- Rewriting the files that cite `docs/runner-api.md`.
- Fixing stale routes (#1653) or editing the "Routes obid does not serve" list.
- Changing `scripts/oby-check.sh`, `tools/oby-check-blok` or `routes_guard.rs` (see Notes: those are the owner's to narrow).

`## Objects`, `## Endpoints` and `## obid only` are the old file's part headings: they hold little text of their own and go to `overview.md` with the introduction, so an area file starts at its first `###`.

**Renamed from R13-15's areas.** check → `ci` (docs/contracts/ci.md covers the check and Mac check); publishing and merging → `publishing` and `merging`, one per contract; sphere → `obysphere`, with `rooms`, `peer-thread`, `ask-an-oby` and `teammate-review` where their own contracts cover a section; accounts → `accounts`, with the limits sections in `account-limits`.

**New areas** (no `docs/contracts/<area>.md` of that name):
- `overview`: the title, introduction, "Reaching it" and the part headings: what every area shares, and no contract is about the API as a whole.
- `jobs`: the Job object and the job routes, R13-15's area; `tasks.md` covers only the task page's actions, and the API's word is job.
- `conversations`: the conversation, `POST /v1/plans` and the conversation harness, R13-15's area; its contracts (chat-first, conversation-agent, task-conversations) each cover one part, none the routes.
- `events`: `GET /v1/events`, the stream every client reads, R13-15's area; no contract.
- `inbox`: the inbox item, its routes and its sorting; `alerts.md` covers only how what waits reaches the owner.
- `failures`: the failure record and its routes; no contract.
- `settings`: what the runner doesn't do by itself, "Limits and settings" and `/v1/settings/jobs`, R13-15's area; `agents.md` covers only Settings › Agents.
- `egress`: the egress proxy; no contract.
- `configuration`: obid's `config.json`; `released-files.md` covers only loading an older one.
- `github`: GitHub's sign-in, repositories and GitHub work; `sign-in.md` covers every tool's sign-in errors.
- `tetrix`: Tetrix's connection and MCP server; no contract.
- `vault`: the vault and the secrets a check declares; `keychain.md` covers the agents' logins.
- `memory`: what Oby remembers (#378); no contract.
- `artifacts`: what an agent makes to be looked at; no contract.

No area is `routes` or `dead-client-calls` (`docs/api/routes.txt` and `docs/api/dead-client-calls.txt`, read by `routes_guard.rs`, stay as they are).

### Notes

- Land it when few jobs that edit `docs/runner-api.md` are open, and rebase those onto the index.
- AGENTS.md is a security path (`merge::SECURITY_PATHS`), so the pull request waits for the owner. AGENTS.md has a byte budget (R13-04): the per-area lines must fit it.
- Any change under `docs/api/` makes `scripts/oby-check.sh` plan `routes_guard.rs` (docs/contracts/ci.md, CI-9 to 11), so a docs-only edit to an area file would run Rust tests unless the owner narrows that rule.
- Moving `GET /v1/status` changes which file CAPS-2 reads (`docs/api/capabilities.md` in the map). Whether the check still plans `runner_api.rs` when that area file changes is a question to answer here.
- The index must not repeat ``### `GET /v1/status` `` with a `| Name |` table under it (CAPS-2 fails on two files holding it).
- Links inside the moved text that point at another section of the old file (`](#…)`) still point inside the file they're in; whether they stay as they are, so every old line is unchanged, or point at the area file, is a question to answer here.
- tools/brain and CAPS-2 already read `docs/api/*.md` (R13-15).
