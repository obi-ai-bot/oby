# refactor(obid): one handoff builder for every session replacement

<!-- Roadmap R08-14 · Sprint 6 · R08 One interface for every agent CLI · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

A job move, a job whose session grew too long, and a conversation that changes account or tool or renews its session all hand over with the same packet: latest owner words and agent answer kept whole, recent turns, older excerpts, steps, files changed, all redacted before it is cut.

### Status and scope

Proposed (roadmap R08-14, milestone R08 One interface for every agent CLI).

**Why:** Three texts do this today: `Jobs::handoff_text` (jobs/moves.rs:73, LIMITS-17), `Jobs::new_session` (jobs.rs:8324), which tells the agent 'a new one with none of its history', and `first_prompt` in brain/harness.rs:2162 (the last 20 turns, `EARLIER`, each cut to 500 characters). A conversation that fails over loses context; the renewal path has no handoff at all.

**In:**
- new: core/crates/obid/src/handoff.rs: `build(source: Source::Job(..) | Source::Conversation(..), budget) -> Result<String, String>` with fixed sections; mask (`detail::mask`) and vault-check (`vault::for_agent`) each field before cutting.
- Callers: `move_to` (as today), `new_session` (RECOVERY-8), the conversation's account/tool switch and renewal (`first_prompt`).

**Out:**
- Where the conversation's packet is put: R08-15 (this task keeps it inline).
- Any model call of obid's to summarize (AGENTS.md: rules write it, the incoming agent compresses).

### Actors and ownership: what obid owns

- The handoff text for every session replacement.

### Actors and ownership: what the apps show and send

- Nothing changes for clients; a job's changes line still says `with a handoff`.

### Steps

- Add LIMITS-28, RECOVERY-18 and CONVERSATION-AGENT-24, marked proposed.
- Move `handoff_text` into handoff.rs as the job source; keep LIMITS-17's tests green.
- Add the conversation source from `Turn`s, keeping today's quoting and the 'line about a job, left out' rule for jobs off the allowlist.
- Redact and vault-check each field before the budget cut.
- Use it in `new_session` and in the conversation's switch and renewal; delete `first_prompt`'s own text building.

### Acceptance scenarios

- LIMITS-28 (proposed): Given a job moved past a limit, when the new session starts, then `.obi/inputs/handoff.md` has the sections of LIMITS-17 in the builder's fixed order, and the latest owner words and the latest agent answer are whole or head-and-tail, never dropped.
- RECOVERY-18 (proposed): Given a job whose session grew too long for its model (RECOVERY-8), when the new session starts, then it reads a handoff from the same builder instead of 'none of its history'.
- CONVERSATION-AGENT-24 (proposed): Given a conversation whose turn moves to another account or tool, when the new session starts, then its first prompt carries the builder's packet, and a secret the vault holds never appears in it, even cut in half.
