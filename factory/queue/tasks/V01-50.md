## What
- **Finding from V01-44's own review** (its `round-1/review-pstack.md`, interrogate): `gitleaks stdin`, as `factory/bin/test-run` and `factory/bin/job`'s `secret_scan` call it, can be made to skip a secret by the text it reads. V01-44 made both read the change as text (`factory/bin/outgoing.py`), and these routes are the same before and after it. Each was reproduced on gitleaks 8.30.1, against the real `test-run`, on `factory/tests/test_test_run_remote.py`'s harness:
  - **File-type sniffing.** gitleaks skips all of its standard input when the first bytes read as an `application/*` type. A `.gitattributes` holding `#` and 45 dashes, then `*.ustar binary`, puts `ustar` at byte 257 of the scan copy, so the input reads as a tar archive. The scan exits 0 and the run, token and all, goes to the VM. The same happens with `DICM` at byte 128, which can come from the first changed file's name.
  - **Read chunks.** A token at certain offsets of a large input is missed. In a 504 KB copy, one token alone at byte 41353 gave exit 0 on five runs out of five. With 12000 tokens, 17 were missed, all at chunk edges.
  - **Inline allow.** A `gitleaks:allow` comment on the secret's line makes the scan pass it. `factory/bin/review-codex` already scans with `--ignore-gitleaks-allow`; test-run and job don't.
- **Harm:** a branch can carry a secret past the scan before a run leaves for the VM, or before the re-close pushes, against the "Secret scan" non-negotiable.

## Why
AGENTS.md, "Non-negotiable": everything that leaves is scanned for secrets first. A scan whose input decides whether it reads that input is not that scan.

## How
- Find out how gitleaks 8.30.1 sniffs its input and reads it in chunks (`sources`/`detect` in its source), and choose a call that reads all of its input as text in one piece. That may be a file with a text extension through `gitleaks dir`, or a fixed text prefix long enough to cover the sniffed bytes. Check each choice against the repros below.
- Add `--ignore-gitleaks-allow` to both calls, as review-codex has it. Check first that no file the factory sends relies on an inline allow.
- `scripts/oby-check.sh`'s `uncommitted_leaks` and obid's `scan.rs` gitleaks call read through `gitleaks stdin` too. The audit says which of them share these routes, and any that do become their own task.
