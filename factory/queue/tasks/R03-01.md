# chore(obid): drop the telemetry flag that nothing reads

<!-- Roadmap R03-01 · Sprint 1 · R03 Delete what has no caller · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

obid has no setting that suggests telemetry exists. Oby still sends nothing; a config.json that has the old key keeps working.

### Status and scope

Proposed (roadmap R03-01, milestone R03 Delete what has no caller).

**Why:** `telemetry` is parsed (config.rs:69, 249, 577) and written (app.rs:75 default_config, install/install.sh:441) but never read: `git grep '\.telemetry'` on origin/dev 56c6083f finds only tests. Searched core/crates/obid/src, apps/electron/src, apps/ios, apps/shared, apps/android, apps/web, mcp/, install/ and cloud/control-plane: no reader. The Electron scripts (apps/electron/scripts/test-*.mjs) only write `telemetry: false` into test configs. Issue #1306 asks for exactly this.

**In:**
- Remove the `telemetry` field from the file struct (config.rs:68-69), from `Config` (config.rs:248-249) and from `Config::parse` (config.rs:577).
- Remove `"telemetry": false` from default_config (app.rs:75, and its doc line app.rs:59) and from install/install.sh:441.
- Remove the key from test configs: tests/support/mod.rs:175, jobs_api.rs:109, review_job.rs:101, secretspec.rs:744, status.rs:61, vault_review.rs:91, and apps/electron/scripts/test-{account-limits,chat-first,core,live-task,sphere}.mjs.
- Replace the config.rs test `telemetry_is_off_unless_turned_on` with RETIRED-1; drop the asserts at config.rs:830, 1103, app.rs:246, tests/install.rs:575; give install.rs `an_update_keeps_the_configuration_the_owner_edited` another key to edit.
- docs/runner-api.md (config example at :1720 and the `telemetry` bullet at :1729): say obid sends nothing and that an older `telemetry` key is ignored. docs/ARCHITECTURE.md:97: 'Oby sends no telemetry.'
- Lower `obid_lines_limit` in scripts/oby-check.sh by the production lines removed.

**Out:**
- An opt-in field-failure sender (fixed cause codes, durable queue). It is new work for R09 when the team wants it; the owner-sent diagnostics bundle stays the only path off the Mac.
- The memory guard in memory.rs:1109 and 1132 that refuses 'turn on telemetry': it stays. Its sentence says 'in Settings'; changing words a person sees is Sangam's and the owner's call.
- AGENTS.md:88 ('No telemetry unless the user turns it on'): unchanged, still true.

### Acceptance scenarios

- RETIRED-1 (proposed): Given a config.json with `"telemetry": true` that an older obid wrote, when obid starts, then it starts, `Config.ignored` names `telemetry`, and obid logs the one 'isn't a key this obid knows' warning as it does for `council`.
- RETIRED-2 (proposed): Given a Mac or Linux box with no config.json, when obid writes its first configuration (default_config) or install.sh writes one, then it has no `telemetry` key.
