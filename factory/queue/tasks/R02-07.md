# feat(electron): send a request key with every create, message and answer

<!-- Roadmap R02-07 · Sprint 1 · R02 Commands that are safe to repeat · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/electron/src/renderer/src/AgentPane.tsx

### Outcome

A double click or a resend from the Electron app never makes a second task or follow-up.

### Status and scope

Proposed (roadmap R02-07, milestone R02 Commands that are safe to repeat).

**Why:** apps/electron/src/renderer/src/obid.ts and live.ts post messages and answers with no key; only the turn id (live.ts:866 crypto.randomUUID) is sent for POST /v1/plans.

**In:**
- One UUID per click, kept across that click's retries, for POST /v1/jobs, /messages, /stop, /move and inbox answers.
- Send it only when GET /v1/status says obid takes it.

**Out:**
- A pending state in the UI (R06).

### Actors and ownership: what obid owns

- Nothing new.

### Actors and ownership: what the apps show and send

- Nothing visible; the app sends the key.

### Interfaces and dependencies

- GET /v1/status: `receipts: true` once obid takes keys (add-only; R02-04 adds it).

### Files

- apps/electron/src/renderer/src/obid.ts
- apps/electron/src/renderer/src/live.ts
- apps/electron/src/renderer/src/AgentPane.tsx
- apps/electron/src/shared/words.ts
- apps/electron/src/main/notify.ts

### Steps

- Add a key argument to the obid.ts calls that create or answer.
- Make the key at the click, not inside a retry loop.
- Include the key in the signed body (shared/words.ts) so a repeat is signed the same.
- Test RECEIPTS-15 against the mock and a real obid.

### Acceptance scenarios

- RECEIPTS-15 (proposed): Given the app sends words to an ended task and the answer is lost, when it sends them again, then it sends the same key and the task has one follow-up.

Contract: new: docs/contracts/receipts.md (prefix RECEIPTS)
