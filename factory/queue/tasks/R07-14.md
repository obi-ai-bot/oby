# feat(ios): an encrypted read-only snapshot at iPhone start

<!-- Roadmap R07-14 · Sprint 6 · R07 One wire contract · effort M · risk low -->

### Sangam's screen

needs Sangam's design first

### Outcome

The iPhone shows the last conversations, recent turns and open inbox at once while the relay connects, read only, and the copy never leaves the phone.

### Status and scope

Proposed (roadmap R07-14, milestone R07 One wire contract).

**Why:** On a slow relay connect the phone shows an empty screen. Phone state lives in one store and UserDefaults (Phone.swift, 17 UserDefaults.standard uses per the map).

**In:**
- Write on background and after each full load: one file in Library/Caches, sealed with CryptoKit (ChaChaPoly or AES-GCM), the Mac id as additional data, a Keychain key of class after-first-unlock, capped at a few MB
- At start show it read only until obid's reads replace it
- Unpair or revoke deletes file and key; a failed decrypt deletes the file

**Out:**
- Any copy off the phone
- Android

### Actors and ownership: what obid owns

- Nothing changes in obid.

### Actors and ownership: what the apps show and send

- The last data, marked read only (Sangam's marker).

### Acceptance scenarios

- IOSNEW-19 (proposed): Given the phone loaded its Mac's conversations once, when it starts again with the relay down, then it shows them read only with no send action.
- IOSNEW-20 (proposed): Given the owner unpairs, when unpair ends, then the snapshot file and its key are gone.
