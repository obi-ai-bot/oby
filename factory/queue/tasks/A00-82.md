Design: docs/design/oby-home/ (README: "Each profile has its own of both"; screen 07). Contract: docs/contracts/profiles.md, docs/contracts/routines.md.

What. A00-79 moves conversations, jobs, projects, helpers, accounts, settings, permissions and the vault under each profile, and a request that names no profile is the default profile's. Routines (`home/routines/`, `crate::routines`) are not on that list. A routine's run is started by obid itself (its schedule, or a GitHub feed event, R12-05), not by a request, so after A00-79 every routine's run lands in the default profile: on the default profile's accounts, vault and repositories, whatever profile the routine was made in.

Why. The owner keeps one profile per company. A nightly routine made in the Acme profile would then run on the Deskree profile's Claude Code account and vault, and its task would show up among Deskree's conversations. That is the leak profiles exist to stop, coming in through the one door A00-79 doesn't cover.

How. Keep routines under the profile's root, like the stores A00-79 moves (the default profile's root is obid's home, so an install with one profile moves nothing). `/v1/routines` answers for the profile the request names (A00-79's add-only key), the default one when it names none. A routine's run, scheduled, caught up or from a GitHub event, creates its job in the routine's own profile, on that profile's accounts and vault; a GitHub feed event starts only the routines of profiles that follow that repository. A routine's waiting run counts in its own profile's `waiting`.

Add the model below as `docs/models/oby_profile_triggers.qnt`, unchanged unless the design changes. A00-83 and A00-84 check their parts against the same model.

### Formal verification
The Quint model `docs/models/oby_profile_triggers.qnt` (below). Verified with quint 0.33.1 on the gate VM on 2026-11-15: `triggers_specs` (A00-79 as written: routines and the Obysphere membership left Mac-wide, a request with no profile the default one's, main following the current profile's events) holds `typeOk` and violates `runsInItsProfile` and `everyWaitAlerts` (counterexamples: a routine made in p2 fires and its job runs in p1; a job waiting in p2 while the window shows p1 raises no alert). `triggers_fixed` holds `runsInItsProfile`, `everyWaitAlerts` and `phoneSeesOnlyWhatItMay` in every run of up to 10 steps, and violates its witnesses `neverP2Trigger` and `neverWaitsElsewhere`, so the pass is not vacuous. This task makes `runsInItsProfile` true for routines. A Kani harness over the pure function that picks a routine run's profile: it is always the routine's own.

Acceptance (ROUTINES scenarios, each a test named after it):
1. A routine made in profile B is not listed from profile A, and `/v1/routines` with no profile lists the default profile's.
2. A scheduled run of a routine of profile B creates its job in B, on B's account; A's jobs don't list it.
3. A GitHub feed event on a repository only profile B follows starts B's routine, and no routine of A.
4. An install with one profile behaves exactly as before: its routines stay where they are and run as they did.

### The model
```quint
// verify: main=triggers_specs steps=8 invariants=typeOk witnesses=runsInItsProfile,everyWaitAlerts
// verify: main=triggers_fixed steps=10 invariants=runsInItsProfile,everyWaitAlerts,phoneSeesOnlyWhatItMay witnesses=neverP2Trigger,neverWaitsElsewhere
//
// Profiles (A00-75, A00-79) and the work nobody starts from a profile's window: a routine's run (routines.rs,
// home/routines/), a request from an Obysphere the Mac is a member of (sphere/membership.rs, home/sphere/),
// and what waits on the owner raising an alert (apps/electron/src/main/notify.ts, following obid's events once,
// R06-08) or reaching the paired phone (crate::relay; devices are Mac-wide, PROF-2).
//
// runsInItsProfile: a job a routine or an Obysphere started runs in the profile the routine or the membership
//   belongs to, on that profile's accounts and vault.
// everyWaitAlerts: anything that waits on the owner in any profile raises an alert on the Mac, whatever profile
//   the window shows.
// triggers_specs is A00-79 as written: it moves conversations, jobs, projects, helpers, accounts, settings,
//   permissions and the vault under the profile, but not routines or the Obysphere membership; a request that names
//   no profile is the default profile's; every route (the event stream too) answers for one profile, so the
//   window's main process follows the current profile's events. Expected: runsInItsProfile and everyWaitAlerts are
//   VIOLATED (witnesses there).
// triggers_fixed keeps routines and memberships under a profile, runs their work there, and has main follow
//   every profile's waits (its alert names the profile, opening it switches). The phone sees only the profiles the
//   owner let it (`phoneProfiles`, default: the default one). Expected: all three hold.
// The limit: a model checks the design, not that obid implements it.

module triggers_common {
  pure val Profiles = Set("p1", "p2")      // p1 is the default profile
  pure val Default = "p1"
  type Trigger = { kind: str, id: int, madeIn: str }          // kind: routine, sphere
  type Job = { id: int, trigger: int, runsIn: str, waits: bool, alerted: bool, phone: bool }
}

module triggers_specs {
  import triggers_common.*
  var current: str
  var triggers: Set[Trigger]
  var jobs: Set[Job]
  var n: int
  // the stores A00-79 leaves under obid's home are read by no profile: their work goes where a request with no
  // profile goes, the default profile
  def runsInOf(t: Trigger): str = Default
  action init = all { current' = Default, triggers' = Set(), jobs' = Set(), n' = 1 }
  action make = {
    nondet k = Set("routine", "sphere").oneOf()
    all { n < 5, triggers' = triggers.union(Set({ kind: k, id: n, madeIn: current })), n' = n + 1,
          current' = current, jobs' = jobs }
  }
  action fire = {
    nondet t = triggers.oneOf()
    nondet w = Set(true, false).oneOf()
    val p = runsInOf(t)
    all { n < 5, jobs' = jobs.union(Set({ id: n, trigger: t.id, runsIn: p, waits: w,
                                          alerted: w and p == current, phone: w and p == Default })),
          n' = n + 1, current' = current, triggers' = triggers }
  }
  action switch = {
    nondet p = Profiles.oneOf()
    all { current' = p, triggers' = triggers, jobs' = jobs, n' = n }
  }
  action step = any { make, fire, switch }

  val typeOk = jobs.forall(j => Profiles.contains(j.runsIn))
  val runsInItsProfile = jobs.forall(j => triggers.exists(t => t.id == j.trigger and t.madeIn == j.runsIn))
  val everyWaitAlerts = jobs.forall(j => j.waits implies j.alerted)
}

module triggers_fixed {
  import triggers_common.*
  var current: str
  var triggers: Set[Trigger]
  var jobs: Set[Job]
  var n: int
  var phoneProfiles: Set[str]
  action init = {
    nondet extra = Set(Set(), Set("p2")).oneOf()       // the owner may let the phone see p2 too
    all { current' = Default, triggers' = Set(), jobs' = Set(), n' = 1, phoneProfiles' = Set(Default).union(extra) }
  }
  action make = {
    nondet k = Set("routine", "sphere").oneOf()
    all { n < 5, triggers' = triggers.union(Set({ kind: k, id: n, madeIn: current })), n' = n + 1,
          current' = current, jobs' = jobs, phoneProfiles' = phoneProfiles }
  }
  action fire = {
    nondet t = triggers.oneOf()
    nondet w = Set(true, false).oneOf()
    all { n < 5, jobs' = jobs.union(Set({ id: n, trigger: t.id, runsIn: t.madeIn, waits: w,
                                          alerted: w, phone: w and phoneProfiles.contains(t.madeIn) })),
          n' = n + 1, current' = current, triggers' = triggers, phoneProfiles' = phoneProfiles }
  }
  action switch = {
    nondet p = Profiles.oneOf()
    all { current' = p, triggers' = triggers, jobs' = jobs, n' = n, phoneProfiles' = phoneProfiles }
  }
  action step = any { make, fire, switch }

  val runsInItsProfile = jobs.forall(j => triggers.exists(t => t.id == j.trigger and t.madeIn == j.runsIn))
  val everyWaitAlerts = jobs.forall(j => j.waits implies j.alerted)
  val phoneSeesOnlyWhatItMay = jobs.forall(j => j.phone implies phoneProfiles.contains(j.runsIn))
  // witnesses: work is started from p2's triggers, and something waits outside the window's profile
  val neverP2Trigger = not(jobs.exists(j => j.runsIn == "p2"))
  val neverWaitsElsewhere = not(jobs.exists(j => j.waits and j.runsIn != current))
}
```
