# feat(obid): Hand back reads the worktree again and checks the owner's commit

<!-- Roadmap R12-08 · Sprint 10 · R12 Developer workflows · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

After the owner works on a job by hand, Oby picks it up with a true picture of the branch and publishes the owner's commit only through the check and the secret scan.

### Status and scope

Proposed (roadmap R12-08, milestone R12 Developer workflows).

**Why:** Without this, the next round acts on a stale branch, and resuming a session that the owner continued in Terminal can fail or fork it.

**In:**
- POST /v1/jobs/{id}/hand-back: clear `takenOver`, record the new HEAD and whether the worktree has uncommitted changes.
- Run the job's check on the owner's commit before any publish, then the secret scan, as for every job.
- The next round's first prompt gets one fixed obid line: the owner worked in this worktree and may have changed it; read the state again.
- If the session file changed while held, resume the session obid last recorded only when it is unchanged, else start a new session with the LIMITS-17 handoff.

**Out:**
- Checking out the branch in the owner's own clone (#987).

### Actors and ownership: what obid owns

- The HEAD record, the check, the publish decision, the session choice and the fixed line.

### Steps

- Record the session file's size and mtime at take-over.
- On hand-back, read HEAD and status in the job's git folders as obid pins them.
- Queue the check on the new HEAD, then publish through the existing path.
- Choose resume or a new session with the handoff writer from LIMITS-17 (or R08's one handoff).
- Add the fixed first-prompt line.

### Acceptance scenarios

- TAKEOVER-7 (proposed): Given a held job and an owner commit on its branch, when Hand back arrives, then the job records the new HEAD, runs the check on it, and publishes only if the check passes and the scan is clean.
- TAKEOVER-8 (proposed): Given a handed-back job, when its next round starts, then its first prompt holds the fixed 'the owner worked in this worktree' line.
- TAKEOVER-9 (proposed): Given a session file changed while held, when the next round starts, then obid starts a new session with `.obi/inputs/handoff.md` (LIMITS-17) and does not resume the changed one.
- TAKEOVER-10 (proposed): Given uncommitted changes at Hand back, when the job goes on, then nothing is lost and the job's changes list that the owner left uncommitted work.
