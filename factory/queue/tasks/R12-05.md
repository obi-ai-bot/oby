# feat(obid): start routines from GitHub feed events, once each

<!-- Roadmap R12-05 · Sprint 9 · R12 Developer workflows · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

The owner confirms once 'review every PR that requests me in obi' or 'fix red CI on my PRs', and each matching event starts one ordinary job. A restart or a second read never starts a second job.

### Status and scope

Proposed (roadmap R12-05, milestone R12 Developer workflows).

**Why:** #1120: events never start work. github_work::Feed already reads review requests, assigned issues and the owner's PRs with their checks every 180 s (github_work.rs EVERY), but only offers them. The old rules.rs/event_work engine was deleted (docs/trim.md batch 2).

**In:**
- An add-only trigger on a routine beside `schedule`: `{"on": {"github": {"repo", "event": "reviewRequested" | "assigned" | "checksFailed" | "labeled", "label"?}}}`.
- The feed hands each new item to routines.rs; one path into Jobs::create, no second engine.
- A receipt in the routine's file, written before Jobs::create: key `repo#number@event@marker` (marker: head commit for reviewRequested and checksFailed, the label for labeled, empty for assigned), outcome started, ignored or held, job id, no GitHub text; kept 7 days.
- One open job per item per routine; a later event waits as `held`.
- At most 3 runs on one item per routine in 24 hours, then `held` with a reason.
- The job's issue or PR is quoted by the existing ISSUETASK path; creating such a routine from chat stays a Confirm card (oby_routine).

**Out:**
- Events the feed does not read (pushes, comments, other people's PRs).
- Webhooks (R12-16).
- The Electron screen (R12-06).

### Actors and ownership: what obid owns

- Matching, receipts, holds and limits; every job is made by Jobs::create under every rule a job has.

### Actors and ownership: what the apps show and send

- The routine's `on` and its receipts in GET /v1/routines/{id}; the apps show them only after R12-06.

### Interfaces and dependencies

- Routine: optional `on.github` (add-only) and `receipts` (add-only) on GET /v1/routines and the `routine` event.

### Steps

- Spike in code first: confirm the feed's `head` and `checks` fields give the markers; write them down in the PR.
- Add `On` to `Routine` and `Draft` with validation; a routine has a schedule or an `on`, never neither.
- Add a hook from Feed's read to `Routines::on_github(items)`.
- Write the receipt and save the routine file, then call Jobs::create; on failure mark the receipt as `failed`.
- Add the held and 24-hour rules with tests.
- Let oby_routine propose an `on` trigger; the Confirm card stays.

### Acceptance scenarios

- ROUTINES-9 (proposed): Given a routine on `reviewRequested` for a repo, when the feed reads a new review request, then one job starts and the receipt is in the routine's file before the job exists.
- ROUTINES-10 (proposed): Given a receipt for an item, when the feed reads it again or obid restarts, then no second job starts.
- ROUTINES-11 (proposed): Given an open job of this routine on an item, when a new event on the same item arrives, then its receipt is `held` and starts nothing until that job ends.
- ROUTINES-12 (proposed): Given 3 runs on one item in 24 hours, when a 4th event arrives, then it is `held` with a reason and no job starts.
- ROUTINES-13 (proposed): Given a trigger routine, when its job starts, then the issue or PR text is only in the quoted inputs file (ISSUETASK-1) and the routine's file holds no GitHub text.
