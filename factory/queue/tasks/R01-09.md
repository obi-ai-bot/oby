# feat(obid): a tested and known-bad CLI version table

<!-- Roadmap R01-09 · Sprint 2 · R01 Safety net · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

obid says per tool whether its version is tested, untested or known bad, and automatic routing does not send work to a known-bad CLI. The owner can still run it: a pinned job runs with one advisory line.

### Status and scope

Proposed (roadmap R01-09, milestone R01 Safety net).

**Why:** Version facts are scattered in comments and contracts (#1096 counts 21 places). A CLI known to break (for example a resume break) still gets automatic work and fails mid-job with an unclear error.

**In:**
- A checked-in table per tool: tested range and knownBad list with reason and issue number, compiled in with include_str!
- status.tools[].versionStatus: tested | untested | knownBad (add-only), and for knownBad the reason
- Jobs::by_room (jobs/account_limits.rs:638) treats a knownBad tool like a held account for automatic routing only
- One advisory transcript line on a job the owner pinned to a knownBad tool
- First entries: the versions docs/runner-api.md and code already name as tested

**Out:**
- Updating the table automatically (the canary, R01-11)
- UI for the warning (#1097)

### Actors and ownership: what obid owns

- The table, the status per tool, and the routing rule.

### Actors and ownership: what the apps show and send

- Nothing new on screen until #1097; the keys are add-only.

### Steps

- Define the table format and add the versions the docs already name as tested.
- Compute versionStatus in cli_versions.rs; add it to status.tools.
- In by_room, skip a knownBad tool for automatic routing only; leave a pinned job alone.
- Add the advisory line for a pinned job on a knownBad tool.
- Write the tests with a test-only table path; update docs/runner-api.md.

### Acceptance scenarios

- CLIVERSIONS-7 (proposed): Given codex's version is in the table's knownBad list, when status is read, then tools[codex].versionStatus is knownBad with its reason.
- CLIVERSIONS-8 (proposed): Given claude is knownBad and codex is tested, when a job is routed automatically, then it goes to codex.
- CLIVERSIONS-9 (proposed): Given the owner pins a job to a knownBad tool, when it starts, then it runs and its transcript has one advisory line with the reason.
