# test(ci): one shrink-only list of flaky tests, retried in CI and once on the Mac, each with a task to fix it

<!-- Roadmap R01-13 · Sprint 1 · R01 Safety net · effort S · risk low · new 2026-11-13 from docs/ci-architecture.md -->

### Sangam's screen

engine only

### Outcome

A known flaky test no longer costs a factory job a whole builder round or a merge-queue batch. The list lives in one file and names each test with the task that fixes it. GitHub retries those tests twice; the Mac check runs one of them a second time only when it failed and is on the list. A test not on the list is never retried on the Mac. Removing a line is the only way the list changes, unless a new line comes with its fixing task.

### Status and scope

Proposed (new, docs/ci-architecture.md, "Flaky tests: one list that only shrinks"). It changes the check's own files (scripts/oby-check.sh, tools/oby-check-blok): **the owner decides**.

**Why:** 4 of the 5 gates that failed on 2026-11-13 failed on known flaky tests, each costing a builder round and another 10-minute gate:
- `merge_api::merging_39_a_second_red_head_asks_the_owner`, twice
- `plans_api::a_turn_says_it_is_thinking_within_half_a_second` (#1804)
- `obid codex::tests::a_command_ends_the_codex_process_at_once`
- `plans_api::plans_map_replies_cancellations_and_dispatched_jobs`

`merging_24` was also reported flaky. R01-06 fixes #1656 and #1804, but nothing stops the rest from costing rounds meanwhile.

**In:**
- `core/.config/nextest.toml`: `[[profile.ci.overrides]]` with one `filter` per listed test, `retries = 2`, each with a comment naming its fixing task
- scripts/oby-check.sh's Rust node: when a test binary fails, read the failed tests' names, and run that binary once more filtered to them only if every failed test is on the list; say `retried flaky: <name>` in the output
- A check in scripts/oby-check-test.sh that the list only shrinks against the base, unless the same change adds the line's task file
- Task files for the three listed tests no task fixes yet (R01-06 covers #1656 and #1804)

**Out:**
- Fixing the tests (R01-06 and the new tasks)
- Retrying tests not on the list, on the Mac

### Steps

- Confirm each listed test is flaky: run its binary 20 times on the Mac and note the failures in the pull request.
- Write the overrides and the Mac retry.
- Write the shrink-only check and prove it red by adding a line with no task.
- Write the three task files in the queue's format.

### Acceptance scenarios

- CI-26 (proposed): Given a listed test fails once and passes on retry in the Mac check, when the check ends, then it passes and its output says `retried flaky: <name>`.
- CI-27 (proposed): Given a test not on the list fails in the Mac check, when the check ends, then it fails with no retry.
- CI-28 (proposed): Given a change adds a line to the list without the task file it names, when the check runs, then it fails.
