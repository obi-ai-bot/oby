# feat(electron): draw the task card's buttons from obid's actions

<!-- Roadmap R04-12 · Sprint 9 · R04 One owner for job state · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/electron/src/renderer/src/TaskCard.tsx

### Outcome

The Mac app shows Stop, Try again, Another round, Publish and Delete exactly when obid would accept them, after a Stop, a failure or a retry alike.

### Status and scope

Proposed (roadmap R04-12, milestone R04 One owner for job state).

**Why:** live.ts askOf and taskOf derive the buttons from Job fields and local state; a wrong derivation shows a button that obid then refuses (#1779) or hides one it would accept.

**In:**
- In live.ts, read `actions` when present; keep today's derivation as the fallback for an older obid.
- Delete the parts of askOf/taskOf that only guessed allowed actions once the fallback is the only user.

**Out:**
- iPhone and Android (R10).
- Any new button, word or layout.

### Actors and ownership: what obid owns

- Nothing new.

### Actors and ownership: what the apps show and send

- Sangam's existing task card buttons, shown from obid's list.

### Files

- apps/electron/src/renderer/src/live.ts
- apps/electron/src/renderer/src/TaskCard.tsx
- apps/electron/src/renderer/src/test/taskActions.test.ts
- docs/contracts/tasks.md

### Steps

- Add `actions?: string[]` to the renderer's Job type.
- Use it in askOf/taskOf; fall back when absent.
- Write TASKS-23; run npm run typecheck and the renderer tests.
- Real Mac: stop a task, fail one, retry one; the buttons match what obid accepts.

### Acceptance scenarios

- TASKS-23 (proposed): Given obid sends a failed job with actions [dismiss], when the card draws, then it shows no Try again; given actions [tryAgain, dismiss], then it shows both.

Contract: docs/contracts/tasks.md (existing)
