Step 1 of the Agents plan (docs/decisions/2026-11-16-agents-follow-openbot.md).

## What
An agent's "Can use" offers Gmail and Slack, but on obid they are mock only and refused (HELPERS-2, HELPERS-16). The owner's MCP server registry (R11-06), its broker (R11-07) and its OAuth sign-in (R11-09) are planned for jobs only. In OpenBot, every server the person adds goes to every agent, unless that server is limited to a list of agents, and an OAuth token never reaches the agent.

## Why
- **The owner, 2026-11-16:** "definitely those tools comes for every Agent", and per-agent choice as OpenBot has it.
- **Lane: dispatcher.** Which servers a run gets, and holding their logins, is the dispatcher's.

## How
1. **Access per server.** A registry server gains an add-only `agents`: null (every agent, also ones made later) or a list of agent ids. Null when absent.
2. **Agents' turns get them.** An agent's turn gets every registry server its access allows, through R11-07's broker: the run sees obid's loopback MCP endpoint with the turn's broker token, never the server's own credential.
3. **Credentials.** OAuth tokens and keys stay in the vault (`oby.mcp.<server>.*`); obid adds them to each forwarded call. Every forwarded call passes the secret scan; a finding, or a scan that can't run, sends nothing (non-negotiable).
4. **The chips.** "Can use" lists the registry's servers that reach this agent, instead of the fixed Gmail and Slack; Gmail and Slack appear once a server for them is added.
5. **Oby's own tools.** Every agent keeps all `oby_*` tools (the owner's word); the GitHub grant (HELPERS) stays as it is.
