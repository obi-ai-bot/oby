# spike: a signed inbound webhook over an outbound socket

<!-- Roadmap R12-17 · Sprint 10 · R12 Developer workflows · effort S · risk medium -->

### Sangam's screen

engine only

### Outcome

A written answer on whether a non-GitHub sender needs a webhook, and if so the design: an outbound socket from obid to Oby's control plane, HMAC check in obid, receipt before the job.

### Status and scope

Proposed (roadmap R12-17, milestone R12 Developer workflows).

**Why:** GitHub events come from the feed (R12-05) and local events from the payload (R12-03). A webhook is only for senders that cannot reach either, and the control plane's old hooks are being deleted (R03).

**In:**
- Name at least one sender that needs it, or close the spike.
- Route ids, the short-lived signed list, the Worker's checks (route, size, type, rate), no body kept, 503 with no socket.
- obid's check: 5-minute timestamp, delivery-id pattern, HMAC-SHA256 over timestamp.deliveryId.body in constant time, receipt before 202.
- Where the secret lives (vault) and that no agent sees it.

**Out:**
- Code.
- The Obysphere (Dmytro's).
