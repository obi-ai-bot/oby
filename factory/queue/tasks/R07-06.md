# refactor(electron): generate obid-wire types from the schema

<!-- Roadmap R07-06 · Sprint 5 · R07 One wire contract · effort M · risk low -->

### Sangam's screen

engine only

### Outcome

The Electron app's obid types come from the schema; a change in obid that breaks them fails the Electron tests on any machine.

### Status and scope

Proposed (roadmap R07-06, milestone R07 One wire contract).

**Why:** apps/electron/src/shared/obid-wire.ts (393 lines) is a hand copy of obid's answers, used by main/obid.ts, main/notify.ts and several renderer files, with no contract test (map: 'obid's API re-modelled by hand in TypeScript with no contract test').

**In:**
- new: apps/electron/src/shared/obid-wire.gen.ts generated from docs/contracts/wire/
- Move obid-wire.ts fields to the generated types one object at a time; delete hand-written fields
- A vitest that decodes every corpus file through the generated types and checks the generated file is current

**Out:**
- apps/web/src/api.ts (orphaned web client; R03 decides)
- UI logic in live.ts

### Actors and ownership: what obid owns

- Nothing changes in obid.

### Actors and ownership: what the apps show and send

- Nothing visible changes.

### Files

- apps/electron/src/shared/obid-wire.ts
- new: apps/electron/src/shared/obid-wire.gen.ts
- apps/electron/package.json
- new: apps/electron/src/renderer/src/test/wire.test.ts

### Steps

- Add the generator chosen in R07-03 as a dev dependency and an npm script.
- Generate; re-export from obid-wire.ts.
- Replace hand-written fields object by object; run typecheck after each.
- Add the corpus and staleness tests; prove WIRE-9 red.

### Acceptance scenarios

- WIRE-9 (proposed): Given the schema changed and obid-wire.gen.ts was not regenerated, when the Electron tests run, then they fail and name the command that regenerates it.

Contract: docs/contracts/wire.md

### Done when

- scripts/oby-check.sh passes
- obid-wire.ts holds only re-exports and client-only types
