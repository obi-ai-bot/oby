# feat(obid): GET /v1/diagnostics, a redacted, scanned, loopback-only bundle

<!-- Roadmap R09-06 · Sprint 7 · R09 Ship and debug safely · effort M · risk low -->

### Sangam's screen

engine only

### Outcome

obid can answer one JSON document with its versions, start history, job counts, failure summaries and recent warnings, with secrets removed and the whole body scanned. It never leaves the Mac by itself.

### Status and scope

Proposed (roadmap R09-06, milestone R09 Ship and debug safely).

**Why:** Today the owner reads ~/Library/Logs/obid.log by hand; reports arrive with no versions or state (map: 'No post-mortems or telemetry'). #919 (open) plans the numbers and rings; obid.log rotation from #919 already landed (app.rs `rotate`).

**In:**
- GET /v1/diagnostics with `schemaVersion`: app-reported and obid versions, agent CLI versions, obid start times and unclean exits, job counts by status and phase, failure record summaries (trigger, step, outcome code), the last 50 WARN/ERROR log lines, the last 20 turn timings.
- Every value through `secrets::known().redact`; the whole body through obid's built-in scan (scan.rs `built_in`/`matches`); refused (500, no body) unless clean.
- A `privacy` block listing what it never holds: words, prompts, paths, repository names, tokens.
- Not on the gateway allowlist (gateway.rs `allows`).

**Out:**
- Writing the file and the menu item (R09-07).
- Settings › About's Diagnostics group (#919, needs Sangam).

### Actors and ownership: what obid owns

- What the bundle holds, its redaction, its scan, and its refusal.

### Actors and ownership: what the apps show and send

- Nothing in this task; R09-07 writes it to a file.

### Steps

- Read #919's ring design; add the two rings (log lines, turn timings) in memory only.
- Build the document in diagnostics.rs from existing state; no new files on disk.
- Redact each value, then scan the body; refuse on any finding.
- Register the route; add a gateway test that it is refused.
- Write DIAG-1 to 5 with a planted secret and a planted repository name.

### Acceptance scenarios

- DIAG-1 (proposed): Given obid on loopback with the runner token, when GET /v1/diagnostics is called, then it answers with schemaVersion, versions, job counts and a privacy block.
- DIAG-2 (proposed): Given a paired phone through the gateway, when it calls GET /v1/diagnostics, then the gateway refuses it.
- DIAG-3 (proposed): Given a known secret in a job's summary and in obid.log, when the bundle is built, then neither appears in the body.
- DIAG-4 (proposed): Given the scan finds something redaction missed, when the bundle is built, then obid sends no body and says why.
- DIAG-5 (proposed): Given a job in a repository, when the bundle is built, then the repository's name and the worktree path do not appear.
