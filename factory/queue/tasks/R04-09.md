# refactor(obid): one function decides whether a follow-up carries a job's branch

<!-- Roadmap R04-09 · Sprint 3 · R04 One owner for job state · effort S · risk medium -->

### Sangam's screen

engine only

### Outcome

The ten copies of 'does a follow-up carry this branch' become one function in one module, so the rules can be fixed once and Publish, Try again, delete and the follower stop disagreeing by accident.

### Status and scope

Proposed (roadmap R04-09, milestone R04 One owner for job state).

**Why:** The check is copied with different rules at jobs.rs:4340 (exact branch, any status), 11863 and 12184 (exact branch, active), 12117, 13618 publish_action_of (same_branch, not dismissed, active or done), 14322, 14427 done_with (exact branch, active or needs_you or PR open), jobs/after_pr.rs:206 (same_branch), jobs/account_limits.rs:857; follow_up uses a third rule (`unmerged && published && pull_request_open`, jobs.rs:14622) and Job::can_publish (job.rs:1457) ignores it.

**In:**
- new: core/crates/obid/src/job/chain.rs with `pub fn carrier<'a>(jobs: &'a HashMap<String, Job>, job: &Job, holds: Holds) -> Option<&'a Job>` where `Holds` names the few real cases (AtWork, AtWorkOrDone, Open) found in today's code.
- Replace each copy with a call that keeps its current case; use same_branch (case-insensitive) everywhere, which is the one behaviour change, with a test.
- Move same_branch and chain_tip into chain.rs.

**Out:**
- Storing the chain (R04-10).
- Changing follow_up's carry rule (R04-10).
