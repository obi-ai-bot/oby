# feat(electron): a start-recovery page after three failed starts of one version

<!-- Roadmap R09-10 · Sprint 9 · R09 Ship and debug safely · effort M · risk medium -->

### Sangam's screen

needs Sangam's design first (words and layout of an error page; the page is an error path, not a product screen)

### Outcome

When Oby or obid failed to start three times in a row on one version, the owner gets a page that works without obid: Try again, Download the previous version, Export start diagnostics, Open the log folder, Quit. A broken install no longer needs a terminal or a reinstall.

### Status and scope

Proposed (roadmap R09-10, milestone R09 Ship and debug safely).

**Why:** startObid (main/obid.ts:293-350) piles up launchd workarounds and ends in a `problem` string the normal window shows; if the window itself or obid cannot start, nothing helps the owner (map: 'Engine supervision is a pile of macOS workarounds').

**In:**
- Main opens, instead of the normal window, one BrowserWindow loading a `data:` URL built in main: no preload, no IPC to obid, `will-navigate` and every web request blocked except the buttons' own actions.
- Buttons: Try again (resets nothing, relaunches), Download previous version (the previous signed build's zip URL from the verified feed, opened in the browser), Export start diagnostics (versions, attempts, last log lines, redacted, saved 0600), Open log folder, Quit.
- Trigger: the app's or obid's start-attempts count reaches 3 for the running version.

**Out:**
- Installing the previous build from the page: it only opens the download.
- New product screens.

### Actors and ownership: what obid owns

### Steps

- Get Sangam's words for the five buttons and the one-line explanation.
- Build the page in startRecovery.ts as a `data:` URL; set `webPreferences` sandbox, contextIsolation, no preload.
- Block navigation and requests with `will-navigate`, `setWindowOpenHandler` and `session.webRequest`.
- Read the previous build from the last verified feed (R09-01); hide the button when none is known.
- Write ENGINE-21 to 24.

### Acceptance scenarios

- ENGINE-21 (proposed): Given start-attempts is 3 for this version, when the app starts, then the recovery page opens and the normal window does not.
- ENGINE-22 (proposed): Given the recovery page, when it tries any navigation or request other than its buttons' actions, then it is blocked.
- ENGINE-23 (proposed): Given Export start diagnostics, when the owner picks a path, then a 0600 file with versions, attempts and redacted log lines is written.
- ENGINE-24 (proposed): Given Try again and a start that succeeds, when the window loads, then the attempts reset and the recovery page does not open next time.
