# feat(obid): recover conversation deliveries when obid starts

<!-- Roadmap R05-03 · Sprint 3 · R05 Durable words · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

After a crash, a kill or an update, the owner sees which message was not answered, and words that only waited are answered by one turn, with no work done twice.

### Status and scope

Proposed (roadmap R05-03, milestone R05 Durable words).

**Why:** Words already written as the owner's turn when obid stops get no answer and no notice (map problem 'In-flight turn state does not survive a restart'; no restart path in conversation.rs or brain/mod.rs). Jobs have RECOVERY-2 and TASKCONV-18 for this; conversations have nothing.

**In:**
- At start (lib.rs after `Conversations::open`, once `Shared` exists): every user turn whose delivery is `starting` or `running` becomes `interrupted`, and its conversation gets one obid-worded Oby turn (one per conversation, not per message).
- The line differs for a clean stop (an update or a quit) and a crash, as RECOVERY-2 does; nothing counts tries.
- Then each conversation's `queued` deliveries run as one batch, oldest first, through the same path as today's joined words.
- A turn that was cut is never sent again by itself: the owner's next words or 'continue' resume the session from session.json.
- Until #2045 `convo-delete-oby-shell` merges: settle open `shell-*` permission items (`brain::shell::is_item`) at start, since no command waits for them.

**Out:**
- Running a cut turn again by itself.
- Any app change: the line is an ordinary Oby turn.

### Actors and ownership: what obid owns

- Which deliveries are cut, the line it adds, and the batch it starts.

### Actors and ownership: what the apps show and send

- Nothing changes for clients: the line arrives as an Oby turn and the status as the `delivery` key.

### Steps

- Expose whether the last stop was clean: `Jobs::open` removes `home/stopped-cleanly` (jobs.rs:1147), so keep the flag on `Jobs` and read it there, do not read the file again.
- Add `Conversations::recover(clean)` that settles cut deliveries and appends the obid line with one write per conversation.
- Add `brain::resume_queued(shared)` that starts one batch per conversation with queued deliveries; call both from lib.rs next to `report_job_ends`.
- Settle stale `shell-*` items if `brain/shell.rs` still exists.
- Write the kill test with the fake harness: a long turn, words sent behind it, SIGKILL, start, assert DELIVERY-7 and 8.
- Ask Sangam for the two lines' words; until he answers, use the contract's text and mark it in the PR.

### Acceptance scenarios

- DELIVERY-7 (proposed): Given a turn under way, when obid is killed and starts again, then that turn's words read `interrupted`, the conversation has one Oby turn in obid's words saying they were not answered, and no agent turn starts for them.
- DELIVERY-8 (proposed): Given words waiting behind a turn when obid is killed, when obid starts again, then one new turn answers them together, as the owner's own word only when each was signed.
- DELIVERY-9 (proposed): Given obid stopped cleanly (an update or a quit), when it starts again, then the cut turn's line says Oby was restarted, not that it went down, and the rest is as DELIVERY-7.
- DELIVERY-10 (proposed): Given conversations whose turns have no `delivery` key, when obid starts, then nothing is added to them.
