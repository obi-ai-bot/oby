# feat(obid): vault health in GET /v1/status

<!-- Roadmap R11-15 · Sprint 8 · R11 Connections: MCP, sign-in and the vault · effort S · risk low -->

### Sangam's screen

engine only now; the visible line needs Sangam's design first (his design has no vault-health line; Settings › Vault is hidden)

### Outcome

Every app reads the vault's state and the names of secrets left in the Keychain from GET /v1/status, instead of only obid's log.

### Status and scope

Proposed (roadmap R11-15, milestone R11 Connections: MCP, sign-in and the vault).

**Why:** #1685: vault::left_in_keychain (vault.rs:815, called from lib.rs:563) names leftover Keychain items only in the log. status.vaultProblem (api.rs:647) says why the vault can't be read but nothing says 'ready' or lists what was left. runner-api.md 'While obid runs' says the start log names 'never a name', which the warnings contradict.

**In:**
- Add `vault: {"state": "ready" | "unreadable", "leftInKeychain": [names]}` to GET /v1/status (add-only; vaultProblem stays).
- Keep the names left_in_keychain returns in memory for the status.
- Fix runner-api.md's vault section.

**Out:**
- The app's line (needs Sangam's words, R11-01).
- Reading the Keychain again (KEYCHAIN-1 forbids obid's own secrets there).

### Actors and ownership: what obid owns

- The vault's health and the leftover list.

### Actors and ownership: what the apps show and send

- Nothing until Sangam gives the line's words and place (R11-01); then Settings shows it.

### Interfaces and dependencies

- GET /v1/status: new key vault {state, leftInKeychain}.

### Steps

### Acceptance scenarios

- VAULT-12 (proposed): Given a readable vault, when an app reads GET /v1/status, then vault.state is ready and vault.leftInKeychain lists the Swift runner's names the file lacks, oby.tetrix names included, never a value.
- VAULT-13 (proposed): Given a vault file with wider permissions, when an app reads GET /v1/status, then vault.state is unreadable and vaultProblem says why, as today.
- VAULT-14 (proposed): Given a leftover name added again with PUT /v1/obid/vault, when status is read, then that name is no longer in leftInKeychain.
