# chore(process): turn GitHub Actions on and get linux.yml green on dev

<!-- Roadmap R01-01 · Sprint 1 · R01 Safety net · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

Every pull request into dev and every push to dev runs the existing Linux workflow (Rust fmt, clippy, the whole obid suite, gitleaks, control plane, make e2e) on GitHub's runners, with no person starting it.

### Status and scope

Proposed (roadmap R01-01, milestone R01 Safety net).

**Why:** Actions is off for the repository (gh api repos/obi-ai-bot/oby/actions/permissions: enabled false). The last Linux run was 2026-10-27 and failed on dev. The Mac check runs only touched test binaries (scripts/oby-check.sh:309-315), so cross-module breaks like #2100 and #1975 stay unseen. docs/ci.md still says the workflows were removed on 2026-10-23, but .github/workflows/linux.yml is there.

**In:**
- The owner's decision and the switch to turn Actions on (repository setting, owner step)
- One run of linux.yml on current dev; an issue for each red test that is not about the Linux runner
- docs/ci.md rewritten: what runs on GitHub, what runs on the Mac

**Out:**
- Lanes and the Check job (R01-02)
- Branch protection (R01-03)
- Fixing the red tests themselves: each one is its own PR

### Actors and ownership: what obid owns

- Nothing changes in obid.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- .github/workflows/linux.yml
- docs/ci.md

### Steps

- Ask the owner why Actions is off and get a yes to turn it on; the repository is public and linux.yml uses standard ubuntu-latest runners. The owner turns it on (Settings > Actions).
- Push a no-op branch with the full-ci label or open a ready PR to run linux.yml on current dev.
- For each failing job, decide: runner problem (fix it in linux.yml) or a real red test (open a bug issue with the test name and log, link #1975 or #1804 when it is one of those).
- Rewrite docs/ci.md: GitHub runs the Linux workflow on every PR into dev and every push to dev; the Mac check keeps the Apple suites, swift test and the touched-suite run; the coordinator's full Mac run is no longer the only full run.
- Open the PR into dev with the run link in its body.

### Acceptance scenarios

- CI-1 (proposed): Given Actions is on, when a pull request into dev is opened or pushed, then the Linux workflow runs all of its jobs on that head with no person starting it.
- CI-2 (proposed): Given a push to dev, when the Linux workflow runs, then it runs to the end (no cancel by a newer push) and its result shows on that commit.

Contract: new: docs/contracts/ci.md (prefix CI)

### Tests

- No new test: the proof is a linked Linux workflow run on the PR's head (CI-1) and on dev after merge (CI-2).

### Done when

- gh api repos/obi-ai-bot/oby/actions/permissions says enabled true.
- The PR shows a Linux workflow run on its head; each red job has an open issue linked in the PR body.
- `scripts/oby-check.sh` passes on the same commit.
