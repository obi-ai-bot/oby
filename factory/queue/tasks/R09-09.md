# feat(electron): the app's run marker, renderer and child crash records, a 30 s quit deadline, and launchd back-off

<!-- Roadmap R09-09 · Sprint 7 · R09 Ship and debug safely · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

The app records its own unclean exits, renderer crashes and hung quits, counts its failed starts per version, and a crashing obid no longer restarts in a tight loop.

### Status and scope

Proposed (roadmap R09-09, milestone R09 Ship and debug safely).

**Why:** apps/electron/src/main has no `render-process-gone`, `child-process-gone` or quit deadline handler (grep finds none). The launch agent plist has no ThrottleInterval, so a crashing obid restarts at launchd's default pace.

**In:**
- A run marker and start-attempts file in the app's userData folder, as R09-08's.
- `render-process-gone` and `child-process-gone` handlers that append a line (reason, exit code, time) to a bounded file in userData.
- A hard 30 s quit deadline after `before-quit`.
- `ThrottleInterval` in build/com.deskree.oby.electron.obid.plist and in the session job's plist in obid.ts `forThisSession`.
- The app part of the diagnostics export (R09-07) reads these.

**Out:**
- The recovery page (R09-10).

### Steps

- Write runMarker.ts (marker, attempts per `app.getVersion()`, bounded crash lines).
- Hook it in index.ts: start, window loaded (reset), `before-quit`, the two process-gone events.
- Add the quit deadline.
- Add ThrottleInterval to both plists; a test keeps them equal.
- Write ENGINE-17 to 20 with Electron stood in.

### Acceptance scenarios

- ENGINE-17 (proposed): Given the renderer process is gone, when main sees it, then one line with the reason is recorded and the window is reloaded once.
- ENGINE-18 (proposed): Given quit was asked and something holds it, when 30 s pass, then the app exits and records `quit_timeout`.
- ENGINE-19 (proposed): Given the app exited before its window loaded three times for one version, when it starts again, then its start-attempts count is 3.
- ENGINE-20 (proposed): Given the packaged plist and the session plist, when they are read, then both carry the same ThrottleInterval.
