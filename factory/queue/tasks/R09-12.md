# feat(install): protect a Linux obid from its agents' memory use

<!-- Roadmap R09-12 · Sprint 7 · R09 Ship and debug safely · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

On a small Linux box, a runaway build is killed before obid is, and one killed agent does not stop the whole service.

### Status and scope

Proposed (roadmap R09-12, milestone R09 Ship and debug safely).

**Why:** install/install.sh writes a systemd unit with only `Restart=on-failure` (install.sh:461-463). When an agent's build exhausts memory, the kernel may kill obid and take every job, the Sphere link and the phone relay with it.

**In:**
- install.sh's unit: `MemoryMax=90%`, `OOMPolicy=continue`, `OOMScoreAdjust=-500`.
- obid: on Linux, write 500 to /proc/<pid>/oom_score_adj for each process group it starts (agents, checks) at spawn.

**Out:**
- A new memory admission reason: obid already waits on memory pressure (status.memory.waiting, docs/runner-api.md).

### Actors and ownership: what obid owns

- The oom_score_adj of what it starts.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Steps

- Add the three lines to the unit in install.sh.
- Find the one spawn path for agents and checks in process.rs and set oom_score_adj after spawn on Linux only.
- Write LINUX-1 in tests/install.rs and LINUX-2 as a Linux-only test.
- Document both in docs/install.md 'What it does'.

### Acceptance scenarios

- LINUX-1 (proposed): Given install.sh on Linux, when it writes the unit, then the unit has MemoryMax, OOMPolicy=continue and OOMScoreAdjust=-500.
- LINUX-2 (proposed): Given obid on Linux starts an agent, when the agent's process is read, then its oom_score_adj is 500.
