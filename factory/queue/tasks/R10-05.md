### Sangam's screen

engine only

### Outcome

A written answer to: which route reads the policy, which token scope writes it, how a client knows the owner is the Sphere's admin, and what the server says on a version conflict. The next two tasks build on it with no guess.

### Status and scope

Proposed (roadmap R10-05, milestone R10 Finish the Obysphere client).

**Why:** A new Sphere's policy is `[]`, so every question is `policy_denied` (ask-an-oby.md 'The Obysphere's policy'). Only an owner token with `admin` can write it (PUT /v0.1/spheres/{sphere}/policy). obi-protocol has the wire schemas (spec/schemas/v0.1/wire/policy.schema.json, policy-put.request.schema.json with `expected_version`), but this repository has no copy of sphere-api.md, and the Electron main asks only for `directory:read` (apps/electron/src/shared/sphere.ts:221).

**In:**
- Read obi-sphere's spec/sphere-api.md at the commit sync-spec.sh last copied, read only.
- Run a local obi-sphere with e2e/rig.mjs and call GET and PUT policy with an owner assertion.
- Write the answer as a section of the new docs/contracts/sphere-policy.md.

**Out:**
- Any change in obi-ai-bot/obi-sphere. If the server cannot do it, write that down for Dmytro; do not plan the server work.
