# fix(obid): one queue per account for sign-in, refresh, sign-out and removal

<!-- Roadmap R08-11 · Sprint 3 · R08 One interface for every agent CLI · effort S · risk low -->

### Sangam's screen

engine only (a 'Stop and sign out' choice in the app needs Sangam's design first; this task ships only the engine order)

### Outcome

Connection commands of one account run one at a time; a new sign-in cancels one that waits; a sign-out or removal waits for a running turn's end (or the owner picks Stop and sign out), so a login is never pulled from under a running job.

### Status and scope

Proposed (roadmap R08-11, milestone R08 One interface for every agent CLI).

**Why:** jobs/logins.rs has 10 fix commits and accounts.rs 10; `refresh_if_due` (logins.rs:1409), sign-in (accounts.rs:1439, 1666), `remove` (accounts.rs:1173) and the usage read's refresh run independently, guarded only by the `changing` set (`being_changed`, jobs.rs:2661). Map: 'Login refresh is fragile and keeps being reworked' (high; #1867).

**In:**
- A per-account async queue in accounts.rs that `sign_in`, `sign_in_code`, `remove`, sign-out and `refresh_if_due` before a boxed run go through.
- A newer sign-in cancels a waiting one; removal waits for the account's running turns to end.

**Out:**
- The Keychain keeper thread (deleted by #2045 `convo-delete-keeper`).
- Which login files are copied: R08-13.

### Actors and ownership: what obid owns

- The order of connection commands per account.

### Actors and ownership: what the apps show and send

- Nothing changes until Sangam designs a 'waits for the running task' state; the account row shows `being changed` as today.

### Steps

- Add ACCOUNTS-19 to 21, marked proposed.
- Add a per-account queue (one `tokio::sync::Mutex` per id, created on demand) and route the five commands through it.
- Make a new sign-in cancel a queued one.
- Make sign-out and removal wait for `running_on(account) == 0` or a stop.
- Write the three tests with stand-in CLIs that block.

### Acceptance scenarios

- ACCOUNTS-19 (proposed): Given a sign-in of an account under way, when a refresh before a boxed run of that account is due, then the refresh runs after the sign-in ends, never at the same time.
- ACCOUNTS-20 (proposed): Given a sign-in that waits behind another command of the same account, when the owner starts a new sign-in, then the waiting one is cancelled and only the new one runs.
- ACCOUNTS-21 (proposed): Given a job running on an account, when the owner signs that account out, then the login stays until the job's turn ends, and the account then signs out; Stop and sign out ends the turn first.
