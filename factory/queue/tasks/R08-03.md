# refactor(obid): AgentDriver trait for a job's turn, with each driver's own error mapping

<!-- Roadmap R08-03 · Sprint 4 · R08 One interface for every agent CLI · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

A job starts its agent's turn through one call, `driver(tool).run_turn(..)`, and each driver turns its own error fields into `agent::Cause`, so jobs.rs no longer branches on the tool to run a turn or classify how it ended.

### Status and scope

Proposed (roadmap R08-03, milestone R08 One interface for every agent CLI).

**Why:** jobs.rs ~8110-8190 has three arms that call `agent::run_turn`, `codex::run_turn` and `acp::run_turn`, each with its own options type; argv building branches again at ~7404-7504 and ~7865. jobs.rs is the fix magnet (156 of 289 commits are fixes; `jobs_rs_limit=15208`). Error classification (RECOVERY-7, `Failure::of_claude` in agent.rs) sits beside the Claude adapter only.

**In:**
- new: core/crates/obid/src/drivers/mod.rs with `trait AgentDriver: Send + Sync` and `fn driver(tool: Tool) -> &'static dyn AgentDriver`; this task adds only `argv`, `run_turn` and `cause`.
- One shared `TurnOptions` (resume, model, effort, mode, plan, account name) that each driver maps to `agent::Options`, `codex::Options` or `acp::Options`.
- jobs.rs launch: the three arms become one call.

**Out:**
- The conversation harness and sphere answering: R08-04.
- read_usage, list_models, identity: R08-05.
- Sign-in and login copy: R08-12, R08-13.
- Any change to the protocols themselves.

### Actors and ownership: what obid owns

- Which driver runs a job's turn and how each tool's failure becomes a `Cause`.

### Steps

- Read jobs.rs ~7400-7520, ~7790-7870 and ~8100-8200 and list every input each arm passes.
- Define `AgentDriver` with `argv`, `run_turn`, `cause`, and `TurnOptions`; implement it for the three adapters by calling their existing functions.
- Move `Failure::of_claude` and the Codex and ACP error readers behind `cause`.
- Replace the three arms in jobs.rs with one `driver(tool)` call; keep the order of side effects (process group record, worktree lock).
- Run `cargo test -p obid --test adapters` and `--test long_jobs` one at a time; add PROVIDERS-7 and 8.
- State the jobs.rs line count before and after; lower `jobs_rs_limit` if it fell.

### Acceptance scenarios

- PROVIDERS-7 (proposed): Given a job on each of Claude Code, Codex and Cursor (scripted stand-ins), when it runs a round, then it starts its turn through `AgentDriver::run_turn` and the job record (events, session, `cause`) equals today's for the same stand-in output.
- PROVIDERS-8 (proposed): Given each driver's own error shape for a usage limit, a rate limit, an expired login and an unknown error, when the turn ends, then the driver's `cause` gives the same `agent::Cause` as dev 952bc03d does (RECOVERY-7).
