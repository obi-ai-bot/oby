# feat(obid): messages and inbox answers take a request key

<!-- Roadmap R02-05 · Sprint 1 · R02 Commands that are safe to repeat · effort S · risk medium -->

### Sangam's screen

engine only

### Outcome

Words sent twice to an ended task start one follow-up. An inbox answer sent twice (Try again, One more round, Start) acts once and answers the same twice.

### Status and scope

Proposed (roadmap R02-05, milestone R02 Commands that are safe to repeat).

**Why:** routes.rs `message` (POST /v1/jobs/{id}/messages) calls Jobs::message_attaching, whose message_as (jobs.rs:4086) calls self.create for a follow-up each time the job has no active follow-up (`following`, jobs.rs:2162). sphere/routes.rs `answer` (POST /v1/inbox/{id}/answer) answers a second Start with 409, not the first answer. #1851.

**In:**
- Optional `requestId` in the body and `Idempotency-Key` header on POST /v1/jobs/{id}/messages and POST /v1/inbox/{id}/answer; also /stop and /move.
- A repeat returns the first status and body.

**Out:**
- Requests with no key keep today's behaviour, 409 included.
- Brain tool calls and the internal Try again (R02-06).

### Actors and ownership: what obid owns

- Key check and receipt around Jobs::message_attaching, the inbox answer, Jobs::stop and the move route.

### Actors and ownership: what the apps show and send

- Nothing yet; clients send the key in R02-07 and R02-08.

### Interfaces and dependencies

- Optional `requestId` body key and `Idempotency-Key` header on POST /v1/jobs/{id}/messages, /stop, /move and POST /v1/inbox/{id}/answer. Job JSON: optional `requestId` on a follow-up.

### Steps

- Use it in routes.rs `message`, the stop route, the move route (LIMITS-16) and sphere/routes.rs `answer`.
- Keep the signed-words check (typed_by_owner) before the receipt lookup: a repeat must be as signed as the first.
- Document each in docs/runner-api.md.
- Write RECEIPTS-8 to 11.

### Acceptance scenarios

- RECEIPTS-8 (proposed): Given an ended job, when POST /v1/jobs/{id}/messages comes twice with key K, then one follow-up is made and both answers are 201 with it.
- RECEIPTS-9 (proposed): Given a running job, when the same words come twice with key K, then the agent hears them once.
- RECEIPTS-10 (proposed): Given an inbox item answered Try again with key K, when the same answer comes again with K, then the job has one more round, not two, and the second answer equals the first.
- RECEIPTS-11 (proposed): Given a job stopped with key K, when POST /v1/jobs/{id}/stop comes again with K, then the answer is the first one and `stoppedBy` is unchanged.
