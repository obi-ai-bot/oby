# spike(obid): what Claude Code stream-json and Codex turn/steer accept during a turn

<!-- Roadmap R05-01 · Sprint 2 · R05 Durable words · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

A written answer, with recorded transcripts, of how each agent CLI that Oby drives can take more words while a turn runs, and how obid can know that it took them. The steer tasks (R05-05, R05-07) build on it.

### Status and scope

Proposed (roadmap R05-01, milestone R05 Durable words).

**Why:** The code does not show it. obid writes one `user` line per turn on Claude Code's stdin (`agent::user_message`, agent.rs:403, sent at agent.rs:527; a warm process gets the next turn only after its `result`). Codex `turn/steer` is called only for obid's own decline notes (codex.rs:812, `decline`), with `conn.request` and its reply not read. Cursor's ACP path has no equivalent in harness_cursor.rs or acp.rs.

**In:**
- Claude Code (the tested 2.1.302) with `-p --input-format stream-json --output-format stream-json`: a second `user` line written while a turn runs. Is it read at the next tool boundary, after the `result`, or refused? Does it start a second `result`? Is there an acknowledgement on stdout (for example an echo of the user message: check `--replay-user-messages` in `claude --help`)? Does it break `Conn::quiet` or the warm process (brain/harness.rs `Warm`)?
- Codex app-server (codex-cli 0.162.1) `turn/steer` with `expectedTurnId`: the reply on success, on a finished turn and on a wrong turn id; whether steered input is kept in the thread so `thread/resume` hears it.
- Cursor (cursor-agent 2026.10.01) over ACP: a second `session/prompt` during a turn; expected answer: not supported.
- The same three questions for a job's run (jobs use agent.rs and codex.rs too).

**Out:**
- Any production change in obid.
- Gemini and Antigravity.

### Steps

- Read how obid drives each CLI: agent.rs (stdin lines, control requests), codex.rs `turn`, `decline`, `Conn::request` vs `Conn::call`, acp.rs.
- On a real Mac, outside obid, drive each CLI with a small script as obid does (same flags) and send words during a long turn (for example a turn that runs `sleep 20` twice).
- Record the stdin/stdout lines of each case as fixtures under tests/fixtures/steer/ (secrets removed) so the fake harnesses can replay them later.
- Write the answer as a table (CLI, version, accepted?, when it is read, acknowledgement, failure reply, kept on resume) in a new 'Steering a turn' section of docs/conversation-harness.md, and as a comment on the R05-05 issue.
- Say plainly what is unknown or version-bound (#1095 list of tested versions).
