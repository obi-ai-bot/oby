## What
- **Finding from V01-44's audit** (its `build.md`, "Audit: scans of outgoing content", the `factory/bin/test-run` `to_send` line): V01-44 made gitleaks read the change as text (`factory/bin/outgoing.py`), but the payload test-run sends is still `git diff --binary --full-index <base> <tree>`, which follows a configured `diff.<driver>.textconv` or `diff.<driver>.command`.
- With such a driver in git config and a `.gitattributes` line naming it, the payload holds the driver's output in place of the file's text. Those bytes leave this Mac on ssh's standard input, and the secret scan never read them: it read the file's own text. A textconv that decodes a file (base64 to text, say) sends a secret the scan saw only encoded. The VM then refuses the payload (`the slot's tree is …, not …`), but it has already left.
- Seen in V01-44's red-first run: with `diff.hide.textconv` or `diff.ext.command`, the run fell back with that VM refusal.
- **Harm:** narrow, as it needs a driver in git config as well as the attribute line, but it is still a way for content to leave unscanned.

## Why
AGENTS.md, "Non-negotiable": everything that leaves is scanned for secrets first. The payload and the scanned copy should differ only in the binary encoding.

## How
- Build the payload with `git diff --binary --full-index --no-ext-diff --no-textconv <base> <tree>`. It then also applies on the VM under a driver.
- A test in `factory/tests/test_test_run_remote.py` beside REMOTE-66: with `diff.hide.textconv` printing text that isn't in the file, the run reaches the VM, its tree matches, and that text is not on ssh's standard input.
