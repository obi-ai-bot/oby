# fix(obid): keep the owner's words until the agent is launched

<!-- Roadmap R04-05 · Sprint 5 · R04 One owner for job state · effort S · risk medium -->

### Sangam's screen

engine only

### Outcome

Words the owner sent, or a move's handoff note, are never lost when the run fails before its agent starts: Try again then delivers them.

### Status and scope

Proposed (roadmap R04-05, milestone R04 One owner for job state).

**Why:** #1649 part 2: take_heard (jobs.rs:4549) runs in run_owner_job before steps that can fail the run (Claude login copy, memory read, MCP config, safety-limit stall, launch). After a failure the words survive only in `notes`, and Try again resumes with only 'Try again'.

**In:**
- Take the words only once the agent launched, or put them back into `heard` when the run ends before launch.
- The same for the handoff note of a move (moves::TAKING_OVER).

**Out:**
- Changes to what `notes` shows on the task page.

### Actors and ownership: what obid owns

- When the owner's words leave `heard`.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Steps

- Find every take_heard call in run_owner_job and the steps between it and launch.
- Choose the smaller change: move take_heard after launch, or restore on the early-exit paths through one guard value dropped on success.
- Write TASKS-22 with a fake login that is not ready, then Try again, and assert the agent's first message holds the answer.
- Close #1649 with R04-04 and this.
