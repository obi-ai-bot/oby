<!-- Roadmap R04-15 · Sprint 7 · R04 One owner for job state · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

A written answer, with numbers, on whether cross-file writes still cause bugs once every job write goes through Jobs::apply, and if so a migration outline that follows the add-only and no-backup rules.

### Status and scope

Proposed (roadmap R04-15, milestone R04 One owner for job state).

**Why:** A job end and its inbox card, a conversation turn and its job, and R04-10's root-plus-follow-up save are separate JSON files a crash can split; about ten stores have their own load and save code. Whether this still causes bugs after R04-07 is not measured.

**In:**
- Count fix commits and open issues since R04-07 merged whose cause is two files out of step; list each two-file write path that remains.
- Measure load time and size of home/jobs on a real Mac with the owner's data (read-only copy).
- If yes: outline rusqlite (bundled, MIT/public domain, Apache-2.0 compatible), numbered append-only migrations each with its marker in one transaction, a fresh-install schema with a parity test, a newer-version refusal, and a one-time JSON import kept read-only.
