# feat(obid): move a saved model the CLI no longer lists to the newest of its family

<!-- Roadmap R08-16 · Sprint 6 · R08 One interface for every agent CLI · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/electron/src/renderer/src/SettingsView.tsx (Agents, Model menu); the words for the move are Sangam's

### Outcome

When a fresh model list no longer has an account's saved model, obid moves the account (and its queued jobs) to the newest listed model of the same family, else the tool default, and notes the move; a running turn keeps its model.

### Status and scope

Proposed (roadmap R08-16, milestone R08 One interface for every agent CLI).

**Why:** AGENTS-6 runs the tool default when a saved model is no longer offered, judged only against a list read since start (#1973). A retired version thus drops to the default (for Claude, `claude-opus-5-5`, settings.rs:208) instead of its successor; #1953 shows how silent model drift confuses the owner.

**In:**
- On a fresh list in model_lists.rs (never a failed one): family = id without version, date and variant words; pick the newest listed of that family.
- Update the account's `model` and each queued job's model; a `changed` line on each.

**Out:**
- config.json's `conversation.model` (#1953: the owner decides).
- Running turns.

### Actors and ownership: what obid owns

- Which listed model replaces a retired one.

### Actors and ownership: what the apps show and send

- Settings › Agents shows the new model; the 'Previous model unavailable · using default' row shows only when no family member is listed.

### Interfaces and dependencies

- Add-only: the account JSON may carry `modelMoved` (`from`, `to`, `at`).
