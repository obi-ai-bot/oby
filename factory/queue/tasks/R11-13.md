# feat(electron): Settings › Vault on obid's vault routes

<!-- Roadmap R11-13 · Sprint 8 · R11 Connections: MCP, sign-in and the vault · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/electron/src/renderer/src/SettingsView.tsx (Vault, hidden by LATER); unhiding needs the owner's word (AGENTS.md 'The launch build')

### Outcome

Sangam's Settings › Vault lists, adds and removes secrets in obid's vault, with his rows and words unchanged.

### Status and scope

Proposed (roadmap R11-13, milestone R11 Connections: MCP, sign-in and the vault).

**Why:** SettingsView.tsx function Vault (:1050) keeps names in a local setting only, and 'vault' is in LATER (:37), so the page is hidden. AGENTS.md hides it for launch because 'under obid it does nothing'; R11-12 removes that reason.

**In:**
- Vault() on obid: names from GET /v1/obid/vault, Add Secret through the main process (signed PUT), Remove through a signed DELETE.
- The value field stays a secure field cleared after Add; the value never reaches the renderer's state after send or any log.
- Remove 'vault' from LATER on obid only after the owner's word (R11-01).

**Out:**
- The iPhone (it has no Vault page).
- Moving the Swift app's old Keychain items (the Swift app is deleted).

### Actors and ownership: what obid owns

- Nothing new.

### Actors and ownership: what the apps show and send

- Sangam's Vault page, live on obid.

### Steps

- Add vaultNames, addSecret, removeSecret to the renderer's api (obid.ts) through preload and main, which signs PUT and DELETE.
- Make Vault() use them when onObid; keep the mock path for `npm run web`.
- Remove 'vault' from LATER when onObid, after the owner's word.
- Add tests for VAULT-6 and 7 in the renderer's test folder.

### Acceptance scenarios

- VAULT-6 (proposed): Given Settings › Vault on obid, when the owner adds a name and value, then the list shows the name from obid and the field is empty.
- VAULT-7 (proposed): Given a value obid refuses, when the owner adds it, then the page shows obid's words under the group and keeps the name.
