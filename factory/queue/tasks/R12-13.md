# feat(obid): import as stage, preview and apply, at a fresh obid's level

<!-- Roadmap R12-13 · Sprint 10 · R12 Developer workflows · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

On a new Mac the owner sees every item an export holds, picks what to apply, and nothing arrives with more trust than a fresh obid has.

### Status and scope

Proposed (roadmap R12-13, milestone R12 Developer workflows).

**Why:** #1300: no import exists. A hostile file could name a command as an MCP server or bring routines that fire jobs before the owner sees them.

**In:**
- POST /v1/import/stage: read entries one at a time with size caps, SHA-256 of the file, a preview of each item as `ready`, `confirm` or `skipped`, under a random single-use token that ends after 30 minutes.
- POST /v1/import/{token}/apply with the chosen items: check the fingerprint again, write each item atomically.
- Routines arrive paused; Always rules and repository checks arrive as `confirm`; MCP servers arrive off; no device key, pin or Sphere membership is imported.
- The preview shows `cleared` items as 'enter again'.
- A higher manifest `version` is refused with why.

**Out:**
- The Settings screen (#1301).
- Merging two homes' memories beyond equal-text dedupe.

### Actors and ownership: what obid owns

- Parsing, caps, the preview, the token and every trust default.

### Actors and ownership: what the apps show and send

- Nothing until #1301's screen.

### Interfaces and dependencies

- POST /v1/import/stage and POST /v1/import/{token}/apply (new, loopback only).

### Steps

- Stage into a 0700 folder under `home/tmp/`; never unpack paths outside it.
- Build the preview from typed items only.
- Apply each item through the same functions the API uses for that item (routines' create, memory's save), with the fresh-level defaults.
- Expire tokens after 30 minutes and on use.
- Test MOVE-6 to 11, with a zip that holds `../` paths.

### Acceptance scenarios

- MOVE-6 (proposed): Given an export, when it is staged, then every item is listed with `ready`, `confirm` or `skipped` and nothing in the home changed.
- MOVE-7 (proposed): Given a staged token, when apply runs with chosen items, then only those are written and the token cannot be used again.
- MOVE-8 (proposed): Given an imported routine, when apply ends, then it is paused and no job starts.
- MOVE-9 (proposed): Given an MCP server or a check command in the file, when apply ends, then the server is off and the check waits for the owner's confirm.
- MOVE-10 (proposed): Given the file changed after staging, when apply runs, then nothing is written and it says why.
- MOVE-11 (proposed): Given a manifest with `version: 2` or an entry over its size cap, when staged, then it is refused and nothing is kept.

Contract: new: docs/contracts/moving.md (prefix MOVE)
