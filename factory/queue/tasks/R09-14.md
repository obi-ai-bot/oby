# chore(process): cut the Mac release from a tag on main in CI, with no Swift leftovers

<!-- Roadmap R09-14 · Sprint 7 · R09 Ship and debug safely · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

A tag on main builds both architectures, signs, notarizes, staples, writes and signs latest-mac.yml, and uploads zips first and the feed last. No release step depends on one developer's Mac or on apps/mac.

### Status and scope

Proposed (roadmap R09-14, milestone R09 Ship and debug safely).

**Why:** package.sh runs only on a Mac with a keychain profile; helpers.sh calls apps/mac/app/Tools/bundle-{obid,gh,gitleaks}.sh, the last files of the deleted Swift app (AGENTS.md line 118). package.sh cites docs/release.md and scripts/release.sh, which were deleted. A signing regression needed a fix (bab22bc5).

**In:**
- Move apps/mac/app/Tools/bundle-*.sh to apps/electron/scripts/ and update helpers.sh and AGENTS.md line 118.
- new: .github/workflows/release.yml on `v*` tags of main, using the custody chosen in R09-13.
- package.sh: secrets from env when in CI, keychain profile when local; feed signing from R09-01.
- Upload with the order the contract states: zips, then latest-mac.yml with `Cache-Control: no-cache`.
- Fix stale docs: package.sh header, docs/install.md (Settings › Runner, 'nothing is published yet'), docs/ci.md, updates.md 'Publishing a release'.

**Out:**
- Staged rollout (dropped for now).
- Linux archives (R09-16).

### Steps

- Move the three bundle scripts with `git mv`; fix helpers.sh's `sources` list and call.
- Make package.sh read credentials from env in CI; keep the local path working.
- Write release.yml: guard that the tag's commit is on main, build, sign, notarize, sign the feed, upload in order.
- Run it on a test tag against a test bucket path; then on a real tag.
- Fix the stale docs in the same PR.

### Acceptance scenarios

- RELEASE-1 (proposed): Given a `v*` tag on main, when the workflow runs, then it publishes both zips and then a signed latest-mac.yml, and a Mac on the previous version sees the update.
- RELEASE-2 (proposed): Given a tag not on main, when the workflow runs, then it publishes nothing.
- RELEASE-3 (proposed): Given gitleaks finds something in the app, when the workflow runs, then nothing is notarized or uploaded.

Contract: new: docs/contracts/release.md (prefix RELEASE)
