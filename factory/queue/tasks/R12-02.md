# feat(cli): `oby inbox` and `oby answer`, with the same limits as oby-mcp

<!-- Roadmap R12-02 · Sprint 9 · R12 Developer workflows · effort S · risk medium -->

### Sangam's screen

engine only

### Outcome

The owner can see what waits for them and settle it from a shell, where the API allows a token holder to settle it. For the rest, the CLI says to answer in Oby.

### Status and scope

Proposed (roadmap R12-02, milestone R12 Developer workflows).

**Why:** Exit code 3 (R12-01) needs a way forward from the shell. oby-mcp already settles the inbox with fixed rules (docs/mcp.md, 'The inbox, as the apps settle it'); #2043 SIGN makes Allow and widening changes need the owner's signed words.

**In:**
- `oby inbox [--json]` on GET /v1/inbox.
- `oby answer <item> <option>` on POST /v1/inbox/{id}/answer, only with one of the item's own options, and `--words -` for a question.
- The same 'answer that in Oby' refusals as oby-mcp: confirm items, publish, merge, settings, and every answer that obid refuses to an unsigned caller.

**Out:**
- Any automatic answer: the CLI never answers unless the owner runs `oby answer`.
- Signing: the CLI has no device key.

### Actors and ownership: what obid owns

- Which answers an unsigned caller may give (SIGN, #2043). The CLI repeats none of that rule: it shows obid's refusal.

### Actors and ownership: what the apps show and send

- Nothing changes for the apps.

### Steps

- Add `inbox` and `answer` subcommands on the shared client.
- Refuse confirm items locally, as oby-mcp does; pass every other answer to obid and print its refusal as is.
- Test CLI-9 to 11 against a stub runner that answers as obid with SIGN does.

### Acceptance scenarios

- CLI-9 (proposed): Given an open question item, when the owner runs `oby answer <id> --words -` with text on stdin, then the job hears those words and the command exits 0.
- CLI-10 (proposed): Given a permission item, when the owner runs `oby answer <id> Allow` and obid refuses it to an unsigned caller (SIGN), then the CLI prints 'answer that in Oby', exits 3 and the item stays open.
- CLI-11 (proposed): Given a confirm item, when `oby answer` runs, then nothing is sent to obid and it exits 3.
