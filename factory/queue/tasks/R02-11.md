# feat(obid): a home format file, and refuse a home a newer obid wrote

<!-- Roadmap R02-11 · Sprint 2 · R02 Commands that are safe to repeat · effort S · risk medium -->

### Sangam's screen

engine only

### Outcome

After a downgrade, obid stops before it writes anything and says which version wrote the home. No job or setting is lost by an older obid.

### Status and scope

Proposed (roadmap R02-11, milestone R02 Commands that are safe to repeat).

**Why:** obid's home has no format number. An older obid reads a newer job file, drops the keys it does not know on its next save, or skips the file (store::load_dir).

**In:**
- home/schema.json `{"format": n, "writtenBy": "<version>"}`, written at start.
- A higher format: obid exits with a new StartError before any write.

**Out:**
- Migrations.
- Keeping unknown keys (R02-13).

### Actors and ownership: what obid owns

- The home's format number.

### Actors and ownership: what the apps show and send

- The Electron app shows obid's start error as today.

### Steps

- Read schema.json first in obid::serve (lib.rs:253), before Jobs, Conversations or the vault open.
- Add a StartError variant and its exit code; write it in docs/runner-api.md, configuration.
- Write HOME-5 to 7; HOME-6 compares the home's file times before and after.

### Acceptance scenarios

- HOME-5 (proposed): Given a home with no schema.json, when obid starts, then it writes format 1 and its version.
- HOME-6 (proposed): Given a home whose schema.json format is higher than obid's, when obid starts, then it exits non-zero before any file in home changes and its error names `writtenBy`.
- HOME-7 (proposed): Given a home with a lower format, when obid starts, then it raises the format and goes on.
