# feat(obid,ios): stable reasons on refused phone connections and the device's current expiry

<!-- Roadmap R07-09 · Sprint 4 · R07 One wire contract · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/shared/ReachNotice.swift, apps/ios/app/SettingsScreen.swift (words from Sangam)

### Outcome

A removed phone says it was removed, an expired one says it expired, and 'Paired until' shows the date obid holds now.

### Status and scope

Proposed (roadmap R07-09, milestone R07 One wire contract).

**Why:** #1967: the iPhone keeps `expiresAt` from redeem (Phone.swift:355, 661, 679) and ReachNotice.swift words a 401 as expired or removed from that date, so a phone revoked on day 45 reads 'expired'. gateway.rs:759-771 answers 401 with English text only; ApiError::because (api.rs:384-415) already gives sign-in routes a stable `reason`.

**In:**
- Every 401, 409 and update refusal from the gateway and relay gets `reason`: device-removed, device-expired, wrong-route, client-update-required, obid-update-required
- An add-only route or key on an allowlisted route that gives the device its current `expiresAt`
- iPhone: ReachNotice and Settings branch on `reason` and read the current expiry
- Android equivalent (skip if R03 freezes Android)

**Out:**
- The relay socket close codes (4001, 4003, 4008): R07-11 uses them as they are

### Actors and ownership: what obid owns

- Which reason applies; the device's current expiry.

### Actors and ownership: what the apps show and send

- Sangam's sentence for each reason; obid's English stays the fallback for an unknown reason.

### Interfaces and dependencies

- Add-only `reason` on gateway and relay refusals.
- Add-only current `expiresAt` for the calling device on an allowlisted route.

### Steps

- List each refusal in gateway.rs and relay/mod.rs.
- Return ApiError with because(...) for each.
- Add the current expiry to the device's own answer.
- Change the iPhone to branch on reason and refresh expiresAt.
- Write PAIRING-8 and 9 tests; document reasons as add-only words.

### Acceptance scenarios

- PAIRING-8 (proposed): Given a phone the owner revoked, when it calls obid through the relay, then the answer is 401 with reason device-removed, and the phone shows the removed sentence, not the expired one.
- PAIRING-9 (proposed): Given obid slid a phone's token (PAIRING-6), when the phone opens Settings, then 'Paired until' shows obid's current expiresAt.
