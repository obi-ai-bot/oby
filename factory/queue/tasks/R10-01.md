# feat(obid): call off outgoing Obi-to-Obi requests when their work ends

<!-- Roadmap R10-01 · Sprint 7 · R10 Finish the Obysphere client · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

When the owner's work ends, the teammate's Oby stops reviewing or approving it. No teammate review or GitHub approval of a stale commit runs for up to 2 hours after the job stopped or the pull request moved on.

### Status and scope

Proposed (roadmap R10-01, milestone R10 Finish the Obysphere client).

**Why:** obid receives the spec's `cancel` (follower.rs:282, it stops the job and dismisses a GitHub approval) and lists `cancel` in its card's FEATURES (link.rs:82), but it never sends one: no outgoing `cancel` exists in sphere/link/sender.rs or routes.rs. ask_teammate (sphere/link/reviews.rs:1090) sends a review_request with approve_on_host and a 2-hour expiry; a stopped job or a new head leaves it open. The schema exists (obi-protocol spec/schemas/v0.1/actions/cancel.schema.json, empty body).

**In:**
- Send `cancel` (in_reply_to the request) for every open outgoing review_request or question of a job that ended stopped (Jobs::stop, Jobs::stop_all), whose pull request merged or closed, or whose pull request head moved past the request's `head_sha` (approval::requests already keys on head).
- Send `cancel` for an open question asked by a conversation turn that the owner stopped (POST /v1/conversation/stop).
- Mark the outgoing exchange `cancelled` (a value the exchange state already has) and emit an `exchange` event; the peer thread then reads `Called off` as for theirs.
- Add `POST /v1/obid/sphere/exchanges/{id}/cancel` for a manual call-off, outgoing exchanges only: `404` unknown, `409` already ended or incoming.

**Out:**
- Any change to the cancel action, its schema or the Sphere server.
- An app button for the manual call-off (no Sangam screen yet).
- handoff and introduction (obid does not send them today).

### Actors and ownership: what obid owns

- Which outgoing exchanges belong to which job, pull request head or conversation turn; when a call-off is due; sending it once through the existing outbox.

### Actors and ownership: what the apps show and send

- Nothing new: the peer thread and the ask card already show `cancelled` as `Called off` (ASK-20).

### Interfaces and dependencies

- Add `POST /v1/obid/sphere/exchanges/{id}/cancel` (loopback, obid's token). No new key or enum value elsewhere.

### Steps

- Write docs/contracts/obi-requests.md with OBIREQ-1 to 6 from the template.
- Add `Link::call_off(correlation_id, why)`: build the `cancel` reply (prepare_reply), put it in the outbox, set the exchange `cancelled`.
- In the Link, follow `job` events (Events) and call off the open outgoing requests of a job that ended stopped, merged or closed; do not add lines to jobs.rs (jobs_rs_limit only shrinks).
- In ask_teammate, before a new request for the same pull request, call off any open one at another head.
- Hook the conversation stop (brain::stop) to call off the open question of that turn's `asked_in`.
- Add the route, document it in runner-api.md 'obid only: Obi-to-Obi exchanges', and write the tests against the fake Sphere in sphere_api.rs.

### Acceptance scenarios

- OBIREQ-1 (proposed): Given a job that asked a teammate's Oby for a review, when the owner stops the job, then obid sends one `cancel` for that exchange and the exchange reads `cancelled`.
- OBIREQ-2 (proposed): Given an open teammate approval request at head A, when the pull request's head moves to B and obid asks again, then the request at A is called off before or with the new one, and only one request per pull request stays open.
- OBIREQ-3 (proposed): Given an open outgoing request, when its pull request merges or closes, then obid sends `cancel` once.
- OBIREQ-4 (proposed): Given a question a conversation turn asked, when the owner stops that turn, then the question is called off and the conversation card reads `Called off`.
- OBIREQ-5 (proposed): Given an outgoing exchange that already ended, when the call-off route or a job stop runs, then nothing is sent and the route answers `409`.
- OBIREQ-6 (proposed): Given the Sphere cannot be reached, when a call-off is due, then the `cancel` waits in the outbox and goes once, also across an obid restart.
