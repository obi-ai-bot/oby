# chore(factory): a nightly full Mac check of dev, run by the factory when no gate waits

<!-- Roadmap R01-14 · Sprint 1 · R01 Safety net · effort S · risk low · new 2026-11-13 from docs/ci-architecture.md -->

### Sangam's screen

engine only

### Outcome

Once a day, when no factory gate is waiting, the factory runs the full Mac check (`OBY_CHECK_ALL=1`) on `origin/dev` as merged, under the same check lock. It writes the result where the dashboard shows it. On a failure it tells the owner and writes a fix task file. So a break that only a Mac can see, such as Seatbelt, the Keychain or Swift, is found within a day even when no pull request's affected check reached it, without a macOS runner on GitHub.

### Status and scope

Proposed (new, docs/ci-architecture.md, "Who runs what, once").

**Why:** the Mac check runs only what a change reaches, and GitHub tests dev as merged nightly, on Linux only. The only full run of the Mac suites is the coordinator's by hand. A macOS runner on GitHub is billed even for a public repository ($0.062 a minute; `oby` paid $17.50 for 282 of them in October 2026). A self-hosted runner on a public repository would run a fork's workflow file.

**In:**
- new `factory/bin/nightly`:
  - when the last run is older than 20 hours and no job is in `gate` or `merging`, make a detached worktree of `origin/dev` under `.worktrees/nightly`
  - run `factory/checks.sh` there with `OBY_CHECK_ALL=1` (it takes the lock as any gate does)
  - write `factory/jobs/nightly/<date>.md` (`GATE: PASS|FAIL`, the commit, the time, the last 80 lines), then remove the worktree
- `/factory run` calls it between jobs when it is due (SKILL.md)
- On FAIL: merges pause as for a red GitHub night (R01-03), one line to the owner in the orchestrator's message, and a task file `factory/queue/tasks/A00-<n>.md` naming the failing tests, uncommitted, as the skill already does for new tasks
- The dashboard shows the last nightly result

**Out:**
- A macOS runner on GitHub, hosted or self-hosted
- Opening GitHub issues (the factory reads and writes none)

### Steps

- Write `factory/bin/nightly` (Python, as `factory/bin/gate`), reusing gate's way of running checks.sh in a worktree; it never touches a job's worktree or branch.
- Make `factory/bin/job queue` print `nightly due` when it is.
- Update SKILL.md, README.md and the dashboard.
- Run it once on dev and link the result file's summary in the pull request.

### Acceptance scenarios

- CI-29 (proposed): Given no nightly run in the last 20 hours and no job in `gate` or `merging`, when the orchestrator checks between jobs, then the full Mac check runs on `origin/dev` and its result is written to `factory/jobs/nightly/<date>.md`.
- CI-30 (proposed): Given a job enters `gate` while the nightly run waits for the lock, when the lock frees, then whichever came first runs first, and the nightly worktree is removed after its run, passed or failed.
- CI-31 (proposed): Given the nightly run fails, when it ends, then the orchestrator tells the owner in one line and leaves one uncommitted task file naming the failing tests.
