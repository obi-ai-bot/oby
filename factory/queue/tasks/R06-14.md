# feat(ios): resume the event stream with `after` and refetch only on `resync`

<!-- Roadmap R06-14 · Sprint 4 · R06 Events that clients only apply · effort S · risk low -->

### Sangam's screen

engine only (client plumbing; no screen changes)

### Outcome

The iPhone back from the background, or after a dropped relay, gets the events it missed instead of reading everything again.

### Status and scope

Proposed (roadmap R06-14, milestone R06 Events that clients only apply).

**Why:** Runner.swift `events()` (apps/shared/Runner.swift:1603) opens v1/events with no id, and the phone refetches after every reconnect; over the relay that is the slowest path.

**In:**
- EventParser keeps the `id:` field; the follower keeps the last id in memory and reconnects with `v1/events?after=<id>` when status lists `events-replay-v1`.
- A `resync` event, or a new launch, does today's full read.

**Out:**
- The relay's recovery state machine (R07 'One recovery state machine for the relay connection').
- The Watch: it follows only while Oby is on screen (docs/runner-api.md).

### Actors and ownership: what obid owns

- The ring and `resync` (R06-02).

### Actors and ownership: what the apps show and send

- Nothing visible; fewer reads after a reconnect.

### Files

- apps/shared/Runner.swift
- apps/shared/LiveSession.swift
- apps/ios/tests/RunnerTests.swift
- apps/ios/tests/RelayTests.swift

### Steps

- Add the id to EventParser's output and a `.resync` RunnerEvent.
- Keep the last id in the follower; add `after` to the request when the capability is listed.
- Write EVENTS-11 to 13 in RunnerTests and RelayTests.
- Run `xcodebuild ... -scheme ObyPhone ... test` and swift_client.rs.

### Acceptance scenarios

- EVENTS-11 (proposed): Given the phone saw id E-20, when the relay drops and it reconnects, then it asks for `?after=E-20` and applies the replay without a full read.
- EVENTS-12 (proposed): Given the phone gets `resync`, when it is parsed, then the phone does its full read as after a launch.
- EVENTS-13 (proposed): Given an obid without `events-replay-v1`, when the phone reconnects, then it sends no `after`.
