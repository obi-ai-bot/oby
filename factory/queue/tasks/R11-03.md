# refactor(obid): agent tools as a table with their gates as data

<!-- Roadmap R11-03 · Sprint 8 · R11 Connections: MCP, sign-in and the vault · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

Each tool an agent can call (the conversation's oby_* tools, oby_ask_owner, Tetrix's forwarded tools) is one table entry: name, schema, handler and gate fields. A reader sees who may call what, and the registry (R11-07) adds rows instead of code.

### Status and scope

Proposed (roadmap R11-03, milestone R11 Connections: MCP, sign-in and the vault).

**Why:** Gates are spread: CONFIRMS (brain/tools.rs:265) and ONLY_READ (:317) lists, owners_word (brain/owners_word.rs), owners_call (brain/actions.rs), session.taint() calls in call() (:363, :432, :445, :498), Tetrix's reads() (tetrix.rs:81) and TOOLS (:33), and asks_through_oby in connections.rs. A new rule must be added in the right branch of each.

**In:**
- A `Tool` entry type in mcp.rs: name, description, input schema, handler, and gates: `confirm_unless_owners_word`, `owner_only`, `marks_on_result` (taints the turn or marks the job where read), `read_only`, `server` (conversation, broker, tetrix).
- tools/list and tools/call of the three servers read the table.
- Delete CONFIRMS, ONLY_READ and Tetrix's reads() in favour of the entries.

**Out:**
- Changing any gate's outcome: every existing test keeps passing.
- Signed Allow and mode changes (#2043 SIGN).

### Actors and ownership: what obid owns

- Which tool needs the owner's word, which is owner-only, which marks what it reads.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Steps

- List every tool and every gate today in a table in agent-mcp.md (source: brain/tools.rs list() and call(), tetrix TOOLS, connections tools()).
- Add the Tool entry type and the dispatcher in mcp.rs; gates run in one fixed order before the handler.
- Move the conversation's tools one by one; keep each existing test green after each move.
- Move oby_ask_owner and Tetrix's forwarded tools; delete CONFIRMS, ONLY_READ, reads().
- Add AGENTMCP-4 to 7; run conversation_harness.rs, tetrix_api.rs, jobs_api.rs.

### Acceptance scenarios

- AGENTMCP-4 (proposed): Given a turn that is not the owner's signed word, when the agent calls a tool whose entry says confirm_unless_owners_word, then a confirm inbox item is made and the tool doesn't run, as CONFIRMS does today.
- AGENTMCP-5 (proposed): Given a tool whose entry says marks_on_result, when its call answers, then the turn (conversation) or the job (broker) is marked where the answer is read, and a tool without it marks nothing.
- AGENTMCP-6 (proposed): Given a job given Tetrix's tools that called none, when it ends, then it carries no mark (MERGING-30 kept by the table).
- AGENTMCP-7 (proposed): Given the table, when a test lists every entry, then each has every gate field set explicitly (no default), so a new tool can't skip a gate by omission.
