# feat(obid): the owner's MCP server registry: GET/POST/DELETE /v1/connections

<!-- Roadmap R11-06 · Sprint 8 · R11 Connections: MCP, sign-in and the vault · effort M · risk medium -->

### Sangam's screen

engine only for now; the screen needs Sangam's design first (R11-01: his design has no personal MCP server screen)

### Outcome

The owner keeps a list of MCP servers in obid (name, URL, how it signs in, the vault secret's name). The routes the Swift apps already decode come back, add-only.

### Status and scope

Proposed (roadmap R11-06, milestone R11 Connections: MCP, sign-in and the vault).

**Why:** Since 44cd6c0d (#1516) `/v1/connections` answers 404 and connections.rs keeps only the broker (call() says 'connected apps went with the strip to a dispatcher'). Connection (connections.rs:32) and its URL checks (problem()) are still there. Sangam's first run promises any MCP server (#1582); jobs off the own lane and Cursor get none of the owner's servers (#1073).

**In:**
- home/connections.json (0600) with rows: name, mcp, secret, header (existing keys) and new keys transport ("http"), auth ("header" | "oauth"), signIn (null until R11-09), tools (an optional allowlist).
- GET /v1/connections in the shape apps/shared/Runner.swift ConnectedApp decodes (name, mcp, api, secret, header, secretSaved, lastUsed) plus the new keys.
- POST /v1/connections and DELETE /v1/connections/{name}, loopback only, never on the gateway, with the owner's signed words (signed-words.md shape added to apps/electron/src/shared/words.ts).
- A value is never in the request: the secret is a vault name (R11-12 puts the value in).

**Out:**
- Handing rows to agents (R11-07).
- OAuth sign-in (R11-09).
- stdio servers, the `api` kind's forwarding, GitLab and Bitbucket.
- Any Settings screen (R11-01).

### Actors and ownership: what obid owns

### Actors and ownership: what the apps show and send

### Steps

- Write connections.md (outcome, scenarios CONNECT-1 to 5) and the runner-api.md section replacing 'connected apps are gone'.
- Add a `Registry` in connections.rs: load, validate with Connection::problem, save 0600 with store::write_private.
- Add the three routes in connections.rs router(); check X-Oby-Words for POST and DELETE.
- Add the request shapes to apps/electron/src/shared/words.ts so main can sign them.
- Add connections_api.rs with CONNECT-1 to 5; run tests/swift_client.rs.

### Acceptance scenarios

- CONNECT-1 (proposed): Given no connections, when the app sends GET /v1/connections, then obid answers [] (not 404).
- CONNECT-2 (proposed): Given a signed POST /v1/connections with a valid name, an https URL and a vault secret name, when obid saves it, then GET lists it with secretSaved true or false as the vault holds that name, and never a value.
- CONNECT-3 (proposed): Given a POST without the owner's signed words, when obid reads it, then it answers 403 with words to sign from the Mac app, and saves nothing.
- CONNECT-4 (proposed): Given a URL that isn't written the way it is read, has a login, query or fragment, or is plain HTTP off loopback, when it is posted, then 422 with Connection::problem's words.
- CONNECT-5 (proposed): Given the gateway (a paired phone), when it sends POST or DELETE /v1/connections, then it is refused as any route off the gateway's allowlist.
