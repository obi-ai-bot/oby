# feat(electron): sign latest-mac.yml and refuse unsigned, replayed or below-floor feeds

<!-- Roadmap R09-01 · Sprint 6 · R09 Ship and debug safely · effort S · risk low -->

### Sangam's screen

engine only (About's existing rows in apps/electron/src/renderer/src/SettingsView.tsx are unchanged)

### Outcome

A Mac installs an update only from a feed Deskree signed at release time. Someone who can write the oby-downloads bucket can no longer roll Macs back to an older signed build or replay an old feed, and Deskree can set a signed minimum version.

### Status and scope

Proposed (roadmap R09-01, milestone R09 Ship and debug safely).

**Why:** #1615 (open): latest-mac.yml is unsigned; electron-updater checks the zip's sha512 against the same file on the same host, and Squirrel.Mac checks only the Developer ID. updates.md 'Invariants' admits that a bucket writer can serve an older signed build under a higher number. The Swift app's Sparkle feed was signed.

**In:**
- package.sh: after latest-mac.yml is written, add `issued` (UTC time) and `minimumVersion`, then an ed25519 signature over the canonical bytes of every other field, from a key read from an env var or a file outside the repo; never printed.
- shared/updates.ts: a pinned public key and a pure `verifyFeed(info, lastIssued, running)` that refuses no signature, a bad signature, `issued` <= the last accepted one, or an offered version under `minimumVersion`.
- main/updates.ts: call it in the same `isUpdateSupported` wrapper as `onFeed`; on success store `updatesIssued` in settings.json next to `updatesAuto`.
- updates.md: new invariant and scenarios; delete the 'is a follow-up of its own' sentence.

**Out:**
- Making a bad release go away by downgrade: `allowDowngrade` stays false. Withdrawal is done by publishing the last good code under a higher version with a raised `minimumVersion`; write that as a runbook step only.
- CI signing (R09-13, R09-14).
- A 'critical update' behaviour for a Mac under the floor (needs Sangam's words).

### Actors and ownership: what obid owns

- Nothing: obid cannot replace the app it runs in (updates.md).

### Actors and ownership: what the apps show and send

- About shows Check for Updates again on a refusal, as for any failure today; the reason goes to main's log.

### Steps

- Choose the canonical form: sign the YAML bytes of the file without its `signature` line, so electron-updater still parses it unchanged; write the rule in updates.md.
- Add `verifyFeed` with Node's `crypto.verify('ed25519', ...)` and the pinned public key in shared/updates.ts.
- Wire it into the `isUpdateSupported` wrapper in main/updates.ts before `onFeed`; keep `updatesIssued` with `writeOwn` as `updatesAuto` is kept.
- Make package.sh sign with a key from `OBY_FEED_KEY_FILE` and refuse to finish without one; the key never enters dist/ or the log.
- Write UPDATES-11 to 14 as tests with a test key pair; prove each fails with its check removed.
- Add the withdrawal runbook step to 'Publishing a release'.

### Acceptance scenarios

- UPDATES-11 (proposed): Given a latest-mac.yml with no signature or a signature that does not verify against the pinned key, when Oby looks, then nothing downloads and About offers Check for Updates again.
- UPDATES-12 (proposed): Given this Mac accepted a feed with `issued` T, when a feed with `issued` at or before T arrives, even correctly signed, then it is refused as a replay.
- UPDATES-13 (proposed): Given a signed feed whose `version` is under its own `minimumVersion`, when Oby looks, then it is refused.
- UPDATES-14 (proposed): Given a correctly signed, newer feed, when it is accepted, then its `issued` is kept in settings.json and survives a relaunch.
