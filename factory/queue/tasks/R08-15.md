# feat(obid): a conversation's new session reads its handoff as a room file

<!-- Roadmap R08-15 · Sprint 7 · R08 One interface for every agent CLI · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

A conversation moved to a new session gets a short prompt and its handoff as a file in its room, which it reads with its own tools; the file stays until a turn accepts it, so a failed first turn retries with the same packet.

### Status and scope

Proposed (roadmap R08-15, milestone R08 One interface for every agent CLI).

**Why:** `first_prompt` (brain/harness.rs:2162) puts up to 20 quoted turns inline in the prompt; if the new session's first turn fails, the next try rebuilds the text. Jobs already get `.obi/inputs/handoff.md` (LIMITS-17).

**In:**
- Write the R08-14 packet to `room/handoff/<turn>.md` (create-new, no-follow, as the room's other writes), with the full quoted transcript of earlier turns beside it.
- Remove it once a turn of the new session ends well; keep it when the turn fails.

**Out:**
- A new obid tool to read it (the agent's Read or `oby_read`, CONVO-3, reads it).

### Actors and ownership: what obid owns

- The room's handoff file and its removal.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

- CONVERSATION-AGENT-26 (proposed): Given that new session's first turn fails, when it is tried again, then it reads the same file; once a turn ends well, the file is gone.
