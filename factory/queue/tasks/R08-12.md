# refactor(obid): describe each tool's sign-in and login layout as data in its row

<!-- Roadmap R08-12 · Sprint 6 · R08 One interface for every agent CLI · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

Each provider row says how it signs in (`SignIn`) and where its login lives and what a boxed copy keeps (`LoginLayout`). accounts.rs reads the row instead of branching per tool, and a new sign-in kind fails to compile until every caller handles it.

### Status and scope

Proposed (roadmap R08-12, milestone R08 One interface for every agent CLI).

**Why:** accounts.rs (2,887 lines, 77 `Tool::` references) branches per tool in `command` (2224), `tool_command` (2254) and `identity_from` (2139); jobs/logins.rs has per-tool Keychain names (`keychain_service`, `cursor_keychain_*`) and login file names (`cursor_login_file`).

**In:**
- `enum SignIn { PasteCode, DeviceCode, CliCommand, AcpAuthenticate { method }, ObidOAuth }` and `struct LoginLayout { home_env, login_files, keychain_services, keep, drop, identity }` in providers.rs, exhaustive.
- accounts.rs `command`, `tool_command`, `identity_from` read the row (through the driver's `sign_in` / `identity`).

**Out:**
- Writing a login copy: R08-13.
- ChatGPT's OAuth flow itself (chatgpt.rs): only named as `ObidOAuth`.

### Actors and ownership: what obid owns

- How each tool signs in and where its login lives, as data.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Steps

- Write each row's `SignIn` and `LoginLayout` from the code: login files, Keychain service names (`keychain_service`), fields kept and dropped.
- Add `sign_in` to `AgentDriver`; switch `command`, `tool_command`, `identity_from` to the row.
- Add PROVIDERS-14 and 15; run `cargo test -p obid --test sign_in_reasons`, then `--test accounts_api`.

### Acceptance scenarios

- PROVIDERS-14 (proposed): Given each tool's row, when the owner signs an account in, then obid runs the same command with the same environment as dev 952bc03d (stand-ins record argv and env).
- PROVIDERS-15 (proposed): Given each tool's row, when obid reads a signed-in account's identity, then the account's `email`/`plan`/`login` fields equal today's for the same CLI answer.
