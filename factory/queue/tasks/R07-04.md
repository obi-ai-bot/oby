# test(obid): wire schema for Job, InboxItem, Status and the event envelope, with a fixture corpus

<!-- Roadmap R07-04 · Sprint 3 · R07 One wire contract · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

The first schema files exist and obid's own tests fail on Linux when obid drifts from them. A fixture corpus of real answers is written for the clients to decode.

### Status and scope

Proposed (roadmap R07-04, milestone R07 One wire contract).

**Why:** The only compatibility test, core/crates/obid/tests/swift_client.rs, is #![cfg(target_os = "macos")] and the Linux CI (.github/workflows/linux.yml) never runs it; the Mac check runs only touched suites. The add-only rule (AGENTS.md:39) is checked nowhere automatically for TypeScript or Kotlin.

**In:**
- docs/contracts/wire/*.schema.json for Job, InboxItem, Status and the SSE event envelope (name, data), each enum marked open or closed
- A hook in core/crates/obid/tests/support/mod.rs that validates every answer and event a test reads against its schema
- A corpus: tests write one JSON per answer and event under docs/contracts/wire/fixtures/ (regenerated, checked for staleness)
- A Linux test that diffs the schema against the merge base and fails on a removed key, a renamed key or a new value in a closed enum

**Out:**
- Conversation, Turn, Account and other events (R07-05)
- Client generation

### Actors and ownership: what obid owns

- The schema is the contract; obid answers must validate.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Acceptance scenarios

- WIRE-5 (proposed): Given obid sends a Job without a key the schema requires, when the HTTP tests run on Linux, then the validation fails and names the path.

- WIRE-7 (proposed): Given the fixture corpus is older than the schema, when the check runs, then it fails and says how to regenerate it.
