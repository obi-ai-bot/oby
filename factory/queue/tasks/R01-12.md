# chore(factory): pull requests stay drafts until approved, and an approved one merges with no second Mac check

<!-- Roadmap R01-12 · Sprint 1 · R01 Safety net · effort S · risk medium · new 2026-11-13 from docs/ci-architecture.md -->

### Sangam's screen

engine only

### Outcome

A factory pull request starts no GitHub run while it is being built, gated and reviewed. When the approver says APPROVE, the factory marks it ready and squash-merges the head the gate passed, with no sync and no second Mac check. Each pull request's Mac time falls from about 25–36 minutes to about 11–14, and the Mac gate stops setting the factory's pace (docs/ci-architecture.md).

### Status and scope

Proposed (new, docs/ci-architecture.md, "What changes in the factory").

The owner decided both halves on 2026-11-13: "Yes, drop the Mac merge gate", and "Go with the leaner option, nightly only". So dev as merged is tested by the nightly runs (Linux on GitHub, the Mac by R01-14), and R01-03 pauses merges on a red night. This task also rewrites AGENTS.md's remembered workflow line to say so.

**Why:**
- On 2026-11-13, 27 gates took 286 Mac minutes for 8 merged pull requests, one at a time.
- A needs-human escalation marked a pull request ready, so every later push ran GitHub's jobs.

**In:**
1. `factory/bin/job` `advance`: going to `needs-human` posts the decision but no longer marks the pull request ready.
2. `factory/bin/job merge`:
   - drop the sync with `origin/dev` and `gate --merge`
   - when the approved head is the gated head: `gh pr ready` if it is a draft, then `gh pr merge <n> --squash --match-head-commit <head>`
   - GitHub refusing it for a conflict sends the job to a builder round that merges `origin/dev`; the gate then runs on the new head, as any round's does
3. `.claude/agents/builder.md`: while it works, the builder runs only the test binaries and suites its change touched (`cargo test --test <x>`, `cargo test -p obid <module>::`, `npm run typecheck`), not the whole check; the gate runs it next.
4. AGENTS.md, "Rules Oby never breaks": this repository's remembered workflow becomes:
   - squash-merge a pull request into dev after the review approves and the Mac check passed on its head with a clean secret scan
   - GitHub tests dev as merged nightly, and a red night pauses the factory's merges (R01-03)

   Quote the owner's decisions of 2026-11-13.
5. `.claude/skills/factory/SKILL.md` and factory/README.md describe the above.

**Out:**
- The nightly read (R01-03) and the Mac nightly (R01-14)
- Any change to factory/checks.sh or factory/bin/gate

### Acceptance scenarios

- CI-22 (proposed): Given a factory job in build, gate, review or needs-human, when its builder pushes, then its pull request is a draft and GitHub runs no job on it.
- CI-23 (proposed): Given an approved job whose head is the gated head, when `job merge` runs, then it marks the pull request ready and squash-merges that head without running the Mac check again.
- CI-24 (proposed): Given an approved job whose pull request conflicts with dev, when `job merge` runs, then nothing merges and the job gets a builder round that merges dev, then a gate.
