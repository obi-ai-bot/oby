### Outcome

Every remaining production status write (worker start and end, crash, parked answers, limit waits, restart, routines) goes through Jobs::apply, so the state_owner test counts zero writers outside lifecycle.rs.

### Status and scope

Proposed (roadmap R04-07, milestone R04 One owner for job state).

**Why:** Left after R04-06: Jobs::open restart (jobs.rs:1220, 1239), crashed (3910), answer_parked (5575), answer_kept_question (5835), run_obi_review (9561, 9643), run_owner_job (10325, 10618, 11199), end_done (12216), routines.rs:1457/1474, jobs/account_limits.rs:53/1113/1119, plus writes in jobs/retry.rs, jobs/unjudged.rs and jobs/research.rs.

**In:**
- Commands RoundStarted, Finished{commits, pushed}, Crashed, Answered, LimitWait, LimitResume, Restarted{continues, cleanly}, Interrupted{why}.
- Jobs::open applies Restarted through the pure transition before it inserts the job (it has no Jobs yet: call lifecycle::transition directly).
- Each worker-side command carries the run token from R04-04.
- One PR per group if the diff grows: worker (run_owner_job, run_obi_review, end_done), owner answers (answer_parked, answer_kept_question), limits and restart.

**Out:**
- Splitting run_owner_job's 20 local flags into states (a later milestone).
- phase and cut semantics: they are read as today, written by the same commands.
