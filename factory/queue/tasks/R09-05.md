# feat(obid): Fix it starts a research job on the owner's agent that writes the post-mortem

<!-- Roadmap R09-05 · Sprint 7 · R09 Ship and debug safely · effort M · risk low -->

### Sangam's screen

engine only

### Outcome

Fix it on a failure no longer answers 409. It starts a normal research job on the owner's chosen agent, which reads the record and the trace as quoted files and writes the post-mortem as its report; the record's `postMortem` then holds it.

### Status and scope

Proposed (roadmap R09-05, milestone R09 Ship and debug safely).

**Why:** failures.rs:388-393 `fix_route` always returns 409 'Oby hasn't studied this failure yet.' and every `postMortem` is null (#571, closed without the feature; #903 open). 'Dispatcher, not harness' rules out obid making its own model call, so the study must be an agent's job.

**In:**
- POST /v1/failures/{id}/fix dispatches a job of kind `research` on the default agent and account (or the ones in the body), with the record and its trace written as quoted files in the job's folder, never in the prompt.
- When that job ends done, its report fills the record's `postMortem` (text) and `fix` (the job id); a repeated Fix it on the same record returns the existing job.
- Record keys stay as they are; `studyError` holds why the job failed.

**Out:**
- Filing `oby-failure` issues on GitHub (an outgoing action; separate).
- An inbox item per failure (#911).

### Actors and ownership: what obid owns

- Dispatching the job, quoting the files, linking the job to the record, writing `postMortem` from the report.

### Actors and ownership: what the apps show and send

- Wherever Fix it exists today, it now starts a job; the job shows as any research job does.

### Interfaces and dependencies

- POST /v1/failures/{id}/fix answers 200 with the job instead of 409 (same route).
- Failure record `postMortem`, `fix`, `studyError` filled (keys exist).

### Steps

- Read how a research job is dispatched today (job.rs KINDS, `POST /v1/jobs`) and reuse that path; no new job kind.
- Write the record and trace into the job's quoted input files; the prompt only names them.
- On the job's end, write `postMortem` and `fix` into the record (failures.rs owns the record file).
- Make Fix it idempotent per record.
- Write FAILURES-5 to 8 with a stand-in agent (tests/agents).

### Acceptance scenarios

- FAILURES-5 (proposed): Given a failure record, when the owner sends Fix it, then a research job starts on the owner's default agent with the record and trace as quoted files, and the answer names that job.
- FAILURES-6 (proposed): Given that research job ends done, when the record is read, then `postMortem` is its report and `fix` is its id.
- FAILURES-7 (proposed): Given a Fix it job already exists for a record, when Fix it arrives again, then no second job starts.
- FAILURES-8 (proposed): Given the research job fails, when the record is read, then `postMortem` stays null and `studyError` says why.
