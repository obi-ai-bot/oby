## What
The factory is driven from a terminal today (`factory/bin/oby-feed`, `/factory run`). From the message box, `/factory` should offer: Run a task (a ready one, or the next in order), What's running (the factory beside the conversation, screen 5), Add a task (the words after it become a task), Pause and Resume (finish what runs, start nothing new), and Settings (B00-09).

## Why
- **The owner wants the factory reachable from the box**, for every project, not only this repository.
- **The owner's answer on where a task goes (2026-11-15):** "on obid, to not mess with people's project." A task added from the box lives in a queue obid keeps for the project, never in the project's own files.

## How
1. `GET /v1/commands/factory?project=<id>`: the actions, and the project's tasks with `state` (`ready`, `waits`) and `waitsFor`.
2. `POST /v1/projects/{id}/factory/run` `{task?, words?, clientRequestId}`: a named ready task, the words as a new task started at once, or with neither the next ready task. `409` names what a waiting task waits for, or says the factory is paused.
3. `POST .../factory/pause` and `.../factory/resume`: a flag obid keeps in the project's home; running jobs go on; oby-feed (B00-08) reads it and starts nothing while it's set.
4. `POST .../factory/tasks` `{title, text, depends?}`: a task in obid's queue for the project (the profile's home, written whole by rename). A repository that keeps its own task files, as this one does in `factory/queue/tasks`, is read as the queue too; obid never writes there.
5. Every create carries `clientRequestId` and a repeat answers the first (R02).
