## What
obid's merge rules carry this repository's own names, so every repository Oby works in inherits them. `SECURITY_PATHS` (`core/crates/obid/src/merge.rs:1305`) holds 22 general entries and four of this repository's docs (`docs/agents-rules-manifest.md`, `docs/build-and-run.md`, `docs/agent-clis.md`, `docs/contracts/publishing.md`). `MAC_ONLY` (`merge.rs:978`) holds nine of this repository's folders, three of which (`Engine/`, `Runner/`, `RunnerTests/`) are in neither the repository nor its check script any more. Those names move into a file this repository keeps, `oby.json` at its root, which obid reads from the job's base. obid keeps only what is true for anyone.

## Why
- **The owner, 2026-11-16:** "those are our own rules … they can't be written in stone on the Oby app; they need to be modular, dynamic, easy for people to create their own workflows like T3 Code and OpenBot."
- **It leaks today.** In anyone else's repository, a change under `Engine/` (common in game projects) counts as Mac-only, so its check can't stand for the Mac's and the merge waits for the owner (`merge.rs:972`, `merge.rs:1169`); a change to `docs/build-and-run.md` needs two approving reviews.
- **The factory reads Rust with a regular expression.** `factory/bin/oby-feed:178-183` finds `SECURITY_PATHS` in `merge.rs`'s text. If the constant changes shape the match finds nothing and the factory's list quietly shrinks.
- **T3 Code does it this way:** one optional checked-in file at the root (`t3.json`, `packages/contracts/src/t3ProjectFile.ts:8`); a missing or invalid one counts as none (`apps/server/src/project/T3ProjectFileLoader.ts`).
- **Lane: dispatcher.** Which rules hold a job before it merges. Nothing here reads, edits or runs anything for an agent, and obid makes no model call.

## How
1. **One place for the rules.** `core/crates/obid/src/rules.rs` (new, pure): `Rules { protected_paths, mac_only_paths }`, the built-in values, and `rules_for(file: Option<RepoFile>) -> Rules`. Built in: the 22 general `SECURITY_PATHS` entries plus `oby.json`, under a constant named `BUILT_IN_PROTECTED`; Mac-only by file type only (`.swift`, `.xcodeproj`, `.xcworkspace`, `Package.resolved`, as `merge.rs:991-999` does). An entry's syntax is today's (`Anchor`, `merge.rs:1336`): ending in `/` a folder, with a `/` inside a whole path from the root, else a file name, all in any case.
2. **The file.** `oby.json`, schema `oby.repo/1`, keys `protectedPaths` and `macOnlyPaths` (arrays of entries). Keys obid doesn't read are left alone, so later tasks can add `commitStyle`, `hooks` and `workflows` without an older obid refusing the file.
3. **Read from the base, never the change.** obid reads `refs/remotes/origin/<base>:oby.json` from the job's clone, as it reads the base's `AGENTS.md` for its review (`core/crates/obid/src/jobs.rs:9822-9828`), never from the worktree.
4. **A file only adds.** `protectedPaths` and `macOnlyPaths` are added to the built-in ones. Nothing in the file takes a built-in entry away; removing one is the owner's word (B00-28).
5. **A file that can't be read fails closed.** An `oby.json` on the base that isn't valid JSON, isn't schema `oby.repo/1`, or is over 64 KB makes every change of that job need two approving reviews, as when Oby can't read what a change touches (`merge.rs:1393`, `two_reviews`). The job's report says `oby.json on <base> isn't valid: <reason>, so this change needs two approving reviews.`. No file at all is the built-in rules.
6. **Callers.** `security_paths`, `two_reviews`, `mac_only` and their callers (`jobs.rs:9888`, `merge.rs:1169`) take the job's `Rules`. `SECURITY_PATHS` and `MAC_ONLY` go; nothing else in obid holds a list.
7. **This repository's `oby.json`** (new, at the root): `protectedPaths` holds the four docs; `macOnlyPaths` holds `apps/mac/`, `apps/ios/`, `apps/watch/`, `apps/shared/`, `apps/Oby.xcodeproj/` and `character/` (what `scripts/oby-check.sh:504` sends to the Apple apps). `Engine/`, `Runner/` and `RunnerTests/` are dropped. The factory's own `protected_paths` stay in `factory/config.json`.
8. **The factory reads the same file.** `oby-feed`'s `security_paths()` takes `BUILT_IN_PROTECTED` (the regular expression now matches that name), `protectedPaths` from `oby.json` on `origin/<base>`, `factory/config.json`'s `protected_paths` and `scripts/oby-check`, as today. When the expression finds no entries it stops the pass with an error, never an empty list.
9. **Docs.** `docs/contracts/repo-rules.md` (new): what the file is, the four guards of the plan's §1 that apply here (read from the base, the file itself protected, a file only adds, an unreadable file fails closed), and REPORULES-1 to 5. `docs/contracts/merging.md`: MERGING-2's "what scripts/oby-check.sh sends to the Apple apps" and MERGING-15's list say "the repository's `oby.json` on the base, with obid's own". `docs/agents-rules-manifest.md` if any rule it lists moves.

This change edits a security path (`merge.rs`'s list) and adds one (`oby.json`), so it waits for the owner's click or two approving reviews by different tools.
