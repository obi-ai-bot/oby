## What
obid runs two commands of the owner's in a job's life: the repository's `setup` as each run of its agent starts (PUBLISHING-23) and its `check` before anything goes out. There's nowhere for a third, such as a licence or format check that must pass before publishing, and nowhere for a team to share these commands with each other. This task makes them a short list of hooks at fixed points, set by the owner, and lets a repository's `oby.json` offer them.

## Why
- **The owner, 2026-11-16:** workflows that are "modular, dynamic, easy for people to create … like T3 Code".
- **T3 Code runs a project's scripts when a worktree is created and when a thread settles** (`runOnWorktreeCreate`, `runOnSettle`: `packages/contracts/src/t3ProjectFile.ts:37-50`). A person imports the file's scripts into their own settings ("Import from t3.json", `apps/web/src/components/settings/ProjectActionsSettings.tsx:139`); the file alone runs nothing.
- **PUBLISHING-23 already says it:** the setup is "the owner's line in config.json, never the repository's". An offer the owner confirms keeps that true.
- **Lane: dispatcher.** obid starts a command at a point in a job's life and reports its result, as it does for `setup` and the check. The agent's own work, and anything it runs, stay the agent's.

## How
1. **Two hooks on the repository's entry**, in B00-28's owner's layer: `hooks.afterWorktree`, which is today's `setup` (reading and writing the same value, so `setup` keeps working), and `hooks.beforePublish`, one line of up to 200 characters, like `check`.
2. **`beforePublish`** runs after the check passes, on the same commit, in the same clean checkout and box, under the check's rules (PUBLISHING-6 to 8). It fails as a check fails: nothing goes out, the agent's message quotes the end of its output, fenced, and it gets a fix round; past the rounds the owner is asked as for a check. With no `beforePublish`, publishing is as today.
3. **Each hook is a stage** of the job, `setup` and `beforePublish`, with its state and time. `stages` is a list of open strings on the wire (`apps/electron/src/shared/obid-wire.ts:22`), so the apps show them with no change.
4. **A repository can offer them.** B00-27's `oby.json` may hold `hooks.afterWorktree` and `hooks.beforePublish`. When the base's value differs from the owner's, obid opens one `confirm` inbox item for that repository, like `set_check` (docs/api/inbox.md): action `set_hook`, payload `{hook, command, was, commit}`, its text saying what the command runs and when. The owner's signed Confirm keeps it on the repository's entry; Cancel keeps what's there and remembers the no for that exact command. The repository's command never runs before that Confirm. The apps read `action` as a string (`apps/ios/app/InboxView.swift:261`, `apps/electron/src/renderer/src/live.ts:342`), so `set_hook` breaks none of them.
5. "After a merge" isn't a hook: it's a routine on a merge event (R12).
6. **Docs.** `docs/contracts/hooks.md` (new): HOOKS-1 to 5. `docs/api/configuration.md` and `docs/api/inbox.md`: the new key and action. `docs/contracts/publishing.md`: PUBLISHING-23 says `setup` is also `hooks.afterWorktree`.

Acceptance (each scenario a test named after it; time faked through the existing hooks, never a sleep):
1. HOOKS-1 (`hooks_1_setup_is_after_worktree`): a repository whose entry has `setup` runs it as today, and `GET /v1/repos/rules` shows it as `hooks.afterWorktree`; one set as `hooks.afterWorktree` runs the same way.
2. HOOKS-2 (`hooks_2_before_publish_failing_sends_nothing`): a `beforePublish` that exits 1 after a passing check pushes nothing, and the agent's next message quotes the end of its output.
3. HOOKS-3 (`hooks_3_before_publish_passing_publishes`): one that exits 0 lets the job publish as today, and the job's stages show `beforePublish` done.
4. HOOKS-4 (`hooks_4_a_repository_offers_the_owner_adopts`): an `oby.json` on the base with `hooks.beforePublish` opens one `set_hook` confirm item; before the owner's signed Confirm no job runs it, after it every new job does, and a Cancel isn't asked again for the same command.
5. HOOKS-5 (`hooks_5_no_hooks_is_today`): a repository with no hooks and no `oby.json` behaves as on `origin/dev`.
