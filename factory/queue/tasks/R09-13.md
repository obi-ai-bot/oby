# spike(process): release from a tag in CI, key custody, and the dev-to-main cadence

<!-- Roadmap R09-13 · Sprint 7 · R09 Ship and debug safely · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

A written answer the owner approves: whether a macOS GitHub Actions runner can sign, notarize and staple with Deskree's Developer ID; where the notary credentials and the feed's ed25519 key live; and the release cadence that ends the 322-commit gap between dev and main.

### Status and scope

Proposed (roadmap R09-13, milestone R09 Ship and debug safely).

**Why:** Releases are cut by hand on one Mac (package.sh 'no CI', keychain profile `oby-notary`). AGENTS.md says GitHub Actions does not run for this repository, and `dev` goes to `main` only after a real-Mac list; the last merge was 2026-11-01 and main is 322 commits behind.

**In:**
- Test, on a fork or a private branch, a macOS runner importing a Developer ID .p12 from secrets and running `notarytool` with an App Store Connect API key.
- Propose key custody for the feed's private key (GitHub environment secret with required reviewer, or kept on the owner's Mac and used by a manual job).
- Propose a cadence: after Friday's demo, tag the dev head, run the real-Mac list and the human-drive on that tag, fast-forward main to it; a failing item blocks only that tag.
- Get the owner's answer and write it into AGENTS.md 'How we work' in the follow-up task.

**Out:**
- Building the workflow (R09-14).

### Files

- apps/electron/scripts/package.sh
- apps/electron/scripts/helpers.sh
- .github/workflows/linux.yml
- AGENTS.md

### Steps

- Read package.sh, helpers.sh and linux.yml; list every secret and machine dependency.
- Run a throwaway workflow that signs and notarizes a hello-world app on macOS-latest.
- Write the custody options with their risks.
- Write the cadence proposal with how it keeps the real-Mac rule's intent.
- Post the answer on the issue and ask the owner to decide.
