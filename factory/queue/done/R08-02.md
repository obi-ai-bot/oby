# fix(clients): show an agent id the app does not know instead of breaking or calling it Claude Code

<!-- Roadmap R08-02 · Sprint 4 · R08 One interface for every agent CLI · effort M · risk low -->

### Sangam's screen

uses existing screens: apps/electron/src/renderer/src/SettingsView.tsx, TalkPill.tsx, SetupCard.tsx; the neutral mark is Sangam's to choose (ask him in the PR, ship a plain placeholder until then)

### Outcome

When an obid newer than the app names a fourth tool, the Electron, iPhone and Android apps still show that account and its jobs, with a neutral mark and the id as its name, and pickers show it disabled. No job or account is dropped or reset.

### Status and scope

Proposed (roadmap R08-02, milestone R08 One interface for every agent CLI).

**Why:** Electron types `Agent = 'claude' | 'codex' | 'cursor'` (apps/electron/src/shared/obid-wire.ts:4) and indexes `Record<Agent, ...>` maps (renderer/src/mock.ts `AGENTS`, talk.ts `TOOL_NAME`, TalkPill.tsx `MARKS`, SettingsView.tsx `OWN_LOGIN`, SetupCard.tsx `AGENT_SUB`), which give `undefined` for a new id. apps/shared/Runner.swift:229 and Android Models.kt:211 map any unknown id to "Claude Code". AGENTS.md: no new value in an enum the Swift apps decode as closed.

**In:**
- Electron: decode `agent` as an open string at the wire edge (`Agent | string`), one `agentLabel(id)` / `agentMark(id)` helper with a neutral fallback, used by every `Record<Agent, ...>` lookup; pickers list an unknown agent disabled.
- Swift (apps/shared): `agentName` and `AgentMark` fall back to the id itself and a neutral mark, never "Claude Code".
- Android (Models.kt, Logic.kt): the same fallback.

**Out:**
- Any obid change.
- A mark or name for a real new provider.

### Actors and ownership: what obid owns

- Nothing new.

### Actors and ownership: what the apps show and send

- An unknown agent id with a neutral mark and the id as its name; disabled in pickers.

### Acceptance scenarios

- PROVIDERS-5 (proposed): Given obid lists an account and a job whose agent is `gemini`, when the Electron app, the iPhone app or the Android app shows them, then each shows the account and the job with a neutral mark and the name `gemini`, and never `Claude Code`.
- PROVIDERS-6 (proposed): Given an account whose agent the app does not know, when the owner opens a model or account picker, then it is listed disabled and the app sends no request for it; no stored choice (`agent.default`, `models.mine`) is dropped or reset because of it.
