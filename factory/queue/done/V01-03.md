## What
- **Property:** a changed path is caught exactly when it is on an entry of `SECURITY_PATHS`, in any letter case, and is not caught otherwise. The input is any path git prints for a change, as `Jobs::changed_files` (jobs/worktree_git.rs) reads `git diff --name-only --no-renames -z`, so a path never has `./`, `//` or a trailing `/`. Each kind of entry is on in its own way:
  - a name entry (`AGENTS.md`) when it is the path's last part, at any depth;
  - a folder entry (`.claude/`) when the path lies inside that folder at any depth, or is the folder's own name (`.claude`, which git prints for a symlink or a file of that name);
  - a whole-path entry (`docs/build-and-run.md`) when it is the whole path from the root.
  - `security_paths(changed, None)` returns exactly the changed paths some entry catches.
- **Harm:** a change to `AGENTS.md`, `.claude/` or CI merges by itself after one review, where two approving reviews by different tools were needed.
- **Code it covers:** `core/crates/obid/src/merge.rs`:
  - `SECURITY_PATHS` (line 1305, 26 entries), `caught_by` (about line 1377), `security_paths` (about line 1362, its entries half) and `fits`.
  - The half of `security_paths` that reads the check's own files (`check_files`) is not in this task.

## Why
`docs/proofs.md` lists `merge::caught_by` under "Not proved yet". The `merging_15_*` Kani harnesses prove `fits(Anchor, Fit)` over an abstract fit, never the byte matching of real paths. A Kani harness over `caught_by`'s strings ran CBMC out of memory. Three example tests (`merging_15_*` in `merge::tests`) cover a handful of paths.

## How
- **Tool:** a bounded-exhaustive Rust test in merge.rs's `mod tests`, on the real `caught_by` and `security_paths`. It needs no new dependency. The owner allowed proptest, but a dependency would make obid's `Cargo.toml` this task's file and every Kani harness required (`scripts/kani-required.sh`).
  - Each generated path carries its expected answer from how it was built, so the test never re-implements `caught_by`.
- **The space**, for each of the 26 entries:
  - **Case:** every upper/lower flip of its ASCII letters for an entry with at most 10 letters. For a longer one: every one- and two-letter flip, all upper and all lower.
  - **Depth:** prefixes `""`, `a/`, `src/a/`, `x/y/z/` and `.github/`. That gives depth 0 to 3, and one prefix that begins two entries (`.github/workflows/`, `.github/actions/`).
  - **Expected answers:** name and folder entries are caught at every depth. Whole-path entries are caught only at depth 0; deeper ones are near misses.
  - **Folder entries** also get the suffixes `f`, `a/b/f` and none (the folder's own name without `/`).
- **Near misses** (never caught):
  - one character added before or after an entry (`xAGENTS.md`, `AGENTS.mdx`, `AGENTS.md.bak`), or one removed;
  - a folder entry's name as part of another name (`.claudex/f`, `x.claude/f`, `.claude.json`);
  - a whole-path entry under another folder (`a/docs/build-and-run.md`);
  - a name entry used as a folder (`AGENTS.md/f`).
- **Non-ASCII letters:** `ſ` (U+017F) for `s` and `K` (U+212A, the Kelvin sign) for `k` (`Jenkinsfile`, `.buildkite/`). First check once on this Mac, with `touch` in a scratch folder, whether macOS's file system takes them for the same name.
  - If it does, they count as "any letter case" and a miss is a finding.
  - If it doesn't, they are near misses.
  - The skill records which.
- **Measured:** the whole test runs in under 10 seconds in `cargo test -p obid --lib merge::tests::merging_15_`, or the pull request names its time.
- **Shown failing** (each one line, red in build.md and in the pull request, then restored):
  1. `let lower = path.to_ascii_lowercase();` → `let lower = path.to_owned();` (compares case-sensitively).
  2. `.any(|(i, b)| b == b'/' && lower[i + 1..].starts_with(&p))),` → `.any(|(i, b)| i == 0 && b == b'/' && lower[i + 1..].starts_with(&p))),` (folders only one level down).
- **Expected finding:** a path that is a folder entry's own name (`.claude`, `.github/workflows`) is not caught today, because `caught_by`'s folder test needs the entry's `/` after the name.
  - If the test confirms it, that one case is a test of its own, `merging_15_a_folder_entrys_own_name_is_caught`, with `#[ignore = "finding V01-39"]`. The rest stays green.
  - The finding is `factory/queue/tasks/V01-39.md` in this format, SPRINT 0, in the same pull request. `V01-39` to `V01-42` are this task's numbers.
  - Never a GitHub issue, and `caught_by` stays as it is.
- **Verify skill:** `.claude/skills/verify-security-paths/SKILL.md`.
  - Frontmatter: `name: verify-security-paths`, and a description saying to use it when a change touches `SECURITY_PATHS`, `caught_by`, `security_paths`, `fits` or `Jobs::changed_files`.
  - Body:
    - the property and the harm;
    - the coverage record, and the bound in plain words;
    - the input assumption (git's `--name-only -z` paths);
    - the Mac's answer on `ſ` and `K`;
    - `SYNC: <the dev commit this branch was cut from>`;
    - one command: `cd core && cargo test -p obid --lib merge::tests::merging_15_`;
    - how to tell a bug from a test error: a failure names the path, the entry and the expected answer. A wrong expected answer is the generator's error; anything else is a bug;
    - a new entry in `SECURITY_PATHS` is covered by itself, since the test reads the array.
- **Prove it before hand-off:** follow the skill once on scratch break 1, see the test red, restore and see it green. build.md records both runs.
- **Merging:** `.claude/` is a security path, so the pull request merges after two approving reviews of its head by different tools (the owner's answer of 2026-11-22).
