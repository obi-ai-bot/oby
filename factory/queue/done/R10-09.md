# feat(obid): a member's changed owner key becomes one Confirm on Home

<!-- Roadmap R10-09 · Sprint 8 · R10 Finish the Obysphere client · effort S · risk medium -->

### Sangam's screen

uses an existing screen: the Confirm card on Home (apps/electron/src/renderer/src/AskStack.tsx)

### Outcome

When a teammate's owner key changes, the owner sees one card asking them to compare the new fingerprint with that person, instead of the member silently going missing from the directory.

### Status and scope

Proposed (roadmap R10-09, milestone R10 Finish the Obysphere client).

**Why:** A changed owner key removes that member until the owner calls POST /v1/obid/sphere/pins/{owner} (runner-api.md 'Pinned owner keys'), but no app calls /pins (grep of apps/electron/src) and 'A changed key does not yet become an ask on Home' (docs/obysphere.md part 4). So a teammate who rotated a key looks gone, and a swapped key is never shown.

**In:**
- When pins.rs sees a changed key, obid adds one `confirm` item, action `trust_key`, payload `{owner, fingerprint}`, titled with the owner id and the new fingerprint.
- Its device-signed Confirm calls the existing accept path (Pins::accept); Cancel keeps the member out.
- The item closes when the owner accepts through the route, the member leaves, or obid leaves the Sphere.

**Out:**
- A screen to compare and mark a first-seen key verified (R10-10).
- Carrying the owner key to a second Mac (#1222).

### Actors and ownership: what obid owns

- When to ask, the one card per changed key, and the accept.

### Actors and ownership: what the apps show and send

- The Confirm on Home's stack and on the phones, as any Confirm (action is an open string for the phones).

### Interfaces and dependencies

- New `confirm` action value `trust_key` (phones decode `action` as an open string, ask-an-oby.md 'The API stays add-only').

### Steps

- Find where the directory read drops a member for a changed key (pins.rs `check`) and raise one item there, keyed by owner and new fingerprint.
- Handle `trust_key` in inbox_actions.rs with the device signature, calling Pins::accept.
- Close the item on the other two paths.
- Confirm the Swift and Kotlin decoders read `confirm.action` as an open string before merging.
- Add SPHERE-8 to 10 and their tests.

### Acceptance scenarios

- SPHERE-8 (proposed): Given a pinned member whose owner key changes, when obid reads the directory, then one `trust_key` Confirm shows the owner id and the new fingerprint, and no second card comes on the next read or after a restart.
- SPHERE-9 (proposed): Given that card, when the owner's device signs Confirm, then the new key is pinned verified and the member is back in the directory; unsigned is `403`.
- SPHERE-10 (proposed): Given that card, when the member leaves or the owner accepts through POST /v1/obid/sphere/pins/{owner}, then the card closes with an `inbox` event.
