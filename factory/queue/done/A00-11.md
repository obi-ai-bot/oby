## What
`lanes_1_the_owners_job_runs_in_its_own_lane_and_another_obys_stays_boxed` (core/crates/obid/tests/jobs_api.rs, around line 5625) failed in R03-01's gate on 2026-11-13 with its recorded arguments equal to `["--version"]`. The fake `claude` records the arguments of its last call, and since R01-07 (#2156) obid also runs the agent CLI with `--version` to record its version at the start of each round. When that version read lands after the job's real call, the test reads the version call's arguments instead of the run's and fails. R03-01's change (dropping the telemetry flag) doesn't touch this path, so the race is on `dev`.

## Why
A flaky test costs a whole gate, about 45 minutes on this Mac, each time it fires, and it reads as the change's fault.

## How
- Make the fake record every call, or skip `--version` calls when it records the run's arguments, and have lanes_1 (and any other test that reads the fake's recorded arguments, `grep` for it) assert on the run's own call, not the last one.
- Prove it: with the version read forced to land after the run (a short sleep in the fake for `--version`, test-only), the old test fails and the new one passes.
- Change no production code. Run the touched test binaries through factory/bin/test-run.
