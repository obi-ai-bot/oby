# feat(electron): a deadline and an error code for every busy update phase, and one install per session

<!-- Roadmap R09-02 · Sprint 6 · R09 Ship and debug safely · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/electron/src/renderer/src/SettingsView.tsx (About's update rows, unchanged)

### Outcome

About never stays on a disabled Check for Updates or a download that stopped moving; it returns to Check for Updates with a logged reason. A second Update and Restart does nothing.

### Status and scope

Proposed (roadmap R09-02, milestone R09 Ship and debug safely).

**Why:** shared/updates.ts `next` has no timer: `checking` and `downloading` end only on an updater event, so a hung request needs a relaunch. `install` on `ready` returns 'restart' on every click, and main/updates.ts calls `quitAndInstall()` each time.

**In:**
- shared/updates.ts: a typed table `DEADLINES: Record<BusyState, number>` (checking 90 s, downloading 120 s since the last progress event, install 300 s), so a new busy state without one fails to compile.
- A `failed` event carries `code: 'check_failed' | 'download_failed' | 'install_failed'`; `idle` keeps it as an optional `error` (add-only, About ignores it).
- main/updates.ts: one timer per busy state, re-armed on `download-progress`; a fired timer feeds `failed`.
- A one-shot install latch in main.

**Out:**
- New words in About.

### Steps

- Add the deadline table and the error code to the types in shared/updates.ts; make `next` return the deadline to arm.
- Arm and clear one timer in main/updates.ts; listen to `download-progress` to re-arm.
- Add the install latch; keep `next` pure by passing `installed` in.
- Write UPDATES-15 to 17 with fake timers (vi.useFakeTimers), not real waits.

### Acceptance scenarios

- UPDATES-15 (proposed): Given Oby is `checking`, when 90 s pass with no answer, then About shows Check for Updates and main's log says `check_failed`.
- UPDATES-16 (proposed): Given Oby is `downloading`, when 120 s pass with no progress event, then the download is abandoned with `download_failed`; progress resets the deadline.
- UPDATES-17 (proposed): Given Update and Restart was clicked on a `ready` update, when it is clicked again in the same session, then nothing more happens.
