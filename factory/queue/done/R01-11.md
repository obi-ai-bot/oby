# test(ci): a scheduled canary of the newest agent CLIs against a fake model

<!-- Roadmap R01-11 · Sprint 2 · R01 Safety net · effort M · risk low -->

### Sangam's screen

engine only

### Outcome

Every 6 hours, GitHub runs the newest Claude Code and Codex (and cursor-agent if the spike says so) through obid's adapters against a fake model; two failures in a row open one cli-drift issue, so drift is found before the owner's first job.

### Status and scope

Proposed (roadmap R01-11, milestone R01 Safety net).

**Why:** CLI drift is found by users today (#1867 --bare default, #1953 conversation model), and the real-CLI probes run only by hand.

**In:**
- new: .github/workflows/cli-canary.yml on a schedule and on workflow_dispatch
- A fake model server and an obid test binary of adapter cases chosen by R01-10
- A JSON report artifact with each CLI's version and each case's result
- Opening or updating one issue labelled cli-drift on the second failure in a row

**Out:**
- Real-login runs on the owner's Mac (#1099)
- Editing the version table automatically
- Replaying recorded streams in the stand-ins (#1098)

### Actors and ownership: what obid owns

- Nothing new at runtime; the cases drive obid's existing adapters.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- new: .github/workflows/cli-canary.yml

- docs/ci.md

### Steps

- Write the fake model server (Anthropic messages and OpenAI responses shapes that the spike found necessary).
- Write cli_canary.rs as #[ignore] tests that read the CLI path from an env var and start obid with that bin.
- Write the workflow: install newest CLIs into a temp prefix, run the ignored tests, write the JSON report, upload it.
- Add the two-in-a-row rule: read the previous run's report artifact, open or comment on one cli-drift issue with gh.
- Run it by workflow_dispatch and link a green run and a forced red run.

### Acceptance scenarios

- CI-14 (proposed): Given the schedule fires, when the canary runs, then it installs the newest version of each CLI and writes a report naming each version and each case's result.
- CI-15 (proposed): Given a case fails on two runs in a row for the same CLI version, when the second run ends, then exactly one open cli-drift issue names the version and the case.
- CI-16 (proposed): Given a case fails once and passes on the next run, when that run ends, then no issue is opened.

Contract: new: docs/contracts/ci.md

### Tests

- cli_canary cases named after CI-14..16 and the adapter cases (new, #[ignore], in core/crates/obid/tests/cli_canary.rs)

### Done when

- Four scheduled runs on dev with report artifacts.
- A forced failure twice in a row opened one issue.
