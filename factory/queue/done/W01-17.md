## What
The port plan's L5 (docs/plans/artifacts-port.md, "L5. React artifacts, still local"; ARTIFACTSAPP-13 and 14 are reserved for it). LibreChat gives a React artifact to Sandpack's `react-ts` template, whose bundler fetches every npm package from CodeSandbox's CDN and Tailwind from `cdn.tailwindcss.com` (the plan, "What LibreChat and Sandpack do"). Oby keeps LibreChat's shape and drops the hosted parts, as "How Sandpack runs fully local in Oby" says: the app compiles the artifact itself and hands Sandpack's `static` template an `index.html` whose import map points at vendored builds of `react`, `react-dom`, `lucide-react` and `@tailwindcss/browser`, served by main's relay on loopback.

So an agent's folder with an `App.tsx` (or `App.jsx`) and no `index.html` draws in Preview, in the card's picture and after the owner's edits, every request on loopback. An import outside the vendored set shows its error in the preview and fetches nothing. The set grows only by vendoring, one package and its licence at a time.

**obid first, as the plan says.** On `dev` it refuses such a folder: `check_kind` (core/crates/obid/src/artifacts/mod.rs, `fn check_kind`) makes a folder `html` only with an `index.html`, else "a folder is an html artifact with an index.html, or a canvas or a design with a canvas.json."; a single `.tsx` file is refused by its extension. The change is add-only and tiny (a condition in `check_kind`, one rename in `copy`): no new `Kind` value (the Swift apps decode `kind` as closed: it stays `html`, the Page the card already names), no new key or route. It is kept here as ARTIFACTS-26, its own first commit with its Blok proof; it needs no task of its own.

Known limits, left for later: `GET /v1/artifacts/{id}/export/{version}?as=html` of a React artifact is an empty page (export.rs's `html` wants an `index.html`; the zip is whole), and the iPhone shows its files, not the page.

## Why
LibreChat's React artifacts are what an agent most often makes when asked for something interactive: a counter, a chart, a small form. Today Oby refuses to keep them, and the preview couldn't draw one if it did. The owner, 2026-11-21: "do it like LibreChat and Sandpack … but first make it work"; local first means none of it may come from a CDN.

## How
Read the code on `dev` after W01-15 merges (verify each before relying on it).

1. **obid (ARTIFACTS-26)**, `artifacts/mod.rs`. In `check_kind`'s folder branch, a folder with `index.html`, or with no `index.html` and an `App.tsx` or `App.jsx` at its root, is `Kind::Html`; the refusal's line names both. In `copy`, a single `.tsx` or `.jsx` file is kept as `App.tsx` or `App.jsx`, as a single `.html` is kept as `index.html`, and `check_kind`'s file branch takes `tsx` and `jsx` as `Kind::Html`. Every other check (names, limits, secret scan, `same_files`, edits through L3a) is unchanged and runs on it. `seed.rs`'s `is_folder` already lays an `html` artifact out as a folder.
2. **The vendored set**, `apps/electron/resources/sandpack-vendor/`, committed, one folder per package with its licence beside it:
   - `react/react.mjs`, `react/jsx-runtime.mjs`, `react/LICENSE`;
   - `react-dom/react-dom.mjs`, `react-dom/client.mjs`, `react-dom/LICENSE`, and `scheduler/LICENSE` (react-dom's client build holds scheduler);
   - `lucide-react/lucide-react.mjs`, `lucide-react/LICENSE` (ISC, with the MIT text for the Feather icons, both in the package's own file);
   - `tailwindcss-browser/index.global.js` (the package's own browser build, byte for byte; check its `exports`), `tailwindcss-browser/LICENSE`;
   - `README.md`: each package, its version from `package-lock.json`, its licence, and how to rebuild.

   React 19 ships CommonJS only (`react/cjs/*.production.js`), so the `.mjs` files are built: `apps/electron/scripts/vendor-sandpack.mjs` (`npm run vendor:sandpack`) runs Vite's own `build()` (already a devDependency, no new tool) in library mode, ES format, `process.env.NODE_ENV` `"production"`, minified, from the installed packages. Every file but `react.mjs` keeps `react` (and `client.mjs` keeps `react-dom`) external, so the frame has one React. `lucide-react.mjs` is its main entry only, never `DynamicIcon` or `dynamicIconImports`. Each LICENSE is copied from the package.

   Licences, read from the packages (`package-lock.json` and their own LICENSE files), all permissive, Apache-2.0 compatible: they ask only that the notice travel with the copy, which the LICENSE beside each file does.

   | Package | Version | Licence |
   |---|---|---|
   | react, react-dom | 19.3.0 | MIT |
   | scheduler (inside react-dom/client) | 0.28.0 | MIT |
   | lucide-react | 1.55.0 | ISC, plus MIT for the icons derived from Feather |
   | @tailwindcss/browser | 4.3.5 | MIT (npm; if its tarball has no LICENSE, the MIT text from tailwindlabs/tailwindcss's own, said so in README.md, as resources/sandpack-relay/README.md did for Apache-2.0) |
   | sucrase (bundled into preview.html's chunk, not vendored) | 3.35.1 | MIT; what its `transform` pulls in: lines-and-columns (MIT), ts-interface-checker (Apache-2.0), @jridgewell/gen-mapping (MIT) |

   Nothing GPL, nothing under the Sustainable Use License. `package.json`: `sucrase` `3.35.1` in dependencies and `@tailwindcss/browser` `4.3.5` in devDependencies (the vendor script copies it), both pinned exactly, plus the `vendor:sandpack` script; `package-lock.json` with them.
3. **The relay serves them**, `main/sandpackRelay.ts`: each vendored file (the `.mjs` and `.js`, not the LICENSE or README) at `/__csb_vendor/<package>/<file>`, `text/javascript; charset=utf-8`, on any host the relay already serves, read in as the relay's own files are (`?raw`, or `import.meta.glob` with `?raw`). The path is under `/__csb` on purpose: the service worker already sends a same-origin `/__csb…` request to the network (its `pathname.startsWith("/__csb")` line), so it reaches the relay from the preview's own origin (`<id>-preview.localhost:<port>`), which PREVIEW_CSP's `'self'` and `previewRules.ts`'s `allowed` already let go. No third change to the worker, the CSPs or `allowed`. Because they're in main's bundle, `local-only.mjs`'s guard checks them as it builds: if one holds a forbidden address, the build fails; look at it and say so in build.md, never loosen the guard.
4. **The compile**, `renderer/src/artifacts/react.ts` (new), called from `showable.ts` for an `html` version with no `index.html` and an `App.tsx` or `App.jsx`; anything else is shown exactly as now. It runs in the preview's host page (host.ts, preview.html), never in the window's page.
   - Each `.tsx`, `.ts`, `.jsx` or `.js` file is compiled with sucrase's `transform` (`typescript` and `jsx` for `.tsx`, `typescript` for `.ts`, `jsx` for `.jsx` and `.js`; `jsxRuntime: 'automatic'`, `production: true`) to `/<path without its extension>.js`. Other files go as they are.
   - The written `/index.html` holds an import map: `react`, `react/jsx-runtime`, `react-dom`, `react-dom/client` and `lucide-react` to their `/__csb_vendor/…` paths. Then each compiled file's own URL with its extension, without it, and a folder's for its `index`, to its `.js`, so `import Label from './Label'` needs no rewriting (an import map's URL-like keys match a relative import once resolved). And each `.css` file's URL to an empty module of the shown files (`/__oby_empty.js`), its stylesheet linked from the head instead.
   - It also holds `<script src="/__csb_vendor/tailwindcss-browser/index.global.js">`, a `<div id="root">`, and one inline module that mounts `App`'s default export with `createRoot` (as LibreChat's template does). It catches the import of `/App.js`, `createRoot`'s `onUncaughtError` and `window.onerror`, and shows any error's own text in a `<pre>` (set with `textContent`).
   - An import outside the map is the browser's own resolve error ("Failed to resolve module specifier \"recharts\"…"), shown there; a bare name outside the map is never fetched. A sucrase error makes an `index.html` holding only its message (escaped), and no script.
   - The words are the engine's, not Oby's: no word of Oby's is added.
5. **What comes with it for free, checked on the Mac, not changed:** Code shows `App.tsx` (Code.tsx already highlights `tsx`); an owner's edit recompiles (main overlays it, the host page compiles); the card's picture (W01-13, W01-15) goes through the same `showable`. If W01-15's "drawn" signal fires before React renders, say so in build.md as a follow-up; don't change artifactPreview.ts here.
6. **The contracts.** `docs/contracts/artifacts.md`: "Kinds come from the shape" adds the React folder and file, ARTIFACTS-26 under the scenarios (implemented). `docs/api/artifacts.md`: the **Kinds** line, the same (add-only). `docs/contracts/artifacts-app.md`: "What each kind shows" adds a React page; "Local only" adds the vendored set, its path on the relay, and that it grows only by vendoring; ARTIFACTSAPP-13 and 14 written and moved from Proposed to Implemented. `docs/plans/artifacts-port.md`: L5 built, and its licence row corrected (lucide-react is ISC; sucrase is bundled, not vendored).
