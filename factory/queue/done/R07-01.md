# fix(ios,electron): every wire enum decodes an unknown value

<!-- Roadmap R07-01 · Sprint 3 · R07 One wire contract · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/shared/JobList.swift (badge), apps/electron/src/renderer/src/TaskCard.tsx

### Outcome

The next iPhone and Electron builds keep working when obid sends a status, state or kind they do not know. They show it as a neutral 'unknown' state instead of failing to decode the whole list.

### Status and scope

Proposed (roadmap R07-01, milestone R07 One wire contract).

**Why:** apps/shared/Runner.swift:5 `enum Status: String, Codable { case queued, running, done, failed, stopped, interrupted }` is closed, as are Runner.swift:295, 803, 880 and Decisions.swift:11, 65. One new value makes JSONDecoder throw for the whole answer, so a shipped iPhone shows nothing. AGENTS.md:39 forbids new values for this reason, which blocks obid's state work (R04). Android's Models.kt:36 uses coerceInputValues, which silently maps an unknown value to a default (wrong state).

**In:**
- Swift: a custom init(from:) or a RawRepresentable wrapper that maps an unknown raw value to `.unknown(String)` for every `enum ...: String, Codable` that crosses the wire in apps/shared
- Each switch over those enums gets a neutral branch (badge gray, no action buttons)
- Electron: the TypeScript unions in apps/electron/src/shared/obid-wire.ts get a `(string & {})` fallback and each switch in the renderer gets a default branch
- Android (skip this step if R03 decides to freeze Android): replace coerceInputValues with an explicit Unknown case in Models.kt enums (JobStatus, Who, StepState)

**Out:**
- Sending any new value from obid (R07-02 and R04 do that)
- Generated types (R07-06, R07-07)

### Actors and ownership: what obid owns

- Nothing changes in obid.

### Actors and ownership: what the apps show and send

- An unknown state shows as a neutral row. The words come from Sangam's screen; until he gives them, the existing gray badge with no text change.

### Steps

- List every `enum ...: String, Codable` in apps/shared that decodes obid JSON (grep), and each TS union in obid-wire.ts.
- Add the unknown fallback to each Swift enum; keep the raw string so it encodes back unchanged.
- Fix every exhaustive switch with a neutral branch; the compiler lists them.
- Add TS fallbacks and default branches.
- If Android is in scope: explicit Unknown in Models.kt and remove coerceInputValues.
- Write WIRE-1 and WIRE-2 tests; prove each fails before the change.

### Acceptance scenarios

- WIRE-1 (proposed): Given a job whose status is a value the app does not know, when the iPhone reads GET /v1/jobs, then the list decodes, the other jobs show as before, and that job shows a neutral state with no action.
- WIRE-2 (proposed): Given an inbox item whose kind is unknown, when the Electron app renders Home, then the item shows with its title and no answer buttons, and nothing throws.
