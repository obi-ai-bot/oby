# chore(process): triage the 425 gap-map issues into a verdict list for the owner

<!-- Roadmap R13-12 · Sprint 4 · R13 How we work · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

The owner gets one list per gap-map epic with a verdict and evidence for each issue. Only after the owner approves an epic's list are its issues labelled, rewritten or closed, exactly as approved.

### Status and scope

Proposed (roadmap R13-12, milestone R13 How we work).

**Why:** 425 open gap-map issues (44 epics) come from the report of 2026-10-21 against dev f56b9972, which measured obid against the deleted Swift engine and against harnesses (Codex desktop, Cursor, Claude Code). 'Dispatcher, not harness' (2026-11-05) says harness features are the CLI's; plug-ins and the Swift engine are cut. Landed work shows as open.

**In:**
- One tracking issue with a comment per epic: issue, verdict (agent, dispatcher, between-owners, obsolete, done + PR, duplicate), evidence, proposed action.
- After the owner approves an epic's comment: apply only those actions, with the reason in each closing comment.

**Out:**
- Closing, labelling or editing any issue before the owner approves its epic's list.
- Rewriting kept issues (they are rewritten when planned, with plan-feature).
- A pull request: this task writes issues and comments only.

### Actors and ownership: what obid owns

- Nothing changes in obid.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Steps

- List the issues: `gh issue list --repo obi-ai-bot/oby --label gap-map --state open --limit 1000 --json number,title,labels,body`.
- Group by epic (the 44 `epic`-labelled ones; map the 19 older issues by their 'Oby Gap Map' footer).
- Give each epic to one subagent with the triage skill (R13-11), read-only; check the evidence of each row before you accept it.
- Post one comment per epic on the tracking issue; ask the owner to approve, change or reject each list.
- For each approved list only, apply the actions with `gh`; record what was done under the comment.

### Acceptance scenarios

- None: this task changes no product behaviour.

Contract: none

### Done when

- Every open gap-map issue has a row in an epic list.
- Every applied action matches a row the owner approved; no issue was closed without it.
