## What
Since O1 (#2816) the page is each agent tab's own `<webview>` (BROWSERAPP-26). The window still carries the pieces of obid's old Chrome: the streamed picture of the page, main's followers of that stream, and the owner's mouse and keys signed for obid. obid answers all of those routes `410 retired` (`core/crates/obid/src/browser/routes.rs`: `…/stream`, `…/input`, `…/take`, `…/giveBack` and `…/secret` go to `retired`).

One of them is a live bug on `dev`. Verify each step before relying on it:

- `connectLive` in `renderer/src/browser/live.ts` calls `watchAll()` after every list read and every event. `watchAll()` calls `calls.watch(tab)` for each tab not yet watched.
- The preload's `browser.watch` invokes `browser-watch`.
- In `main/browser.ts`, `browser-watch` starts `follow(browserTabPath(tab, 'stream'), …)`. `follow()` stops only on a `404`. On any other answer it waits `AGAIN_MS` (1 s) and asks again, while not stopped.
- obid answers `410`. So the window asks obid for each tab's old picture stream once a second, for as long as the tab exists.

Pull request #2838 (branch `browser-w3-retire-v2`, one commit, `f7535f9a`) removes these pieces, but it also removes the Take control and Give back signing. The owner's decision D1 keeps board 6's hold and does it in obid (task W01-08 brings the two routes back). So #2838 can't merge as it stands: under D1 it removes too much. It also conflicts with `dev` today.

## Why
The 410 loop is one wasted request per tab per second, to the owner's own obid, forever. The dead stream, frame and input code is the reach of a browser that no longer exists: a signed `…/input` shape in `device.ts` and a preload call that starts a follower in main. Every later browser-window task edits the same files (`Panel.tsx`, `store.tsx`, `live.ts`, `preload/index.ts`). So this cleanup goes first, and it keeps the signing that board 6 needs once obid holds tabs again.
