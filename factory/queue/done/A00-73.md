What. A job doesn't say which project it belongs to, so nothing can list a project's work across its conversations.

How, add-only. A job gains a project key (its conversation's project when it started, or null). GET /v1/jobs takes project=<id> and answers that project's jobs, running ones first. Nothing else changes: the stages a factory shows are the job's pipeline, as it is.
