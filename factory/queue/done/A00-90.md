What. Settings › General has an "Open at login" switch, on by default (`SettingsView.tsx`, `useSetting('login', true)`). It is kept as a window setting and read by nothing: main registers only obid's own launch agent (`main/obid.ts`, `register`, `setLoginItemSettings` for the service). So the window never opens at login whatever the switch says, and turning it off changes nothing.

Why. The owner expects Oby's window back after a restart when the switch is on (it is on by default), and expects a switch to do what it says. obid starting by itself is a separate thing and stays as it is.

How. Main owns the setting (R06-13 keeps rows obid has no value for in main's settings file): it registers or removes the app's own login item (`app.setLoginItemSettings({ openAtLogin })` for the app, apart from obid's service entry) when the switch changes, and once at start so a fresh install's default (on) is applied. Opened at login, the window starts hidden or shown as macOS's login item says (`wasOpenedAtLogin`). The switch reads macOS's actual state, so a change made in System Settings › Login Items shows.

### Formal verification
None: no rule decides an outcome. The tests stub `app.setLoginItemSettings` and `getLoginItemSettings` and fail on today's code.

Acceptance (tests named after each):
1. Turning Open at login off removes the app's login item and leaves obid's service entry as it was; turning it on adds it.
2. A fresh install registers the app's login item once at start.
3. The switch shows macOS's state when it differs from the saved value.
