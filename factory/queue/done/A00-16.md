## What
Since 2026-11-14, `dev` has a GitHub ruleset with a merge queue (ruleset 27249392: squash, groups of 2 to 5, required `Check`). With a merge queue on the base branch, GitHub refuses a merge-method flag: `gh pr merge --squash` fails with "The merge strategy for dev is set by the merge queue". `factory/bin/job` line ~818, in `cmd_merge`, always passes `f"--{CONFIG['merge_method']}"`, so every factory merge into `dev` now fails and the job goes to needs-human.

## Why
Every approved job would stop at the last step. The factory can't merge anything into `dev` until this is fixed.

## How
- `cmd_merge` asks GitHub whether the base branch has a merge queue (for example `gh api repos/{owner}/{repo}/rules/branches/{base}` and look for a `merge_queue` rule) and, when it does, calls `gh pr merge <pr> --auto --match-head-commit <head>` with no merge-method flag; without a queue it keeps today's call with `--squash`.
- The job then ends `queued` as R01-12 designed (CI-23): it holds no slot, and `job queue` settles it when GitHub merges it or removes it from the queue.
- If GitHub refuses with a message naming the merge queue anyway, retry once without the flag rather than escalating.
- Tests in `factory/tests/` with the fake `gh`: a base with a queue gets no `--squash`; a base without one keeps it; the refusal message triggers one retry. Each test fails without the change.
- Change nothing else in `cmd_merge`; `factory/config.json` stays as it is (`merge_method` still applies where there is no queue).
