The owner's word (2026-11-14): "Add it now, advisory", on adding formal verification (Kani) as a step of the software factory; the plan is the Formal Verification session's proposal, Phase 1. This task is the script and state half; A00-38 is the agents half.

What: a new stage `prove` between `gate` and `review`, run by a new script `factory/bin/prove <job-id>`, for jobs whose intake SURFACES include `proofs`. Every other job skips it (PROOFS: SKIPPED) and goes from gate to review as today.

1. factory/bin/job: TRANSITIONS gains `prove`. gate PASS -> prove; prove PASS, ADVISORY-FAIL or SKIPPED -> review; prove FAIL -> build (like a gate FAIL; the builder gets round-N/proofs.md). In advisory mode prove never returns FAIL. When a job leaves `spec`, job.json records the sha256 of spec.md's `## Proofs` section (none if absent). `job sync` shows the PROOFS line per round.
2. factory/bin/prove, on the gated commit (round-N/checks.md COMMIT):
   - the `## Proofs` hash is unchanged since spec, else FAIL "properties changed after spec";
   - the diff has no `kani::stub`, no `should_panic` on a harness, no `#[cfg(kani)]` outside a test module, no `kani::assume` and no unwind bound the spec's Proofs section does not list;
   - each harness listed in the Proofs section: `cargo kani -p <crate> --tests --harness <name>` through factory/bin/test-run (it goes to the gate VM's builder slots, REMOTE-47/48), with a per-harness timeout (default 600 s, from config); expect `VERIFICATION:- SUCCESSFUL`; a timeout is TIMEOUT, never a pass;
   - each harness's declared broken rule (a one-line change the Proofs section names): apply it in a scratch copy, run the harness, expect `VERIFICATION:- FAILED`, discard the copy; a harness that stays green is FAIL "vacuous";
   - writes round-N/proofs.md: first line `PROOFS: PASS | FAIL | TIMEOUT | ADVISORY-FAIL | SKIPPED`, then per harness the command, result, verification seconds and VM seconds, and per broken rule its result.
3. factory/config.json gains `"proofs": {"mode": "advisory", "timeout_s": 600}` and `surface_reviewers` gains `"proofs": {"proofs": "opus"}` (the lens itself lands in A00-38; route must not fail if its agent file is missing yet: the factory skill only spawns lenses whose agent exists).
4. Mode `advisory` turns FAIL and TIMEOUT into ADVISORY-FAIL and goes on to review; `blocking` is accepted but unused until the owner says so.

Tests (factory/tests, named PROVE-<n>, contract in docs/contracts/factory.md or the factory's own contract file): a job without the surface is SKIPPED; a changed Proofs section is FAIL (advisory: ADVISORY-FAIL); a forbidden construct is caught; a green harness and a red broken rule give PASS; a harness green on its broken rule is vacuous; a timeout is TIMEOUT. Stub test-run and cargo: no test reaches a real host (oby-gate, oby-mac-pro) or reads the real config.json. Show each check fails without the code that makes it pass.

Not in scope: proofs inside scripts/oby-check.sh or factory/checks.sh (never); blocking mode's use; Quint or other tools.
