## Why
Since W01-03, another Oby's task, an `untrusted` job and Oby's own review finish without a browser. The owner accepted that cost only until the window's half of the box's edge exists (`docs/plans/browser-t3.md`, O4: "foreign jobs get no browser until the window's box edge lands"). The handoff calls that half B19's second half.

Which partition a tab uses is obid's call, and main checks it ("Partitions: obid decides, main checks"). Main already checks the name. What's left is to make the box partition's session apart, the way T3 makes a session (made before the guest attaches, in memory, cleared when done), and to give it the box's edge.

The edge can't be a filter written in main. A page's host is the job's own decision: its rules, its mode, the owner's card (`Jobs::ask_about`, behind `egress.rs`'s doors). obid already decides that for the job's boxed agent, through its egress proxy and that job's door. So main sets the box session's own proxy (`session.setProxy`) to that job's egress door. Every request the session makes then goes through it: the page's own requests, `fetch` from `oby_browser_evaluate`, a click's navigation, a redirect, a subframe. This closes items 1 and 3 in the one place where the connection is made. Item 2 needs the door to check the address it connects to after resolving the name. `egress.rs:405-406` names that check as its own missing piece ("no address filter once the name resolves").

Item 4 isn't the window's, and the switch doesn't widen it. A job marked mid-run is read as the owner's own (`origin_of` doesn't read `foreign`), so it already browses in its agent's partition today, whatever the switch says. It stays open in the contract as obid's.

obid lacks two things, and this task adds them. Both are in memory only, and neither touches the API's existing keys:
- A way to hand main a foreign job's door: one add-only relay command, on the relay stream only main reads.
- A browser door that checks addresses after resolving.

## How
In obid:

- `egress.rs`: add `Egress::open_browser(id)`, a third kind of door beside the agent's and the setup's (`door`, `egress.rs:153-179`). It is learned as a secret like they are, and `close(id)` ends it with the rest.
  - It decides each site exactly as the job's agent door does: `reach_now`, then `decide`, which is `Jobs::ask_about`.
  - `connect` (`egress.rs:460`) for that door resolves the name itself (`tokio::net::lookup_host`). It refuses if any address is loopback, unspecified, private (10/8, 172.16/12, 192.168/16), shared (100.64/10), link-local (169.254/16, fe80::/10), unique local (fc00::/7) or multicast, IPv4-mapped forms included. It also refuses obid's, the gateway's and the `direct` HTTPS listeners' ports on any address. Then it connects to the very address it checked, so a second lookup can't rebind it.
  - Port T3's ranges (hostClassification.ts:56-64, 95-118) to Rust, and credit them.
  - Refusal answers `403 Forbidden` as `refuse` does.
  - Behind an upstream proxy (`Upstream`), obid doesn't resolve the name, so the door refuses literal private addresses and T3's private names (`.local`, `.localhost`, `.home.arpa`, a name with no dot), and the upstream resolves the rest. Mark that `ponytail:` as its ceiling.
- `browser/contract/relay_command.rs`: add the variant `Box { thread_id, partition, proxy }`, `type: "box"`. `type` only grows. It goes only on `GET /v1/browser/relay`, which only main follows. The page's `browser-event` never carries it.
- `browser/relay.rs`: keep each foreign job's door by job, in memory, until the job ends.
  - Send `box` when a door is set.
  - Send it again from `follow` (`relay.rs:130-134`) for every live door, after subscribing, so a window that follows anew has it before any command.
  - Check that `routes.rs` `relay_commands` (`routes.rs:268-289`) sends it as is (`serde_json::to_string`, no masking) and needs no change.
- `jobs/reach.rs`: `browser_server` gives a foreign job the server (the switch's check goes). For a foreign job, it opens the job's browser door (`self.egress`, a field `jobs/reach.rs` can read as a child of `jobs`) and hands it to the relay. A job with no egress proxy (`confines_egress()` false), or found foreign after its run started unboxed, gets no door. Its box then reaches nothing (main, below): it fails closed. `end_reach` forgets the door. `jobs.rs` isn't touched.
- `browser/box_edge.rs`: `FOREIGN_BROWSER` and `not_yet` go, with `tools.rs:38-40`'s check. `in_box` stays as it is.
- `tools/obid-spec/src/browser_window.rs:307`: the stand-in window takes `box` as it takes `release`, `pointer` and `turn`. Otherwise it refuses the new command.
- `jobs_api.rs` `lanes_23_*` (comment near `jobs_api.rs:7209`): the untrusted run loads `["browser"]` again.
- The five `tools/obid-spec/workflows/routes/browser/another-obys-task-*.json` lose every `ui.expectedRed` that names the window's task and `FOREIGN_BROWSER`, and pass.

In main (`browserRelay.ts`, `browserGuest.ts`, `browser.ts`):

- `relayCommand` takes `box`, checked like the others:
  - `partition` is `oby-box-<threadId>` for that same `threadId`;
  - `proxy` is exactly `http://oby:<token>@127.0.0.1:<port>`;
  - anything else is `null`.
  The relay host passes it to the webviews' side, never to the page. Nothing logs the token.
- A box session is made ready before its guest attaches, as T3's `getSession` does. `prepare` runs in `will-attach-webview` once `harden` passed, and when obid's `tab` event first names a box partition (`heard`, `browser.ts:27-29`), not in `did-attach-webview`. For a box partition it also:
  - installs `webRequest.onBeforeRequest`, which holds each request until main has set that partition's door (`setProxy` resolved), then lets it go. A request held 10 s is cancelled. No door, no request.
  - on `box`, runs `setProxy({ mode: 'fixed_servers', proxyRules: '127.0.0.1:<port>', proxyBypassRules: '<-loopback>' })`, so loopback goes to the door too.
  - answers the guest's `login` event with `oby` and the token only when `authInfo.isProxy` and the host and port are that door's (egress answers `407` with `Basic realm="oby"`, `egress.rs:371`). Every other `login` gets an empty `callback()`.
  - sets each of its webviews' WebRTC to `disable_non_proxied_udp`, so no UDP leaves outside the proxy.
  Agent partitions (`persist:oby-agent-*`) stay exactly as now: no proxy, as T3's.
- When a box partition's last tab goes (its `release`, or its `tabClosed`), main runs T3's clear on that session: `clearStorageData` with T3's storages list, `clearCache()`, `clearAuthCache()`. It then forgets the door, so requests are held again. A box with another tab still open isn't cleared.

Not in this task, and named in the contract as later or obid's:
- item 4 (a mark set mid-run);
- `ws://` from a box page (a plain tunnel carries only TLS, `read_hello`);
- a public address of this Mac other than its listeners' ports.

Port the technique, don't copy T3's code verbatim (verbatim code needs T3's MIT notice in NOTICE, which is not this task). Credit T3 in comments with its paths, as `browserGuest.ts` already does.
