## What
The part of B00-22 its intake left out. Oby's factory starts a build straight from a task file. The Claude Code factory first runs `intake` (accept, scope, risk, surfaces), then `spec-writer` (numbered acceptance criteria, `## Proofs`, `## Models`), and the builder builds against that spec. The agent definitions are in `.claude/agents/`.

## Why
Without a spec, the approver from B00-22 has only the task file's loose acceptance list to check, and B00-21's proving has no spec-named broken rules or witnesses to check. The owner wants Oby's factory at the Claude Code factory's quality.

## How
`factory/bin/oby-feed` starts an intake job first, then a spec job, as Oby jobs, with the same prompts and outputs: an `intake.md` and `spec.md` kept with the task's feeder state. The build job is then told to build against that spec. A NEEDS-INFO or REJECT intake waits for the owner, the way a Claude Code factory job does.

Acceptance:
- Every build Oby's factory starts carries a spec with numbered acceptance criteria.
- An intake that answers NEEDS-INFO starts no build, and the task waits with intake's questions.
- Tests use a stand-in obid.
