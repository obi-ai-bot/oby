## What
Oby's own factory (`factory/bin/oby-feed` feeding the factory's obid, config `~/.oby-factory/config.json`) runs no check of its own: the repo's `check` is `"true"`. A job publishes whatever its builder committed, and the only test before merging is GitHub's merge queue, which runs on Linux only. The Claude Code factory instead runs `factory/bin/gate` on every round: `factory/checks.sh` / `scripts/oby-check.sh`, sharded over the gate VM, the Mac worker and this Mac (`remote_gate`, `mac_worker`, `gate_shards` in `factory/config.json`), with macOS-only code tested on a Mac and every guard of the check (line limits, the flaky list, routes, sleeps, the rules manifest).

## Why
Without it, Oby's factory can merge a macOS-only regression, a broken guard or a failing test GitHub's Linux CI doesn't run, which the Claude Code factory would have stopped. The owner wants both factories at the same quality.

## How
Give the factory obid's repo a check that runs the same gate on the job's worktree at its commit: the same `factory/checks.sh`, the same VM, Mac worker and local-Mac sharding, the same verdict lines, so a failing check sends the job a check-fix round as obid already does for a failing check, and a passing one lets it publish. Reuse `factory/bin/gate`'s remote code (import it, as oby-feed imports `job` and `prove`), don't copy it. Document the setting in `factory/README.md` and set it in the factory's config.

Acceptance:
- An Oby factory job whose commit fails a Rust test, an Electron test, a line limit or a macOS-only test never publishes; obid gives it a fix round with the check's log.
- A job that passes publishes, and its check log names the same parts (VM shards, Mac worker, this Mac) as a Claude Code factory gate of the same commit.
- A test runs the check on a commit with a deliberately failing test and sees it red, and on a clean one and sees it green.
