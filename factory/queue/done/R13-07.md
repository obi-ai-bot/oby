# chore(check): a limit raise names its payback issue and comes in its own pull request

<!-- Roadmap R13-07 · Sprint 4 · R13 How we work · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

The owner still raises a limit with a word, but each raise names the issue whose cut pays it back, and the check fails when a raise is mixed into a feature change. The check prints the open payback issues beside the limit.

### Status and scope

Proposed (roadmap R13-07, milestone R13 How we work).

**Why:** obid_lines_limit was raised 10 times between 2026-11-05 and 2026-11-12 (90,500 -> 100,000). #2131 named its payback ('until OBY-25 deletes oby_shell') and #2137 paid it (99,000 on dev now), but the others named none, and limit edits rode inside feature PRs #2088 and #2064.

**In:**
- A `# payback: #<issue>` comment line required directly above a raised limit in scripts/oby-check.sh.
- A failure when the commit raises obid_lines_limit or jobs_rs_limit against its base and changes any file but scripts/oby-check.sh.
- The check prints each payback line it finds.

**Out:**
- Who may raise: still the owner's word.
- Querying GitHub from the check (it has no network).

### Actors and ownership: what obid owns

- Nothing changes in obid.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- scripts/oby-check.sh
- scripts/oby-check-test.sh
- AGENTS.md

### Steps

- Reuse `limit_in` and `pick_limit` to detect a raise against $base.
- Fail a raise without a `# payback:` line, and a raise whose diff names any other file.
- Print the payback lines with the limit message.
- Add the cases to scripts/oby-check-test.sh and see them fail on the old script.
- Add one sentence to AGENTS.md 'Dispatcher, not harness' (the raise form), with the same removal-condition form as R13-05.

### Acceptance scenarios

- None: this task changes no product behaviour.

Contract: none

### Tests

- raise without payback fails; raise with another file fails; raise alone with payback passes (new cases in scripts/oby-check-test.sh)

### Done when

- scripts/oby-check-test.sh passes and its new cases failed before.
- `scripts/oby-check.sh` passes on the PR's commit.
