## What
W01-05 (#2845) flags a conversation for good once it opens an artifact version made without the proxy (`unproxied`), and `planned_job` sets `ran_unproxied` on every job that conversation plans after that, so its check gets none of the declared secrets (LANE-3a). Its round-6 reviews (factory/jobs/004-w01-05-a-change-asked-with/round-6/review-security.md and review-codex.md, Follow-ups) found paths that build a job without `planned_job`:

- `fix_ci` (`core/crates/obid/src/brain/actions.rs`, ~440);
- a follow-up the brain starts by telling a finished job something;
- a message relayed to a running job (the job itself must then be marked `ran_unproxied`, once and for good).

And one read rule: an I/O error other than "not found" while reading the flag counts as "not flagged"; it must count as flagged.

## Why
In a flagged conversation the brain's words can carry text from an unproxied artifact. Through any of these paths it reaches a clean job whose check still gets the declared secrets.

## How
1. Route the flag through the one place that decides it: each path above sets `ran_unproxied` from the conversation's flag, as `planned_job` does. Prefer calling the same helper `planned_job` uses over a copy.
2. A relayed message into a running job of a flagged conversation marks that job `ran_unproxied` before the message is delivered, saved first, nothing delivered if the save fails (as W01-05 saves the flag before laying files).
3. Reading the flag: `NotFound` is "not flagged"; any other error is "flagged".
4. `docs/contracts/lanes.md` (LANE-3a): name the four paths. Add the scenario ids below under Implemented.
