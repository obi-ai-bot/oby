# test(obid): load a job file and config.json from each released version

<!-- Roadmap R01-04 · Sprint 1 · R01 Safety net · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

An upgrade can no longer lose an owner's jobs or settings silently: a test loads saved files from each released obid with the current code and fails when one is dropped or changes state.

### Status and scope

Proposed (roadmap R01-04, milestone R01 Safety net).

**Why:** Job has many serde(default) fields and stored files carry no schema version (#923). A file that no longer parses is skipped with one log line and the job disappears from every app. Releases v0.4.1 to v0.4.5 (tags, 2026-10-26 and 27) have job files nobody tests against.

**In:**
- Fixtures: one done job with a branch and PR, one failed job, one waiting job, and config.json, per released tag, under core/crates/obid/tests/fixtures/released/<tag>/
- A test that starts obid on a home seeded with them and reads GET /v1/jobs
- A line in docs/ci.md: each release adds its fixtures

**Out:**
- The home schema version and the unreadable-job inbox item (#923)

### Actors and ownership: what obid owns

- Nothing new; the test covers store::load_all and config loading.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- new: core/crates/obid/tests/released_files.rs
- new: core/crates/obid/tests/fixtures/released/
- core/crates/obid/tests/support/mod.rs
- docs/ci.md

### Steps

- For each tag v0.4.1..v0.4.5 that shipped obid, produce job JSON and config.json from that version's job.rs and config.rs (run the tag's obid with the stub agent in a scratch home, or write them by its structs); remove any token or personal path.
- Write released_files.rs: copy each tag's fixtures into a temp home, start obid with support::start_with, assert RELEASED-1..3.
- Prove it can fail: rename a field in a fixture the current Job requires and watch the test go red; record it in the PR.
- Add the release step to docs/ci.md.

### Acceptance scenarios

- RELEASED-1 (proposed): Given a home with job files written by a released obid, when the current obid starts, then every job is listed by GET /v1/jobs.
- RELEASED-2 (proposed): Given a released job with a branch and a pull request, when it is loaded, then its branch and PR URL are unchanged.
- RELEASED-3 (proposed): Given a released config.json, when the current obid starts, then it starts and keeps the configured repositories and agents.

Contract: new: docs/contracts/released-files.md (prefix RELEASED)

### Tests

- released_1_every_released_job_is_listed, released_2_branch_and_pr_are_kept, released_3_released_config_starts (new, in core/crates/obid/tests/released_files.rs)

### Done when

- The new test passes in the Rust lane and in `scripts/oby-check.sh` when it touches job.rs or config.rs.
- The PR shows the red run of the step 3 proof.
