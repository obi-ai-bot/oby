# feat(obid): POST /v1/jobs takes a request key

<!-- Roadmap R02-04 · Sprint 1 · R02 Commands that are safe to repeat · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

A network retry of POST /v1/jobs from the CLI, oby-mcp or the phone returns the job the first request made, not a second job.

### Status and scope

Proposed (roadmap R02-04, milestone R02 Commands that are safe to repeat).

**Why:** routes.rs `dispatch` (POST /v1/jobs) calls task_conversation::create every time. A retry makes a second job, or PUBLISHING-4's 422 for a busy branch.

**In:**
- Optional `clientRequestId` in the body and optional `Idempotency-Key` header (same meaning; both present and different is 422).
- First answer 201; a repeat 200 with the same job; another body 409.

**Out:**
- POST /v1/plans (the turn `id` does this already).
- Messages and inbox (R02-05).

### Actors and ownership: what obid owns

- The key check before task_conversation::create; the receipt after it.

### Actors and ownership: what the apps show and send

- Nothing yet; clients send the key in R02-07 and R02-08.

### Interfaces and dependencies

- POST /v1/jobs: optional `clientRequestId` (string, 1 to 128) in `job`, optional `Idempotency-Key` header; 200 on a repeat, 409 on a different body. Job JSON: optional `clientRequestId`.

### Files

- core/crates/obid/src/routes.rs

### Steps

- In routes.rs `dispatch`, read the key after the body parses and before new_job.
- Hold the receipt's key lock across create, so RECEIPTS-7 holds.
- Store the key on the Job (add-only `clientRequestId`).
- Document it in docs/runner-api.md, POST /v1/jobs.
- Write RECEIPTS-5 to 7 as tests.

### Acceptance scenarios

- RECEIPTS-5 (proposed): Given POST /v1/jobs answered 201 with key K, when the same body comes again with K, then obid answers 200 with the same job and makes none.
- RECEIPTS-6 (proposed): Given POST /v1/jobs answered with key K, when another body comes with K, then obid answers 409 and makes nothing.
- RECEIPTS-7 (proposed): Given two POST /v1/jobs with key K at the same moment, then exactly one job is made and both answers name it.
