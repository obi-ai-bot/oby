## What
`archive_is_at_once_and_delete_waits_for_confirm` (`core/crates/obid/tests/conversation_harness.rs`, the check near line 4061) dismisses a job, then checks that the job's worktree is still there. obid's first cleanup pass runs 30 seconds after it starts (`CLEAN_FIRST` in `core/crates/obid/src/lib.rs`), and a dismissed job counts as put away (`settled_in` in `core/crates/obid/src/jobs/free.rs`), so that pass deletes the worktree. Alone, the test reaches its check in about 15 seconds. On a busy machine it can take more than 30, and then it fails. On 2026-11-16 it failed A00-86's round-8 gate in a 344-second run. On a clean `origin/dev` with a 35-second pause added after the dismiss, it failed at the same check.

## Why
Any job's gate can fail on this test when the machine is busy, through no fault of the job. That costs a build round each time, and a job in its last round can run out of rounds over it.

## How
- Make the test independent of the clock: start its obid with the first cleanup pass pushed past the test's end (a test-only setting), or wait for the state it means to check instead of racing the pass.
- obid's behaviour for owners doesn't change: the first pass still runs 30 seconds after start.
- If a test-only setting is added, it is read only in tests and can't change a real obid.

Acceptance:
- With a 35-second pause after the dismiss, the test still passes, and the change shows that pause failing without the fix.
- The test passes 20 runs in a row under load on this Mac (another Rust build running alongside), through `factory/bin/test-run`.
- obid's own cleanup timing is unchanged for a real run.
- No new `sleep` in tests (the sleep limit holds).
