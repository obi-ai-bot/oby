## What
- **Property 1 (LOGS-1's own words):** after `Secrets::redact`, `Secrets::try_redact` or `Snapshot::redact`, no form that `needles_for` makes of a learned value is left whole in the text. That holds also when:
  - two values overlap;
  - one holds the other;
  - one ends where the other begins;
  - one occurs twice;
  - the whole text is base64 (standard or URL-safe), hex or URL-encoded.
- **Property 2 (no part left):** take a text made only of the values' bytes and padding. After redaction, none of the values' bytes is left outside the `[redacted: …]` markers.
- **Harm:** a vault value or a login, or part of one, lands in obid's log, an answer or an event (LOGS-1, VAULT-4).
- **Code it covers:** `core/crates/obid/src/secrets.rs`:
  - `Secrets::redact`, `try_redact` and `Snapshot::redact`, all three through `redacted` (about line 331);
  - what `redacted` uses: `replace` (about line 501), `unwrapped`, `hits`, `decodings` and `runs()`;
  - `needles_of` (about line 629, longest first, ties in name order) and `needles_for`;
  - `learn` and `learn_forms`, which don't learn a value shorter than `SHORTEST` (8 bytes).
- **Not in this task:** the log writer's held tail across writes (`Held`, `held_tail`, LOGS-2) and `names_in`.

## Why
LOGS-1 has one example test (`logs_1_every_form_of_a_secret_is_taken_out`, one value). Nothing checks two values against each other, and that is where the order `needles_of` sorts them in matters. Its comment says "longest first, so a value goes before the parts that would match inside it".

## How
- **Tool:** a bounded-exhaustive Rust test in secrets.rs's `mod tests`, on the real functions. It needs no new dependency.
  - Not Kani. `redacted` runs `regex::Regex` replacements (`runs()`, `line_breaks()`) and the base64 and hex encoders, which CBMC can't get through. Also, `SHORTEST` = 8 rules out the plan's 3-byte values.
- **Alphabet:** values over `{a, b}`, learned as `x` and `y` in a `Secrets::default()` (label `redacted`), with padding `c`.
  - No run of 8 letters from `{a, b}` can come from a marker, so a value found after redaction was in the text.
  - Property 2 strips every `[redacted: …]` and then looks for `a` or `b`.
- **Families** (the same value twice is skipped):
  - **(a) overlap:** every A of 8 bytes (256), and every B that begins with A's last k bytes, for k = 1 to 7 (B's other 8−k bytes any). The text is `c` + A + B[k..] + `c`. About 65,000 texts.
  - **(b) one holds the other:** every A of 9 bytes (512), with B = A[0..8] or A[1..9].
  - **(c) adjacent:** every ordered pair of distinct 8-byte A and B, as `cABc` (65,280).
  - **(d) repeated:** every A as `cAcAc`.
  - Property 1 runs each text plain and, for (a), (b) and (d), encoded whole in each of the four encodings.
- **Measured:** the pull request names the run's time in `cargo test -p obid --lib secrets::tests::logs_1_`. Past 60 seconds, it keeps the bound and says so. A smaller bound, if the reviewers ask for one, is named in the skill, never cut quietly.
- **Shown failing** (each one line, red in build.md and in the pull request, then restored):
  1. `while let Some(found) = haystack[at..].find(&wanted) {` → `if let Some(found) = haystack[at..].find(&wanted) {`. Only the first copy goes, so property 1 turns red on (d).
  2. `needles.sort_by_key(|needle| std::cmp::Reverse(needle.text.len()));` → `needles.sort_by_key(|needle| needle.text.len());`. Shortest first leaves A's other byte when B lies inside it, so property 2 turns red on (b).
- **Expected finding:** property 2 on (a). Values go one by one (`replace`, per needle), so when two values overlap by 1 to 7 bytes, the first one taken out leaves the other one's remaining bytes in the log.
