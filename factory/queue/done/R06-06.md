# refactor(electron): a pure reducer in src/shared, beside live.ts, for jobs first

<!-- Roadmap R06-06 · Sprint 3 · R06 Events that clients only apply · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/electron/src/renderer/src/TaskCard.tsx and Sidebar.tsx (no visual change)

### Outcome

Jobs reach the Mac app's state through one pure function with one rule (keep the newer revision; a deleted job never comes back), tested on its own. The rest of live.ts keeps working as it is.

### Status and scope

Proposed (roadmap R06-06, milestone R06 Events that clients only apply).

**Why:** live.ts (1,209 lines, 52 commits, 21 fixes) mixes the reducer with side effects: `apply` (live.ts:540) deletes sessions and calls room.ts and peers.ts, and job answers take the `newer` guard (live.ts:118) and the `gone` set (live.ts:62) by hand at each call site. A first small step proves the shape before conversations move.

**In:**
- new: apps/electron/src/shared/live-state.ts with `type ObidState`, `apply(state, event)` and `answer(state, job)` for `job` and `jobGone` only, with no I/O and no React.
- live.ts's `case 'job'`, `case 'jobGone'`, `newer` and every job answer (`take({kind:'job'})`, sync's job merge at live.ts:754-760) call it.
- Tombstones for deleted jobs move into the shared state.

**Out:**
- Other object kinds (R06-07).
- Any screen or store shape: chats.ts and tasks.ts are fed as today.

### Actors and ownership: what obid owns

- Job revisions (job.rs:668).

### Actors and ownership: what the apps show and send

- Nothing changes for the owner: the same tasks and cards.

### Files

- new: apps/electron/src/shared/live-state.ts
- apps/electron/src/renderer/src/live.ts
- new: docs/contracts/live-state.md
- new: apps/electron/src/renderer/src/test/liveState.test.ts

### Steps

- Write live-state.ts with the job rule and its tests (LIVE-1 to 4); prove LIVE-1 red without the revision check.
- Point live.ts's job cases and job answers at it; move `sessions.delete` out of the reducer to the caller.
- Delete `newer` and the job half of `gone` from live.ts.
- Run `npm run typecheck`, `npm test`, and on a real Mac `npm run test:live-task`.

### Acceptance scenarios

- LIVE-1 (proposed): Given the state holds job J at revision 5, when a `job` event or a REST answer brings J at revision 4, then the state keeps revision 5.
- LIVE-2 (proposed): Given a `job` event with `deleted: true` for J, when any later answer brings J, then J stays out of the state.
- LIVE-3 (proposed): Given J with no revision (an older obid), when it comes, then it is taken as it comes.
- LIVE-4 (proposed): Given the same list of events, when `apply` runs twice from the same state, then both results are equal (no hidden state, no I/O).

Contract: new: docs/contracts/live-state.md (new prefix LIVE)

### Tests

- LIVE-1 an older job never replaces a newer one (new, apps/electron/src/renderer/src/test/liveState.test.ts)
- LIVE-2 a deleted job never comes back (new, liveState.test.ts)
- LIVE-3 a job with no revision is taken (new, liveState.test.ts)
- LIVE-4 apply is pure (new, liveState.test.ts)
- taskActions.test.ts and stop.test.tsx (existing, must still pass)

### Done when
