## What
`factory/bin/oby-feed` verifies the Quint models a pull request touches (`check_models`, A00-81, A00-95), but runs no Kani proof, and it never checks that a proof or model can fail. The Claude Code factory's `factory/bin/prove` (PROVE, docs/contracts/factory.md, now in blocking mode) runs each Kani harness and then its broken rule, which must turn it red, and each model's invariants (must hold) and witnesses (must be violated), on the commit the gate passed.

## Why
The owner made formal verification blocking so that only proven work merges. Oby's factory can today merge a Kani harness that fails, or a proof or model that passes by construction, which the Claude Code factory would refuse. Today the proofs reviewer also caught three vacuous models (A00-85, A00-86, A00-77), one of them hiding a real security hole.

## How
Before oby-feed arms a merge, it runs the same proving as `factory/bin/prove` (import it, don't copy it): every Kani harness and Quint model the pull request adds or changes, with each proof's broken rule and each model's witnesses read from a file the builder writes in the branch, in prove's `## Proofs` / `## Models` shape (for example `docs/proofs/<task>.md`, named by the task). A pull request that changes Rust decision code a task asked to prove, but carries no such file, waits, saying why. Any FAIL or TIMEOUT holds the merge, as `proofs.mode: blocking` does; a pass lets it go on.

Acceptance:
- A pull request whose Kani harness fails is not merged, and the task says which harness.
- A proof whose broken rule still passes, or a model whose witness holds, is not merged.
- A pull request whose proofs and models all pass merges as before.
- Tests cover each case with a stand-in for the gate VM.
