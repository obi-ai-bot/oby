# refactor(electron): register every IPC handler through `handle(channel, decode, fn)`

<!-- Roadmap R06-04 · Sprint 3 · R06 Events that clients only apply · effort S · risk low -->

### Sangam's screen

engine only (main process; no screen changes)

### Outcome

No IPC handler in main can forget the sender check or trust an argument it did not decode. The new channels of R06-08 get this for free.

### Status and scope

Proposed (roadmap R06-04, milestone R06 Events that clients only apply).

**Why:** main has 18 ipcMain.handle/on calls in 6 files (index.ts, device.ts, notify.ts, obid.ts, sphere.ts, updates.ts); each calls `trusted(e)` (index.ts:70) and checks its own arguments by hand, and 'obid' takes `method: string, path: string, body?: unknown` as typed, not as decoded (obid.ts:368).

**In:**
- One helper in main, `handle(channel, decoders, fn)` and `on(channel, decoders, fn)`, that refuses an untrusted sender first, then decodes each argument and refuses on a failed decode.
- Small decoders in src/shared: string, boolean, optional, one of, and the 'obid' call (method in GET/POST/PUT/PATCH/DELETE, path starting `/v1/`).
- Every existing handler moved to it, with the same answers as today.
- A test that greps src/main for `ipcMain.handle(` and `ipcMain.on(` outside the helper.

**Out:**
- Changing what any channel does, or the preload's API.
- A lint plugin: R01 'Add a linter with import boundaries to apps/electron' can carry it later.

### Steps

- Write shared/decode.ts (a decoder returns the value or undefined) and main/ipc.ts (`handle`, `on`, taking `trusted`).
- Move the handlers file by file; keep each answer as today (null on an untrusted sender, as now).
- Add the method and path decoders for 'obid'; keep main/obid.ts's own `/v1/` check as a second guard.
- Write the IPC tests; IPC-4 reads the files of src/main.
- Run `npm run typecheck` and `npm test` in apps/electron, then `scripts/oby-check.sh`.

### Acceptance scenarios

- IPC-1 (proposed): Given a message on any registered channel from a frame that is not the window's main frame, when main gets it, then the handler does not run and the answer is null.
- IPC-2 (proposed): Given the 'obid' channel, when the method is not GET, POST, PUT, PATCH or DELETE, or the path does not start with `/v1/`, then main sends nothing to obid and answers a refusal.
- IPC-3 (proposed): Given any channel, when an argument fails its decoder, then the handler does not run.
- IPC-4 (proposed): Given the source of src/main, when the test reads it, then no `ipcMain.handle` or `ipcMain.on` call is outside the helper.

Contract: new: docs/contracts/ipc.md (new prefix IPC)
