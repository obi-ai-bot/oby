## What is broken

`dev` at c08bbabb (#2152, roadmap task R02-06, "Try again and brain-made follow-ups carry a command id") fails two tests that #2152 didn't run:

- `core/crates/obid/tests/plans_api.rs`: `plans_map_replies_cancellations_and_dispatched_jobs` (around line 122-126).
- `core/crates/obid/tests/conversations_api.rs`: `jobs_and_their_events_land_in_the_conversation_that_started_them` (around line 347).

Each has the fake brain answer `REPEAT 2 OBY oby_dispatch {...}`: the same `oby_dispatch` call, with the same arguments, twice in one turn. Each then expects two jobs and gets one (`left: 1, right: 2`).

That is #2152's intended behaviour, not a bug in obid: R02-06 made a brain tool call repeated with the same arguments in one turn act once, keyed by the turn, the tool's name and a hash of its arguments (`brain/tools.rs`, its `tool:` request key; `docs/contracts/receipts.md`). The two tests were written before that rule and still expect the old one. #2152's own check ran only the test binaries its change reached, so it never ran these two.

Shown twice since: R01-06's builder reproduced the plans failure 20 of 20 times against #2152's code, and R03-01's builder reproduced both on c08bbabb's `core/` 3 of 3 times.

## What to do

Keep #2152's rule. Change the two tests so they still prove what they are about with it:

- Where a test needs two jobs, have the brain dispatch two different jobs (different `task` text) rather than one call repeated.
- Where the same call repeated in one turn is what the test meant to send, expect one job, and say in the test's comment that the repeat is collapsed by R02-06's rule.

Read what each test is named after and its contract before choosing. Change no production code in obid, and don't weaken either test's assertions about the conversation, the plan's replies or the jobs' events.
