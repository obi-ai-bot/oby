## What
`factory/bin/oby-feed` checks the Quint models a pull request changes by copying each one to the gate VM and running `quint verify` there. The remote commands build the file name as `/tmp/oby-feed-<sha>-<basename>` and put it into the shell unquoted (`cat > {name}`, `quint verify ... {name}`, `rm -f {name}`). The basename comes from the pull request: any changed file under `docs/models/` ending in `.qnt`.

## Why
A pull request that adds a model whose file name holds shell characters (`;`, `$( )`, a backtick) would run its own commands on the gate VM as the feeder's ssh user. The VM holds no secrets, but it runs every job's gate, so a poisoned VM could pass a gate it should fail. `main`, `steps` and the invariant names are already checked against a safe pattern; the file name is the one input that isn't. Found by reviewer-security on A00-81.

## How
- Refuse (keep the pull request waiting, with a note naming the file) any changed model whose basename doesn't match `^[A-Za-z0-9_.-]+\.qnt$`.
- Also pass every remote path through `shlex.quote`, so the check and the quoting each hold on their own.
- Acceptance: a test where a pull request changes `docs/models/a;touch x.qnt` shows the feeder never builds a remote command with that name, records a no-verdict note, and doesn't merge. The test fails with the check removed. The existing `oby_factory.qnt` path still verifies.
