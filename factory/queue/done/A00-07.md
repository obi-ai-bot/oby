## What
Builders run obid's tests themselves before reporting READY (in their own build folder, `CARGO_TARGET_DIR=<worktree>/core/target`, never factory/checks.sh). That keeps builds apart, but not the CPU: two or three builders compiling and testing at once, beside a gate's check, slow the gate past the check's own caps. R03-01's merge gate on 2026-11-13 was stopped unjudged after its Rust test step ran past `maxDuration` 45m (tools/oby-check-blok/workflows/oby-check.json) while builders' test binaries ran beside it; the Mac's load average reached 15+ on 10 cores.

## Why
A gate that runs past its cap costs a whole round (builder, gate, often reviews), about an hour, and it isn't the change's fault. Gates are the factory's bottleneck (one Rust gate at a time on this Mac), so anything that slows them slows every task.

## How
- Add `factory/bin/test-run` (Python, like the other factory scripts): it runs the command it's given (`factory/bin/test-run -- cargo test -p obid --test jobs_api`, `-- npm test`, and the like) so that:
  - only one builder test run happens on the Mac at a time: it waits on its own lock file (not the check lock, `.factory-check.lock`, which only gates hold), printing that it waits and for whom;
  - it runs at background priority, so a gate's check always gets the CPU first (on macOS `taskpolicy -b` or `nice -n 15`; say which and why);
  - Cargo and the test harness use at most half the Mac's cores (`CARGO_BUILD_JOBS` and `RUST_TEST_THREADS`, or nextest's `-j`, from `os.cpu_count() // 2`);
  - it holds the lock in its own process and runs the command as a child in its own session, ends everything the command left running when it exits or is stopped, and passes the command's exit code through, as factory/checks.sh does since #2178.
- Builders use it for every test, clippy and build run of their own: update `.claude/agents/builder.md` (Test section) and its example commands. Spec writers and reviewers that run tests use it too (`.claude/agents/*.md`, wherever they run cargo or npm).
- Document it in `.claude/skills/factory/SKILL.md` and `factory/README.md`.
- Tests: two overlapping `factory/bin/test-run` calls of a stand-in command run one after the other; the exit code comes through; a process the command leaves behind is gone when it ends; the lock is free after a stop. Each test fails without the change it covers.

## Acceptance
- Two builders' test runs never overlap on the Mac, and the second says it is waiting.
- A builder's test run never takes more than half the cores, and runs at background priority.
- A gate's check never waits on a builder's test run (they use different locks).
- `factory/checks.sh` and the gate are unchanged.
