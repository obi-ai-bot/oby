Bug: obi-ai-bot/oby#2339.

What. obid, configured with a repository under an old GitHub name, pushes and opens the pull request, then ends the job with publishError "Pushed, but gh opened no pull request of this repository." and no pr, so its reviews and merge tracking never start.

Why. A renamed or transferred repository silently loses review and merge.

How. Resolve the repository's canonical owner/name once when it is added or first used (gh repo view --json nameWithOwner), and compare the opened pull request against that, case-insensitively. Keep the configured name for display.

### Files
- core/crates/obid/src/publish.rs
- core/crates/obid/src/github.rs
- docs/contracts/publishing.md

### Formal verification
A Kani harness in publish.rs over the pure function that decides "this pull request is this repository's" (same_repository(pr_repo, configured, canonical)): it is true exactly when pr_repo equals configured or canonical, ignoring ASCII case, and never true for another owner or name. The harness must turn red when the canonical arm is removed.

Acceptance: a new PUBLISHING scenario with a test named after it that fails on today's code; a job on a renamed repository ends with pr set.
