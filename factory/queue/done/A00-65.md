Bug: obi-ai-bot/oby#2337. Found while running the factory's builds through Oby.

What is wrong. A job in Oby's box (every Cursor job; Codex on a ChatGPT login; any job marked untrusted or another Oby's) cannot build this repository's Rust code. `cargo build -p obid --manifest-path core/Cargo.toml`, run by the agent inside the job's worktree, exits 101 before reaching the network: "warn: could not canonicalize path <obid home>/worktrees/<job id>", then "failed to load manifest for workspace member `<worktree>/core/crates/*`" ... "No such file or directory". Seen with an obid whose `home` is a folder under the person's home other than the This Mac home; whether the This Mac home shows the same is not measured, and the fix must hold for both.

Why it matters. Oby's promise is that the owner's agents, of any vendor, do real work; a boxed agent that cannot compile or test can only guess, so Codex and Cursor jobs are useless on Rust repositories, and the factory cannot spread its builds over Claude Code, Codex and Cursor.

How. Find why `realpath` of the worktree (and the glob read of `core/crates/*`) fails under the macOS confined profile in `core/crates/obid/src/sandbox.rs` (the `(deny file-read*)` / `(allow file-read-metadata)` / readable `subpath` rules and the hidden-folder ancestor rules around `job_hidden`), and fix the profile so a boxed job can resolve and read its own worktree and the toolchain it needs (rustup/cargo homes read-only, cargo's registry and target dirs where the box allows), without making obid's home, the person's home or another job's folders readable. Also say how a boxed job gets crates (offline from a pre-fetched registry, or the egress proxy allowing the crates registry) and make one of them work.

Acceptance:
- A test (named after a new scenario in docs/contracts/sandbox or lanes, whichever owns the box's read rules) that runs a confined process with a worktree under a hidden home and shows `realpath` of the worktree and a directory listing inside it succeed, and fails on today's profile.
- A boxed job on a real Mac (an obid with a non-standard home) runs `cargo build -p obid --manifest-path core/Cargo.toml` to exit 0; report the measured result in the PR.
- The existing sandbox tests that prove obid's home, the person's home and other jobs' worktrees stay unreadable still pass unchanged.
