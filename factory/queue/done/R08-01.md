# refactor(obid): one provider descriptor table, data only

<!-- Roadmap R08-01 · Sprint 3 · R08 One interface for every agent CLI · effort M · risk medium -->

### Sangam's screen

engine only

### Outcome

Each agent CLI's facts (id, name, default binary, home env var, effort encoding, default model, efforts, tool API hosts, routing order, whether usage is advisory, CLI versions tested) are one row in one table. A rule that differs per tool is read from the row, so it cannot be missed in one of three copies.

### Status and scope

Proposed (roadmap R08-01, milestone R08 One interface for every agent CLI).

**Why:** `agent::Tool` is a closed enum with 443 `Tool::Claude|Codex|Cursor` references in 22 files (jobs.rs 110, accounts.rs 77, jobs/logins.rs 66, jobs/lanes.rs 50). The same per-tool facts are repeated as `match tool` arms in agent.rs (`id`, `name`, `ALL`), egress.rs `tools_api`, settings.rs (`default_model`, efforts at 235-260), brain/talk.rs and config lookups in jobs.rs (2387, 2807). Map problem 'Every rule is written three times, once per provider' (high).

**In:**
- new: core/crates/obid/src/providers.rs with `pub struct Descriptor` and `pub static PROVIDERS: &[Descriptor]`: `id`, `name`, `bin`, `home_env` (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `CURSOR_CONFIG_DIR`), `effort: Effort::Flag | Param | ModelSuffix | None`, `default_model`, `efforts`, `complex_efforts`, `api_hosts`, `route_order`, `usage_advisory`, `tested_versions`.
- `Tool` stays a `Copy` type whose `id()` / `name()` / `ALL` / `from_id` read the table; wire ids and every JSON key stay as they are.
- Replace the data-only `match tool` arms in agent.rs, egress.rs `tools_api`, settings.rs, model_lists.rs and brain/talk.rs with row lookups.
- A test that each id has exactly one row and that `Tool::ALL` order equals today's routing order (Claude Code, Codex, Cursor).

**Out:**
- Any behaviour (run a turn, read usage, sign in): R08-03 to R08-05, R08-12.
- Lane eligibility (`OwnLane`) in the row: jobs/lanes.rs changes under #2044 and #2045 now.
- config.json's `agents.claude|codex|cursor` shape (`config::Agents`, `deny_unknown_fields`): unchanged.
- A new provider.

### Acceptance scenarios

- PROVIDERS-1 (proposed): Given the provider table, when obid starts, then every tool id that jobs, accounts and config.json use has exactly one row, and `Tool::ALL` lists them in routing order Claude Code, Codex, Cursor.
- PROVIDERS-2 (proposed): Given a job on any tool, when its agent reaches a host, then the hosts that count as its tool's own API (`egress::tools_api`) are exactly the hosts on dev 952bc03d for that tool, read from its row.
- PROVIDERS-3 (proposed): Given `GET /v1/settings/models/options`, when it answers, then each tool's `efforts` and `complexEfforts` are byte-for-byte today's answer (AGENTS-5, AGENTS-8), read from the rows.
- PROVIDERS-4 (proposed): Given a row, when a reader asks which CLI versions its parsers were observed on, then the row says them (Claude Code 2.1.302, codex-cli 0.162.1/0.163, cursor-agent 2026.10.01 as the contracts name them today).
