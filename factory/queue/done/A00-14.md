## What
`obid::publish_api` `a_hand_publish_is_for_the_run_that_was_approved` failed twice in a row (nextest's retry) on GitHub's Ubuntu runner in the first full `ci.yml` run of `dev`: https://github.com/obi-ai-bot/oby/actions/runs/43509555490 (rust-test 1/4), with "assertion `left == right` failed". The other 580 tests in that shard and the other three shards passed. It passes in the Mac's gate.

## Why
It keeps the full CI run red, and the merge-queue rulesets (R01-03) can't be turned on until `dev` is green on GitHub.

## How
- Reproduce it on Linux: the Azure gate VM (`oby-gate`) or a local container, never GitHub minutes for trial runs. Find whether it's a race (fixed waits, ordering) or a real Linux difference (paths, file modes, git version).
- Fix the cause; if it's a wait, wait for the state, not time. Change production code only if the test exposed a real Linux bug, and say so.
- Prove it: the test fails before the fix on Linux and passes after, 10 runs in a row.
