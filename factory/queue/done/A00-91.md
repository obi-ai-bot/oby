Contract: docs/contracts/updates.md and the run records (`apps/electron/src/main/runMarker.ts`: start attempts and `crashes.jsonl`, R09-09).

What. When the window's renderer process dies, main records a crash line and reloads the window once (`render-process-gone` → `rendererGone`, `main/index.ts`). A React render error is not a process death: only one message has an error boundary (`Said.tsx`), so a render error anywhere else (Home, the side panel, a task's page, Settings) unmounts the whole tree and leaves a blank window that stays blank, with nothing recorded and nothing for the owner to click.

Why. A blank Oby window looks like Oby is down while obid keeps working underneath; the owner can't see or answer what waits for them, and nobody learns what broke.

How. One error boundary at the root of the renderer (`main.tsx`) and one around each main pane (Home, the side panel, the view), each sending the error's name, message and component stack (redacted by main's existing log redaction, never props or state) to main over one new IPC channel registered through `handle(channel, decode, fn)` (R06-04). Main records it in `crashes.jsonl` as a crash line of kind `render`, and reloads the window by the same rule as a renderer crash (once; a second within the same window's life shows the start-recovery page when R09-10 has it, else stays as it is). A pane's boundary shows nothing new: it reloads, so no words are added to Sangam's screens.
