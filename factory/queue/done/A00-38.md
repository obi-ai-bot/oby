The owner's word (2026-11-14): "Add it now, advisory", on adding formal verification (Kani) as a step of the software factory. This is the agents half of the Formal Verification session's Phase 1; A00-37 adds the `prove` stage these agents feed. Depends on A00-37.

1. .claude/agents/intake.md: SURFACES gains `proofs`. Set it when the task changes pure, synchronous decision logic (a pure function, a state machine transition, an encode/decode pair, an ordering or arithmetic rule) in Rust (Kani is the only proof tool wired in). Never for async, I/O or concurrency code.
2. .claude/agents/spec-writer.md: for a `proofs` job, spec.md gets `## Proofs`: numbered PROOF-<n>, each with the scenario it restates, the harness name, the only `kani::assume`s allowed, any unwind bound, and the broken rule (a one-line code change) that must turn it red.
3. .claude/agents/builder.md: standing rules from the R04 trial: harnesses in `#[cfg(test)] mod proofs { #![cfg(kani)] ... }`; only enums and integers vary; no text comparison; no stub, should_panic or unwind beyond the spec; run them only through factory/bin/test-run; record each VERIFICATION line in build.md; never edit a property to make it pass; if a harness over a whole function times out, extract the rule into a small named function rather than narrow the inputs.
4. New .claude/agents/reviewer-proofs.md: reads spec.md's Proofs, the harnesses and round-N/proofs.md; judges whether each property says what its scenario means, whether anything is vacuous, and whether inputs were narrowed beyond the spec. VERDICT: PASS | CHANGES like the other lenses. Writes round-N/review-proofs.md.
5. .claude/agents/approver.md: for a `proofs` job, decision.md notes the final round's PROOFS line; in advisory mode it never blocks on it.
6. .claude/skills/factory/SKILL.md: the pipeline gains the `prove` step after gate (run factory/bin/prove in the background like the gate; PASS, ADVISORY-FAIL or SKIPPED -> review; FAIL -> build).

Acceptance: a dry run of a fixture job with the `proofs` surface goes intake -> route (proofs lens added) -> spec (Proofs section) -> gate -> prove -> review (proofs lens spawned) without errors, and a job without the surface is unchanged. These files are security paths: the owner merges this PR.
