## What
The artifact preview in the app's main process keeps a version's files in a plain object and lays the owner's unsaved edits over it. Two places treat a key as a property of that object:

- `apps/electron/src/main/artifactPreview.ts` builds `files` as `{}` and tests `path in read.files`, which is true for inherited keys such as `constructor` and `__proto__`.
- It sends the files to the preview page as JavaScript source: `executeJavaScript('window.obyShow(' + JSON.stringify(...) + ')')`. In an object literal, a `"__proto__":` key sets the prototype instead of making a file.

So an artifact, or an edit, with a file named `__proto__` can change the prototype of the object the preview draws from.

## Why
An artifact's file names come from an agent, or from an imported archive (L4, the next task in this lane). They are text from outside: data, never something that reaches into the app's objects. This lands first and alone because it shipped with #2836 and every later Artifacts task builds on these two functions.

## How
The fix exists as one commit, `092916a7`, on `origin/claude/artifacts-l4-export`. It applies to `dev` with no conflict (`git cherry-pick 092916a7`). It adds to `main/previewRules.ts`:

- `noFiles()`: a files object with no prototype (`Object.create(null)`);
- `overlay()`: lays edits over files with `Object.hasOwn`;
- `shownAs()`: the script `window.obyShow(JSON.parse(<string>))`, so the page parses data instead of evaluating a literal.

Take that commit. Then make the proof behavioural, which it isn't yet: today the test is red on `dev` only because those three functions don't exist there.
