# fix(obid): redact every log line in the writer

<!-- Roadmap R02-14 · Sprint 2 · R02 Commands that are safe to repeat · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

A secret obid holds never reaches stderr or obid.log, whoever wrote the log line.

### Status and scope

Proposed (roadmap R02-14, milestone R02 Commands that are safe to repeat).

**Why:** main.rs:143 builds tracing_subscriber::fmt() with `.with_writer(std::io::stderr)` and no redaction. secrets.rs and vault.rs module docs name a log layer `crate::logs` that no longer exists. A log line is safe only if its author called redact.

**In:**
- A MakeWriter that buffers each formatted line and writes secrets::known().redact(line).
- Fix the secrets.rs and vault.rs module docs.

**Out:**
- Per-call redaction of answers and pushes (stays).
- The scan's built-in rules for log lines (#1032).

### Actors and ownership: what obid owns

- Redaction at the one place every log line passes.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- core/crates/obid/src/main.rs
- core/crates/obid/src/secrets.rs
- core/crates/obid/src/vault.rs
- new: docs/contracts/logs.md

### Steps

- Write a Redacting writer in secrets.rs that collects bytes until the line ends, then redacts and writes.
- Use it in main.rs's tracing_subscriber::fmt().with_writer.
- Check redacted_panics (lib.rs) still applies.
- Write LOGS-1 and 2 against the writer with a test subscriber.
- Fix the module docs that name crate::logs.

### Acceptance scenarios

- LOGS-1 (proposed): Given a vault value V, when obid logs a line holding V plain, base64, hex or URL-encoded, then the writer receives none of them.
- LOGS-2 (proposed): Given a log line split across two writes by the formatter, then V split across them is still taken out.

Contract: new: docs/contracts/logs.md (prefix LOGS)
