What. Today the Mac raises an alert only when something needs the owner (a decision). A task that finishes or merges, and an account that runs out of usage, raise nothing, by the owner's rule of 2026-10-28.

Why. The owner changed that rule on 2026-11-15 ("Turn them on"): with many agents working at once, he wants to know when work lands and when an account stops, without watching the window.

How. obid raises an alert event for: a task that ends done (with its pull request when it has one), a pull request of a task that merges, and an account that reaches its limit (with when it resets). The Electron app shows each as a macOS notification in Sangam's words; clicking one opens its conversation, or Settings › Accounts for an account. Each kind can be turned off in Settings › Notifications (three switches, on by default). Nothing new leaves the Mac: alerts stay local, and the phone keeps today's behaviour. Write a decision file quoting the owner's answer, which replaces the rule of 2026-10-28.

### Formal verification
A Kani harness over the pure function that decides whether an event raises an alert, given the event's kind and the three switches: an alert is raised exactly when its kind's switch is on, and a decision that needs the owner always raises one, whatever the switches.

Acceptance: ALERTS scenarios, each a test named after it: a finished task alerts; a merged pull request alerts; an account at its limit alerts with its reset time; each switch off silences only its kind; a decision still alerts with every switch off.
