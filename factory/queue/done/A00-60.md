The owner's word (2026-11-15), answering "Add tasks to split jobs.rs and to spread the gate across the three machines?": "Yes, add both".

Why: a whole check (factory/checks.sh → scripts/oby-check.sh) takes 25 to 74 minutes and runs on one host at a time, while the Mac worker (oby-mac-pro, 2 builder slots), the gate VM (oby-gate, Linux) and this Mac sit partly idle. GitHub CI already shards its tests 4 ways with cargo-nextest's --partition.

What to build:
1. The gate splits obid's test binaries and lib tests of one check into shards (nextest --partition, or by test binary), runs the shards at once on free slots of the three hosts, and merges their results into one round-N/checks.md with one verdict: any shard failing, or any shard not reporting, is GATE: FAIL. Tests the routing keeps on macOS (the gate's macOS-only list) run only on the Macs.
2. The verdict is the same as the unsharded check on the same commit: prove it with a commit that has one failing test placed in each shard in turn (each run must go red, naming the test), and with a clean commit (green).
3. Measure: the same commit's whole check, unsharded and sharded, wall-clock seconds and VM seconds, recorded in build.md. Report the cost of the extra VM time at config.json's prices.
4. Optional, only if it pays: a shared build cache (sccache) between the hosts; never with a secret on the VM, and the VM's SSH rule unchanged.
