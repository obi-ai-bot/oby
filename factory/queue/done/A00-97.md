What. Four things stop `factory/bin/oby-feed` when nobody is watching:
- **It stops when the queue is idle.** `main()` ends the process on the first pass with nothing under way and nothing ready ("nothing under way and nothing ready: stopping"). Nothing restarts it. A task file committed to dev afterwards never starts, and a `waiting` task the owner merges by hand is never recorded as merged.
- **It crashes when obid is down.** `api()` catches only `HTTPError`. With obid down (a restart, an update), `urlopen` raises `URLError`, nothing catches it, and the process dies. Checked on 2026-11-15: `api('GET','/v1/jobs')` against a closed port raised `URLError: Connection refused`.
- **One passing failure refuses a head for good.** If `gh pr merge --auto` fails for any reason (`arm`), or `check_models` can't reach the gate VM over ssh, the head is marked `refused`, and a refused head is never armed again. A network blip then blocks a twice-approved pull request until someone pushes a new head.
- **One account, no failover.** Every job is started on one named account (`--account`, default `deskree-team`). obid never moves a job whose account was named (`failover_for` skips `named` jobs). So at that account's limit, every task waits for its reset, holding its slot.

Why. An unattended factory has to outlive the things it depends on. T3 Code reconnects with jittered backoff and never gives up (`supervisor.ts`), and it only stops retrying failures that would fail the same way again. The model below shows the feeder as merged leaving a ready task with no feeder to start it.

How.
- **Keep running.** The loop runs until it is stopped (SIGTERM or Ctrl-C). `--until-idle` keeps today's exit for one-off runs. When nothing is under way, passes slow to `--idle-every` (default 300 s).
- **Skip, don't crash.** A pass that can't reach obid (`URLError`, a timeout) or GitHub (`gh` exits non-zero) is skipped with one line in the log, and the next pass tries again. Backoff doubles up to 10 minutes and resets once a pass gets through.
- **Retry passing failures without refusing the head.** A failed `arm` whose words are a passing failure (network, 5xx, 429, "try again") is tried again at the next pass, at most 3 times per head. Only GitHub refusing the head itself (mergeability, a rule) refuses it. The same applies to a model check with no verdict because the VM couldn't be reached: it is retried, and only an invariant that fails or a vacuous witness holds the head.
- **Failover.** `--account any` starts jobs without naming an account, so obid picks the account with the most room and moves jobs at a limit (LIMITS-15). The default stays `deskree-team` until the owner decides otherwise (a question for the owner).

Add the model below as `docs/models/oby_feed_alive.qnt`, unchanged unless the design changes. A00-96 also changes oby-feed: whichever lands second rebases onto the first.

### Formal verification
Quint model `docs/models/oby_feed_alive.qnt` (below), verified with quint 0.33.1 on the gate VM on 2026-11-15:
- **`alive_merged`** (main() and api() as merged): `slotsBounded` holds; `readyNeverOrphaned` is violated. Counterexample: a pass with nothing to do ends the process, then a task file lands and nothing will start it. A pass with obid down ends the process the same way.
- **`alive_fixed`**: `slotsBounded`, `readyNeverOrphaned` and `waitingFollowed` hold in every run of up to 12 steps. Its witnesses `neverStarted` and `neverObidDown` are violated: work starts, and obid goes down and comes back with work done after.

The red proof of the crash, a test below, fails on today's script.

Acceptance (tests in `factory/tests/test_oby_feed.py`, each named after its scenario):
1. FEEDALIVE-1: `api()` against a closed port returns no answer rather than raising, and `one_pass` logs one line and returns.
2. FEEDALIVE-2: the loop doesn't end after an idle pass. With `--until-idle` it does.
3. FEEDALIVE-3: a task file that becomes ready after several idle passes starts at the next pass.
4. FEEDALIVE-4: a `gh pr merge` that fails with a 502 is tried again at the next pass and doesn't refuse the head. One that fails because GitHub refuses the merge does.
5. FEEDALIVE-5: a model check whose ssh to the gate VM fails leaves the head unrefused and is tried again.
6. FEEDALIVE-6: `--account any` sends `POST /v1/jobs` with no `account`. The default still sends `deskree-team`.

### The model
```quint
// verify: main=alive_merged steps=8 invariants=slotsBounded witnesses=readyNeverOrphaned
// verify: main=alive_fixed steps=12 invariants=slotsBounded,readyNeverOrphaned,waitingFollowed witnesses=neverStarted,neverObidDown
//
// The feeder process itself (factory/bin/oby-feed's main loop), unattended: obid may be down for a while (a restart,
// an update), new task files land on dev at any time, and a task may sit `waiting` on the owner (a security path).
// readyNeverOrphaned: while a task is ready to start or waiting to be followed, a feeder is still running to do it.
// waitingFollowed: a waiting task's merge is recorded at the next pass with obid up.
// slotsBounded: never more tasks under way than --max.
// alive_merged: main() as on origin/dev: a pass with nothing under way and nothing started ends the process
//   ("nothing under way and nothing ready: stopping"), and obid unreachable raises URLError out of api(), which
//   nothing catches. Expected: readyNeverOrphaned is VIOLATED (a witness there).
// alive_fixed: the loop runs until it is stopped; a pass that can't reach obid (or GitHub) is skipped and tried at the
//   next one. Expected: all three hold.
// The limit: a model checks the design, not that the script implements it.

module alive_common {
  pure val Max = 2
}

module alive_merged {
  import alive_common.*
  var alive: bool
  var obidUp: bool
  var ready: int       // task files ready to start
  var running: int
  var waitingMerged: bool   // a waiting task whose pull request the owner merged, not yet recorded
  var waiting: bool
  action init = all { alive' = true, obidUp' = true, ready' = 0, running' = 0, waiting' = false, waitingMerged' = false }
  action newTask = all { ready < 3, ready' = ready + 1, alive' = alive, obidUp' = obidUp, running' = running,
                         waiting' = waiting, waitingMerged' = waitingMerged }
  action obidFlips = all { obidUp' = not(obidUp), alive' = alive, ready' = ready, running' = running,
                           waiting' = waiting, waitingMerged' = waitingMerged }
  action taskEnds = {
    nondet w = Set(true, false).oneOf()     // merged, or waits on the owner
    all { running > 0, running' = running - 1, waiting' = (waiting or w), alive' = alive, obidUp' = obidUp, ready' = ready,
          waitingMerged' = waitingMerged }
  }
  action ownerMerges = all { waiting, not(waitingMerged), waitingMerged' = true, waiting' = waiting, alive' = alive,
                             obidUp' = obidUp, ready' = ready, running' = running }
  action pass = {
    val start = if (Max - running < ready) Max - running else ready
    all { alive,
          if (not(obidUp)) all { alive' = false, ready' = ready, running' = running, waiting' = waiting, waitingMerged' = waitingMerged }
          else all { running' = running + start, ready' = ready - start,
                     waiting' = (waiting and not(waitingMerged)), waitingMerged' = false,
                     alive' = (running + start > 0) },
          obidUp' = obidUp }
  }
  action step = any { newTask, obidFlips, taskEnds, ownerMerges, pass }
  val slotsBounded = running <= Max
  val readyNeverOrphaned = (ready > 0 or waiting) implies alive
}

module alive_fixed {
  import alive_common.*
  var alive: bool
  var obidUp: bool
  var ready: int
  var running: int
  var waitingMerged: bool
  var waiting: bool
  var started: int
  var obidWentDown: bool
  var afterUpPass: bool
  action init = all { alive' = true, obidUp' = true, ready' = 0, running' = 0, waiting' = false, waitingMerged' = false,
                      started' = 0, obidWentDown' = false, afterUpPass' = false }
  action newTask = all { ready < 3, ready' = ready + 1, alive' = alive, obidUp' = obidUp, running' = running,
                         waiting' = waiting, waitingMerged' = waitingMerged, started' = started, obidWentDown' = obidWentDown,
                         afterUpPass' = false }
  action obidFlips = all { obidUp' = not(obidUp), obidWentDown' = (obidWentDown or obidUp), alive' = alive, ready' = ready,
                           running' = running, waiting' = waiting, waitingMerged' = waitingMerged, started' = started,
                           afterUpPass' = false }
  action taskEnds = {
    nondet w = Set(true, false).oneOf()
    all { running > 0, running' = running - 1, waiting' = (waiting or w), alive' = alive, obidUp' = obidUp, ready' = ready,
          waitingMerged' = waitingMerged, started' = started, obidWentDown' = obidWentDown, afterUpPass' = false }
  }
  action ownerMerges = all { waiting, not(waitingMerged), waitingMerged' = true, waiting' = waiting, alive' = alive,
                             obidUp' = obidUp, ready' = ready, running' = running, started' = started,
                             obidWentDown' = obidWentDown, afterUpPass' = false }
  action pass = {
    val start = if (Max - running < ready) Max - running else ready
    all { alive, alive' = true, obidUp' = obidUp, obidWentDown' = obidWentDown,
          if (not(obidUp)) all { ready' = ready, running' = running, waiting' = waiting, waitingMerged' = waitingMerged,
                                 started' = started, afterUpPass' = false }
          else all { running' = running + start, ready' = ready - start, started' = started + start,
                     waiting' = (waiting and not(waitingMerged)), waitingMerged' = false, afterUpPass' = true } }
  }
  action step = any { newTask, obidFlips, taskEnds, ownerMerges, pass }
  val slotsBounded = running <= Max
  val readyNeverOrphaned = (ready > 0 or waiting) implies alive
  val waitingFollowed = afterUpPass implies not(waitingMerged)
  val neverStarted = started == 0
  val neverObidDown = not(obidWentDown and started > 0)
}
```
