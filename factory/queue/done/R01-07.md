# feat(obid): read and record each agent CLI's version

<!-- Roadmap R01-07 · Sprint 1 · R01 Safety net · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

The owner and any bug report can say which Claude Code, Codex or cursor-agent version a job ran on. GET /v1/status lists each tool's path and version.

### Status and scope

Proposed (roadmap R01-07, milestone R01 Safety net).

**Why:** obid never reads the CLIs' versions (#1096): main.rs:28 checks only obid's own --version, and codex.rs and acp.rs send obid's version in clientInfo. Failures such as #1867 and #1095 cannot be tied to a CLI version. docs and code depend on specific versions (Claude Code 2.1.296, Codex 0.162, cursor-agent 2026.10.01).

**In:**
- Run `<bin> --version` with the login PATH (accounts::login_path) and a 5 s timeout at start and when the resolved path, size or mtime changes; cache for 60 s on those three
- status.tools: [{agent, path, version}] (add-only)
- agentVersion on the job (add-only key in job.rs) and on the failure record (failures.rs Record)
- One log line per version change

**Out:**
- The tested and known-bad table (R01-09)
- Settings > Accounts showing it (#1097)
- Conversation turn records (R05)

### Actors and ownership: what obid owns

- Reading, caching and storing each tool's version; the agentVersion on jobs and failure records.

### Actors and ownership: what the apps show and send

- Nothing changes for clients yet; the keys are add-only and old apps ignore them.

### Interfaces and dependencies

- GET /v1/status: add tools: [{agent, path, version}]
- Job JSON: add agentVersion (string or null)
- Failure record: add agentVersion

### Steps

- Write the contract file with CLIVERSIONS-1..4.
- In cli_versions.rs: resolve the bin as accounts.rs does (default_bin, accounts.rs:488, and the config's bin), run --version with login_path, parse the first version-looking token, cache by (path, size, mtime) for 60 s.
- Add status.tools in api.rs status(); read off the runtime with spawn_blocking as accounts are.
- Stamp agentVersion on the job when a round starts and copy it into failures::Record.
- Teach the stand-ins (fake-claude, fake-codex, fake-cursor) to answer --version, then write the tests.
- Update docs/runner-api.md 'GET /v1/status' and 'Failure record'.

### Acceptance scenarios

- CLIVERSIONS-1 (proposed): Given claude is on the login PATH, when an app reads GET /v1/status, then tools lists claude with its resolved path and the version its --version printed.
- CLIVERSIONS-2 (proposed): Given a tool whose --version fails or hangs past 5 s, when status is read, then its version is null and status still answers.
- CLIVERSIONS-3 (proposed): Given a job ran a round on codex 0.170.0, when the job file is read, then agentVersion is "0.170.0".
- CLIVERSIONS-4 (proposed): Given the binary at the resolved path changes (new mtime), when the next round starts, then obid reads the version again and logs the change once.

Contract: new: docs/contracts/cli-versions.md (prefix CLIVERSIONS)
