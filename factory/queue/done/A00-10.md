## What
A00-03 (#2192) built the VM's side of the remote gate: `factory/remote/setup.sh` and `factory/remote/oby-remote-gate` on the Azure VM `oby-gate` (resource group `oby-factory`, East US 2, Standard_D32as_v6, 32 vCPUs, SSH host `oby-gate` on this Mac, user `oby`). Nothing calls it yet: every gate still runs the whole check on this Mac, one at a time under the check lock. Measured on #2158: the VM ran the check in 1 min 18 s warm; the Mac took 4 min 35 s after 38 min 20 s waiting for the lock. docs/factory-remote-gate.md and docs/contracts/remote-gate.md ("Still to build") describe the rest.

## Why
Rust gates queue one at a time on the Mac for 45–60 minutes each, and builders' load makes them time out. The VM runs four at once without that queue.

## How
- `factory/bin/gate` runs the Linux part of the check (the groups that don't need macOS: Rust except the macOS-only suites, Electron, the secret scan, the factory group) on the VM through `oby-remote-gate` over SSH, in a free slot, and the macOS-only suites (sandbox, Keychain, own-lane, Swift and iOS) on this Mac, only when the change reaches them. The gate's verdict folds both, and checks.md says where each part ran and how long.
- Start and stop: the gate starts the VM (`az vm start`) when it is deallocated and waits for SSH; the VM deallocates itself after 30 minutes with no gate (a timer on the VM, or the Mac's `job queue` deallocating it — say which and why; the VM has no managed identity today). The daily 05:00 UTC auto-shutdown stays as a safety net.
- Fallback: if the VM can't be reached within 3 minutes, or answers that it couldn't judge for infrastructure reasons, the gate runs the whole check on the Mac as today and says so in checks.md.
- Security (from A00-03's security review): checks on the VM run as a user without `sudo`, separate from the admin user; the remote gate sets the same offline variables the BLOK check sets on the Mac (no network for builds and tests); every argument sent over SSH is quoted, the base and the commit validated first; no secrets, tokens or logins go to the VM; the repository is fetched without credentials.
- Record each gate (Mac or VM, slot, commit, verdict, times) in `~/.oby-flow/pipelines/runs.jsonl`, the file the pipelines viewer reads, and show the VM's state and its four slots in the factory dashboard's header.
- Tests with a fake `ssh` and fake `az`: a VM gate passes and fails with the right verdict; two gates use different slots; an unreachable VM falls back to the Mac; a macOS-only change runs its suites on the Mac; the idle rule deallocates only after 30 idle minutes. Each test fails without the change it covers.
- One real gate on the VM for a real factory job, with its times in the PR body, and the VM deallocated at the end.

`factory/checks.sh` is protected: if the change needs it, put the exact edit in build.md and the PR for the owner, as A00-08 did.
