What. Before `factory/bin/oby-feed` merges a pull request that adds or changes a Quint model, `check_models()` runs each `// verify:` line on the gate VM. A witness passes when `holds or "violation" not in out.lower() and "error" not in out.lower()` is false. Every run on the VM prints a protobuf warning containing the word "error", so in practice any run that doesn't print `[ok] No violation found` counts as a violated witness: a misspelt witness name (`error: [QNT404] Name 'neverMergesByItslf' not found`), a misspelt `main` (`error: module oby_factry does not exist`), Apalache failing to start (`Failed to bind to address 0.0.0.0:8822: Address already in use`), a timeout or a dropped connection.

Why. A witness is what proves a model's pass isn't vacuous. If a typo or a crash passes as "violated", a model that proves nothing merges as if it proved something, which is exactly what the witness rule is there to stop. `factory/bin/prove` already reads the verdict the right way (`[violation] Found an issue`, never the exit code or a stray word).

How. Read each run's verdict with `factory/bin/prove`'s own rule, imported rather than copied (oby-feed already imports `factory/bin/job` the same way): an invariant holds only on `[ok] No violation found` with no `[violation]`; a witness is violated only on `[violation] Found an issue` with no `[ok] No violation found`; anything else is no verdict, and the pull request waits with a note saying which line gave none and the first error line. Run each check against its own Apalache server port (`--server-endpoint`) so two checks on the VM can't collide.

### Formal verification
A red proof, kept as the tests below: on the gate VM (quint 0.33.1, 2026-11-15) `quint verify --main=oby_factory --max-steps=4 --invariant=neverMergesByItslf docs/models/oby_factory.qnt` prints `error: [QNT404] Name 'neverMergesByItslf' not found` and no verdict, and today's `check_models()` takes it as a violated witness. Each test below fails on today's `oby-feed` and passes with the fix.

Acceptance (tests in `factory/tests/test_oby_feed.py`, the ssh call stubbed with recorded Quint output):
1. FEEDMODEL-1: a witness whose run prints `[violation] Found an issue` passes.
2. FEEDMODEL-2: a witness whose run prints `error: [QNT404] Name '…' not found` keeps the pull request waiting, its note naming the line.
3. FEEDMODEL-3: a run that prints Apalache's "Address already in use", or nothing (timeout), keeps it waiting for an invariant and for a witness alike.
4. FEEDMODEL-4: a witness whose run prints `[ok] No violation found` keeps it waiting as vacuous (today's behaviour, kept).
