# test(obid): a byte budget for obid's own prompt text

<!-- Roadmap R13-08 · Sprint 2 · R13 How we work · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

Every byte obid adds to a session's fixed prompt is a reviewed edit: a test fails when ORIENTATION, TETRIX, the oby tools list or a job's first prompt template differs in size from a committed budget, in either direction.

### Status and scope

Proposed (roadmap R13-08, milestone R13 How we work).

**Why:** ORIENTATION in core/crates/obid/src/brain/harness.rs:45 is several KB and grows with each tool (routines, check-ins, merge); `tools/list` in brain/tools.rs:209 sends every tool's schema. Every Claude session and every Codex cold start pays for them, and nothing measures it.

**In:**
- new: core/crates/obid/prompt-budget.txt (one `name bytes` line each).
- A cfg(test) test that renders each text and compares it with the file.

**Out:**
- The agent's own context management.
- Shortening the texts (a later task may lower the budget).

### Actors and ownership: what obid owns

- A committed budget for its fixed prompt text, enforced by a test.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- core/crates/obid/src/brain/harness.rs
- core/crates/obid/src/brain/tools.rs
- new: core/crates/obid/prompt-budget.txt

### Steps

- Find the job's first prompt template (`git grep -n 'fn .*prompt' core/crates/obid/src/job.rs core/crates/obid/src/jobs.rs`) and name it in the budget file.
- Write a test in harness.rs's test module that measures ORIENTATION plus NO_SHELL, TETRIX, `serde_json::to_vec(&tools::list())` and the template with empty inputs.
- Fail on more bytes; fail on fewer bytes with the number to write.
- Commit the current sizes; break one text on purpose and see the test fail.

### Acceptance scenarios

- None: this task changes no product behaviour.
