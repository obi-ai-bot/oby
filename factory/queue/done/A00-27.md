## What

On 2026-11-14 the merge queue landed R02-10 (#2208) and R02-05 (#2203) one after the other. Each was under obid's line limit (`obid_lines_limit` in `scripts/oby-check.sh`) on its own branch. Together they put `dev` at 99,058 production lines against a limit of 99,044. The queue's `Check` passed both, so it doesn't run the line limits on the combined code.

## Why

The merge queue exists to test the code as it will land. A limit the queue doesn't check is enforced only per branch, and any two branches can add up past it. Each later gate then fails on `dev`'s own overrun.

## How

1. Find where GitHub's `Check` (`.github/workflows/`) decides what to run for a `merge_group` event. Make it run the line limits of `scripts/oby-check.sh` (obid's lines, `jobs.rs`'s lines, the tests' sleeps) on the merge group's commit, at least whenever the group changes `core/`. Reuse the script's own counting, don't copy it.
2. Acceptance: a merge group whose combined code is over a limit fails `Check`, and one under it passes. Prove the failing case, for example with a workflow test or by running the step on `dev` at 144ddcd6, which is over.
3. This changes CI files, so the owner merges it.
