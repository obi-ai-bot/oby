A00-34 (#2259) sends builders' macOS-only runs to the Mac worker (`mac_worker`, the owner's second Mac over SSH), where they run as the owner's own user, the same user its gates run as. Its round-2 security review (factory/jobs/090-a00-34-builders-macos-only-runs/round-2/review-security.md) passed it with five notes; fix the ones that matter:

1. A builder run on the worker can rewrite the gates' runner (`~/oby-worker/bin`, `oby-remote-gate`) and their slots, and so steer a later gate result on that Mac. Make the gates' runner and slots on the worker something a builder run can't change, or have each gate verify its runner (for example by a hash setup records) before it runs and refuse a changed one, falling back to this Mac with a reason. Prove it with a test that fails without the fix (fake ssh and local root, as the existing remote tests).
2. List what a builder can still do on the worker in the contract's known limits, including the above if any part stays.
3. docs/contracts/remote-gate.md still has a Scope line calling "sending them to the Mac worker" out of scope: remove it.
4. The builders' clone on the worker loses two Mac-specific git settings when its config is reset before each run: keep them.
5. The command word ending in `\` that breaks fish's quoting on the worker: quote it so fish reads it as bash does, with a test.
