# fix(obid): send a job event only after the job file is saved

<!-- Roadmap R02-01 · Sprint 1 · R02 Commands that are safe to repeat · effort S · risk medium -->

### Sangam's screen

engine only

### Outcome

The apps never show a job state that a restart then rolls back. A failed save is an error the caller sees, not a log line.

### Status and scope

Proposed (roadmap R02-01, milestone R02 Commands that are safe to repeat).

**Why:** Jobs::update_after (jobs.rs:2740) changes the job in memory, then logs `can't keep job` when self.store.save fails, and still sends the `job` event. Jobs::insert (2780), hear_at_work (2199), message_as (4324, 4404) and dismiss (5995) do the same. live.ts sync() has a restart-revision special case for this.

**In:**
- Every `self.store.save(` call in jobs.rs (6 sites).
- Apply the change to a clone, save it, then put it in state and send the event.

**Out:**
- Conversations and inbox (R02-02).
- A typed transition layer (R04).

### Actors and ownership: what obid owns

- The rule: memory and events follow the disk, never lead it.

### Actors and ownership: what the apps show and send

- Nothing changes for clients, but a 500 where a write failed.

### Interfaces and dependencies

- A route whose save failed answers 500 (it answered 2xx before). No new keys.

### Files

- core/crates/obid/src/jobs.rs
- core/crates/obid/src/store.rs
- core/crates/obid/tests/jobs_api.rs
- docs/runner-api.md

### Steps

- Give Store a test hook that makes the next save fail (a read-only jobs folder works without code).
- Change Jobs::update_after to run `change` on a clone of the job, save the clone, and only then replace state.jobs[id] and send the event; return None or an error when the save fails.
- Do the same in Jobs::insert, hear_at_work, the two saves in message_as and dismiss.
- Map the error to 500 in the routes that call them (routes.rs).
- Write HOME-1 and HOME-2 as tests; prove each fails on dev first.

### Acceptance scenarios

- HOME-1 (proposed): Given a job and a store whose write fails, when an action changes the job, then obid sends no `job` event, the job in GET /v1/jobs/{id} keeps its old revision, and the route answers 500 with the reason.
- HOME-2 (proposed): Given a store whose write fails, when POST /v1/jobs makes a job, then no job is in memory or on disk and no event is sent.

Contract: new: docs/contracts/home.md (prefix HOME)
