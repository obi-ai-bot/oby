# fix(obid): conversations and inbox items send an event only after their save

<!-- Roadmap R02-02 · Sprint 1 · R02 Commands that are safe to repeat · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

A conversation turn or an inbox item that the apps show is on disk.

### Status and scope

Proposed (roadmap R02-02, milestone R02 Commands that are safe to repeat).

**Why:** Conversations::write (conversation.rs:586) is followed by `events.send("conversation", …)` at conversation.rs:910, 949, 1202, 1361, 1392 and 1543. Inbox::save (sphere/inbox.rs:1130) returns io::Result that callers may log and ignore.

**In:**
- Each Conversations::write caller and each Inbox::save caller: send the event only on Ok.

**Out:**
- Jobs (R02-01).
- Append-only turns (R05).

### Actors and ownership: what obid owns

- The same rule as R02-01 for conversations and inbox items.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- core/crates/obid/src/conversation.rs
- core/crates/obid/src/sphere/inbox.rs
- core/crates/obid/tests/conversations_api.rs
- core/crates/obid/tests/sphere_api.rs

### Steps

- List every caller of Conversations::write and Inbox::save.
- Make each one change memory and send its event only after Ok.
- Write HOME-3 and HOME-4; prove they fail on dev.

### Acceptance scenarios

- HOME-3 (proposed): Given a conversation folder that cannot be written, when the owner's words arrive by POST /v1/plans, then no `conversation` event is sent and the answer is 500.
- HOME-4 (proposed): Given an inbox folder that cannot be written, when obid makes an inbox item, then no inbox event is sent and the item is not in GET /v1/inbox.

Contract: new: docs/contracts/home.md (prefix HOME)
