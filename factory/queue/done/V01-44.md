## What
- **Finding while fixing PR #2874 (round 5):** the scans that run before something leaves this Mac read the change through `git diff`, which obeys `.gitattributes`. A file marked `-diff` (or `binary`) comes out as `Binary files differ` or an encoded binary patch, so gitleaks never sees its text.
- **Where:** `factory/bin/test-run` (about line 282, the diff it scans and ships to the VM) and `factory/bin/job`'s `reclose_task` scan.
- **Reproduced:** with a known gitleaks fixture secret in a file marked `-diff`, the scan exited 0; with `--text` it exited 1.
- **Harm:** a branch can carry a secret past the "Secret scan" non-negotiable by adding one `.gitattributes` line.

## Why
AGENTS.md, "Non-negotiable": everything that leaves is scanned for secrets first, and nothing goes out unless the scan is clean. A scan that an attribute can blind is not that scan.

## How
- Scan what leaves as text, independent of attributes: for each changed path, read the blob (`git cat-file`) or use `git diff --text --no-ext-diff --no-textconv` for the scan input, while the payload `test-run` applies on the VM stays a byte-exact patch (it may need `--binary` for the payload and `--text` only for the scanned copy).
- Audit every other scan of outgoing content in `factory/` and `core/` (obid's own scan before a push, `scan.rs`'s diff reading) for the same attribute reliance, and list each instance and its verdict in build.md.
- Keep the scan failing closed when it can't read a file.

### Files
- factory/bin/test-run, factory/bin/job (reclose_task), factory/tests (new cases); `core/crates/obid/src/scan.rs` only if the audit finds the same hole there (then say so; it overlaps V01-14).

## Acceptance
1. A test commits a gitleaks fixture secret in a file marked `-diff` in `.gitattributes`: test-run's scan refuses it; the same for `binary` and for `filter=…`/`diff=…` attributes.
2. The same test against the code before the fix passes the secret through (red first).
3. test-run's payload still applies byte-exact on the VM for a real binary file.
4. build.md lists every scan of outgoing content audited and its verdict.
