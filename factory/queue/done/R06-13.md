# fix(electron): Settings rows obid has no value for are kept in main's settings file

<!-- Roadmap R06-13 · Sprint 3 · R06 Events that clients only apply · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/electron/src/renderer/src/SettingsView.tsx (no visual change)

### Outcome

A Settings choice that obid does not keep yet survives a restart, in one file main owns, instead of looking saved and vanishing.

### Status and scope

Proposed (roadmap R06-13, milestone R06 Events that clients only apply).

**Why:** SettingsView.tsx:50 says 'a mock: nothing is saved anywhere'; `useSetting` (SettingsView.tsx:55) keeps rows such as 'login', 'voice.speaks' and 'mac.mode' in memory only. main already keeps one settings file (notify.ts:421 SETTINGS).

**In:**
- `useSetting` reads and writes through one decoded IPC channel to main's settings.json (via R06-04's helper).
- A list of the local rows in docs/contracts/live-state.md, each with the obid issue that will take it over.

**Out:**
- Moving a row into obid: each is obid work with its own issue (AGENTS.md: a local choice is obid work, never hidden).
- Any change to how the rows look.

### Actors and ownership: what obid owns

- Nothing yet; each row's issue moves it to obid later.

### Actors and ownership: what the apps show and send

- The same rows, now kept.

### Files

- apps/electron/src/renderer/src/SettingsView.tsx

### Steps

- Move the settings file helpers out of notify.ts into a small main module; add a get/set channel with a key and a JSON value decoder.
- Point `useSetting` at it; keep the defaults.
- List the local rows and open one issue per row that needs obid.
- Write LIVE-25 and 26; run `npm test`.

### Acceptance scenarios

- LIVE-25 (proposed): Given the owner changes a local Settings row, when the app restarts, then the row shows the changed value.
- LIVE-26 (proposed): Given a value of the wrong type in settings.json, when the row reads it, then it shows its default.
