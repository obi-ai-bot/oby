# docs(github): a Lane field on feature issues and an owner-only `approved` label

<!-- Roadmap R13-10 · Sprint 4 · R13 How we work · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

Each feature issue says whether it is the agent's, the dispatcher's or between owners. An agent starts a feature only when the owner has set `approved`; a request in the agent's lane is answered with the CLI feature that covers it.

### Status and scope

Proposed (roadmap R13-10, milestone R13 How we work).

**Why:** 'Dispatcher, not harness' (2026-11-05) asks this test before any obid state, endpoint, tool or model call, but feature.yml has no field for it and no label marks approval. Features were built and then cut within days (map: 'Built then deleted', docs/trim.md).

**In:**
- A required `lane` dropdown (agent, dispatcher, between-owners) in .github/ISSUE_TEMPLATE/feature.yml.
- One AGENTS.md sentence: no feature work without `approved`.
- plan-feature skill step 1 checks both.

**Out:**
- Creating the labels: the owner creates `approved` and the lane labels (a repository setting).
- bug.yml.

### Actors and ownership: what obid owns

- Nothing changes in obid.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- .github/ISSUE_TEMPLATE/feature.yml
- AGENTS.md
- .claude/skills/plan-feature/SKILL.md

### Steps

- Add the `lane` dropdown after `screen` in feature.yml, with the three definitions from AGENTS.md as its description.
- Ask the owner to create the labels `approved`, `lane:agent`, `lane:dispatcher`, `lane:between-owners`.
- Add the AGENTS.md sentence under 'How we work'.
- Make plan-feature stop when `approved` is missing or the lane is `agent`.

### Acceptance scenarios

- None: this task changes no product behaviour.

Contract: none

### Done when

- A new feature issue form requires the lane.
- The owner created the labels and approved the PR.
