## What
`factory/bin/mutants` runs cargo-mutants through `factory/bin/test-run`, which sends a run whose tests are macOS-only to the Mac worker (`oby-remote-gate --mac --run`). `factory/remote/setup.sh` installs cargo-mutants for the gate VM at its pin (`mutants=27.1.0`), but `factory/remote/setup-mac.sh` never installs it. So every mutation run that went to the Mac worker ended with `error: no such command: mutants` and no result (A00-86 round 3 and A00-59 round 2, 2026-11-16). It was installed on the Mac worker by hand on 2026-11-16; a new or rebuilt worker wouldn't have it.

## Why
Mutation results go to the code reviewer and the approver, and they were missing for every job with macOS-only tests. The owner, 2026-11-16: "add it to setup-mac.sh so it sticks".

## How
- `setup-mac.sh` installs cargo-mutants into `~/.cargo/bin` at the same pin as `setup.sh`, and leaves it alone when the installed version already matches. Running it again changes nothing.
- The pin is written once, in one place both scripts read, never copied.
- Its tool check prints `cargo mutants --version` with the other tools' versions.

Acceptance:
- On a Mac worker without cargo-mutants, `setup-mac.sh` installs the pinned version; run again, it installs nothing.
- A worker with another version gets the pinned one.
- `setup.sh` and `setup-mac.sh` read the pin from the same place.
- A factory test covers the install-or-skip decision with no network.
