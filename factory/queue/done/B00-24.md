## What
The other part of B00-22 its intake left out. Oby reviews each pull request twice, with one generic prompt. The Claude Code factory routes reviewers by risk and surface (`factory/bin/route`, the `routing` section of `factory/config.json`): code, security, proofs, ux and ui, each a different lens with its own model. Any CHANGES sends the builder a fix round with the findings, up to `max_rounds`.

## Why
A proofs lens caught three vacuous models on 2026-11-15, one hiding a security hole. A generic review missed them. The owner wants Oby's factory at the Claude Code factory's quality.

## How
For each task, the feeder starts one review job per routed lens, using `factory/bin/route`'s rules and the lens's prompt from `.claude/agents/reviewer-<lens>.md`, with the lens's model and account from config. Any CHANGES sends the build a follow-up quoting that lens's findings. All PASS lets B00-22's approver decide. The bridge in the factory's home (`carry-reviews.py`) is then no longer needed. Two approvals of the exact head by different tools stay required.

Acceptance:
- A task routed `security` and `proofs` gets both reviews, each with its own lens and model.
- A CHANGES from any lens starts a fix round quoting its findings, up to the cap. After the cap, the task waits for the owner.
- Tests use a stand-in obid.
