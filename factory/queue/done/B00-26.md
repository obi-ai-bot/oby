## What
AGENTS.md's "Dispatcher, not harness" says Oby dispatches agents and never rebuilds them. Reading, editing, running commands, a turn's own retries and its context stay in the agent CLIs (Claude Code, Codex, Cursor and others). obid owns which agent, account and worktree, start, stop and resume, a job's state, asking the owner and showing what was done, and what passes between owners. Today nothing in either factory checks a task against that rule. The only guard was a count of obid's lines, which B00-25 removes.

## Why
The owner, 2026-11-16: "What we should have instead is ways for us to confirm we are not trying to be a harness and take stuff that Claude Code, Codex and Cursor and many others already do since we are an Orchestrator/Dispatcher or whatever else you want to call it Control Plane like T3Code for example."

## How
- **Intake** (`.claude/agents/intake.md`) writes a `LANE:` line for every task, `dispatcher`, `between-owners` or `agent`, with one sentence why. A task whose work is the agent's is REJECT, naming what the CLIs already do. A mixed task is rescoped to its dispatcher part.
- **The spec** (`.claude/agents/spec-writer.md`) gets a `## Not a harness` section for any task that adds state, an endpoint, a tool or a model call to obid. For each one it says what Claude Code, Codex and Cursor already do there, how a control plane such as T3 Code handles it, and why Oby still needs it.
- **The code review** (`.claude/agents/reviewer-code.md`) reads that section and the lane against the diff. New obid code that does an agent's work (reads or edits files for it, runs its commands, retries its turns, builds its context, or calls a model where a rule would decide) is VERDICT: CHANGES, naming what the CLI already does.
- **The approver** (`.claude/agents/approver.md`) checks that the merged change stays in its lane.
- **The scripts** hold it: `factory/bin/job advance <id> spec` refuses an intake with no `LANE:` line, and so does Oby's feeder before it starts a spec.
- **The pull request template** (`.github/PULL_REQUEST_TEMPLATE.md`) gets a "Dispatcher, not harness" section: the lane, and for new obid state, endpoints, tools or model calls, what the CLIs already do.
- Both factories read `.claude/agents/` as `dev` has it, so Oby's own factory gets the same checks.

Acceptance:
- `factory/bin/job advance <id> spec` refuses a job whose `intake.md` has no `LANE:` line, and accepts one that has it. Oby's feeder does the same before a spec job.
- intake.md, spec-writer.md, reviewer-code.md and approver.md each state their part of the check.
- The pull request template has the new section.
- Factory tests cover the refusal and the acceptance, with no network.
