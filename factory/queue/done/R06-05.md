# feat(electron): gate optional actions on obid's capabilities

<!-- Roadmap R06-05 · Sprint 3 · R06 Events that clients only apply · effort S · risk low -->

### Sangam's screen

uses an existing screen: apps/electron/src/renderer/src/Composer.tsx (no visual change)

### Outcome

With an older obid, the Mac app shows no action that obid would refuse; with a current one, nothing changes.

### Status and scope

Proposed (roadmap R06-05, milestone R06 Events that clients only apply).

**Why:** The app tests features one by one (`status.folders` in live.ts:127 and :505, folders.ts:6; the limit-decisions catch at live.ts:668). An install.sh obid that main accepts as 'mine' (main/obid.ts:98) can be older than the app.

**In:**
- `capabilities?: string[]` on Status in apps/electron/src/shared/obid-wire.ts and one `has(status, name)` in src/shared.
- `folders-v1` with a fallback to the `folders` boolean when `capabilities` is missing (an obid before R06-01).
- Each existing per-feature check moved to `has`.

**Out:**
- Hiding controls that have no capability yet: each new obid feature adds its name and its gate in its own pull request.
- The iPhone app.

### Actors and ownership: what obid owns

- The list (R06-01).

### Actors and ownership: what the apps show and send

- The same controls as today; only an older obid hides what it cannot serve.

### Steps

- Add the key and `has` with the boolean fallback table (`folders-v1` ← `folders`).
- Replace `status?.folders` (3 places) with `has`.
- Add CAPS-4 and CAPS-5 to folders.test.ts; prove CAPS-4 red by ignoring the list.
- Run `npm run typecheck` and `npm test`.

### Acceptance scenarios

- CAPS-4 (proposed): Given an obid whose status has `capabilities` without `folders-v1`, when the owner opens a new conversation, then the app sends no `folders` and keeps the conversation's folders locally, as with an obid that has no folders today.
- CAPS-5 (proposed): Given an obid whose status has no `capabilities` key and `folders: true`, when the app reads it, then folders work as today.

Contract: docs/contracts/capabilities.md (prefix CAPS, after R06-01)
