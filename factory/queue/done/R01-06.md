# test(obid): a shrink-only sleep count, and wait-for-state in the flaky tests

<!-- Roadmap R01-06 · Sprint 1 · R01 Safety net · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

The tests that fail under load stop blocking merges, and no new test waits on elapsed time.

### Status and scope

Proposed (roadmap R01-06, milestone R01 Safety net).

**Why:** obid's tests call thread::sleep or time::sleep 203 times (jobs_api.rs 25, merge_api.rs 24, rooms.rs 22). Wall-clock tests fail under load: #1804 ('first thinking event came after 851 ms'), #1656 merging_5, #1975 bypass_3. tests/support/mod.rs:670 already has within(seconds, what, probe), a poll-until helper.

**In:**
- A count of sleep calls under core/crates/obid/tests in scripts/oby-check.sh, shrink-only like jobs_rs_limit
- Convert the tests named in #1804 and #1656 to support::within or follow_events with a generous deadline
- Look at #1975 and convert it if its timeout is a fixed wait

**Out:**
- Converting every other sleep (later PRs lower the count)
- A clippy disallowed-methods rule (clippy.toml would also flag production code in src)

### Steps

- Add tests_sleep_limit=<count> next to jobs_rs_limit in scripts/oby-check.sh with the same shrink-only logic, counted by grep over core/crates/obid/tests.
- Add pass and fail cases for it to scripts/oby-check-test.sh, beside the obid_lines_limit cases.
- Convert the tests of #1804 and #1656 to support::within; remove wall-clock asserts that only measure speed.
- Run each converted test 20 times under load (for example with stress or with all binaries in parallel) and paste the result.
- Lower tests_sleep_limit to the new count.
