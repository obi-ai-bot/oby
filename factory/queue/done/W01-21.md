## What
Fill in fills nothing on `dev`. `fillSecret` (`apps/electron/src/main/device.ts`, about line 201; verify) posts the value to obid's `POST /v1/browser/tabs/{id}/secret`, which answers `410 retired` (`core/crates/obid/src/browser/routes.rs`; W01-08 keeps it retired, BROWSER-30). Since W01-09 it posts no take first, so the strip's "Codex waits" isn't true either.

The plan's W4 (`docs/plans/browser-t3.md`, "The password never reaches obid") has main type the value into the tab's own webview. Commit `1262567f` (branch `claude/browser-w4-fill`, not on `dev`) built it: `git show 1262567f -- apps/electron/src/main`. It must be reworked, not cherry-picked (`reports/w01/readers/browser-window.md`, "(2) W4 without W3" and "Corrections"):

- **D1**: board 6's hold is obid's (W01-08). Fill in holds the tab for the fill, as `dev` did before #2816. `git show 56f3d0f0:apps/electron/src/main/device.ts`, `fillSecret`: read `heldBy` from `GET /v1/browser`; take the tab, signed, if this device doesn't hold it; fill; answer the ask; give back only the hold it took. So "Codex waits" is true while the card fills.
- **D2(a)**: Fill in happens in a fresh document, `FILL_PREP = 'reload'` as `1262567f` built it, and no agent script runs on the filled page until its main frame navigates.
- **W01-20**: obid marks the agent's own script `agentCode: true` on its relay `cdp`. So `NO_SCRIPT` refuses only that, never obid's own `page_info`, `wait_for` or `on_node` reads.
- **W01-02** (#2843) is on `dev`: `METHODS` already refuses `DOMSnapshot.*`, `Page.addScriptToEvaluateOnNewDocument`, `Runtime.compileScript` and `Runtime.runScript`. `1262567f`'s bookkeeping for those (`added`, `Page.removeScriptToEvaluateOnNewDocument`, the `DOMAINS` edit) goes.
- **The brief's security note** (section 11, from W01-09's review): "When `…/secret` comes back in obid, it must refuse a fill from a device that doesn't hold the tab." `…/secret` doesn't come back: the value never goes to obid. The same guard is kept where the fill now happens. Main types only after obid's take answer (or `GET /v1/browser`) says this device holds the tab. A take refused (`held_by_other`, another device holds it) fills nothing.

## Why
A sign-in is where an agent's work stops for the owner. On `dev` the owner types the password into the card, presses Fill in, and nothing reaches the page. The password must reach the page's field and nowhere else: not obid, not the agent, not a log (non-negotiable: vault secrets and the owner's secrets never reach an agent).

## How
Read `git show 1262567f` in full first, then port it onto `dev` with these changes:

1. **`device.ts` `fillSecret`**, the shape of `56f3d0f0`'s with `…/secret` replaced by main's typing:
   - the click checks as now;
   - `GET /v1/browser`, the tab's `heldBy`;
   - if not this device's, `POST …/take` `{}`, signed as now (`signedHeader`). A refusal returns obid's words, and nothing is typed. A 2xx whose `heldBy` isn't this device types nothing either;
   - type through the webviews' host (`typeInPages`, as `1262567f`);
   - on success, `POST …/asks/{id}/answer` `{}`, signed;
   - then, if it took the tab, `POST …/giveBack` `{}`, signed, whatever the fill did.
   No request carries the value.
2. **`browserGuest.ts`**: `1262567f`'s `type(tabId, field, value)`, `FILL_PREP = 'reload'`, `reloaded`, `focusField`, `FIELD_LENGTH`, and the guest's `passwords()` and `isPassword()`. Drop the `Page.removeScriptToEvaluateOnNewDocument` loop: obid can't add such scripts since W01-02. Before typing, the guest gets the keyboard, as T3 does: `wc.focus()` (pingdotgg/t3code@304cf149:apps/desktop/src/preview/Manager.ts:2482). If `Input.insertText` didn't land, the guest's own `insertText` (T3: apps/desktop/src/preview/GuestInput.ts:199-200).
3. **`browserRelay.ts`**:
   - `relayCommand` takes `agentCode` on `cdp` only as `true` or absent. Any other value makes the command `null`. `RelayCommand`'s `cdp` gains `agentCode?: true`.
   - `run` gets it.
   - `NO_SCRIPT` refuses, while Fill in works on a tab and after it until the main frame navigates (`Page.frameNavigated` with no `parentId`), only:
     - a `Runtime.evaluate` marked `agentCode`;
     - a `Runtime.callFunctionOn` whose `objectId` is a password input (`isPassword`).
   - Keep `1262567f`'s reply and event scan: `NOT_PASSED` for any relayed reply or event that carries a value main filled, or the value a password field on the page holds now, in any of `forms()`.
   - `fillStarts`, `fillEnds`, `filled`, and `forget` clearing them all.
   - `METHODS` doesn't change (BROWSERAPP-27 to 29).
4. **`browser.ts`**: `hostBrowser` hands `webviews.type` to `typeInPages`, as `1262567f`.
5. **`shared/obid-wire.ts`**: `browserTabPath`'s verbs become `'take' | 'giveBack'`. `'secret'` goes.
6. **Tests**:
