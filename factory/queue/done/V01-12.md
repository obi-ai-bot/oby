## What
- **Property 1 (one signature per input, WORDS-7):** in any sequence of the owner's inputs and signing attempts, at non-decreasing times:
  - each successful `takeInput(at)` uses one Enter or click `input(t)` saw with `at - t < WITHIN_MS` (2,000 ms), and no input is used twice;
  - so the number of signatures main makes on the owner's input is never more than the inputs it saw, and none is made `WITHIN_MS` or more after its input;
  - a Space (`space`) is used only by a pressed Confirm (`mayConfirm` with an action in `PRESSED`), never by words, and the same rule holds for it.
- **Property 2 (only the app's shapes and chosen folders, WORDS-1, WORDS-8, WORDS-18):** `wordsHeader` gives a header only when `wordsOf` takes the request and every folder the words carry, or every folder of the project main read for them, was chosen in main's own dialog this run (`picked`). Any other method, path, extra key, key of the wrong kind or unchosen folder gives `null`.
- **Property 3 (the again rule, WORDS-16):** through `ownersWords`, a signature made with no new input is only the very same keyed request (method, path and body byte for byte) that main signed on an input and obid didn't answer (status 0), while `takesKeys()` is true, within `AGAIN_MS` (10 s) of the first signature and at most `AGAIN` (2) times.
- **Harm:** a script that took the page gets the owner's words signed for requests the owner never made (docs/contracts/signed-words.md; AGENTS.md, "Approvals": the accepted risk is one request of its choosing per real input, no more).
- **Code it covers:**
  - `apps/electron/src/main/words.ts`: `input` (about line 41), `takeInput` (about line 44), `space` and `takeSpace` (about lines 52 and 55), `mayConfirm` and `PRESSED` (about lines 65 and 66), `wordsHeader` (about line 10), `picked` and `ownFolders` (about lines 30 and 32).
  - `apps/electron/src/shared/words.ts`: `wordsOf` (about line 104), `WITHIN_MS` (about line 217).
  - `apps/electron/src/main/device.ts`: `ownersWords` (about line 175) with `AGAIN_MS`, `AGAIN` and `KEPT` (about line 154), and `notificationWords` (about line 138) read only: it signs with no window input by design (WORDS-15), on main's own notification callback, never over IPC.
  - The plan names `takeInput` in `shared/words.ts`; it lives in `main/words.ts` (stale name in the plan). `shared/words.ts` holds `wordsOf`, `owners` and `WITHIN_MS`.
- **Left to tests, and the skill says so:**
  - The ECDSA signature itself (`signedHeader`, node's `sign`): library code (reports/v01/verification-plan.md, section 5).
  - Where main's inputs come from: `before-input-event` (Enter, Space) and `input-event` (mouseDown) in `src/main/index.ts` (about lines 223 to 227). The test calls `input` and `space` as those handlers do.
  - The preload's `owners` (which held text the words are), covered by `WORDS-2` and `WORDS-3` in words.test.ts.

## Why
`words.test.ts`'s `WORDS-7` checks one hand-picked sequence of five inputs. The rule is a race between the page's script and the owner's real input, and a broken window (a filter that keeps an input, a `shift` that doesn't happen) shows only in sequences nobody writes by hand. It is rank 9 in reports/v01/verification-plan.md.

## How
- **Tool:** a generated-input vitest on the real functions, in a new file `apps/electron/src/renderer/src/test/words.property.test.ts`, beside `words.test.ts`, importing as it does (`../../../shared/words`, `../../../main/words`; `../../../main/device` with device.test.ts's `vi.mock('electron')` and `vi.mock('../../../main/obid')` for property 3).
  - A seeded generator in plain vitest, no new dependency: a small PRNG (mulberry32 or the like) with the seed from `OBY_SEED` or a fixed default, printed in every failure message; 2,000 sequences for property 1, 2,000 requests for property 2, 300 sequences for property 3. The owner allowed fast-check as a dev-only dependency, but these generators are sequences of a few event kinds and a shape mutator, and shrinking adds little; if the reviewers want it, it comes with `package.json` and the lockfile in its own commit.
  - Each generated case carries its expected answer from how it was built (which input a take may use, which mutation makes a shape wrong), so the test never re-implements `takeInput` or `wordsOf`.
- **Module state.** `main/words.ts` keeps `inputs`, `spaces` and `chosen` at module level, and `device.ts` keeps `unanswered`. Each case starts at a time at least `WITHIN_MS` past the previous case's last, drains with `takeInput` and `mayConfirm` as words.test.ts's `drain` does, and uses folder names of its own (the case's seed in them), since `chosen` only grows. For property 3, each case uses its own request key; `vi.resetModules` per case is the fallback if that proves leaky, and the pull request says which.
- **Property 1, the space:** sequences of 1 to 12 steps over `input(at)`, `space(at)`, `takeInput(at)`, `mayConfirm(item, clicked, at)` (an item from `PRESSED` or another action, `clicked` either way), with gaps drawn from {0, 1, 500, 1,999, 2,000, 2,001, 5,000} ms, so the window's edge is hit on both sides. The oracle is a list of unused inputs and spaces with their times.
  - One family also steps the clock back once by up to 5 s (`Date.now()` can). There the claim checked is only "no input used twice"; the window may stretch, and the skill says so.
- **Property 2, the space:** start from each request shape words.test.ts signs today (`WORDS-1`, `words_14`, `words_17`, `words_18`, `words_21` to `words_24`, `COMPUTERSAPP-6` and `-11`, the browser hold and answer), then apply one mutation each: another method; the path with a `?query`, a trailing `/`, a `..` segment or another id shape; one extra key; one key of another kind (number, array, object, `null`); a folder not picked, or a project whose folders main read include one not picked, or no project folders read (`undefined`). Expected: the unmutated shape signs when its folders are picked, and every mutation but the `?query` (which `wordsOf` strips by design: `path.split('?')[0]`) gives `null`.
- **Property 3, the space:** sequences of `ownersWords` calls on `POST /v1/jobs/j1/messages` with or without `clientRequestId`, `owners` either way, `input` or not before each, obid answering 200 or status 0 (device.test.ts's `the.lost`), `takesKeys` true or false, and times across 10 s. Expected from the oracle: each signed call either used an input, or is a byte-for-byte resend of a request signed on an input that got status 0, within 10 s, its again-count at most 2.
- **Measured:** the whole file runs in under 60 seconds in `npx vitest run src/renderer/src/test/words.property.test.ts`, or the pull request names its time and the counts above are kept.
