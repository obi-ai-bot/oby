Contract: docs/contracts/permissions.md (Plan: "Plans first, and works once you approve the plan", Sangam's words; PERMISSIONS-5).

What. In Plan mode, Claude Code ends its plan with `ExitPlanMode`, which obid turns into the owner's plan card (`Permission::is_plan`, permissions.rs); the owner's Approve lets the same job go on and do the work, and a no sends it back to planning. Cursor's plan waits for the owner too (acp.rs). Codex has no such step: in Plan obid declines every file change and tells it "End with your plan as your summary" (codex.rs, `Options::plan`), so a Codex Plan job ends `done` with its plan as text, no card, and nothing more happens. The owner has to read the summary and start a follow-up by hand.

Why. Plan is the mode the owner picks to see a plan before any change; on Codex it silently becomes "write a plan and stop", which breaks the promise on the mode's own menu and makes Codex the odd one out (the social contract: vendor agnostic).

How. When a Codex turn in a Plan job ends and its last message is the plan (the turn changed no file), obid puts the same plan card on the job that `ExitPlanMode` makes, with the plan as its text, and the job waits on it instead of ending. Approve resumes the same Codex thread out of Plan, in the mode the job had before Plan (Accept edits when it had none), told to carry out the plan it wrote; a no with the owner's words resumes it in Plan with those words. Only the owner answers it, never the brain, a rule or a mode change (as for `is_plan`). A Codex job that ends in Plan with an error ends as it does today.

### Formal verification
A Quint model (below), to be added as `docs/models/oby_plan_approval.qnt`. Verified with quint 0.33.1 on the gate VM on 2026-11-15: `plan_today` (Codex's path as built) holds `noEditBeforeYes` and violates `planReachesOwner` (counterexample: a Codex job finishes its plan and ends `done` with the plan unanswered). `plan_fixed` holds `noEditBeforeYes`, `planReachesOwner` and `yesStartsWork` in every run of up to 10 steps, and violates its witness `neverApproved`. A Kani harness over the pure decision "this Codex turn's end is a plan to show the owner": true only in Plan with no file changed and a non-empty last message.

Acceptance (PERMISSIONS scenarios, each a test named after it, against the fake Codex app-server the Codex tests already use):
1. A Codex job in Plan whose turn ends with a plan waits on a plan card holding that text; its status is not `done`.
2. Approve resumes the same thread out of Plan and the file change it then asks for goes ahead (Accept edits).
3. A no with words resumes it in Plan with those words; its file changes are still declined.
4. The brain, a saved rule or a mode change never answers that card.

### The model
```quint
// verify: main=plan_today steps=8 invariants=noEditBeforeYes witnesses=planReachesOwner
// verify: main=plan_fixed steps=10 invariants=noEditBeforeYes,planReachesOwner,yesStartsWork witnesses=neverApproved
//
// Plan mode across tools (docs/contracts/permissions.md, Plan: "Plans first, and works once you approve the plan",
// Sangam's words). Claude Code ends its plan with ExitPlanMode, which obid turns into the owner's plan card
// (permissions.rs `is_plan`); Codex in Plan has every file change declined and is told to "End with your plan as
// your summary" (codex.rs), so its job ends `done` with the plan as text and no card; Cursor's plan waits (acp.rs).
// noEditBeforeYes: no file changes before the owner's yes to the plan.
// planReachesOwner: a Plan job whose agent finished planning is waiting on the owner's plan card, or the owner
//   answered it: it never ends `done` with the plan unanswered.
// yesStartsWork: after the owner's yes, the job goes on to do the work (it is running or did it).
// plan_today: Codex's path as built. Expected: planReachesOwner is VIOLATED (witness there).
// plan_fixed: every tool's finished plan becomes the same plan card; a yes resumes the same job out of Plan.
// The limit: a model checks the design, not that obid implements it.

module plan_common {
  pure val Tools = Set("claude", "codex", "cursor")
}

module plan_today {
  import plan_common.*
  var tool: str
  var st: str          // planning, card, working, done
  var planned: bool    // the agent finished its plan
  var answered: str    // none, yes, no
  var edits: int
  action init = { nondet t = Tools.oneOf() all { tool' = t, st' = "planning", planned' = false, answered' = "none", edits' = 0 } }
  // the agent tries an edit while planning: declined (all tools)
  action tryEdit = all { st == "planning", edits' = edits, st' = st, tool' = tool, planned' = planned, answered' = answered }
  action finishPlan = all { st == "planning", planned' = true, tool' = tool, answered' = answered, edits' = edits,
                            st' = if (tool == "codex") "done" else "card" }
  action answer = {
    nondet a = Set("yes", "no").oneOf()
    all { st == "card", answered' = a, st' = if (a == "yes") "working" else "planning", planned' = a == "yes",
          tool' = tool, edits' = edits }
  }
  action work = all { st == "working", edits' = edits + 1, st' = "done", tool' = tool, planned' = planned, answered' = answered }
  action step = any { tryEdit, finishPlan, answer, work }
  val noEditBeforeYes = edits > 0 implies answered == "yes"
  val planReachesOwner = (planned and answered == "none") implies st == "card"
}

module plan_fixed {
  import plan_common.*
  var tool: str
  var st: str
  var planned: bool
  var answered: str
  var edits: int
  action init = { nondet t = Tools.oneOf() all { tool' = t, st' = "planning", planned' = false, answered' = "none", edits' = 0 } }
  action tryEdit = all { st == "planning", edits' = edits, st' = st, tool' = tool, planned' = planned, answered' = answered }
  // Codex's last message in Plan is its plan: obid holds the job on the same plan card Claude's ExitPlanMode makes
  action finishPlan = all { st == "planning", planned' = true, tool' = tool, answered' = answered, edits' = edits, st' = "card" }
  action answer = {
    nondet a = Set("yes", "no").oneOf()
    all { st == "card", answered' = a, st' = if (a == "yes") "working" else "planning", planned' = a == "yes",
          tool' = tool, edits' = edits }
  }
  action work = all { st == "working", edits' = edits + 1, st' = "done", tool' = tool, planned' = planned, answered' = answered }
  action step = any { tryEdit, finishPlan, answer, work }
  val noEditBeforeYes = edits > 0 implies answered == "yes"
  val planReachesOwner = (planned and answered == "none") implies st == "card"
  val yesStartsWork = answered == "yes" implies st.in(Set("working", "done"))
  val neverApproved = answered != "yes"
}
```
