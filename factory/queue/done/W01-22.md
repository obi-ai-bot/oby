## What
Board 12's shelf has two kinds of row: the agent's download, kept in its browser until Save a copy, and the owner's own, already in Downloads. On `dev` (verify each before relying on it):

- **The agent's works.** obid sends `Page.setDownloadBehavior {allow, <home>/browser/downloads/<job>}` when it opens a tab (`window/page.rs`, `enable`). Main's `will-download` (`apps/electron/src/main/browserGuest.ts`, `prepare`) saves each download of that webview there. After an `oby_browser_act`, obid looks at the folder for 5 s (`browser/tools.rs`, `watch_downloads`) and lists what's new, `startedBy: agent`, `place: profile`. The shelf draws the agent's row (`Panel.tsx` `FileRow`), and Save a copy works (BROWSER-13).
- **The owner's isn't.** When the owner clicks a download link in an agent's tab, main saves it into the agent's folder too, since every download of that webview goes there. obid lists it only if an agent act's 5 s watch happens to see it, and then as the agent's. Otherwise it is never listed, and it never reaches the owner's Downloads. obid's own rule says the opposite ("one the person starts is delivered", `docs/contracts/browser.md`, Rules, Downloads). Its delivery code is already there and unused since the window's browser: `download_rule` (`engine/download_fate.rs`) gives `Actor::Person` `Deliver`, and `watch_downloads` copies a delivered file into `downloads_to` (the person's Downloads, `service.rs`, `open`) and removes the profile's.
- The window already draws the owner's row from obid's `download` event: `live.ts` maps `startedBy: person` to "You downloaded it · in Downloads", and `place: delivered` to Show in Finder by its name. No window change is needed.

T3 Code tells the two apart in one way, `humanStartedDownload` (verify each line):
- A download is the person's when no agent input reached that tab in the last 5 s: pingdotgg/t3code@304cf149:apps/desktop/src/preview/DesktopBrowserHost.ts:658-661, `AGENT_INPUT_WINDOW_MS = 5_000` at :29.
- Agent input is a relayed command matching `AGENT_INPUT_COMMAND` (:25-26): `Input.*`, `Page.navigate`, `Runtime.evaluate`, `Runtime.callFunctionOn`, stamped at :654.
- It is decided at `will-download`, before the file is placed (apps/desktop/src/preview/Manager.ts:4051-4066). The page's `Page.downloadWillBegin` names the download (DesktopBrowserHost.ts:545-548). A person's download is copied into Downloads once `done` is `completed`, with T3's `stem (n).ext` naming (Manager.ts:4019-4040). obid's `free_name` (`window/downloads.rs`) already names it that way.

In Oby, obid sends every relayed command, so obid stamps them: the same rule, at the relay's other end.

## Why
Board 12 promises the owner that what they download is theirs, in Downloads, and what the agent downloads stays apart until they choose. On `dev` the owner's own download sits in the agent's folder and nowhere else, or is shown as the agent's.

## How
obid only. Main and the page change nothing.

1. **The stamp** (`browser/relay.rs`): each `RelayTab` keeps when obid last sent it agent input (a `tokio::time::Instant`, so tests can pause time).
   - Stamped by `cdp` for T3's methods (`Input.*`, `Page.navigate`, `Runtime.evaluate`, `Runtime.callFunctionOn`), plus `Page.reload` and `Page.navigateToHistoryEntry`, which obid sends as acts too.
   - Also stamped by `expect`: a tab obid opens loads its first page from the window's `src`, with no command, and that load is the agent's.
   - `pub fn person_started(&self, tab) -> bool` is true only when the tab is known, shown (`shown`, unknown counting as shown, as now), and its last stamp is 5 s or more ago (`AGENT_INPUT_WINDOW`, T3's constant, credited).
   - Also an accessor for a tab's job, if `relay.rs` has none.
2. **The decision** (`browser/service.rs`, `wire`): one task follows `relay.page_events()`.
   - On `Page.downloadWillBegin` it decides by `person_started(tab)` at that moment, and keeps the `guid`s it decided were the person's, in memory.
   - On `Page.downloadProgress` with `state: "completed"` for one of those `guid`s, it forgets the guid and calls `watch_downloads(job, Some(tab), Actor::Person(…))`. Use the tab's holder if it is held, else a fixed id for the window's own click. `watch_downloads` delivers it (`download_rule`), so the `download` event says `person` and `delivered`.
   - `canceled` forgets the guid.
   - A download decided as the agent's is left as today, to the act's watch.
3. **Ceilings**, each marked `ponytail:` in the code and named under the contract's Open:
   - A page script the agent set on a timer, firing 5 s or more after its last command on a shown tab, passes for the owner's. Its download lands in the owner's Downloads, as in T3.
   - An agent's download that an `oby_browser_navigate` starts, or that takes longer than the act's 5 s watch, stays unlisted, as on `dev`.
   - The owner's own ways out that go through obid (signed `…/reload`, `…/back`) count as agent input: such a download stays in the profile, the safe side.
4. **Docs.**
   - `docs/contracts/browser.md`: add **BROWSER-34** and **BROWSER-35** (Acceptance below), implemented, naming their tests, and the Open ceilings. BROWSER-13 stays as it is.
   - `docs/api/browser.md`'s downloads paragraph: a download the person starts in the window's page is listed `startedBy: person`, `place: delivered`, by T3's 5 s rule, and its name is the one in their Downloads. No new key: add-only holds.
   - Classify BROWSER-34 and 35 in `tools/obid-spec/scope.json`'s `browser.md` block only.
