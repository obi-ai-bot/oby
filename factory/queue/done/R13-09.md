# docs(github): a pull request template with surfaces and failure modes

<!-- Roadmap R13-09 · Sprint 2 · R13 How we work · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

Every PR opened by hand or by an agent with `gh pr create` says its issue and scenarios, why it is the smallest useful change, which surfaces it touches, which checks ran, and which failure modes its tests cover.

### Status and scope

Proposed (roadmap R13-09, milestone R13 How we work).

**Why:** .github/ has no PULL_REQUEST_TEMPLATE.md. PRs do not say whether they touch the iPhone's decoding, docs/runner-api.md or stored state, and 'Report the checks you actually ran' is a prose rule in AGENTS.md.

**In:**
- new: .github/PULL_REQUEST_TEMPLATE.md: issue and scenarios; what and why; surfaces (obid, Electron, iPhone/Watch, API docs, contracts, stored job and config files, the check); checks run with output; failure modes, one line each with its test; security path yes or no (MERGING-15).

**Out:**
- The body obid writes for PRs its jobs publish (obid's own code; a later task).

### Actors and ownership: what obid owns

- Nothing changes in obid.

### Actors and ownership: what the apps show and send

- Nothing changes for clients.

### Files

- new: .github/PULL_REQUEST_TEMPLATE.md

### Steps

- Write the template in Oby's words, short headings, each with one hint line.
- Fill it for one recent merged PR as an example in the PR body.
- Ask the owner to approve.

### Acceptance scenarios

- None: this task changes no product behaviour.

Contract: none

### Done when

- `gh pr create` on a branch shows the template.
- The owner approved the PR.
