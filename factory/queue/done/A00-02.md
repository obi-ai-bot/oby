## Why

Five are high, and two of the undici ones touch TLS validation and cross-origin redirects. Even where the risk is low (dev-only tooling, a loopback-only tool), open alerts hide new ones, and the roadmap's safety net (R01) is about machines holding the rules.

## How

- Raise each package to at least its patched version with the project's own package manager (`pnpm` in cloud/control-plane, `npm` in tools/brain and apps/electron), preferring the direct dependency's update over an override. Where a package is only transitive, update the parent that pulls it in; use `overrides` (npm) or `pnpm.overrides` only when no parent release carries the fix, and say so in the PR.
- deepmerge has no patched release: find which package pulls it into tools/brain, and either drop that path, replace it, or leave it and record why in the PR (with the alert number). Don't dismiss any alert on GitHub; the owner does that.
- Change only lockfiles and package.json files, plus code a breaking update forces. No new dependency.
- Run each project's own checks after its update: `pnpm test` and `pnpm check` in cloud/control-plane (the factory's check has no cloud/ group; paste the output in build.md); `npm test` and `npx vitest run` in tools/brain plus `npm run generate`; and factory/checks.sh, which runs Electron's typecheck, tests and build.

## Done when

- `npm ls <pkg>` / `pnpm why <pkg>` in each project shows only patched versions for every package above (deepmerge excepted, with its reason in the PR).
- The PR lists each alert number with the version it moved to.
- All three projects' checks pass, and factory/checks.sh passes.
