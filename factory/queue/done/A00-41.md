The owner's word (2026-11-14): "Phase A now: Quint + mutants (Recommended)", on adding verification layers beyond Kani. This is layer L2, from the Formal Verification session's plan; A00-40 is layer L1 (Quint).

Why: mutation testing changes the code one small way at a time (> to >=, || to &&, return a default) and reruns the tests; a change no test notices is a "missed mutant", a test gap. It measures test strength for all code, async included, which Kani cannot reach. The session's spike on tetrix-open-source (cargo-mutants 27.1.0): 365 mutants tested, 278 caught, 75 missed; 48 of the missed sat inside #[cfg(kani)] harnesses (noise), about 27 were real gaps in shipping code (e.g. no test feeds a wrong separator or hour 24 to the RFC 3339 parser).

What:
1. factory/remote/setup.sh installs cargo-mutants (pinned, e.g. 27.1.0) for the gate VM's builder user, root-owned like Kani (A00-35), and prints its version.
2. factory/bin/test-run sends a run starting with `cargo mutants` to the VM's builder slots.
3. A new script factory/bin/mutants <job-id>, run after the gate passes on every job that changes Rust (no intake surface needed), alongside or right after prove: `cargo mutants --in-diff <the job's diff against its merge base> -p <touched crates>` with the package's full test set, a time budget (config, default 20 minutes), `-j` sized to the slot, one build dir per job. It excludes code under #[cfg(kani)] and #[cfg(test)], and lists functions a Kani proof covers apart (a mutant there may be caught by the proof, not a test).
4. It writes round-N/mutants.md: first line `MUTANTS: <caught> caught, <missed> missed, <timeout> timeout, <unviable> unviable` (or SKIPPED for a job with no Rust change, TIMEOUT when the budget ran out, with what was tested), then each missed mutant as `file:line: <the change> (no test notices)`.
5. Advisory only: it never blocks or sends a job back. reviewer-code reads mutants.md and may raise a missed mutant in shipping code as a finding (a test the job should add); the approver notes the MUTANTS line in decision.md. Blocking only on the owner's word.
6. .claude/skills/factory/SKILL.md runs the step; .claude/agents/reviewer-code.md and approver.md read its file.

Tests: factory tests with a stand-in cargo-mutants (no real host), each rule failing without its code (exclusions, budget timeout, skip with no Rust change, the file's shape). One real run on a small obid diff on the VM recorded in build.md, with its VM time.

Cost to report: VM time per job. factory/config.json is protected: the orchestrator adds the budget setting by hand on the owner's word. .claude/ files are security paths: the owner merges.
