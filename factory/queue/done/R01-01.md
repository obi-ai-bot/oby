# chore(ci): linux.yml stops runs nobody reads: a nightly full run on dev instead of every push

<!-- Roadmap R01-01 · Sprint 1 · R01 Safety net · effort S · risk low · rewritten 2026-11-13 by docs/ci-architecture.md -->

### Sangam's screen

engine only

### Outcome

GitHub Actions is on (the owner turned it on, 2026-11-13). The existing Linux workflow keeps running on ready pull requests, stops running on every push to dev and main (nobody reads those runs: the factory merges before they start), and runs everything once a night on dev and on demand, saving the Rust caches only then. GitHub's minutes for this repository fall by about half before any new infrastructure (docs/ci-architecture.md, "Rollout order" step 1).

### Status and scope

Proposed (roadmap R01-01, rewritten by docs/ci-architecture.md). The intake's three questions (factory/jobs/001-…/intake.md) are answered here: Actions is on; a red test that isn't the runner's goes in this pull request's body by name and log, for the owner to file; AGENTS.md is not touched (its CI remarks are the owner's own pull request).

**Why:** today every ready pull request and every push to dev runs the whole suite (≈19 billed minutes a run), but `factory/bin/job merge` marks a pull request ready and merges it at once, with no branch protection on dev, so no run can stop a merge. The pull-request runs also save Rust caches under `refs/pull/<n>/merge`, which no other pull request can read (464 MB from #2154 alone), churning the repository's 10 GB.

**In:**
- `.github/workflows/linux.yml`: drop the `push` trigger; add `schedule` (nightly, 03:17 UTC) and `workflow_dispatch`, both on dev, which run every job whatever the draft state
- `Swatinem/rust-cache` and the pnpm caches save only on `schedule` and `workflow_dispatch` (`save-if`); every other run only restores
- One nightly run on dev; each red test that isn't about the runner listed by name and log in the pull request's body (today's: clippy `struct Started is never constructed`, seen on #2154's run)
- docs/ci.md rewritten: what GitHub runs (ready pull requests, nightly on dev) and what the Mac runs; it links docs/ci-architecture.md for where this is going
- docs/contracts/ci.md: CI-1 and CI-2 as below

**Out:**
- The new workflow, lanes, shards and Check (R01-02)
- The merge queue and branch protection (R01-03)
- Fixing red tests: each is its own pull request
- AGENTS.md's remarks that Actions doesn't run here (the owner's own change)

### Steps

- Replace `push: branches: [dev, main]` with `schedule: - cron: '17 3 * * *'` and `workflow_dispatch:`; make every job's `if:` also true for those two events.
- Add `save-if: ${{ github.event_name == 'schedule' || github.event_name == 'workflow_dispatch' }}` to each rust-cache step; for setup-node's pnpm cache, which has no save switch, leave it (it is small) and say so in docs/ci.md.
- Run the workflow once by `workflow_dispatch` on the branch, then once on dev after merge; link both.
- Rewrite docs/ci.md and add CI-1, CI-2 to docs/contracts/ci.md.

### Acceptance scenarios

- CI-1 (proposed): Given a ready pull request into dev, when it is opened or pushed, then the Linux workflow runs its jobs on that head with no person starting it; given a draft, its jobs are skipped.
- CI-2 (proposed): Given a push to dev, when it lands, then no Linux workflow run starts; given the nightly schedule or a `workflow_dispatch` on dev, then every job runs to the end and only that run saves caches.

Contract: docs/contracts/ci.md (prefix CI)
