A00-31 (#2243) sends a builder's heavy Rust run to the gate VM, but only when the change touches no macOS-only file by the gate's rule (`MACOS_ONLY` in factory/bin/gate, or a file naming `target_os = "macos"`). About 21 of obid's 126 source files name `target_os = "macos"`, and they are the ones most tasks touch: jobs.rs, jobs/*, conversation.rs, config.rs, accounts.rs, github.rs, push.rs, review.rs, main.rs and others, plus job.rs, codex.rs and agent.rs from the list. So most obid builders still run on this Mac, one at a time under test-run's lock, while the Mac worker (`mac_worker`, the MacBook Pro over SSH, which already runs gates' macOS parts in two slots: REMOTE-13 to 18) sits idle between gates.

Send a builder's macOS-only heavy run to the Mac worker the way A00-31 sends Linux runs to the VM: the worktree's tree (tracked plus non-ignored new files, secret-scanned, never anything gitignored), run in a builder slot of its own on the Mac worker (not a gate's slot, so a gate never waits for a builder), output streamed back, the exit code returned, and the same fallback to this Mac's lock when the worker can't be reached, isn't set up, or every builder slot is busy past a timeout. A run that needs this Mac itself (anything reading this Mac's Keychain or the owner's real home) stays here. The number of Mac-worker builder slots comes from `mac_worker` in factory/config.json (default 0, so nothing changes until it's set). Extend factory/remote/setup-mac.sh for the builder's folders. Tests with a fake ssh and local root, as A00-31's, each failing without its change, and the contract scenarios in docs/contracts/remote-gate.md.
