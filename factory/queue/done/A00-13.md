## What
`scripts/oby-check-test.sh` (the check's own test, run when the check's files change) expects macOS's plan. On Linux it plans the sandbox test binary in its "nested" case and fails, so on the Azure gate VM any change to `scripts/oby-check.sh`, `scripts/oby-check-test.sh` or `tools/oby-check-blok/**` fails its gate for the machine, not the change: A00-09's VM gate on 2026-11-13 ended "oby-check: failed: bash scripts/oby-check-test.sh" / "oby-check-test: nested, it planned a sandbox test binary", while the same commit's tool tests passed. `factory/bin/gate`'s `macos_only()` (A00-10, #2193) doesn't count these files.

## Why
Every change to the check would fail its VM gate and cost a round, and the failure reads as the change's fault.

## How
- In `factory/bin/gate`, count `scripts/oby-check.sh`, `scripts/oby-check-test.sh` and `tools/oby-check-blok/**` as macOS-only, so a change to them runs its rust group (and the check's own tests) on the Mac, as before the VM.
- A test in `factory/tests/test_gate_remote.py`: a change touching `scripts/oby-check-test.sh` runs rust on the Mac; it fails without the change.
- Don't change `scripts/oby-check-test.sh` itself in this task.
