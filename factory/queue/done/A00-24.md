## What

On 2026-11-14, `apps/electron/src/test/alerts.test.ts` › ALERTS-2 (`alerts_2_what_the_mac_said_under_its_own_keys_is_no_news`) failed once on the gate VM for A00-17, a branch that doesn't touch the code under test. It didn't fail in 8 isolated runs, 2 full suites or 12 concurrent runs on the Mac.

A00-17's builder suspects the cause: each `launch()` in the test helper `macAlerts.ts` loads a fresh copy of `src/main/notify.ts`, but never stops the old copies' timers. An old copy's 2-second timer could post a banner into a later test. On the slow gate host, the failing test started about 2.0 s after the test that would have left such a timer. This is a guess, not proven.

## Why

A test that fails at random on branches that don't touch it costs a gate round each time, and teaches everyone to rerun instead of reading the failure.

## How

1. Reproduce it first, for example by slowing the suite down or running the two tests back to back with the timer's delay shortened, and show the stray banner. If it doesn't reproduce, report the evidence and stop.
2. Make each test's notify copy stop its timers when the test ends, or give each launch a clean module state. Change the test helpers, not `notify.ts`'s behaviour, unless the leak is in the product code.
3. Acceptance: a test that leaves a timer running, followed by ALERTS-2, fails on today's code and passes with the fix. The Electron suite passes.
