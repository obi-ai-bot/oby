## What
The card's top (`art-thumb` in `artifacts/Card.tsx`) draws three grey blocks: board 1a's stand-in for a picture. `Card.tsx`'s own comment says the card has "its first screen on top". The owner asked, 2026-11-21: "show the preview of the artifacts instead of that placeholder there". So the card shows a small picture of the artifact's latest version as its preview draws it, and the grey blocks stay only until that picture is ready, or when it can't be taken.

The board's box doesn't change: `art-thumb` stays 104 px high, the card's width and padding stay. Only what's inside it changes. Sangam sees it at the Monday review. His board drew a stand-in, not a choice against a picture.

## Why
The owner finds what an agent made by looking. Three grey blocks look the same for every artifact: a chart, a page and a document can't be told apart until each is opened.

## How
Read from the code on `dev` after W01-11 merges (verify each before relying on it). The preview is drawn in main by `main/artifactPreview.ts`: its own `WebContentsView` in the `oby-artifact-preview` partition (in memory, every request but its host page and the Sandpack relay cancelled, no permission, no window, no download, no navigation), filled by `shownAs` with the version's files read from obid with main's token.

1. **The picture is taken there, never in the window's page.** Add a second view in the same partition, with the same `webPreferences`, the same locked session and the same relay. It is never shown (`setVisible(false)`, or offscreen). One picture at a time, queued:
   - `readVersion` the version;
   - `shownAs` it into that view at 1280x370 (the card's 360x104 ratio);
   - wait for the preview to draw. Use the signal `preview.html` already gives when Sandpack is done if there is one; else a fixed wait, at most 4 seconds, marked `ponytail:`;
   - `capturePage()`, `resize({ width: 720 })` (2x the card), `toPNG()`;
   - send the page a `data:image/png;base64,…` URL.

   The page gets pixels only: no file, no HTML, no script of the artifact.
2. **A channel for it**: `artifact-thumb`, `{ id, version }` to `{ src } | { none: true }`, through `ipc(trusted)` as `artifact-preview` is, its argument checked as `previewAsk` is (a string id that looks like obid's, a whole version ≥ 1). Kept in main's memory per `<id>/<version>`, at most 50 entries, oldest dropped. Nothing goes to disk or to obid. An error, a read that fails or a capture over 10 seconds answers `{ none: true }`, and that version isn't asked again while the window runs.
3. **The card** (`Card.tsx`): ask for the latest version's picture once it is on screen (an `IntersectionObserver`, or simply on mount: the thread already caps what it renders). When `src` comes, draw `<img className="art-thumb-img" src={src} alt="" />` filling `art-thumb` (`object-fit: cover; object-position: top left`, the board's 6 px radius), in place of the grey blocks. Until then, and on `none`, the grey blocks, exactly as now. A new version asks again. The card's button, words and click don't change.
4. **The window's CSP** must allow `img-src data:` for the window's page. Check `vite.config.ts`; if it already does, change nothing there.
5. **The mock** (`npm run web`): `artifact-thumb` answers `{ none: true }`, so the demo keeps the board's blocks.
6. **The contract** (`docs/contracts/artifacts-app.md`): under "The card", say the top is a picture of the latest version, taken in the preview's own locked view, the grey blocks until then or when it can't be taken. Add ARTIFACTSAPP-18 under Implemented.
