# refactor(obid): one MCP JSON-RPC core for the three agent servers

<!-- Roadmap R11-02 · Sprint 8 · R11 Connections: MCP, sign-in and the vault · effort S · risk low -->

### Sangam's screen

engine only

### Outcome

initialize, ping, notifications, unknown-method errors, the protocol version list and result redaction are written once and used by the conversation's tools, the job broker and Tetrix's proxy. Fewer lines, no drift.

### Status and scope

Proposed (roadmap R11-02, milestone R11 Connections: MCP, sign-in and the vault).

**Why:** Three hand-written handlers answer MCP: Connections::handle (connections.rs, MCP_VERSIONS:27, error -32601 'Oby's broker doesn't answer'), brain/tools.rs (VERSIONS:24, handshake:203, plain:215, -32601 'Oby's tools don't answer') and Tetrix::handle (tetrix.rs:1178, hello:1707, unknown:1716). Two version lists and three error texts already differ.

**In:**
- new: core/crates/obid/src/mcp.rs with versions, `hello(params, name, instructions)`, `ping`, `unknown(id, method, server)`, `ok(id, result)`, `refused(id, code, text)` and the scrub now in Connections::clean.
- Use it from the three handlers; delete their copies.

**Out:**
- Tool lists and gates (R11-03).
- Upstream (client-side) MCP calls in connections.rs (send_mcp, upstream_rpc): unchanged.

### Actors and ownership: what obid owns

- The MCP protocol shape for every agent-facing server.

### Actors and ownership: what the apps show and send

### Steps

- Diff the three initialize answers, error codes and texts; write the one shape in agent-mcp.md first.
- Add mcp.rs; move MCP_VERSIONS there (pub(crate)); keep each server's name and instructions as arguments.
- Switch Connections::handle, brain::tools::{handshake, plain, handle} and Tetrix::handle to it; delete VERSIONS, hello, unknown and the duplicate scrub.
- Add the three tests; run the existing tetrix_api.rs, conversation_harness.rs and runner_api.rs suites unchanged.
- Add a test that greps src/ for a second protocol-version list.

### Acceptance scenarios

- AGENTMCP-1 (proposed): Given any of obid's agent MCP servers (a conversation's, a job's broker, Tetrix's), when an agent sends initialize with a protocolVersion obid knows, then it answers that version; with one it doesn't know, then it answers obid's newest.
- AGENTMCP-2 (proposed): Given any of the three servers, when an agent sends a method obid doesn't serve, then it answers JSON-RPC error -32601 naming the method cut to 64 characters, the same shape on all three.
- AGENTMCP-3 (proposed): Given a vault secret in a tool result, when any of the three servers answers, then the secret is replaced by its [vault: <name>] marker in strings and keys.

Contract: new: docs/contracts/agent-mcp.md (prefix AGENTMCP)
