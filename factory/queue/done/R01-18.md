# test(obid): admission_5 orders its jobs by state, not by how long their checks sleep

<!-- Roadmap R01-18 · Sprint 2 · R01 Safety net · effort S · risk low · new 2026-11-13 from R01-13's flaky list -->

### Sangam's screen

engine only

### Outcome

An admission test stops failing when the Mac is busy, and comes off the flaky list.

### Status and scope

Proposed (new, R01-13's flaky list).

**Why:** `runner_api` `admission_5_a_job_back_from_the_check_queue_never_passes_max_running` is on the flaky list in `core/.config/nextest.toml` (R01-13). Its jobs' real checks run `sleep 15`, `sleep 3` and `sleep 60` (runner_api.rs:627-633), and the order it expects (the first check ends and frees its slot while the second waits, then the fifth runs and the third checks) rests on those durations against fixed `within` deadlines of 30 to 90 seconds. Under load the order slips.

Evidence (factory job logs on the factory's Mac, `factory/jobs/`):
- It failed in R01-08's run of the planned test binaries, a change that didn't touch admission, and failed the same way on a clean `origin/dev` checkout (f3ad6e17) under the same load (job 020, build.md).

**In:**
- Let the test end each check when it chooses (a check that waits for a file the test writes, say), so the order is the test's, not the clock's.
- Remove its entry from `core/.config/nextest.toml` in the same pull request.

**Out:**
- Any change to obid's admission code.
