## How
### obid (COMPUTERS-29; add-only)
1. `COMPUTER_ROUTES` gains the browser's routes the window calls, each named with its board. Every one of these is the window's own browser, there:
   - `GET /v1/browser` (2);
   - `GET /v1/browser/events` (2);
   - `GET /v1/browser/relay` and `POST /v1/browser/relay` (2);
   - `POST /v1/browser/tabs/*/take` and `…/giveBack` (6);
   - `POST /v1/browser/tabs/*/close` (2);
   - `POST /v1/browser/asks/*/answer` (7);
   - `GET /v1/browser/downloads` and `POST /v1/browser/downloads/*/saveCopy` (12);
   - `GET /v1/browser/settings` and `PUT /v1/browser/settings` (Settings › General).

   `allows_computer` reads `COMPUTER_ROUTES` with `allows`' own segment matcher; don't write a second one. `…/secret` stays off: it is retired (W01-21). `POST /v1/browser/mcp` stays off: it is the agents'. The owner's signed acts count there by COMPUTERS-15.
2. `forward.rs` streams `GET /v1/browser/events` and `GET /v1/browser/relay` as it streams `/v1/events`: no whole-answer limit, ended once the window is on another computer or the Mac forgot it.

### Main
3. **Partitions.** While another computer is in use (`openedComputer()`), each agent partition its obid names, `persist:oby-agent-<agent>`, opens in main's own `persist:oby-agent-<agent>-on-<computer id>`, the id being obid's 16 hex characters. devbox's sign-ins are kept apart from this Mac's and from another computer's, as T3 gives each environment its own partition. `PARTITION` (`browserRelay.ts`) takes that shape only for the computer in use. `will-attach-webview` checks it as now.
4. **Routing.** That session gets its proxy before any request goes, as a box partition's does (BROWSERAPP-36's hold):
   - Every request waits until main has set the proxy to the computer's door. The door comes from `POST /v1/computers/{id}/door` with `here`, since it is this Mac's route.
   - The bypass is T3's, `*,<-loopback>,169.254.0.0/16,fe80::/10`, so only loopback goes to the door.
   - `0.0.0.0` and `[::]` are redirected to `localhost`, and a WebSocket to them is cancelled.
   - Then `closeAllConnections()`.
   - The door's login is answered only for its host and port, as `browserGuest.ts` answers a box door's (about line 238).
   - With no door within 10 s, or none given, every request is cancelled. It is never this Mac's `localhost`.
5. **Relay commands.** On another computer, a relay `box` command is refused. Its door is the other computer's loopback, and the box is off. A tab whose partition is `oby-box-*` isn't opened.
6. **Switching back.** When the window switches back to This Mac, or to another computer, the old computer's webviews go, as any tab does when obid's list no longer has it. Their partition stays for its next visit, and its proxy stays set (T3's "off stays routed").

### The page
7. `live.ts` takes a tab's computer from the computer in use (the computers store's name for `openedComputer`), not from the tab's `computer`. Board 14's words then show on obid exactly as on the demo: the strip, "on devbox" in the address, "New tab on devbox".
