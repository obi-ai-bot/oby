# Browser: a browser of each job's own, served by obid to every agent, the person in control

The business behavior contract for Oby's browser in obid: the engine that drives it, the API the app reads and the person acts through, and the tools every agent is given, from [the template](../business-contract-template.md). Proven first in the Blok lab (`tools/obid-spec/src/lab/browser.rs`, `browserapi.rs`, `browsersphere.rs`, `browser_contract.rs`; #2593, #2599, #2601, #2602), then ported. Its screens are the app's (`apps/electron`), from the approved design (https://claude.ai/artifact/Cs7t741EJKCD7JXNfzSRXb); the lab's are `tools/obid-spec/lab-ui/browser` (#2600).

## Feature and status

- **Outcome:** An agent can open, read and drive web pages in a browser of its job's own, while the person watches it live, takes control whenever they want, types a password the agent never sees, and keeps what the agent downloads apart from their own files. What a page says reaches the agent as quoted outside data, never as instructions. Another Oby's task gets a browser only inside Oby's box.
- **Status:** **Partly implemented.** obid serves the browser's API, its events and the agents' MCP server (`core/crates/obid/src/browser/`); each scenario says whether it's implemented, and an implemented one names its tests. Since the window's browser ([docs/plans/browser-t3.md](../plans/browser-t3.md)), every agent tab is a `<webview>` in Oby's window, driven by obid over the window's relay in page-level CDP; obid runs no browser of its own, and the scenarios for what the window does now are retired. Still proposed: giving a conversation's agent the server, and a browser for foreign jobs (BROWSER-18 to 22: obid's side is built, and no foreign job gets a browser until the window's side of the box's edge lands). Each scenario says `(proposed)` until its test passes against the real obid. The owner's decisions behind it: [the browser](../decisions/2026-11-19-the-browser.md), [how it reaches a Mac and where it runs](../decisions/2026-11-20-browser-install-and-limits.md) (its install and limits superseded by the window's browser), and the window's browser itself ([docs/plans/browser-t3.md](../plans/browser-t3.md), which supersedes [its earlier engine, chrome-headless-shell](../decisions/2026-11-20-headless-shell.md)).
- **Scope:** obid's `browser` module: agent-browser driven per job, the person's hold, refs, deadlines, outside data, downloads, the live stream, the API under `/v1/browser`, its events, the agents' MCP server, its gates (settings, lanes, the box's edge, the secret scan on what goes back through the Sphere). Outside it: the app's screens and words (Sangam's design; the next session's port), desktop control (agent-desktop, a contract of its own), another computer's browser (Remote computers, after the launch), and anything agent-browser itself does inside a page.

## Behavior

### Actors and ownership

- **obid** owns every agent tab's state, the event log, asks, downloads, each tab's partition, and the gates on every tool, and drives each tab's page for its agent over the window's relay in page-level CDP. It runs no browser of its own. Rules decide; no model call of obid's does.
- **Agents** (Claude Code, Codex, Cursor; own lane and foreign) call `oby_browser_*` tools on obid's MCP server with their job's broker token.
- **Oby's window** (the Electron app's main process, [docs/plans/browser-t3.md](../plans/browser-t3.md)) mounts a `<webview>` for every agent tab in the partition obid names, relays CDP between its debugger and obid (`GET` and `POST /v1/browser/relay`, obid's token), and lets the person use the page as any page: taking control is clicking it, and Fill in is typed by the window into the webview, so a password never reaches obid.
- **The owner's apps** read `GET /v1/browser` and its events with obid's token, and act (answer an ask, Reload, Back, a dialog's answer, save a copy, change the settings) with the device's signed words (`X-Oby-Words`, [signed-words.md](signed-words.md)).
- **No browser of obid's.** obid downloads, installs and runs no Chrome or agent-browser (the owner's "NO FALLBACK REMOVE CHROME ENTIRELY"; this supersedes [the headless-shell decision](../decisions/2026-11-20-headless-shell.md)). With no window, an agent's page tool is refused `no_window`. A headless Chrome runs only in obid-spec's stand-in for the window, as test tooling.

### Rules

- **On by default.** "Agents can use the browser" and "Agents can use the Mac" are on until the owner turns them off in Settings › General (`PUT /v1/browser/settings`, signed) ([why](../decisions/2026-11-19-the-browser.md)). With the first off, every tool refuses `browser_off`.
- **A tab of the job's own, in its partition.** Each agent tab is a webview of the window's, in `persist:oby-agent-<agent>` for the owner's own job (sign-ins kept for that agent's next job) or `oby-box-<job>` for another Oby's, an `untrusted` job or Oby's own review (not kept). A job sees and acts on only its own tabs (`not_your_tab`). A new tab waits up to 10 s for the window to attach it.
- **Page level only.** obid's CDP is the page's (Page, Runtime, DOM, Accessibility, Input, Emulation), never `Target`, `Browser` or a session id; downloads go only into `<home>/browser/downloads/<job>/`. The window refuses anything else.
- **The person's ways out of a page state** (board 10): Try again and Reload (`POST …/reload`), Go back (`…/back`) and the page's own dialog answered, Leave or Stay (`…/dialog`), each signed by one of the owner's devices (no hold: the page is theirs to use), each said to the page in CDP and answering the tab as it is after; none is an agent's tool. A reload that still shows the browser's error page is refused `browser` and the tab stays failed; a dialog answer with no dialog on the tab is refused `no_dialog`.
- **The certificate page is the person's.** On a tab whose navigation stopped at a certificate problem (`net::ERR_CERT_*`), or whose page is the browser's own error page (`chrome-error://`, as obid knows it or as read right before the call runs), every agent tool that acts on the page or runs code in it (act, evaluate, dialog) is refused `certificate_page`, before any ref is looked at. Reads (snapshot, screenshot, wait_for, list_tabs, which says `certificatePage`), navigating elsewhere and closing the tab still work; a page of the web loading lifts it. Going on past a certificate (Go on anyway) is the window's to build on its webview; the owner decided that only the person's signed click trusts that host and that exact certificate, that a different certificate is still refused, and that the agent can never proceed itself.
- **Stale refs.** A ref dies on navigation, a new snapshot or a handover; obid checks the URL right before each act that names one (`stale_ref`).
- **Deadlines.** Every command has one (15 s by default, `deadlineMs`); a command past it answers `timed_out` and is never replayed; its tab settles first, refusing calls (`settling`) rather than queueing them.
- **Outside data.** Page words, titles, dialogs, snapshots and `evaluate`'s value reach the agent only under `outside` with `marksTurnUntrusted`; reading them marks the turn as having read something untrusted ([why](../decisions/2026-11-19-the-browser.md)).
- **Passwords** go from the owner's device through `POST …/secret` straight into the page's field. The value is in no answer, event, log line or file obid writes, and the agent never gets it ([why](../decisions/2026-11-19-the-browser.md)).
- **Downloads.** An agent's download stays in its profile; Save a copy (signed) copies it to the person's Downloads and leaves the agent's; one the person starts is delivered ([why](../decisions/2026-11-19-the-browser.md)).
- **The live stream** sends the newest frame only: a slow reader drops frames, never queues them.
- **Events.** Every change is one event with a `seq`; `GET /v1/browser` and `GET /v1/browser/downloads` carry the last `seq` they reflect, so a reader never takes a list older than an event it applied. A reader reconnecting with `Last-Event-ID` gets what it missed while obid holds it (2000 events).
- **Every agent, both lanes.** Every job of the owner's own is given obid's browser server, whatever its tool, account or lane, while the first switch is on; a foreign job is given none yet (the foreign lane, below). Every other outside MCP tool stays refused ([permissions](permissions.md), `policy::fixed_denial_as`).
- **The foreign lane.** A job's origin comes from obid's own records (the incoming exchange whose `job` is this job), never from what a request says. Another Oby's task, one marked `untrusted` and Oby's own review, and a follow-up of any of them (read back along the jobs it follows up), get no browser yet; a job is read from obid's records on every browser call, so one found foreign after its first call is foreign from its next, in its box's partition, and never goes back. obid gives them no browser server, and every browser tool their agent calls with its broker token is refused `browser_off` ("Finish without a browser"), until the window's side of the box's edge lands (`browser::box_edge::FOREIGN_BROWSER`, off) ([why](../decisions/2026-11-19-the-browser.md)). Built in obid for then: their tabs' partition `oby-box-<job>`, apart from every agent's; `browsers[].origin`; and open and navigate refused `outside_box` for anything but `http` and `https` (never `file:` or browser-internal pages) and for obid's and the gateway's ports on loopback. The window renders pages on the owner's Mac and network, outside the box's egress proxy, and obid's edge reads only the address open and navigate are given, so the window's task must close, before the switch turns on:
  - each foreign page's host held to the job's own egress decisions (another Oby's task reaches only what its box reaches; an `untrusted` job's sites follow its rules and the owner's card; Oby's review reaches none that would ask);
  - private, LAN and link-local hosts (`169.254.169.254`) and every loopback port refused, with names resolved first (a public name for 127.0.0.1), the gateway at any address it binds and the `direct` HTTPS listeners' ports included;
  - script (`oby_browser_evaluate`, `location`, `fetch`), clicks (`oby_browser_act`), redirects and every navigation a page starts held to the same rules;
  - a job whose code is someone else's (`Job::foreign`: a received review, a teammate's Mac, another person's pull request) read as foreign, which obid doesn't yet tell apart from an own job's page read, which sets the same mark.
- **Asks** go to the host's own devices only; another owner's device can't take a tab or answer one.
- **What goes back** through the Sphere passes the secret scan first; a finding, or a scanner that can't run, sends nothing with text ("Non-negotiable").

### Failures and recovery

- No window following the relay: an agent's page tool is refused `no_window` at once, and nothing runs anywhere else (BROWSER-31).
- The window's relay drops: every call waiting on it fails `no_window`, its tabs are detached, and a window that follows again gets only new commands.
- A job that ends: its token dies, its tabs are released in the window and leave the list.
- obid restarting: no tab survives a restart.

## Interfaces and dependencies

- **API:** [docs/api/browser.md](../api/browser.md). Every path is the lab contract's (`browser_contract.rs`), add-only from there on.
- **The agents' server:** `POST /v1/browser/mcp` with the job's broker token; the server is named `browser`, its tools `oby_browser_*`, permission rules `mcp__browser__<tool>`.
- **Events:** the browser's own stream, `GET /v1/browser/events`; nothing new on `/v1/events`.
- **Persistence:** none across restarts but the two settings (obid's settings file) and each job's downloads folder until the job is cleaned up; the window keeps each agent's persistent partition.
- **External:** none of obid's: the page is the window's webview (Electron's).
