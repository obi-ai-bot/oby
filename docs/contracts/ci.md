# CI: what GitHub runs, and the check guards obid's API

The business behavior contract for what GitHub's `CI` workflow runs and what the check itself guards, from [the template](../business-contract-template.md). Roadmap milestone R01 (Safety net); CI-1 and CI-2 are task R01-01, CI-3 to 6 and CI-17 to 20 are task R01-02, CI-9 to 11 are task R01-05, CI-22 to 25 are task R01-12.

## Feature and status

- **Outcome:** GitHub spends minutes only on runs someone reads: a ready pull request gets the secret scan, fmt and clippy, the merge queue and a `full-ci` pull request test what their change reaches, and `dev` is tested in full once a night and on demand, never on every push. One job, `Check`, says whether each run passed (docs/ci.md, "What GitHub runs"). obid's API stays add-only (AGENTS.md, "How we work"): the iPhone, the Apple Watch, the Electron app and oby-mcp keep working after obid changes. Removing a route that a client still calls fails the check, as does a client call to a path obid doesn't serve and a gateway allowlist entry with no route, instead of showing up as a `404` on someone's phone.
- **Status:** `.github/workflows/ci.yml` replaced `.github/workflows/linux.yml` (R01-02). CI-5 and CI-6 are **implemented**, shown by runs of `ci.yml` on its own pull request. CI-1, CI-2, CI-3, CI-4, CI-17, CI-18, CI-19 and CI-20 are **proposed** until the run each names below shows them on `ci.yml`; CI-1's and CI-2's runs of `linux.yml` stay as history. CI-9 to 11 are **implemented**: one test binary, `core/crates/obid/tests/routes_guard.rs`, with the committed lists `docs/api/routes.txt` and `docs/api/dead-client-calls.txt`. The gateway's dead entries it found were deleted with it; nothing else in obid changed, and no client changed. CI-22 to 25 are **proposed**: `factory/bin/job` does what they describe (R01-12), and none of the runs that prove them has run yet.
- **Scope:** For CI-1 to 6 and CI-17 to 20, the triggers, modes, lanes, jobs, shards, `Check` and cache saving of `.github/workflows/ci.yml`, and `core/.config/nextest.toml`'s `ci` profile (R01-02). Out of scope there: the merge queue, its ruleset and making `Check` required (R01-03), and the quarantine list (R01-13). For CI-9 to 11, the paths of obid's routes, of the clients' calls and of the gateway's allowlist. Out of scope: request and response keys, enum values and frozen client decoders (R07); matching a client call by its HTTP method; paths built only by concatenation past a literal prefix; the iPhone and Watch app targets (`apps/ios`, `apps/watch`), the Electron app's tests and mock, `mcp/tests` and `cloud/`; removing the dead client calls themselves (each is a task of its own). For CI-22 to 25, `factory/bin/job` and the factory's pull requests: when one is a draft, how an approved one is handed to GitHub, and how `job queue` reads a queued one (R01-12). Out of scope there: the merge queue's settings (R01-03) and the nightly Mac run (R01-14).

## Behavior

### Actors and ownership

- **The check** (`scripts/oby-check.sh`) runs the route guard when a change reaches what it reads (below). No model call is involved, and nothing changes at runtime for obid or any client.

### Rules

- **The route list.** `docs/api/routes.txt` lists every route obid serves, one `<METHOD> <path>` line per method, the path as axum declares it (`{id}`, `{*path}`), sorted by path, then method. It is rebuilt from every `.route(` under `core/crates/obid/src` whose path is a literal starting `/v1/`, outside test modules (`production_lines`' rule in `scripts/oby-check.sh`) and comment lines; each method router (`get`, `post`, `put`, `patch`, `delete`, or `axum::routing::` one) is a line, and a layer is skipped. A method router the guard doesn't know fails it, naming the file and the path. The routes `gateway.rs` declares itself (`POST /v1/pairing`, on the gateway's own listener) sit under their own heading. A new route commits its line with it; a route that goes shows as a deleted line in review.
- **The clients' calls.** The `/v1/` (or Swift's `v1/`) string literals of `apps/electron/src` (its `.ts` and `.tsx`, not under a `test/` folder, not `*.test.ts(x)`, not `renderer/src/mock.ts`), `apps/shared` and `mcp/server` are paths the clients call. Each is compared, segment by segment and whatever the method, with every route in the list: an interpolated segment matches any, a route's `{x}` matches any one and `{*x}` one or more, and a literal ending in `/` matches when a route starts with it. A query is cut, and an interpolation glued to the end of the text (`/v1/jobs${q(..)}`) is dropped.
- **The known-dead list only shrinks.** `docs/api/dead-client-calls.txt` holds the calls that were already dead when the guard came, `<file> <path>` a line. A dead call not on it fails, and so does a line whose call is gone from its file or served again: delete that line.
- **The gateway's list holds only served routes.** Each `ROUTES` entry in `core/crates/obid/src/gateway.rs` (`*` one segment, a final `**` one or more) must reach a route of the API's with the same method; one that reaches none fails, and is deleted.

### Failures and recovery

- Each failure names what to fix: the route that went or appeared, the file and path of a dead call, the list line to delete, or the gateway entry. The fix is the route put back, its line committed, the call changed, or the entry or line deleted.

### Invariants

- The guard never writes a list: a person commits each change to it, so it shows in review.
- `gateway::ROUTES` stays private: the guard reads gateway.rs's source.

## Interfaces and dependencies

- **Workflow:** `.github/workflows/ci.yml` (GitHub's `CI` workflow) and `core/.config/nextest.toml` are what CI-1 to 6 and CI-17 to 20 describe; GitHub's own runs prove them, since no test runner in this repository runs a workflow's triggers. Until R01-02, CI-1 and CI-2 described `.github/workflows/linux.yml`, whose runs below stay as history.
- **Files:** `docs/api/routes.txt`, `docs/api/dead-client-calls.txt`, read by `core/crates/obid/tests/routes_guard.rs`.
- **Check:** `scripts/oby-check.sh` plans the Rust group with `tests/routes_guard.rs` when `core/crates/obid/src/api.rs` or `gateway.rs` changes, another file under `core/crates/obid/src/` with a `.route(` in it, anything under `docs/api/`, or a client source as above (`apps/electron/src` but its tests and mock, `apps/shared/*.swift`, `mcp/server/*.swift`); the groups those paths planned before stay as they were. `scripts/oby-check-test.sh` proves that plan.
- **Cost:** an Electron-only or Swift-only change to client sources now also runs `cargo fmt`, clippy on obid and a build of one obid test binary.

## Acceptance scenarios

- **CI-1** (proposed for `ci.yml`). Given a ready pull request into `dev`, when it is opened, reopened, pushed or marked ready, then the CI workflow starts by itself on that head and runs `plan` with the secret scan, plus `lint` (`cargo fmt --check` and clippy) when the change reaches Rust. Given a draft without `full-ci`, its jobs are skipped. Proof on `ci.yml`: run [43449498424](https://github.com/obi-ai-bot/oby/actions/runs/43449498424) (#2175, a draft before its label: every job skipped). Missing: a ready pull request without `full-ci` on `ci.yml`, the owner's step. History, on `linux.yml`: run [43444624617](https://github.com/obi-ai-bot/oby/actions/runs/43444624617) (#2170, a ready pull request reaching Rust: Changes, Secret scan and Rust (core) with fmt and clippy passed, `cargo test` skipped, E2E and Control plane skipped), run [43445078023](https://github.com/obi-ai-bot/oby/actions/runs/43445078023) (#2171, `factory/` only: the secret scan alone), and run [43428763381](https://github.com/obi-ai-bot/oby/actions/runs/43428763381) (a draft: every job skipped).
- **CI-2** (proposed). Given a push to `dev`, when it lands, then no CI workflow run starts. Given the nightly schedule or a `workflow_dispatch` on `dev`, every job runs to the end, and only that run saves the Rust caches. Proof, on `linux.yml`: the pushes to `dev` after #2166 (`9991deb0` to `80d9d398`) started no run (`gh run list --workflow linux.yml --branch dev --event push`: the latest is [43430439449](https://github.com/obi-ai-bot/oby/actions/runs/43430439449), on `f3b0120f`, #2165, before #2166). `ci.yml` has no `push` trigger either. Missing: a nightly or `workflow_dispatch` run of `ci.yml` on `dev`; none can run before `ci.yml` is on `dev`.
- **CI-3** (proposed). Given a ready pull request that changes only `docs/**` or `factory/**`, when the workflow runs, then only `plan` and `Check` run and Check passes. `plan`'s lane step, run by hand on `docs/ci.md` and `factory/x.md`, prints every lane `false`. Missing: a ready pull request without `full-ci`, the owner's step.
- **CI-4** (proposed). Given a run in the merge queue whose group changes `core/Cargo.toml`, when the workflow runs, then every lane runs. `plan`'s lane step, run by hand as a `merge_group` on a diff of `core/Cargo.toml` alone, prints every lane `true`. Missing: a real `merge_group` run, after R01-03.
- **CI-5** (implemented). Given one Rust shard fails, when the workflow ends, then Check fails and its summary names the shard and the test. Proof: run [43449622565](https://github.com/obi-ai-bot/oby/actions/runs/43449622565) (#2175, a temporary `obi-protocol::ci_5_probe ci_5_probe_always_fails`, since reverted: `rust-test (4/4)` red, `Check` red, its summary naming "rust-test 4/4" and `obi-protocol::ci_5_probe ci_5_probe_always_fails`).
- **CI-6** (implemented). Given `plan` fails, when the workflow ends, then Check fails rather than passing over skipped lanes. Proof: run [43453297449](https://github.com/obi-ai-bot/oby/actions/runs/43453297449) (#2175, a temporary `exit 1` in `plan`'s lane step, since reverted: `plan` red, every other job skipped, `Check` red: "plan failure, so no lane can be trusted").
- **CI-9** (implemented). Given a change that removes a route from obid, when the check runs, then it fails and names the route (`` `POST /v1/clear` went ``). Test: `ci_9_a_removed_route_fails` (core/crates/obid/tests/routes_guard.rs), seen red on an inline router and list.
- **CI-10** (implemented). Given a client file that calls a `/v1/` path obid does not serve, when the check runs, then it fails and names the file and path. Test: `ci_10_a_client_path_without_a_route_fails` (core/crates/obid/tests/routes_guard.rs), seen red on an inline client snippet and known-dead list.
- **CI-11** (implemented). Given a `gateway.rs` `ROUTES` entry with no route, when the check runs, then it fails and names the entry. Test: `ci_11_a_dead_gateway_entry_fails` (core/crates/obid/tests/routes_guard.rs), seen red on an inline `ROUTES` snippet.
- **CI-17** (proposed). Given a ready pull request into `dev` that changes `core/`, when the workflow runs, then it runs `plan` (with gitleaks) and `lint` (fmt and clippy), and no `rust-build`, `rust-test`, `e2e`, `electron`, `control-plane` or `tools` job. Missing: a ready pull request without `full-ci` that changes `core/`, the owner's step.
- **CI-18** (proposed). Given a `merge_group` run that changes `core/`, when the workflow runs, then the Rust suite is compiled once (`rust-build`) and its tests run across 4 shards, each uploading a JUnit report. Shown on a `full-ci` pull request: run [43453425366](https://github.com/obi-ai-bot/oby/actions/runs/43453425366) (#2175: `rust-build` once, `rust-test (1/4)` to `(4/4)` passed, artifacts `junit-1` to `junit-4`). Missing: a real `merge_group` run, after R01-03.
- **CI-19** (proposed). Given a test that fails once and passes on its retry in a `merge_group` or nightly run, when the workflow ends, then Check passes and its summary lists the test as flaky. Evidence on a `full-ci` pull request: run [43453425366](https://github.com/obi-ai-bot/oby/actions/runs/43453425366) (#2175, a temporary `obi-protocol::ci_19_probe ci_19_probe_fails_on_its_first_attempt_only`, since reverted: `Check` passed and listed it under "Flaky" with shard 3/4). Missing: a queue or nightly run.
- **CI-20** (proposed). Given any run but `schedule` or `workflow_dispatch`, when it ends, then it has saved no cache. By construction: every `Swatinem/rust-cache` step in `ci.yml` has `save-if: ${{ github.event_name == 'schedule' || github.event_name == 'workflow_dispatch' }}`, `rust-test` has none, and no other step saves a cache but `actions/setup-node`'s small pnpm and npm caches. Missing: a queue or nightly run showing which caches it saved.
- **CI-22** (proposed). Given a factory job in build, gate or review, when its builder pushes, then its pull request is a draft and no GitHub job runs on it, a needs-human escalation included. Proof: the first factory job merged after R01-12, its pull request a draft until APPROVE with exactly one pull-request Check run. None has run yet.
- **CI-23** (proposed). Given an approved job whose head is the gated head, when `job merge` runs, then it marks the pull request ready, runs `gh pr merge --auto --match-head-commit <head>`, runs no Mac check, and the job is `merged` (no queue) or `queued` (a queue). Proof: the no-queue half on the first factory job merged after R01-12; the queued half on R01-03's runs. None has run yet.
- **CI-24** (proposed). Given a queued job the queue removes for the first time, when `job queue` reads it, then it is queued again with no builder round; removed a second time, it gets one builder round with the failed log in `queue-failure.md` and its pull request is a draft again. Proof: R01-03's runs (a deliberately red pull request in the queue). None has run yet.
- **CI-25** (proposed). Given four queued jobs, when `job queue` runs every minute for an hour, then it makes at most 30 GitHub reads per job. Proof: R01-03's runs. None has run yet.
