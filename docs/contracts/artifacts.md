# Artifacts: what agents make to be looked at, every version kept

The business behavior contract for Oby Artifacts in obid's store, from [the template](../business-contract-template.md). Proven first in the Blok lab (`tools/obid-spec/src/lab/artifacts.rs`, `artifacts_contract.rs`; #2682), then ported piece by piece as [the port plan](../plans/artifacts-port.md) orders it. Its runner API is [docs/api/artifacts.md](../api/artifacts.md).

## Feature and status

- **Outcome:** Whatever an agent makes to be looked at (a page, a document, an image, a PDF, a canvas of pages, or a design made in Claude Design) is kept by obid with every version, exactly as the agent made it, so the owner can open, rename and export it, and a later turn or job of the same conversation can improve it.
- **Status:** **Partly implemented.** ARTIFACTS-1 to 8, the store (the port plan's P1), ARTIFACTS-9 to 11, export and import (P2), ARTIFACTS-12, the turn's artifact (P3), ARTIFACTS-16 to 18, the owner's edit (L3a), ARTIFACTS-19 to 25, a change asked with an artifact open, and ARTIFACTS-26, a React folder or file kept as a page (the port plan's L5), are implemented, each naming its tests. The rest of the plan (Oby's runtime, the agents' tools, the artifact tab, sharing, public links, Settings) adds its scenarios here as it lands. The owner's decisions behind it are in the port plan's "Decided" (2026-11-20): Claude's limits, and one origin per version.
- **Scope:** obid's `artifacts` module: what it copies and refuses, the kinds, a design's uploads, the limits, versions, renames and the files it serves. Outside it: how an artifact is drawn (the apps, and Oby's runtime in P4), and anything an agent does to make one.

## Behavior

### Actors and ownership

- **obid** owns every artifact: `home/artifacts/<id>/artifact.json` and each version's folder. It copies, checks, scans and keeps; rules decide, no model call of obid's.
- **Agents** publish by writing into a job's `.obi/artifacts/` (published when the job ends) or with the conversation's `oby_artifact` tool, from its room.
- **The owner's apps** list and read artifacts and their files, rename and delete them, export a version and import a Claude Design project, a page or a document (`/v1/artifacts`), and save the owner's edit as a new version (`POST /v1/artifacts/{id}/versions`, signed by one of their devices).

### Rules

- **Kinds come from the shape.** A folder with `index.html` is `html`, and so is a React folder, one with no `index.html` and an `App.tsx` or `App.jsx` at its root; with a `canvas.json` that is a list of frames, or Swift's `{"frames": […]}`, a `canvas`; with Claude Design's `canvas.json` (an object with `boards` or `v`), a `design`. A single file is `html`, `markdown`, `image` or `pdf` by its extension; a single `.tsx` or `.jsx` file is `html`, kept as `App.tsx` or `App.jsx`.
- **A design is kept byte for byte.** obid checks Claude Design's `canvas.json` and its `.dc.html` boards as they are and never rewrites them: `v` is 3; each board is a file of the folder holding `<x-dc>` and one logic script; `order` and `launch` name its boards or pages; page ids are plain; `notes` under 1 MB; each design system's folder is there. A refusal says which.
- **A design's uploads are kept under `assets/`.** Claude names an upload `/_blob/<id>`, with no extension. obid keeps it as `assets/<id>.<ext>`, its type from its bytes, and the version's `blobs` maps the id to it; `{version}/_blob/<id>` serves it, inside that version only. An id that looks like a token is kept under a hash of it instead, so the design isn't refused for a name Claude chose.
- **Claude's limits** (the owner's decision, 2026-11-20): a text file 16 MB, a binary file 15 MB, an SVG 2 MB; a version 512 files and 256 MB; an artifact 50 versions; a job's artifacts, or a conversation's own, 4096 MB between them; no cap on the store. Each refusal says what is over and by how much.
- **Versions follow the conversation.** A new version comes from the conversation the artifact belongs to, from any of its jobs (a follow-up is a new job of the same conversation), or, for one with no conversation, from the job that made it. Each version says which job published it. A job publishing files it already published (its `.obi/artifacts/` again, as its end may) gets the version it made back, never a new one over a version made since.
- **Words follow the artifact open.** Words the owner says with an artifact open (`POST /v1/plans`' `artifact`) land in the artifact's conversation, whatever conversation the app had open, and the turn's agent is told which artifact and version is open. An artifact with no conversation (an import, one kept from before, one whose conversation was deleted) gets the conversation its first words start, as a task does (TASKCONV-4); two first words at once land in one. An artifact obid hasn't, or one whose conversation is another profile's, is `404`.
- **The owner's edit is a new version.** An edit names the version it was made on (`base`) and the new text of some of that version's files. It must be made on the latest version, so two edits never pass each other unseen. The new version is the base's files with the changes laid over them, through every check a publish has (the kind, Claude's limits, the names and the secret scan), and says `by: "owner"`. Only the owner's devices edit: the request is signed (`X-Oby-Words`). The same text as the base makes nothing new.
- **A rename is said.** Renaming sends `artifact` with `renamed`, so every open view retitles it.
- **Nothing untrusted is followed.** Every file is opened without following a link and only from inside the folder obid names; links, hard links, other disks and paths out are refused, as before this contract.
- **An export is the version as kept.** A zip is the same bytes every time (names sorted, one fixed time, mode 0644, deflate); a design's is Claude Design's project, `project/` with each upload back at `_blob/<id>`, so a design imported from Claude Design goes back to it as it came. The standalone HTML holds every file and reaches nothing outside itself.
- **An import is the owner's, and only signed.** It needs the owner's words signed over its exact bytes (WORDS-21). A zip is read in memory, never unpacked by following anything: a link, a path out or a file over its limit refuses it whole. What it holds is then published as an agent's folder is, with every rule above, as a new artifact of no conversation and no job, `origin` the import.
- **The secret scan.** Every file and every name (the path, the title, each kept file's path, each upload's id) passes the publish gate's scan before anything is kept; a name that looks like a token is refused, an upload's id excepted, as no file is kept by it.

### Failures and recovery

- A refusal is one line starting `Not published: ` (`Not saved: ` for an edit); nothing is kept and no event goes out. A refusal that would repeat a name that looks like a secret says so instead of the name.
- A publish cut short (obid stopping) leaves a `.staging-*` folder, removed when obid next starts.
- The same files again make no new version: the latest is the answer.

## Interfaces and dependencies

- **API:** [docs/api/artifacts.md](../api/artifacts.md), add-only: `kind` gains `design`; an artifact gains `origin`, left out for an agent's; the routes gain `GET /v1/artifacts/{id}/export/{version}` (the phone's gateway reads it too) and `POST /v1/artifacts/import`; a version gains `blobs` and `job`, each left out when empty; the file route serves `_blob/<id>`; the types gain `font/ttf`, `font/otf`, `video/mp4`, `video/webm` and `image/avif`.
- **The owner's edit:** `POST /v1/artifacts/{id}/versions` with `{base, files}`, signed; a version gains `by` (`"owner"`), left out for an agent's. The app's Code tab sends it (the port plan's L3b).
- **Events:** `artifact` on `/v1/events` ([docs/api/events.md](../api/events.md)), now also `{renamed: true}` on a rename and `{joined: true}` when words gave it a conversation.
- **The turn's artifact:** `artifact: {id, version}` on `POST /v1/plans`, announced by `artifact-turn-v1` ([docs/api/conversations.md](../api/conversations.md)). The app sends it in P8.
- **Persistence:** `home/artifacts/<id>/artifact.json` and `home/artifacts/<id>/<version>/`, files 0600, folders 0700.
- **The agent's tool:** `oby_artifact`'s `kind` enum still lists the five older kinds; left out, a design is found from its shape. The agents' tools gain `design` with the guide (the port plan's P5).
