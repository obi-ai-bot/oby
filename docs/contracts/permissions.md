# Permission modes: Bypass asks nothing

The business behavior contract for how much a job asks its owner, from [the template](../business-contract-template.md). Scenarios are numbered `BYPASS-n`; the tests that prove them name the scenario.

## Feature and status

- **Outcome:** The owner picks how freely their agents work, in Settings and on each task, with Sangam's four modes, and Bypass, the default, asks nothing but secrets. On the 2026-10-28 call every task asked for permissions although Settings showed Bypass ([#1570](https://github.com/obi-ai-bot/oby/issues/1570)): obid wasn't in Bypass, and the app's Mode menu did nothing.
- **Status:** **Implemented** by [#1592](https://github.com/obi-ai-bot/oby/pull/1592) (Bypass holds where the brain, the conversation's shell and approved plans lost it; only what touches secrets asks) and by the change that added this contract (a new install starts in Bypass, the Mode menu, hooks, Question cards). Sangam's design (General › Permissions: Ask, Accept edits, Plan, Bypass · "Asks nothing", Bypass the default; the task card's Mode button) and the owner's decision of 2026-10-27 lead.
- **Scope:** obid's default mode, the modes the Electron app offers, what Bypass still asks, the agent's own questions. **Out of scope:** the words of the secrets card (Sangam's to design), the Swift apps (frozen; they keep decoding every mode), Linux's network reading.

## Behavior

### Actors and ownership

- **obid** keeps the default mode (`home/permissions.json`), gives each new job its mode, decides every call by its fixed rules, the owner's saved rules and the mode, and asks the owner what's left.
- **The Electron app** shows and sets the default (Settings › General › Permissions on this Mac) and a task's mode (its Mode menu), shows what a job asks on its card, and sends the owner's answers.
- **The owner** answers what's asked, from the app.

### The modes

| Mode | Asks the owner about |
|---|---|
| Ask | every edit and command |
| Accept edits | every command |
| Plan | a command or a site that doesn't only read (what only reads goes ahead; an edit is refused until the owner approves its plan) |
| Bypass | only what touches secrets, a login or the vault |
| Sandbox (obid's old default) | the network beyond the model's API, a read outside the worktree, what obid can't read, secrets |

The app offers the first four. Sandbox stays in obid's API, add-only, for the installs that saved it and the jobs that have it: Settings shows it only while it's the saved one, and a task in it shows `Sandbox` on its Mode button.

### Decisions

- **A new install starts in Bypass.** No `permissions.json`, or one with rules and no `mode`, means `bypass`. A mode the owner saved is never changed by an upgrade, `sandbox` included. An install that never saved a mode (most 0.4.x installs, which ran in Sandbox by default) is in Bypass after the upgrade too: the owner's decision of 2026-10-30, said in the release notes. A saved mode obid can't read (a newer obid's, a hand edit), or a file that doesn't read, fails closed: Ask, as a job whose mode obid can't read does.
- **Bypass asks nothing but secrets.** Commands, edits, the network, the conversation's shell, a repository's hooks (Cursor's), approved plans and the brain's own Bypass jobs all go ahead. What touches secrets, a login or the vault asks in every mode, Bypass too, and no mode change or rule settles that card. A repository's hooks are judged as the agent's commands are (`permissions::decide`), when the job starts and when its mode changes alike, so a hook that touches secrets asks in Bypass too, with no Always.
- **The agent's own question is not a permission.** Claude Code's `AskUserQuestion` (and Codex's and Cursor's questions) waits for the owner in every mode, because the agent chose to ask; the app shows it as Sangam's Question card, the question as its headline and the agent's options as buttons, never as a Permission card with Allow and Deny. His Tell it something follows the options and opens the card's field for the owner's own words, so a question with no options is answered too. A pick or the words answer the inbox item itself (`POST /v1/inbox/{id}/answer`), never the job's permission, which can lag behind the inbox between a call's questions.
- **What only reads never asks, Plan too.** A command whose every part only reads (`cat`, `grep`, `rg`, `ls`, `nl`, `od` with their reading options, `command -v`, `sed -n` with line numbers from a file or a pipe; git's `diff`, `log`, `show`, `status`, `rev-parse`, `ls-files`, `ls-tree`, `cat-file`, `blame`, the listing forms of `branch` and `tag` and the other reads of PERMISSIONS-9, from the worktree's top), inside the job's box, with nothing written to a file, runs without a card in every mode. So Oby's own review, which stays in Plan, reads the change (`git diff origin/dev...HEAD`) without leaving the owner a card. A write (`git commit`, `rm`), the network and secrets still follow the mode: in Plan they ask, an edit is refused, and a push is refused in every mode. The `rg` Codex ships beside its binary (its package's `pathDir`, first on its commands' `PATH`, out of the box's reach) counts as the system's.
- **A task's Mode menu changes that task only**, from now on (`POST /v1/jobs/{id}/mode`): a waiting permission the new mode allows is answered; a secret or a question keeps waiting.

### Failures and recovery

- A `permissions.json` that can't be read (its permissions, a folder in its place) or doesn't parse is logged and taken as no rules and Ask, until the owner picks a mode again. Only a missing file is a new install.
- A Mode or an answer obid refuses (an unknown job, a mode that isn't one, a question already answered) shows obid's words in the app, and the card stays.

### Invariants

- The box, the fences (the worktree only, no publishing by the agent, no background work) and the secret scan hold in every mode. Bypass changes what obid asks, never what the box allows.
- obid's API stays add-only for the Swift iPhone and Watch apps: `sandbox` stays a mode they may see.

## Interfaces

`GET`/`PUT /v1/settings/permissions`, `GET /v1/status` (`permissions.mode`), `POST /v1/jobs/{id}/mode`, the `agentQuestion` inbox item and `POST /v1/inbox/{id}/answer` ([runner-api.md](../runner-api.md)).

## Acceptance scenarios

- **BYPASS-1** A new install, no `permissions.json` or one with rules and no mode: Settings and `GET /v1/status` say `bypass`, a new job is in `bypass`, and its `npm install` runs without a card. A saved mode obid can't read, or a file that doesn't read, is Ask. `jobs_api::bypass_1_2_a_new_install_starts_in_bypass_and_a_saved_mode_stays`, `permissions::tests::bypass_1_a_missing_mode_is_bypass_and_an_unreadable_one_is_ask`; `status.rs`'s fresh home says `bypass` too.
- **BYPASS-2** An install that saved `sandbox` (or `bypass`) upgrades: it keeps it, and a Sandbox job asks before `npm install`. `jobs_api::bypass_1_2_a_new_install_starts_in_bypass_and_a_saved_mode_stays`.
- **BYPASS-3** A Cursor job in Bypass on a repository with hooks starts without a card; in any other mode it asks, as before; a hook that touches secrets asks in every mode. `permissions::tests::bypass_3_a_repositorys_hooks_ask_in_every_mode_but_bypass`, `adapters::bypass_3_cursor_asks_you_before_it_runs_a_repositorys_hooks`.
- **BYPASS-4** A Bypass job that reads `.env` asks; changing its mode to any other doesn't settle the card. `jobs_api::bypass_4_a_mode_change_never_settles_a_secret`, `permissions::tests::bypass_4_only_what_touches_secrets_asks_in_bypass` (#1592).
- **BYPASS-5** An agent asks "Which store?" with SQLite and Postgres: the task's card is a Question card with that headline, those buttons and Tell it something; a pick, or the owner's words, answers that inbox item. A question with no options offers Tell it something. `apps/electron/src/renderer/src/test/asks.test.ts` (`bypass_5_…`); obid's side, `jobs::tests::bypass_5_the_agents_question_waits_for_the_owners_answer` (#858).
- **BYPASS-6** On a running task in Accept edits, the owner opens Mode and picks Bypass: the menu offers Ask, Accept edits, Plan and Bypass, the task shows Bypass, and its waiting command card is answered. The app: `asks.test.ts` (`bypass_6_changes_the_jobs_mode_through_obid`: `POST /v1/jobs/{id}/mode`), and the menu checked on the mock in the browser. obid: `runner_api::bypass_6_modes_answer_what_they_allow_and_stopping_drops_the_permission`.
- **BYPASS-8** A job's background helper (`Agent` or `Task` with `run_in_background`) runs in Bypass, where nothing asks for a permission; in any other mode it's refused, as before, and one run remotely (`isolation: remote`, outside Oby's box) in every mode. `policy::tests::bypass_8_a_background_helper_runs_in_bypass`.
- **BYPASS-9** A Cursor job on a repository whose `.cursor/cli.json` allows commands without asking obid asks the owner with a card, as for its hooks (BYPASS-3), where it used to refuse to start: Allow starts it, Deny says why, Bypass answers it. `adapters::bypass_9_a_repository_allowlist_asks_you_before_cursor_starts`.
- **PERMISSIONS-1** git that stays on the Mac runs in a job (`submodule`, `lfs` but its push, `gc`, `sparse-checkout`, `bundle`, `format-patch`); what writes to a code host is refused in every mode, because agents keep no login, and the agent hears that obid pushes its branch and the owner can tell Oby to push, merge or post anything else. `policy::tests::permissions_1_local_git_runs_and_a_code_host_write_says_how`.
- **PERMISSIONS-2** A job's agent reaching telemetry elsewhere than its tool's vendor (Datadog, Sentry) is decided as any site is (its rules, its mode, the owner's card), not refused; a plain `http://` request is decided the same way and forwarded alone, without the job's token, instead of refused. `jobs::tests::permissions_2_the_egress_proxy_lets_through_asks_and_refuses_by_site`, `egress::tests::permissions_2_a_plain_request_names_its_site_and_goes_on_alone`.
- **PERMISSIONS-3** Oby's own review (Plan) runs `git diff origin/dev...HEAD`, `git ls-tree`, `git cat-file -p`, `git blame`, `cat`, `grep` and `ls` with no card and nothing on Home; its edit and its push are refused, and a `git commit` or `rm` waits for the owner. Codex's own `rg` is a reader as the system's is. `jobs_api::permissions_3_a_review_reads_without_asking_and_a_write_still_asks`, `permissions::tests::a_command_that_only_reads_never_asks`, `permissions::tests::a_reader_the_agent_ships_never_asks`, `codex::tests::codex_ships_its_programs_beside_its_binary`.
- **PERMISSIONS-4** A `permissions.json` that doesn't read (a hand edit, a file a newer obid wrote) is Ask with no rules, as before, and the owner's next change (a mode, an Always) copies it aside to `permissions.json.unreadable-<time>` before writing: the rules it holds are never written over. When it can't be copied, nothing is written and the change fails. `permissions::tests::permissions_4_an_unreadable_file_is_kept_aside_never_written_over` (#1652).
- **PERMISSIONS-5** Plan asks before a command that doesn't only read, WebFetch included, and refuses an edit until the plan is approved (Sangam's "Plans first, and works once you approve the plan"); what only reads never asks. `permissions::tests::permissions_5_each_mode_allows_or_asks` (#1652).
- **PERMISSIONS-6** A shell's grouping words don't change what a command does (#1811). A job's `printenv` or `curl` inside `{ }`, `if`, `while`, `until`, `for`, `select`, `case`, `!`, `( )`, a function's body, a coprocess, a `trap`, or a `$(…)` in a here-document whose end word isn't quoted is judged as the plain command is: `printenv` asks in Bypass, `curl` is the network, and a saved deny rule for it holds. No allow rule covers, or is offered for, a command behind `!`, in `( )`, in a coprocess or in a `trap`. A word of another command (`echo if printenv`, `git log --grep '{ x'`), a parenthesis in quotes (`git commit -m "fix(obid): x"`, which keeps its rule and its Always) and a quoted here-document's lines stay plain text. `coproc curl if x` is read both ways, since bash takes `curl` for its name and zsh runs it. `permissions::tests::permissions_6_grouping_words_hide_nothing`, `permissions::tests::permissions_6_a_saved_rule_reads_grouping_words_too`. Where a `cd` in a branch leads is read as if the branch ran, as `cd a || cd b` is: the box holds the rest.
- **PERMISSIONS-7** The rest of what a line's words can hide (#1811). Where a redirect goes isn't an argument (`printenv 2>&1`, `set > o.txt`, `{ printenv > o.txt; }` print every variable; `printenv HOME > o.txt` still only one, and a file a redirect names is still a file it touches). `$'…'` is a quote (`echo $'\'' ; printenv ; echo ''`). `<<` in `(( ))` shifts, so the next line is a command. Nested backticks are code, `bash -c -- x` runs `x`, `find -exec` runs what follows it, and an option of a wrapper that takes a value isn't the program (`env -u FOO printenv`, `exec -a x printenv`, `xargs -I {} printenv`, `sudo -u root curl x`), zsh's `noglob`, `nocorrect` and `repeat 1` are wrappers, and its `{ printenv }` still prints everything. `set` alone prints every variable, and `set -e` asks nothing. A deny rule holds past a wrapper and a variable set before the program (`command curl x`, `{ FOO=1 curl x; }`), and for the wrapper it names (`Bash(sudo:*)`, `! sudo curl x`), and text in a here-document or in quotes is no command to it. A `>` or `;` in quotes keeps a command's allow rule and its Always (`git log --format='%h > x'`). `permissions::tests::permissions_7_only_what_runs_chains_a_command`. `permissions::tests::permissions_7_redirects_quotes_and_wrappers_hide_nothing`, `permissions::tests::permissions_7_a_deny_rule_reads_past_wrappers`.
  **Limits, on purpose:** obid reads a line's words and is no shell, so these aren't seen as what they run, and the box holds them (no secret is in a job's environment, the egress proxy decides each site, what it hides from reading is hidden from reading only): code a shell reads from a pipe (`echo printenv | bash`), brace expansion (`{printenv,}`, `cat {.env,}`), a glob or a variable that spells a secret's path (`cat ~/.a*/credentials`), a program a variable or an escape names (`c=printenv; $c`, `$'\x70rintenv'`), which counts as the network, not as a secret, zsh's short forms with no separator (`if [[ -n x ]] printenv`), and a saved deny rule with quotes in it on a chained line, read from the words without their quotes. Reading more of them would make harmless lines ask, and `echo if` and `git log --grep "{ x"` stay clean.
- **PERMISSIONS-8** What obid can't fully see never passes as allowed or read-only. A `<<` in `$(( ))`, nested `(( ))`, `$[ ]`, `${ }` or a first word's subscript (`a[1<<2]=3`) is a shift, as bash, zsh and sh run it, so the lines after it are read as commands and every check sees them (`echo $[1<<2]⏎curl y` is the network, and a saved `Bash(curl:*)` refuses it; this was a limit of PERMISSIONS-7). A here-document ends at the line a shell ends it at: `<<'E F'`, `<<E\ F`, `<<$'E'`, `$(cat <<E⏎…⏎E)`. Even so a line with such a `<<`, or with a here-document that never ends (a shell may have ended it where obid didn't), counts as no read, in a job and in the conversation's shell, and no allow rule covers it or is offered for it; what it may hide from reading is hidden from reading only, and Bypass stays quiet unless what obid reads touches secrets. `ps` with the environment's letter (`ps e`, `ps auxe`, `ps -E`) prints the environment as `printenv` does and asks in Bypass; `ps -e` and `ps -o user` don't. A command longer than the 2,000 characters its card shows says how many are hidden (`… (345 more characters not shown)`, proposed words, Sangam's to change), in its `title` and `detail`, and offers no Always. `permissions::tests::permissions_8_what_a_shell_runs_is_what_obid_reads` runs each form in `/bin/bash` first. `permissions::tests::permissions_8_what_obid_cant_read_is_no_read_and_gets_no_rule`, `permissions::tests::permissions_8_a_cut_command_says_what_is_hidden_and_offers_no_always`, `permissions::tests::permissions_8_ps_with_e_prints_environments`, `brain::shell::tests::permissions_8_a_line_obid_cant_read_is_no_read_here_too`.
  **Limits, on purpose:** a `<<` in `$(( ))` a shell takes for a real here-document, because the `$((` turned out to be a `$(` with a subshell in it, is read as a shift: the line is no read and has no rule, but a quote in its text could still hide a later line from a deny rule or the secrets check. `declare a[1<<2]=3` is a here-document in bash and zsh, and read so. On this Mac `ps E` printed no other process's environment when it was tried (macOS 26), so what the scenario holds there is the same answer as on Linux, where procps prints it.
- **PERMISSIONS-9** More of git's reads never ask, Plan too: `git branch` listing (`-a`, `-r`, `-v`, `--show-current`, `--list`, `--contains`, `--merged`, `--points-at`, `--sort`, `--format`), `git tag` listing (`-l`, `--list`, `-n`, and the same), `git remote`, `git remote -v`, `git remote get-url`, `git reflog` (its `show`, `list`, `exists`, `HEAD`, or options), `git stash list`, `git stash show`, `git worktree list`, `git grep`, and `git config` reading one setting (`--get`, `--get-all`, `get`, or a key alone). Each is read form by form, so anything else follows the mode: a word after `git branch` makes a branch (`git branch -v x` does, on real git) unless an option lists, `git reflog expire`, `git stash`, `git remote update`, `git remote show` and `git ls-remote` (the network), `git config --list` and `--get-regexp` (they can print a login), and a setting whose name says it may hold one (`credential`, `token`, `pass`, `secret`, `key`, `auth`, `header`, `cookie`, `proxy`, `insteadOf`). `--textconv` has git run a repository's program, so no git read takes it. `permissions::tests::permissions_9_gits_read_only_forms_never_ask`.
- **PERMISSIONS-10** A saved allow rule, and what Always offers, read past variables and wrappers that don't change what runs: `RUST_LOG`, `RUST_BACKTRACE`, `NODE_ENV`, `GOOS`, `GOARCH`, `LANG`, `LC_ALL`, `TZ`, `NO_COLOR`, `FORCE_COLOR`, `CI` set to a plain value, then `timeout`, `time`, `nice`, `nohup` and `stdbuf` with the options known to change nothing else. So `RUST_LOG=debug timeout 60 cargo test` is `Bash(cargo test:*)`. Nothing else is read past: `env`, `sudo`, `xargs`, `watch`, `command` or a shell, `PATH`, `IFS`, `LD_*`, a login's variable, a value with a quote or a `$`, `time -o f` (it writes a file), an option obid doesn't know, or a program with a folder. What follows them runs anything as it did (`timeout 5 bash -c x` has no rule), and a chained line stays chained. A deny rule read past them already. `permissions::tests::permissions_10_a_saved_rule_reads_past_harmless_wrappers_and_safe_variables`.
- **PERMISSIONS-11** A refusal says what happened and doesn't invite a way around it. The owner's no, a saved deny rule, the conversation's shell and Plan each tell the agent the call did not run and changed nothing, and not to reach the same result another way; a no says to do the rest of the work and to say in the summary what it needed; the owner's own words come quoted, and what they say goes (a no with `use the lockfile` is a way the owner chose). All of it is obid's one helper, in proposed words, Sangam's to change. A words field on a permission card isn't on his screen, so it isn't here: words reach a card as they did. `permissions::tests::permissions_11_a_refusal_says_what_happened_and_invites_no_way_around`, a parked call's in `jobs_api::a_parked_job_survives_a_restart_and_words_are_its_no` and `adapters::codex_and_cursor_park_and_resume_with_the_answer`.
- **PERMISSIONS-12** Always saves something narrow and says what it saves. A tool's subcommand keeps what follows it (`Bash(swift test:*)`); anything else saves that very command (`rm -rf build` is `Bash(rm -rf build)`, never `Bash(rm:*)`), so a tool with no subcommand asks more in Ask. A command a rule can't keep whole offers no Always: more than one line, one ending in `*` (read as a prefix), one holding a token or a login. `always` names what's saved, and the Mac's card shows it on hovering Always allow (proposed, Sangam's to change). A rule saved before keeps its reach until the owner removes it in Settings. An Edit card's Always is as it was: what his button does there is his to say. `permissions::tests::permissions_12_always_saves_something_narrow_and_says_what`, `asks.test.ts` (`permissions_12_…`).
- **BYPASS-7** (#1592) In Bypass, the conversation's shell runs an install with the network (`brain::shell::tests::bypass_7_installs_and_the_network_ask_in_every_mode_but_bypass`; outside Bypass it asks, `conversation_shell::bypass_7_an_install_asks_outside_bypass`); an approved plan goes on in the owner's default, and a Bypass the brain names, continues or carries on asks for no Confirm where Bypass is the default (`jobs::tests::bypass_7_an_approved_plan_goes_on_in_the_owners_default_mode`, which checks `Jobs::bypass_widens`); the owner's words to a finished Bypass job start its follow-up in Bypass (`jobs::tests::bypass_7_the_owners_words_carry_a_jobs_bypass_into_its_follow_up`).

**Test it when it's done (real Mac):** on a fresh obid home, Settings › Permissions shows Bypass; a task that runs `npm install` finishes with no card; the task page's Mode menu changes a running task to Ask and its next command asks; a Claude Code task told to ask a question with options shows a Question card, and a pick lets it go on; one with no options takes Tell it something's words.
