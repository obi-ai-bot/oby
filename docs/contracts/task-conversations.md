# Task conversations: every task has one

The business behavior contract for where a task's words go ([#1631](https://github.com/obi-ai-bot/oby/issues/1631)), from [the template](../business-contract-template.md). Scenarios are numbered `TASKCONV-n`; the tests that prove them are named after them (`core/crates/obid/tests/plans_api.rs`, `github_work.rs`, `conversation_harness.rs`, `publish_api.rs`, `src/brain/`, `src/jobs.rs`, `src/conversation.rs`, `apps/electron/src/renderer/src/test/taskActions.test.ts`).

## Feature and status

- **Outcome:** Whatever started a task, it has a conversation, and every task that follows it up is in the same one. What the owner tells a task, Oby's answer and the follow-up's card stay together, in one place the owner can open.
- **Status:** **Implemented** (Wellington, 2026-10-30). Before, a task started from the Tasks view or from GitHub had no conversation. Words sent from its page started a follow-up that showed only as another task row, and "Go to conversation" opened the task's bare thread, so the owner's question and Oby's answer were lost.
- **Scope:** obid's side: which conversation a task and its follow-ups are in, and what goes into it. **Out of scope:** how the side panel shows a conversation's tasks and follow-ups (nested under it, as Claude Code nests sessions, or not), which is Sangam's design (the preview he was sent on 2026-10-30), and tasks started for other Obys over an Obysphere.

## Behavior

### Actors and ownership

- **obid** decides a task's conversation and writes its turns: `crate::task_conversation`, with `Jobs::join_conversation`.
- **obid** decides that Oby's own review of a task is in the task's conversation: `jobs/reviews.rs` (`Jobs::start_review`).
- **The app** sends a task page's words with `"conversation": true` and opens the conversation obid names. It decides nothing.

### Rules

- **A task started on its own gets a conversation** (`POST /v1/jobs`, `POST /v1/github/work/{id}/start`, and a `github` card's `Review it`, `Fix it` or `Fix CI` on `POST /v1/inbox/{id}/answer`), named after the task. Its first turn is the owner's words when the task's words are theirs (`POST /v1/jobs`'s `task`), with the task's card under them. Then comes Oby's line saying it started, in Oby's existing words (`On it. Claude Code is investigating …`), with the card.
- **Fix CI on the owner's own pull request pushes onto it.** Its fix goes straight onto that pull request's branch, a fast-forward only, with no pull request opened or edited, as T3 Code does; anyone else's pull request gets a pull request into its branch ([why](../decisions/2026-11-17-fix-ci-pushes-onto-the-owners-own-pull-request.md)).
- **Words from GitHub are never the owner's.** A task from GitHub gets no owner turn, and its conversation counts as having read something from outside, because its title is GitHub's.
- **A follow-up is in its task's conversation.** obid's follow-up carries its job's conversation on (`jobs::follow_up`), so every task started from the first one is in the same conversation.
- **Oby's own review of a task is in the task's conversation, and adds nothing to it.** The review (`reviewOf`) carries the reviewed job's conversation, with no turn of its own; its end puts no turn, card or notification there (`conversation::job_report`).
- **A task started in a conversation keeps it.** It never gets a second conversation.
- **A task with none gets one when the owner writes to it.** This covers a task kept from before this change, or one whose conversation was deleted. The first time its page's words reach obid, its whole chain gets the conversation: the first task, the follow-ups and theirs. It is named after the first task, opens with Oby's line and that task's card, and then has the words and Oby's answer.
- **Starting the task matters more.** When a conversation can't be made, the task starts without one, and the log says so.

### Invariants

- obid's API only grows: `conversation` was already a job key; no key is renamed or removed.
- No turn puts words from outside (GitHub's) in the owner's mouth.

## The owner's word in a conversation (#1668, "Oby forbids nothing")

- **Outcome:** What the owner tells Oby in a conversation, Oby does: it merges a pull request into any base (`main` too), writes on GitHub, answers a card waiting in the inbox (a merge card's Merge, a job's plan, its agent's question, a permission, a Confirm), and changes Settings. The limits are the code host's (branch protection, required reviews) and the agents' own; when one stops a request, Oby says what stopped it. Nothing the owner asks is refused on Oby's own account.
- **Status:** **Implemented** (2026-10-31).
- **What counts as the owner's word:** a turn whose words an app of the owner's signed (docs/contracts/signed-words.md), that read nothing untrusted (the web, a repository's files, a job's report, Tetrix, an attachment). An inbox item made after the turn began is one the owner hasn't seen: it is never settled by that turn's words.
- **Otherwise:** what the owner asked becomes a Confirm card in the inbox, saying in obid's words what it does and quoting what goes out; their click carries it out. It is never an error. Text Oby read never decides anything, whatever it says. One such turn asks for the owner's OK at most 10 times, so what it read can't flood their inbox.
- **What keeps a click either way:** letting a job reach a secret (#586), and approving a teammate's pull request over the Obysphere or keeping that standing permission (crate::sphere::approval).
- **The limits of a merge:** a job's own pull request merges on the owner's own word over every hold of Oby's, saying what was still open (crate::merge `Lift::Word`, docs/contracts/merging.md MERGING-27), with GitHub's own rules as the limit; anyone else's pull request has only GitHub's own protection (branch protection, required reviews and checks) as its limit. A pull request of a review another Oby asked for never merges from a conversation.
- **The record:** every merge and write a conversation asks for, done or refused, goes in obid's connection-use log (`vault/uses.jsonl`, job `conversation-<id>`, connection `github`, a `write`).
- **obid owns** the decision (`brain::tools::owners_word`, `brain::actions::owners_call`) and the doing (`brain::owners_word`: Oby's own GitHub login, which no agent gets; the secret scan on every write first). **The apps** show the cards and the answers; they decide nothing.
- **Defaults kept** (what Oby does unasked): Confirm before a Bypass job when Bypass isn't the default, before deleting a job, before saving a routine.

## Steering a task while it works (#1661)

obid owns where the words go (`Jobs::message`, `Jobs::left_words`) and the report (`summary`); the apps show them.

- **TASKCONV-14:** Words the owner tells a task while it's queued, getting ready or at work reach its agent: with its first prompt, or as its next turn (#1661); a Claude Code task at work hears them in the turn under way (TASKCONV-33). When the owner's own words were among a turn's, its reply is added to the task's report after the work's (`After what you told it: …`), the work's first line still first; the conversation's line when it ends, Oby's briefing and its read of the job show that reply too, past a long report. A turn only obid's words started (a rebase, a commit, Try again) adds nothing. (`taskconv_14_words_wait_for_a_job_that_isnt_at_work`, jobs_api.rs; `taskconv_14_a_running_job_hears_the_words_next_and_its_reply_joins_the_report`, runner_api.rs)
- **TASKCONV-15:** The owner's own words (signed, by the API or a Confirm) told a task before it started or while it wrapped up are kept with it, apart from obid's own, a restart included. If it ends without hearing them (it failed getting ready, say), they start its follow-up, each the way it came, and the rest ride along with it; when that can't start, a Confirm in the inbox says they weren't heard and keeps them, but for the owner's own work (TASKCONV-21). Words that weren't the owner's own (what Oby read, an event's) never start one or ride along. Try again's words the owner told it while queued run it again, once, when it has a session to pick up (the rest wait for that run), and are dropped when it never started; Try again that ran it again never comes back as the owner's words. A follow-up that fails getting ready too does the same with what it carried. (`taskconv_15_words_a_queued_task_never_heard_start_its_follow_up`, obid's lib tests)
- **TASKCONV-21:** The owner's signed or confirmed words their own conversation work (`merge::own_work`, MERGING-44) never heard, whose follow-up can't start, make no Confirm: the task's line (`step`) says why, `<title> ended before it heard what you told it, and that couldn't start its follow-up: <why> Your words are kept with it.` (obid's words, proposed, Sangam's to change), the words stay with it and go with its next follow-up, and the line clears then. Nothing is lost or sent twice, and nothing retries by itself. Words that came unsigned, and anyone else's work, still get the Confirm. One function decides it (`jobs::asks::unheard_words`). (`jobs::tests::taskconv_21_own_work_keeps_unheard_words_without_a_confirm`, `jobs::asks::tests::taskconv_21_unheard_words_ask_only_outside_own_work`; Kani: `jobs::asks::proofs::taskconv_21_unheard_words_ask_only_outside_own_work`.)
- **TASKCONV-22:** In a turn whose words an app of the owner's signed, `oby_offer` makes no card and starts nothing, and costs none of the turn's ten: its agent is told to start what they asked for with `oby_dispatch`, or say in words what it would suggest. Unsigned and event turns still offer, as docs/conversation-harness.md says; `oby_dispatch` and its untrusted mark are unchanged. One function decides it (`jobs::asks::offer_card`). (`conversation_harness::taskconv_22_a_signed_turn_makes_no_start_card`, `jobs::asks::tests::taskconv_22_a_signed_turn_offers_no_card`; Kani: `jobs::asks::proofs::taskconv_22_a_signed_turn_offers_no_card`.)

## What the conversation knows about its work

obid owns all of this; the apps show nothing new.

- **TASKCONV-16:** `oby_job` says what the orientation promises: what was asked, the files changed, Oby's real verdict (who, which round, which commit), why reviewing or merging stopped, and a note wherever it cut something. Its text stays quoted, and reading it stays untrusted. (`taskconv_16_oby_job_says_what_the_orientation_promises`)
- **TASKCONV-17:** The session going on hears, once, how its jobs ended since the owner last spoke, quoted, before their words: the first line of obid's report on each. What the job's agent wrote stays out, but for the reason on that line of a job that stopped to wait, so hearing it leaves the turn the owner's word (TASKCONV-6). Of a job that isn't on obid's allowlist, whose title and reason may hold someone else's words (MERGING-32: a reach or withheld secrets alone don't put it off), only its id and status are said; `oby_job` reads the rest, and reading that is what taints a turn. A turn that got no answer heard nothing, so its reports are said with the next one. A new session gets the reports with the earlier turns, the same way. (`taskconv_17_the_next_turn_hears_how_its_jobs_ended`, `taskconv_17_a_foreign_jobs_words_stay_out_of_the_prompt`, `taskconv_17_a_turn_with_no_answer_leaves_its_reports_to_say`)
- **TASKCONV-18:** A job's end is told once and can't be lost: a mark kept in the job's file with the turn, and whatever ended unmarked is told at the next start and when obid falls behind its own events. What ended before obid first kept the mark (`home/job-reports-since`) says nothing, so an upgrade adds nothing to old conversations. An event still on the bus for an end told already tells nothing. (`taskconv_18_a_job_end_notice_cant_be_lost`, `taskconv_18_events_missed_are_looked_for`, `taskconv_18_a_late_event_doesnt_tell_it_twice`)
- **TASKCONV-19:** **Retired** with `oby_shell` (OBY-25): a boxed conversation runs no commands (lanes.md, CONVO-2), so no command of Oby's outlives a turn to be mentioned in the next one.
- **TASKCONV-20:** A new session (a session lost, moved to another account or grown too long) is handed the earlier turns, and those can hold words from outside that a session going on never heard: a job's, a line naming a job. A job's own words stay out as TASKCONV-17 says, and so does a line naming a job off obid's allowlist: it hears that there was one, and `oby_job` reads the rest. When the conversation has read something untrusted the turn isn't the owner's word, whatever signed it, and that mark stays with the conversation. A mark that carries no one else's words (an unsigned turn, a tool that read nothing) leaves a signed word theirs (ASK-16), as in a session going on. (`taskconv_20_a_new_session_hears_no_line_naming_a_foreign_job`, `taskconv_20_a_new_session_of_a_conversation_that_read_something_isnt_the_owners_word`, `taskconv_20_a_new_session_of_a_clean_conversation_stays_the_owners_word`)
- **TASKCONV-33:** Words to a Claude Code task at work (its thread's box, the chip "Tell Claude Code…", or Oby relaying them from the conversation) reach its agent in the turn under way, at its next step, in the same Claude Code process: obid writes them into its stream-json input as they come, and never waits for the turn to end nor starts Claude Code again for them (Sangam's line for it: "It'll pick that up after its current step"; on by default, [why](../decisions/2026-11-17-words-reach-a-working-claude-code.md)).
