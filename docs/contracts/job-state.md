# Job state

The business behavior contract for how obid moves a job between its states today, from [the template](../business-contract-template.md), scaled down: it records behavior and adds none. Scenarios are numbered `JOBSTATE-n`; the tests that prove them are named after them.

## Feature and status

- **Outcome:** Every change to who writes a job's state runs against a fixed record of what Stop, Try again, Another round, a run's end, the owner's words to an ended job, Dismiss, Move and a restart do, so a change in behavior shows as a failing test.
- **Status:** **Implemented (characterized).** Each scenario below pins obid's behavior as it is, including where it may change later.
- **Scope:** obid's job lifecycle: `Jobs::stop`, `Jobs::message` (Try again and the owner's words), `review_round_again`, the end of a run that didn't end done (`settle_end` in `jobs.rs`), `next_round`, `Jobs::end_done`, `Jobs::dismiss`, `Jobs::move_to` and the restart path in `Jobs::open`, and a count of the places that write a job's state. **Out of scope:** what the apps show for each state, the account-limit wait and move (docs/contracts/account-limits.md) and recovery's tries (docs/contracts/recovery.md), which these scenarios cite but don't restate.

## Behavior

- **Actors and ownership:** obid owns every transition below; the apps send the owner's click or words (`POST /v1/jobs/{id}/stop`, `/messages`, `/dismiss`, `/move`, `POST /v1/inbox/{id}/answer`) and show the job obid answers with. No model call decides any of them.
- **How a run ends:** [recovery.md, "End-of-job rules"](recovery.md#end-of-job-rules) states it; JOBSTATE-3 pins it end kind by end kind.
- **Stop, Try again and a worker's end:** [tasks.md](tasks.md), TASKS-18 to 22, states who stopped a job, Try again on a task that never started, and that a worker ends only its own round; JOBSTATE-1, 6 and 18 pin them with the side fields each touches.
- **Persistence:** a job's file (`home/jobs/<id>.json`) holds everything below; `recovery` and `cut` are kept there only, never in the API.
