### obid only: artifacts

What an agent makes to be looked at (docs/conversation-harness.md, section 4): a page, a document, an image, a PDF, a canvas of pages. obid keeps every version of each in `home/artifacts/<id>/<version>/` (0700, files 0600), described by `home/artifacts/<id>/artifact.json`, which is what the API shows:

```json
{"id": "3f0c…", "title": "Landing page", "kind": "html", "conversation": null, "job": "79f64f22",
 "created": "2026-10-17T09:12:00Z",
 "versions": [{"version": 1, "created": "2026-10-17T09:12:00Z", "files": ["index.html", "style.css"], "bytes": 1832}]}
```

- `id`: a lower-case UUID. `title`: one line of 1 to 100 characters. `conversation` and `job`: what made it, either may be null. `versions`: oldest first, numbered from 1; each lists its `files` (paths inside the version, sorted) and their `bytes`.
- **Kinds**, from its shape: `html`, a folder with an `index.html` (a single `.html` or `.htm` file is kept as one, named `index.html`); `markdown`, a `.md` or `.markdown` file; `image`, a `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp` or `.svg` file; `pdf`, a `.pdf` file; `canvas`, a folder with a `canvas.json`, a list of frames `[{"title": "Phone", "file": "phone.html", "x": 0, "y": 0, "w": 390, "h": 844}]`, each `file` an HTML file of the folder. Anything else isn't published, saying what it can be.
- **Made** by a job: when it ends (done, failed or stopped; not when obid shuts down mid-job), each entry of its worktree's `.obi/artifacts/` (a file or a folder, hidden names left out), the first 20 by name of them all, is published as an artifact of that job (the rest are one line in `artifactProblems`, `5 more entries: Not published: a job publishes at most 20 artifacts.`; a folder holding more than 2000 names, hidden ones too, publishes none: `Not published: .obi/artifacts holds more than 2000 names, so none of it is.`, and obid stops reading it there), titled by its name without the extension, with `conversation` the job's. Its next end gives the same entry a new version, and the same files again change nothing. Agents are told to put there what they want shown. `.obi/` is never committed. The conversation's `oby_artifact` tool (docs/conversation-harness.md, section 3) publishes from the conversation's room the same way.
- **What is copied.** Only from inside the folder obid names (a job's worktree, a conversation's room): a path that's absolute or holds `..` is refused. Every folder and file on the way and inside is opened without following a link, inside the folder already opened, so a link anywhere (`.obi/artifacts/away.md -> /etc/hosts`, a folder inside that's a link) is refused, not followed, and so is anything that isn't a plain file or folder (a named pipe, a device). A file with another link to it (a hard link, which may be to a file outside the folder) is refused, and so is anything on another disk than the folder. Names starting with `.` are left out, but count; a name with `\` or `:`, or that isn't UTF-8, is refused. At most 2000 files and folders (hidden ones too), 32 folders deep and 50 MB per version, and 50 versions per artifact: past it, a new version is refused before anything is copied or scanned (`… has 50 versions, the most obid keeps; publish it as a new one.`). A job's artifacts hold at most 500 MB, every version of each counted: an entry that would take it past is refused, with the entries after it, in one line of `artifactProblems` (`3 entries: Not published: this job's artifacts hold 498 MB, and 500 MB is the most one job's may.`). A conversation's own artifacts (those with no `job`, from `oby_artifact`) have the same 500 MB between them: `Not published: this conversation's artifacts hold … MB, and 500 MB is the most one conversation's may.` Each file is checked again by its name after it's opened (`fstatat`, not following a link): another file in its place since (`… changed while obid copied it`) or a second link to it is refused. There is no cap on the store as a whole yet.
- **The secret scan.** Before anything is kept, every file goes through the publish gate's scan (`crate::scan`, obid only: publishing the owner's work): the built-in rules, the secrets obid holds and the vault's in every form it knows, and gitleaks (none is a scan that can't run: nothing is kept), on every file read as text whatever its bytes (bytes that aren't UTF-8 read as U+FFFD, so the ASCII a key is written in stays whole), and once more with its NUL bytes taken out when it has some, so UTF-16 text is read too. What a compressed stream holds isn't looked inside: a PDF's Flate streams, a PNG's `zTXt` or `iTXt` chunks, gzip or zip content. A finding, or a scan that can't run (the vault can't be read), and nothing is kept: `Not published: the secret scan found what looks like a secret in config.js line 1 (AWS access key).` Never the value.
- **Names are scanned too.** The path asked for, the title and every file's path inside the artifact go through the built-in rules, the secrets obid holds and gitleaks, each as a line of its own, and so does every part of each between `/`s and every piece of a part between `.`s (gitleaks finds a key only where a word ends, so `<key>.md` and `<key>/index.html` would hide it); one that looks like a secret, and nothing is kept. A name, a title or a refusal that holds a run of 32 or more letters, digits, `_`, `+` or `-` with both letters and digits in it is refused the same way, as a token joined to a name (`notes-<key>.md`, `notes~<key>.md`, `<key>@x.md`) gets past gitleaks; one of obid's own ids (a UUID, `8-4-4-4-12` hex) isn't, nor is a run of lower-case hex alone (a bundler's hashed name, `main.<32 hex>.js`). A refusal never repeats such a name: any refusal (`Err`, and each line of a job's `artifactProblems`) that holds what looks like a secret, read part by part the same way, is said as `Not published: a name in it looks like a secret, so obid doesn't say it.` instead, and a job's line for such an entry is that sentence alone, never with the entry's name before it. A file that starts like a PDF, a zip or a gzip is still read by gitleaks; one it sniffs as a tar or an ISO image further in makes the scan one that couldn't run, so nothing is kept (publishing the owner's work, above, says how).
- **For whoever writes the publishing call** (the conversation's `oby_artifact`): `Artifacts::publish(Publish {root, path, title, kind, conversation, job, artifact})` in `core/crates/obid/src/artifacts.rs` answers `Ok((id, version))` once the `artifact` event went out, or `Err` with one line starting `Not published: `. `root` is obid's own folder (the room), `path` the agent's, relative to it; `kind` `None` takes it from the shape, and one given must be it; `artifact` asks for a new version of that one, which must have the same `conversation` and `job` and the same kind, and keeps its title (the owner may have renamed it). `shared.artifacts` holds it.

**`GET /v1/artifacts?conversation=&job=`**: every artifact, newest first, or only a conversation's or a job's; `[]` when none.

**`GET /v1/artifacts/{id}`**: the artifact; `404` when there's no such one.

**`GET /v1/artifacts/{id}/{version}/{*path}`**: one of the version's files, `path` as `files` lists it (`assets/site.css`); anything else (another name, `..`, a hidden name, a version that isn't there) is `404`. `Content-Type` by its extension (`text/html; charset=utf-8`, `text/css; charset=utf-8`, `text/javascript; charset=utf-8`, `text/markdown; charset=utf-8`, `image/png`, `application/pdf`…; `application/octet-stream` when unknown), and on every file:

```
Content-Security-Policy: default-src 'self' data: blob:; script-src 'self' 'unsafe-inline' data: blob:; style-src 'self' 'unsafe-inline' data:; img-src 'self' data: blob:; connect-src 'none'; frame-ancestors 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; sandbox allow-scripts
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
```

A page's scripts run, but:

- it loads only its own files (any file of obid's served on the same address, but every one needs the token) and `data:`/`blob:` URLs: no other server, no font or script from the web;
- `connect-src 'none'`: no `fetch`, XHR, WebSocket or EventSource, not even to obid's own API;
- `sandbox allow-scripts`: the page has an origin of its own, not obid's, so it can't read what obid's other pages keep, its cookies, or a frame of another of obid's pages; it opens no window or popup;
- `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`: no plug-in, no `<base>` sending its links elsewhere, no form sent anywhere;
- `frame-ancestors 'none'`: no other page can frame it.

**What the policy doesn't stop**, so this isn't "no network" by itself: the page navigating itself to another address (a link, `location = …`, `<meta http-equiv="refresh">`), WebRTC, and DNS prefetch. A CSP has no rule for those. What such a request can carry is only what the page holds, since it reads nothing else; the apps must deny every navigation and load it with network access denied (the client contract in docs/conversation-harness.md, section 4). Text files are also scrubbed of the vault's secrets as every `/v1` answer is (obid only: the vault).

**`PATCH /v1/artifacts/{id}`** with `{"title": "…"}` renames it and answers the artifact: `422` for a title that isn't one line of 1 to 100 characters, `400` for another body, `404` for no such artifact.

**`DELETE /v1/artifacts/{id}`** deletes it with every version: `204`, `404` for no such artifact. Jobs keep its id in their `artifacts`.

**Through the gateway** a paired phone lists and reads them (the three `GET`s), files byte for byte with their headers; renaming and deleting stay on the loopback API. A file that isn't text (an image, a PDF) passes the gateway unscrubbed, as the API's own layer passes it: nothing takes the vault's secrets or the accounts' homes out of it there. That's accepted: it was scanned before it was kept (above).
