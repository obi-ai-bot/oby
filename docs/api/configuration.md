### obid only: configuration

Internally, `Config.mac_home` names the Mac-wide stores (API token, devices and pairing,
gateway, phone relay, push and cleanup measurement; [PROFILES-12](contracts/profiles.md)).
It is always initialized to `home` today, so file locations and API behavior are unchanged.
It is not a configuration-file key. Profile stores and `Jobs::open` remain unchanged in PROF-2.

```sh
obid serve --config /path/to/config.json
```

```json
{"listen": "127.0.0.1:7811",
 "home": "/abs/path/obid-home",
 "owner": "wellington",
 "agents": {"claude": {"bin": "claude", "accounts": [{"id": "default", "name": "Default", "configDir": null}]}},
 "repos": [{"repo": "obi-e2e/fixture-app", "remote": "file:///abs/path/remote.git", "defaultBranch": "main", "check": "node --test"}],
 "allowFileRemotes": false}
```

- `listen`: an address on 127.0.0.1. obid binds only that, and refuses with `403` every request whose `Host` isn't `127.0.0.1`, `localhost` or `[::1]` (with or without a port), as a Mac runner does. Required, but on macOS, where it is `127.0.0.1:7777` when left out: where the Mac app looks for the runner on the same Mac.
- `home` (required, absolute): everything obid keeps, and the only place it writes besides its `HOME` and `TMPDIR`: its format (`schema.json`, 0600, `{"format": 1, "writtenBy": "<obid's version>"}`: obid writes it at start into a home with none or an older `format`, and refuses a newer or unreadable one, below; HOME-5 to 7), its database, the API token (`api-token`, 0600), the accounts the API changed (`accounts.json`, 0600, and the folders it makes, `accounts/<id>`), the Obi key (`keys/`, 0600), clones (`clones/<owner>/<name>`), job worktrees (`worktrees/<job id>`), plug-ins (`plugins/`, `plugin-data/`), and the settings the API changes: `settings.json` (`maxRunning`, `PUT /v1/settings/jobs`; `noCheck`, the repositories the owner said No check for, Job; an older obid's `checksOffered` isn't read) and `permissions.json` (the permission settings and the saved rules: `PUT /v1/settings/permissions`, `/v1/permissions/rules`), each kept across restarts.
- `owner` (required): the owner's id, as their Sphere knows them.
- `agents.claude.bin`: the Claude Code adapter's binary, a path (a relative one is taken from obid's own folder, and run by its absolute path) or a command name found on the login shell's `PATH` (AGENTS.md, "PATH"; its absolute folders only), then in `~/.local/bin`, `~/.bun/bin`, `~/.cargo/bin` (where `cargo install` puts tools, `oby-check-blok` among them), nvm's default node's `bin` (the newest `~/.nvm/versions/node/v*` that `~/.nvm/alias/default` names) and `/opt/homebrew/bin`, where installers put the CLIs that only an interactive shell's `.zshrc` adds to `PATH`. Every process obid starts gets that `PATH`. `accounts`: each `{id, name, configDir, payer}` (`payer` optional); they are the seed the accounts API changes ([obid only: accounts](#obid-only-accounts)); `configDir` is the account's folder, where its login is kept (and, on macOS, what names its Keychain item), or null for the tool's own default login; no box ever gets the folder itself: every run gets a folder of its own with a copy of the login ("The job sandbox", #655). `GET /v1/status` sends each one with `signedIn` true when its login is there and a run can use it (#626): Claude Code's `.credentials.json` in its `configDir`, or `~/.claude/.credentials.json` when `configDir` is null; Codex's `auth.json` in its `configDir`, or `~/.codex/auth.json`, unless its access token ends within 5 minutes (then `signedIn` false and `label` `Run codex once`: a run's copy can't refresh it); Cursor's login file (`.cursor/auth.json` on macOS, `.config/cursor/auth.json` elsewhere) in its `configDir`, or in the person's home for Cursor's own login, holding an `accessToken` or `apiKey`, or for Cursor's own login with no such file, its macOS Keychain items with `cursorKeychain`; an empty value is none, and an access token whose JWT `exp` has passed counts only with an `apiKey` beside it. The Keychain's values are read for this at most once a minute (whether an item exists, every time); one that has ended reads `signedIn: false` with `label` `Run cursor-agent once`, and a job on it doesn't start, saying the Mac's Cursor login has ended (only the Mac's own cursor-agent refreshes it). Each is a regular file, never a link. obid only looks whether Claude Code's exists; Codex's and Cursor's it reads for those fields alone, and sends nothing of them anywhere. A Claude Code login only in the macOS Keychain counts when `claudeKeychain` is on, since obid then copies it where a run reads it (The job sandbox, under obid only: Obi-to-Obi review jobs); with it off it doesn't, since the job sandbox denies the Keychain. Routing (a job with no `account`, the brain's dispatches and reviews) takes the signed-in account with the most room, of any tool with `agent` left out (USAGE-11: `defaultAccount` first, then the fullest window each last reported emptiest first, a window reset since reading empty, then one reporting none, a Cursor figure counting as none beside another tool's; ties in the tools' order, Claude Code, Codex, Cursor); when none is signed in, it takes the first account as before, and the tool's own words say why it can't run. A job naming its account runs there. Codex and Cursor take the same shape when their adapters land (`CODEX_HOME`, `CURSOR_CONFIG_DIR`).

`home/settings.json` is read one key at a time (docs/contracts/home.md, HOME-11 and HOME-12): a value that doesn't read is its default, and obid logs the file and the key, never the value; every other value is kept. A file that isn't a JSON object, or can't be read, gives every default, as before. The API token is the one in `home/api-token` (0600, at least 32 visible characters): obid makes it on first start, or takes the one put there before it starts. The shells on the same machine read it there. It is never in obid's environment or arguments, where any process of the same user can read it (on macOS through `KERN_PROCARGS2`, which no sandbox holds back; #439): obid refuses to start when `OBID_API_TOKEN` is set, saying to put the token in that file instead. The same holds for every secret obid holds: none is ever in its environment or arguments, nor in a child's. Every request sends `Authorization: Bearer <token>`; anything else is `401`. Every `/v1` answer carries `Cache-Control: no-store` (unless it sets its own, like the event stream's `no-cache`) and `X-Content-Type-Options: nosniff`. `GET /v1/status` adds `"engine": "obid"` to `runner`. **While it starts** obid answers as soon as it listens: until it has opened everything (the Keychain and vault probes, the accounts, the sandbox's self-check, the jobs), `GET /v1/status` with the token answers `503` with `Retry-After: 1` and `{"error": "Oby’s engine is starting.", "starting": {"ms": <since it started>, "done": [{"step": "listen", "ms": 0}, …], "now": "<the step under way>"}}`, and every other call waits until obid is ready, then answers as usual. A call without the token, or from a name other than loopback's, is refused at once (`401`, `403`), never held; an agent's own routes (`/v1/agent/mcp/<id>`, `/v1/agent/tetrix/<id>`, one Bearer token, from loopback or, on Linux, `10.0.2.2`) wait too, at most 64 at once (`503` starting beyond), and their tokens are checked once obid is ready. A start that fails answers the calls that waited `503` (`Oby’s engine didn’t start.`) and says why in `home/last-start-error`; a stop while starting answers them `503` (`Oby’s engine is stopping.`). On SIGTERM or SIGINT obid stops taking requests, leaves its jobs as a restart would (After any restart, above) and exits 0 within 10 seconds.

**A start that fails says why.** obid logs a line as each step of its start ends (`starting: vault done in 3 ms`), then one with them all (`obid started in 312 ms: …`), so a start that hangs names the step after the last one logged. A top-level key of the configuration it doesn't know (one a later obid retired, or an earlier one wrote), and a key retired from a section (`conversation.harness`), are ignored, with a warning in the log that names each (`conversation.harness isn't a key this obid knows: ignored`), so an update never stops on one; any other unknown key inside a section (`agents`, a tool, an account, `repos`, `vault`) is still refused, so a typo (`checks` for `check`) never quietly drops a check. Nothing optional stops a start either: a busy gateway, a Sphere key that can't be read (left out and said in the log and `GET /v1/obid/sphere`'s `lastError`; `POST /v1/obid/sphere/key` is then `409` rather than make a new key over it, which would end the Obi and its paired phones), or a folder for exchanges, the inbox or artifacts it can't make (each save then fails with its own reason). Its last words before it exits are on stderr with the time, like its log's lines. When it can't start (a configuration it refuses, a token it can't use, a home it can't make, the API's address taken), it writes the reason it logs to `home/last-start-error` (the configuration's `home` as its JSON names it, else Oby.app's `~/Library/Application Support/Oby/Runner`) and exits non-zero; the apps on the Mac show it in place of a wait. It's removed once obid listens. A home whose `schema.json` names a higher `format` than this obid's (a newer obid wrote it: the downgrade case), or one obid can't read (not JSON, no whole-number `format`, a folder), stops the start before obid changes anything in the home but `last-start-error`, with exit code `3`, used for nothing else: the reason names the file and, for a newer home, the version in its `writtenBy`, both formats and this obid's version (`… schema.json: written by Oby 9.9.9 in home format 2, newer than this obid's format 1 (Oby 0.1.0): run that version of Oby or newer`). obid checks it right after it reads the configuration, before it makes or tightens the home or touches `api-token`, and again first thing in `serve` (docs/contracts/home.md, HOME-5 to 7). The `security` probes obid asks while it starts end within 5 seconds (60 for a value, which can wait on the Keychain's prompt), so a Keychain that doesn't answer can't hold its start up.
